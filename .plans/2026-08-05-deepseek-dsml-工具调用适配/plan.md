# DeepSeek DSML 工具调用适配计划

目标：将 DeepSeek Flash 文本响应中的 DSML 工具调用转换为现有工具循环可执行的调用，并避免原始协议显示在页面。

范围：仅扩展 `vw-agent` 的文本工具调用回退解析，识别完整的 `<｜DSML｜tool_calls>` 包装、`invoke` 与 `parameter` 标签，复用现有 XML 参数解析、工具名规范化、展示文本清理和回退调用 ID 逻辑。

范围外：不修改 DeepSeek/Shiju API 请求格式、原生工具调用协议、工具权限与执行策略，也不改 GUI 渲染。

假设：附件中的 DSML 输出由 provider 作为普通响应文本返回，并进入 `parse_tool_calls`；现有 MiniMax 属性 XML 解析器已能正确解析规范化后的 `invoke` 与 `parameter` 内容。

## 设计决策

- 只在完整 DSML 工具调用包装内规范化标签，避免对普通文本中的相似片段做宽泛替换。
- 复用现有属性 XML 解析器与 canonical 工具名映射，保持 `Bash`、`Write` 等名称的既有行为。
- 未闭合或无有效调用的 DSML 只报告解析问题，不执行猜测出的内容。

## 架构说明

- 入口保持为 `parse_tool_calls`，DSML 是优先于通用 XML 回退的显式协议分支。
- 测试覆盖附件中的多调用、长 HTML 参数、周边文本清理，以及损坏 DSML 的拒绝路径。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
