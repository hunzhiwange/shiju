# 任务 5: 网关合并迁移

批次：【批次 3】依赖批次：批次 2 的任务 4

状态：未开始

目的：将 `/v1/git/merge` 的分支校验、目标保存、祖先判断、快进、合并提交与冲突回滚迁移到 git2。

来源任务：无

预计会话范围：只处理网关合并域和测试；复用任务 4 的 git2 提交辅助逻辑，不处理远程分支、rebase 或 cherry-pick。

## 文件

- 修改：`crates/vw-agent/src/gateway/api/handlers/git.rs`
- 修改：`crates/vw-agent/src/gateway/api/handlers/git_tests.rs`

## 上下文

- 当前合并会切到目标 worktree、自动提交目标脏改动、判断祖先、执行 fast-forward 或 merge commit，并在失败后 abort/reset。
- git2 可通过 worktree 列表、reference、merge analysis、merge trees/index 和 cleanup_state 实现等价本地语义。
- 合并与自动保存原本使用 `--no-verify`，迁移后继续不执行 hooks。

## 测试计划

- 行为：无 Git PATH 时支持 already-merged、fast-forward、two-parent merge、脏目标自动提交，并在冲突后恢复目标分支和干净仓库状态。
- 失败验证测试：新增 `gateway_git2_merge_works_without_git_executable` 与 `gateway_git2_merge_conflict_restores_target_state`。
- 失败验证命令：`cargo test -p vw-agent gateway_git2_merge_works_without_git_executable`
- 预期失败原因：当前 verify、checkout、merge-base、merge 与 abort 都依赖外部 Git。
- 通过验证命令：`cargo test -p vw-agent gateway_git2_merge_ && cargo test -p vw-agent git_merge_v1_`
- 模拟策略：使用真实分叉提交图和真实冲突文件；不模拟 merge analysis 或 index conflict。

## 步骤

1. 编写覆盖四种成功形态和冲突恢复的失败测试。
2. 运行失败验证并确认外部 Git 缺失。
3. 用 git2 定位目标分支所在 worktree并 checkout；保存目标脏改动。
4. 根据 merge analysis 实现已合并、快进和普通合并；普通合并写入双父提交。
5. 冲突时 hard reset 原目标 OID、checkout、cleanup_state，并返回保留上下文的明确错误。
6. 删除 `git_command_success`、`git_worktree_path_for_branch`、`abort_git_in_progress_states` 与剩余合并 CLI 辅助代码。
7. 运行聚焦合并测试与全目标 Clippy。

## 验证

- 运行：`cargo test -p vw-agent gateway_git2_merge_ && cargo test -p vw-agent git_merge_v1_ && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：提交图父节点、分支 OID、worktree 路径、响应字段和冲突恢复全部符合断言；Clippy 退出码为 0。
- 所需证据：实现前失败；实现后 fast-forward 与 merge commit 图断言、冲突后状态断言、无 Git PATH 和 Clippy 成功证据。

## 完成

完成时 `/v1/git/merge` 不启动 Git 子进程，保持现有响应和目标脏改动保护，并能在冲突后可靠恢复。
