# 任务 1: 扩展公证脚本

批次：【批次 1】 无

状态：已完成

目的：让 bundle 脚本支持 CI 临时钥匙串，并对最终 DMG 完成公证与装订。

来源任务：用户要求最终 macOS 包通过 CI/CD 生成，同时保留手工本地打包。

预计会话范围：仅修改现有 macOS bundle 脚本的公证边界，不改变构建内容或其他平台流程。

## 文件

- 修改：`scripts/bundle_macos.sh`

## 上下文

- 当前脚本只通过默认钥匙串 profile 公证 ZIP，并在创建 DMG 前结束公证。
- CI 的 Notary profile 将存入 runner 临时钥匙串，需要把钥匙串路径传给 `notarytool submit`。

## 验证计划

- 行为：指定临时钥匙串时 ZIP 和 DMG 均使用该 profile 公证，且拒绝不存在的钥匙串。
- 失败验证命令：`rg -n 'NOTARY_KEYCHAIN_PATH|stapler staple.*DMG' scripts/bundle_macos.sh`
- 预期失败原因：当前脚本没有临时钥匙串参数，也没有 DMG 公证。
- 通过验证命令：`bash -n scripts/bundle_macos.sh && rg -n 'NOTARY_KEYCHAIN_PATH|submit_for_notarization' scripts/bundle_macos.sh`
- 模拟策略：模拟 `security`、`codesign`、`xcrun` 与 `spctl`，不上传真实构建产物。

## 步骤

1. 记录 CI 钥匙串和 DMG 公证入口缺失。
2. 添加可选 Notary 钥匙串路径和统一提交函数。
3. 复用函数完成 ZIP 与 DMG 公证，保持本地默认钥匙串兼容。
4. 运行语法与模拟路径验证。

## 验证

- 运行：`bash -n scripts/bundle_macos.sh`
- 运行：模拟正式 ZIP/DMG 签名公证命令
- 预期：两个产物均出现 Accepted、staple 和 validate，错误状态立即退出。
- 所需证据：退出码、关键模拟命令输出、已审查差异。

## 完成

`scripts/bundle_macos.sh` 接受 CI 临时钥匙串路径，并让正式 DMG 成为签名、公证、装订完成的顶层发布产物。
