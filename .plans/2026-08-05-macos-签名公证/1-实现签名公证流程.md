# 任务 1: 实现签名公证流程

批次：【批次 1】 无

状态：已完成

目的：提供独立开发构建目标和默认正式签名、公证目标。

来源任务：用户要求将原 `make macos` 改名为 `make macos-dev`，并让 `make macos` 成为签名版本。

预计会话范围：仅修改 macOS 构建入口、组包脚本与相邻文档，围绕一个发布行为完成实现和聚焦验证。

## 文件

- 修改：`Makefile`
- 修改：`scripts/bundle_macos.sh`
- 修改：`scripts/BUILDING.md`

## 上下文

- 当前脚本使用 `codesign --deep --sign -` 做 ad-hoc 签名并忽略验证失败。
- 正式包包含 `vw-webview`、`shiju`，可选包含 `vibe-agent`、`acp`，最后签名 `ShiJu.app`。
- 当前机器没有可用签名身份，因此只能验证缺参失败和静态流程，不能完成真实 Apple 公证。

## 验证计划

- 行为：`make macos-dev` 走开发签名，`make macos` 走正式签名公证且缺少安全配置时明确失败。
- 实现前验证：`make -n macos-dev`
- 预期失败原因：原 Makefile 没有 `macos-dev` 目标。
- 通过验证命令：`bash -n scripts/bundle_macos.sh && make -n macos-dev && make -n macos`
- 缺参验证：`env -u MACOS_SIGN_IDENTITY -u MACOS_NOTARY_PROFILE MACOS_SIGN_MODE=developer-id MACOS_NOTARIZE=1 PACKAGE_APP=1 scripts/bundle_macos.sh`
- 预期：正式路径在执行构建前报告缺少签名身份；不会访问网络或写入凭据。

## 步骤

1. 记录 `macos-dev` 目标缺失的失败证据。
2. 在 Makefile 中拆分开发目标与正式目标，并更新兼容别名语义。
3. 在 bundle 脚本中增加正式签名预检、内嵌二进制签名、公证、装订和最终验证。
4. 更新构建文档，说明钥匙串凭据初始化与两个目标的用途。
5. 运行聚焦验证与仓库要求的 clippy。

## 验证

- 运行：`bash -n scripts/bundle_macos.sh`
- 运行：`make -n macos-dev`
- 运行：`make -n macos`
- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：shell 语法正确；Make 目标展开到各自模式；缺参正式流程明确失败；clippy 无本次变更引入问题。
- 所需证据：命令退出码、关键目标展开内容、缺参错误文本、已审查差异。

## 完成

完成后，`make macos-dev` 可继续生成本地 ad-hoc `.app`；`make macos` 仅在提供 Developer ID 身份和公证钥匙串 profile 时生成签名、公证并装订票据的最终 ZIP。
