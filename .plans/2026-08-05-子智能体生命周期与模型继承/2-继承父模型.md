# 任务 2: 继承父模型

批次：【批次 1】 无

状态：已完成

目的：AgentTool 创建的子会话请求继承父智能体当前显式选择的模型。

来源任务：无

预计会话范围：沿既有请求链增加一个可选模型值，并用注入的 stream 执行器验证最终 Gateway 请求。

- 测试：`crates/vw-agent/src/session/child_agent_tests.rs`

## 上下文

- `processor::Request.model` 是父轮次已解析的显式模型。
- `resolve_delegate_request_overrides` 已定义显式 model 优先于 agent 绑定模型。

## 测试计划

- 行为：父 AgentTool 带 `provider/model` 时，子 Gateway 请求包含相同 model。
- 失败验证测试：`run_inherits_parent_selected_model_in_child_stream_request`
- 失败验证命令：`cargo test -p vw-agent run_inherits_parent_selected_model_in_child_stream_request`
- 预期失败原因：当前 `stream_request` 始终让 `model` 使用默认 None。
- 通过验证命令：`cargo test -p vw-agent run_inherits_parent_selected_model_in_child_stream_request`
- 模拟策略：只注入 LLM stream 边界，真实创建子 Session 并检查真实请求对象。

## 步骤

1. 编写捕获子 Gateway 请求 model 的失败测试。
2. 运行测试并确认 model 缺失。
3. 以可选字段贯通 ToolRuntimeContext、AgentTool 与 ChildAgentRunInput。
4. 在 processor runner 中注入当前请求模型。
5. 运行聚焦测试与相关周边检查。

## 验证

- 运行：`cargo test -p vw-agent run_inherits_parent_selected_model_in_child_stream_request`
- 预期：捕获的子请求 model 为 `provider/model`。
- 所需证据：失败验证与通过验证输出、退出码 0、无模型时保持 None 的现有测试。

## 完成

完成后 `stream_request` 必须显式携带父模型，且不改变未指定模型的现有默认行为。
