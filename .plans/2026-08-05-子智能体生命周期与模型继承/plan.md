# 子智能体生命周期与模型继承计划

目标：后台子智能体不因父消息流被新消息替换而取消，并继承父智能体当前显式选择的模型。

范围：调整 AgentTool 后台子会话收尾语义；把会话处理请求中的模型沿工具上下文、AgentTool、子会话 Gateway 请求传递；补充聚焦回归测试。

范围外：不改变显式 stop/任务计划停止的取消语义，不改变 agent 自身配置，不调整子智能体模式 UI 的默认开关。

假设：桌面端当前选择模型已通过 Gateway 请求进入 `processor::Request.model`；AgentTool 的 `launch` 是应跨父消息轮次存活的后台操作。

## 设计决策

- 父消息事件接收端关闭只终止该轮事件转发，不再隐式取消已启动的后台子任务。
- 父请求显式模型写入子请求的 `model` 字段；现有 Gateway 规则继续保证显式模型优先于 agent 绑定模型。
- 显式 `AgentTool stop` 与任务计划停止仍是取消子任务的唯一主动控制路径。

## 架构说明

- 模型从 `processor::Request` 进入 `ToolRuntimeContext`，再由带生命周期回调的 AgentTool 构造路径注入 `ChildAgentRunInput`。
- 后台任务状态仍由全局 `ChildAgentCoordinator` 持有，避免与单次父消息流生命周期耦合。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
