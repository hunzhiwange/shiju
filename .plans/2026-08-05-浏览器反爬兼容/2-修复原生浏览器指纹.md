# 任务 2: 修复原生浏览器指纹

批次：【批次 2】 依赖批次 1

状态：未开始

目的：让 Rust Native WebDriver 后端在有头和无头模式下都使用与默认后端一致的基础自动化指纹修复。

来源任务：用户要求浏览器访问网页不再总被反爬拦截。

预计会话范围：仅修改 ChromeDriver 会话能力及其请求捕获测试；不改变 WebDriver 端点探测、重连、动作实现或后端选择。

## 文件

- 修改：`crates/vw-agent/src/tools/browser/native_backend/session.rs`
- 测试：`crates/vw-agent/src/tools/browser/native_backend/session_tests.rs`

## 上下文

- `NativeBrowserState::ensure_session` 集中生成 `goog:chromeOptions`；当前有头模式不发送任何 Chrome 参数，无头模式只发送 `--headless=new` 和 `--disable-gpu`。
- 现有 WebDriver stub 会捕获 `/session` 请求体，可直接验证发送给 ChromeDriver 的能力，而无需启动真实 WebDriver。
- 目标参数必须应用于两种显示模式；无头参数和自定义 Chrome 路径仍按现有规则保留。

## 测试计划

- 行为：有头和无头 WebDriver 会话都包含一次 `--disable-blink-features=AutomationControlled`，无头会话仍保留原有参数。
- 失败验证测试：新增 `ensure_session_always_disables_automation_controlled`，并收紧现有 `ensure_session_sends_headless_arguments_and_trimmed_binary` 断言。
- 失败验证命令：`cargo test -p vw-agent --features browser-native --lib ensure_session_always_disables_automation_controlled`
- 预期失败原因：当前有头会话没有 `args`，无头会话也没有自动化规避参数。
- 通过验证命令：`cargo test -p vw-agent --features browser-native --lib ensure_session`
- 模拟策略：模拟边界仅为 ChromeDriver HTTP 端点；测试真实的 W3C `/session` 请求结构和 `goog:chromeOptions` 数据形状。

## 步骤

1. 新增有头会话失败测试，并更新无头会话预期参数。
2. 运行失败验证命令并确认 `/session` 能力缺少目标参数。
3. 在 `ensure_session` 的公共 Chrome 参数列表中加入自动化规避参数，再按 `headless` 条件追加原有参数。
4. 确认空 Chrome 路径、会话复用和关闭流程没有行为变化。
5. 运行聚焦测试和仓库 clippy。

## 验证

- 运行：`cargo test -p vw-agent --features browser-native --lib ensure_session`
- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：所有 `ensure_session` 聚焦测试通过；请求体在两种模式下均包含目标参数；clippy 无本次变更引入的问题。
- 所需证据：失败断言、通过测试数量与退出码、捕获请求体断言、clippy 退出码和已审查差异。

## 完成

完成后，`NativeBrowserState::ensure_session` 会为有头和无头 ChromeDriver 会话统一关闭 Blink 自动化标记，同时保留现有无头参数、二进制路径和生命周期行为。
