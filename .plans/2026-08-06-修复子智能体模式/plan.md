# 修复子智能体模式计划

目标：子智能体模式保留 AgentTool 编排能力，但不再强制至少一次委派，并让子 Agent 使用自身配置模型。

范围：调整桌面端与 TUI 的子智能体模式请求和提示词；移除 AgentTool 对父会话模型的覆盖；更新聚焦测试并执行仓库规定的 clippy。

范围外：不修改 AgentTool 的深度、并行度、安全权限、后台终态等待和子会话持久化机制。

假设：Gateway 在请求未显式指定模型时，会根据 `agent` 配置补全 provider/model；现有日志已证明父模型 `openai/glm-5` 覆盖会导致子会话找不到模型。

## 设计决策

- 子智能体模式改为优先使用 AgentTool，不以未委派为错误终止条件。
- 子会话模型由所选子 Agent 配置决定，不继承父请求的显式模型。

## 架构说明

- 桌面端与 TUI 继续注入模式提示并确保 AgentTool 在允许列表中。
- AgentTool 继续创建持久化子会话，Gateway 负责按 `agent` 解析模型。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
