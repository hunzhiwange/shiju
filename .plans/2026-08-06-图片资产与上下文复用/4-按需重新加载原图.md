## 上下文

- `ImageInfoTool` 可选返回 Base64，但不具备稳定资产范围语义，不能复用为本功能。
- `ToolUseContext` 在同一工具循环中共享，适合保存有界的待重看 `image_id` 队列。
- 工具返回文本会进入历史，因此绝不能把 Base64、绝对路径或原始图片写入工具结果。

## 测试与验证计划

- 行为：只接受当前范围可见 ID；未知/跨范围 ID 明确拒绝；工具结果无图片字节；下一 step 注入一次；成功后再次恢复文本；重复 ID 去重并受数量上限约束。
- 测试优先：先新增 `tool_rejects_unknown_or_cross_scope_image_id`、`tool_result_never_contains_image_payload`、`requested_image_is_attached_to_next_step_once`、`successful_reload_returns_to_text_context`、`pending_reload_ids_are_deduplicated_and_bounded`。
- TDD 例外：仓库禁止未经用户要求运行 `cargo test`；先写测试但不执行断言，以 Clippy 编译测试目标、捕获型假 LLM 和安全差异审查作为证据。
- 编译验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 模拟策略：资产存储使用临时目录，工具和 LLM 使用进程内假实现。

## 步骤

1. 在工具上下文加入线程安全、去重、有数量上限的待重看 ID 状态，并绑定当前资产范围。
2. 先写范围拒绝、无载荷结果、一次性注入、恢复文本和上限测试。
3. 实现只读 `ImageAssetReadTool`，参数只包含 `image_id`；解析当前范围资产后登记待重看状态。
4. 工具结果只返回简短确认或明确错误，不返回路径、MIME data URI、Base64、OCR 或摘要正文。
5. 在 `tools/mod.rs` 和默认工具集中注册稳定小写 key `image_asset_read`，不增加别名。
6. 在 session processor 与旧 Agent 循环的下一 LLM step 前消费待重看 ID，读取压缩模型输入并一次性注入。
7. 只有该 LLM step 成功后才清除对应待重看状态；网络失败重试允许继续携带，成功后恢复引用/解析表示。
8. 为数量上限、失效资产和并发工具调用保留清晰错误。
9. 运行强制 Clippy并检查所有路径解析都经过当前范围。

## 验证

- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：退出码 0，无警告；工具已注册且测试目标可编译；工具输出中无原始图片载荷。
- 所需证据：五类测试存在；跨范围访问被拒绝；下一 step 只注入一次；失败重试与成功清除语义明确；无任意路径参数。

## 完成

完成后，模型可通过 `image_asset_read(image_id)` 安全请求重新看图，图片只在下一次成功 LLM step 临时出现，随后继续使用缓存文本上下文。
