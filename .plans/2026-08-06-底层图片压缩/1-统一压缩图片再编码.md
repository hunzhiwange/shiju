# 任务 1: 统一压缩图片再编码

批次：【批次 1】无

状态：已完成，待回归

目的：让底层 Agent 在生成 Base64 前按请求预算压缩静态图片，并保持现有安全拒绝边界。

来源任务：无

预计会话范围：变更集中在 `vw-agent` 多模态模块及其独立测试；包含一个压缩助手、三类图片来源接线和一次强制 Clippy 验证，适合单个聚焦会话完成。

## 文件

- 新建：`crates/vw-agent/src/multimodal/image_compression_tests.rs`

## 上下文

- `prepare_messages_for_provider` 已知整次请求图片数量。
- `normalize_data_uri`、`normalize_remote_image`、`normalize_local_image` 当前校验后直接 `STANDARD.encode(bytes)`。
- 使用已有 `image 0.25.9`，不得新增依赖或用户配置。
- 所有图片处理必须是进程内 Rust 代码；禁止 Python、ImageMagick、FFmpeg、shell 命令和外部压缩 API。
- 源图片上限与 MIME 白名单保持安全默认拒绝。

## 测试与验证计划

- 行为：静态大图在 Base64 前按最长边与请求级字节预算压缩；小图保持原格式；多图共享总预算；GIF 不静默降为单帧。
- 测试优先：先新增 `large_static_image_is_resized_and_bounded_before_base64`、`small_image_preserves_original_bytes_and_mime`、`multiple_images_share_normalized_byte_budget`、`gif_is_not_silently_flattened`。
- TDD 例外：仓库明确禁止未经用户要求执行 `cargo test`，因此不运行失败断言；先提交测试代码，再以 Clippy 编译测试目标并审查差异证明接线。
- 编译验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 模拟策略：使用内存生成的真实 PNG/JPEG fixture；远程来源沿用现有单次 HTTP fixture，只模拟网络边界。

## 步骤

1. 在独立测试文件中加入压缩、小图保留、多图预算和 GIF 语义测试。
2. 新建 `image_compression.rs`，仅用 Rust `image` crate 实现像素尺寸检查、白底合成、等比缩放、分级 JPEG 质量与有界失败。
3. 在 `prepare_messages_for_provider` 按图片数量计算单图输出预算，并传入三类来源归一化函数。
4. 让 data URI、远程字节和本地字节在现有 MIME/源大小校验后共用压缩助手，使用返回的新 MIME 与字节生成 data URI。
5. 保留不需要压缩的原始字节；GIF 仅走原内容路径，超过请求输出预算时返回明确不支持压缩的错误。
6. 运行强制 Clippy，检查只修改计划内文件且无大规模格式化。
