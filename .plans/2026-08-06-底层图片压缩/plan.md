# 底层图片压缩计划

目标：在底层多模态归一化阶段压缩图片，再生成 Base64 data URI，降低单图及多图模型请求体积。

范围：仅使用 Rust 修改 `vw-agent` 多模态模块；本地文件、远程图片和 data URI 共用压缩路径。保留现有源图片数量、源字节大小和 MIME 白名单边界，限制归一化后的图片尺寸与总字节预算，并补充独立单元测试。

范围外：不使用 Python、ImageMagick、FFmpeg、系统命令或外部压缩服务；不修改 OCR、历史图片缓存、对象存储、供应商文件 ID、桌面附件交互和网关请求体上限。

假设：当前 `image 0.25.9` 依赖可完成解码、等比缩放和 JPEG 编码；主流视觉模型已接受现有白名单中的 JPEG 输入；动态 GIF 不应在本次变更中静默丢失动画语义。

## 设计决策

- 选择在 `vw-agent::multimodal` 归一化边界压缩，覆盖桌面会话、Agent 循环、Gateway 简单聊天和 OpenAI JSON 转换。
- 解码、像素处理、缩放和编码全部使用 Rust `image` crate 在进程内完成，不启动子进程。
- `max_image_size_mb` 继续作为源图片读取安全上限；输出采用内部尺寸和总预算，不新增用户配置。
- 小于预算且尺寸合适的图片保留原字节与 MIME；需要压缩的静态图片转为 JPEG，透明像素先合成白底。
- 动态 GIF 保留原内容并受现有限制约束，不在本次变更中取首帧伪装成完整图片。
- 输出预算按本次请求图片数量分摊，避免多张图片各自合规但总体 Base64 仍过大。

## 架构说明

- `prepare_messages_for_provider` 负责计算请求级图片预算，`image_compression.rs` 只负责有界解码与压缩。
- 本地、远程和 data URI 在 MIME 与源大小校验后调用同一助手，再统一生成 data URI。
- 解码失败、尺寸异常或无法压到预算内时返回明确错误，不发送未受控的大图片。

## 开发策略

- 先新增行为测试，再实现压缩与三类来源接线。
- 仓库禁止未经明确要求运行 `cargo test`；新增测试由强制 Clippy 编译，最终行为证据以测试代码审查、聚焦差异和全量 Clippy 为准。
- 实现仅限多模态模块，不顺带修改 OCR、历史复用或网关限制。
