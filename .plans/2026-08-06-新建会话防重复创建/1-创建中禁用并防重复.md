# 任务 1: 创建中禁用并防重复

批次：【批次 1】 无

状态：已完成

目的：确保任一新会话创建请求进行中时不能再次提交，并在创建结束后恢复入口。

来源任务：无

## 上下文

- `ProjectCreateSession` 直接创建或打开 worktree 选择器；后两种提交消息在 `worktree.rs` 发起异步创建；结果由 `SessionCreated`/`SessionCreateFailed` 处理。
- 状态仅用于当前进程，不写入配置。

## 测试计划

- 行为：创建进行中时重复创建消息被忽略且入口模型标记禁用，成功或失败后状态恢复。
- 失败验证测试：为消息守卫、结果清理和工作模式空间模型增加行为测试。
- 失败验证命令：`cargo test -p vw-desktop project_create_session_ --lib && cargo test -p vw-desktop session_created_ --lib && cargo test -p vw-desktop work_sidebar_ --lib`
- 预期失败原因：应用尚无创建中状态，重复消息仍生成任务，模型也无法表达禁用。
- 通过验证命令：`cargo test -p vw-desktop project_create_session_ --lib && cargo test -p vw-desktop session_created_ --lib && cargo test -p vw-desktop work_sidebar_ --lib`
- 模拟策略：直接调用现有消息处理器并检查 Iced `Task`/应用状态，不模拟网关响应。

## 步骤

1. 为上述行为编写失败验证测试。
2. 运行失败验证命令并确认预期失败。
3. 实现让测试通过所需的最小生产代码变更。
4. 运行通过验证命令和仓库要求的 Clippy。
5. 仅在测试保持通过时进行重构。

## 验证

- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：聚焦测试通过，Clippy 退出码为 0；若仅有无关既有改动造成失败，记录具体错误。
- 所需证据：新增测试先失败后通过、聚焦测试与 Clippy 的退出码、审查差异仅覆盖本任务范围。
