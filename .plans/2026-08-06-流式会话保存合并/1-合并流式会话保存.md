# 任务 1: 合并流式会话保存

批次：【批次 1】 无

状态：未开始

目的：保证同一会话最多一个保存执行中，突发增量只保留最新待保存快照，并让失败日志包含真实 gateway 错误。

来源任务：无

预计会话范围：改动集中在流式保存辅助函数、gateway 同步包装和相邻测试；不改变会话模型、服务端 API 或其它保存路径，适合一个聚焦会话完成。

- 修改：`crates/vw-desktop/src/app/session_gateway.rs`
- 修改：`crates/vw-desktop/src/app/session_gateway_tests.rs`
- 修改：`crates/vw-desktop/src/app/message/chat/stream/mod.rs`
- 修改：`crates/vw-desktop/src/app/message/chat/stream/tests.rs`

## 上下文

- `handle_agent_session_delta` 每个流式增量都会调用 `save_session_task`。
- native `save_session_task` 经 `spawn_blocking_opt` 调用 `gateway_save_session`，后者当前把 `Result` 折叠为 `Option`。
- 保留现有测试 hook；协调器应可本地实例化，以隔离并发测试。

## 测试计划

- 行为：首个保存阻塞期间连续提交三个同会话快照，实际只保存首个和最新一个；其它会话不被合并；保存错误保持原始文本。
- 失败验证测试：在 `stream/tests.rs` 新增 `stream_session_saves_coalesce_to_latest_snapshot_while_in_flight`，在 `session_gateway_tests.rs` 新增同步保存结果入口的错误传递测试。
- 失败验证命令：`cargo test -p vw-desktop stream_session_saves_coalesce_to_latest_snapshot_while_in_flight --lib`
- 预期失败原因：当前每次增量都会独立执行保存，没有按会话单飞与最新值替换能力。
- 通过验证命令：`cargo test -p vw-desktop stream_session_saves_coalesce_to_latest_snapshot_while_in_flight --lib`
- 模拟策略：只用可控回调替代 gateway 网络保存；输入使用真实 `ChatSession` 快照，断言实际保存顺序和最终内容。

## 步骤

1. 编写并发失败测试：阻塞首个保存，提交两个更新快照，证明当前会执行全部保存而非首个与最新一个。
2. 运行聚焦测试并确认按预期失败。
3. 在 `session_gateway.rs` 新增保留原始 `Result` 的 native 同步保存入口，并让旧 `gateway_save_session` 复用它。
4. 在 `stream/mod.rs` 实现按 `session_id` 的模块内单飞协调器；执行中仅替换最新待保存快照，锁外调用 gateway。
5. 让 native `save_session_task` 通过协调器工作，并在实际保存失败时记录原始错误、会话与目录。
6. 补充错误传递和跨会话隔离断言，保持现有测试 hook 可用。
7. 运行聚焦测试及仓库规定的 clippy，审查差异只包含本任务文件。
