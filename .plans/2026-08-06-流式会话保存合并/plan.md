# 流式会话保存合并计划

目标：将流式响应期间的会话持久化改为单会话单飞并合并最新快照，避免 gateway 请求风暴，同时保留实际失败原因。

范围：仅调整桌面端聊天流的会话保存调度、native 阻塞保存的错误传递及相邻测试。流式增量仍实时更新内存与界面；持久化最多保留一个执行中快照和一个最新待保存快照，最终状态必须落盘。

范围外：不修改 gateway 服务生命周期、端口配置、todo 轮询、会话存储格式、非流式会话操作及现有无关工作区改动。

假设：日志已证明 `handle_agent_session_delta` 每个增量都会创建保存任务；`gateway_save_session` 当前将具体错误折叠为 `None`；完成和步骤事件仍会提交更新后的会话快照。

## 设计决策

- 选择模块内按 `session_id` 合并的单飞协调器；相比固定抽样，它不会遗漏最终快照，相比串行队列，它不会积压并回写大量过时快照。
- native 保存继续在阻塞线程执行，避免改变 Iced 运行时边界；新增保留 `Result` 的同步入口，旧 `Option` 入口保持现有调用语义。
- 保存失败按实际执行次数记录，并包含 `session_id`、目录和原始错误；不增加配置项或静默降级。

## 架构说明

- 调度逻辑留在 `app/message/chat/stream`，gateway 领域调用留在 `app/session_gateway`。
- 协调器只持有最新待保存快照；锁内不执行网络或文件操作，避免跨会话阻塞。
- 测试使用本地协调器和可控保存回调验证单飞/合并，避免依赖真实 gateway。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实调度行为；仅模拟 gateway 保存边界，以便稳定控制首个请求处于执行中。
