# 任务 3: 流路由按工作流门控并叠加目标

批次：【批次 3】 依赖批次 2

状态：未开始

目的：只有工作流开启才进入 `task_plan_run`；目标仅决定 plan-run 使用 `Goal` 还是 `Workflow`；单独开启目标不再把请求当成严格工作流。

来源任务：无

预计会话范围：只改桌面 `agent_stream` 请求体路由与相关测试；轻量无工作流续轮留给任务 4。

## 上下文

- 现状：`workflow_mode_active = (workflow || goal) && !resume_history_only`，导致仅开目标也会强制 `task_plan_run` 并走建计划路径。
- 新规则：
  - `plan_run = workflow_mode_enabled && !resume_history_only`
  - `plan_run && goal` → `TaskPlanRunMode::Goal`
  - `plan_run && !goal` → `TaskPlanRunMode::Workflow`
  - `!plan_run` → 普通 gateway chat（即使 `goal_mode_enabled`，本任务暂不续轮）
- 缺项目根目录错误文案仅在工作流开启时触发，不要再因目标模式单独报「需要项目根目录」。
- 日志字段继续记录两个独立开关。

## 测试计划

- 行为：仅 goal 不构造 `TaskPlanRunRequest`；workflow+goal 构造 `mode=Goal`；仅 workflow 构造 `mode=Workflow`。
- 失败验证测试：`goal_only_does_not_activate_task_plan_run`、`workflow_with_goal_uses_goal_plan_run_mode`、`workflow_without_goal_uses_workflow_plan_run_mode`
- 失败验证命令：`cargo test -p vw-desktop --lib goal_only_does_not_activate_task_plan_run -- --nocapture` 与 `cargo test -p vw-desktop --lib workflow_with_goal_uses_goal_plan_run_mode -- --nocapture`
- 预期失败原因：仍用 `workflow || goal` 门控。
- 通过验证命令：同上。
- 模拟策略：抽取/测试可观察的请求构造辅助函数，或对现有请求组装纯函数断言；避免全量网络。

## 步骤

1. 编写路由规则失败验证测试。
2. 运行失败验证命令并确认预期失败。
3. 将 `workflow_mode_active` 改为仅依赖 `workflow_mode_enabled`；`mode` 由 `goal_mode_enabled` 选择。
4. 运行通过验证与 clippy。
5. 更新相关注释，明确目标≠工作流。
