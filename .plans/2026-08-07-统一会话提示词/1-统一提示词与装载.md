## 上下文

- 现状：`system::provider` 按 model id 在 6 份提示间分流；`instructions()` 固定 `codex_header`。
- 旧 tip 自称“最好的编码智能体 / 软件工程 CLI”，与桌面 `WorkspaceMode::{Code,Work}` 冲突。
- 工具段硬推 Grep/Read，会盖过已注入的 `AGENTS.md`（如 rustcodegraph）。
- Compact 技能注入保持不动：摘要在系统提示，正文按需 Skill 加载，避免 Full 撑爆上下文。

## 测试计划

- 行为：任意模型的 `provider` 与 `instructions` 都返回同一份统一提示；提示含指令优先级、非纯编码身份、服从 `AGENTS.md` 的工具规则。
- 失败验证测试：改写 `crates/vw-agent/src/session/system_tests.rs` 中 `provider_selects_prompt_family_from_model_id`、`provider_prefers_the_first_matching_prompt_family`、`instructions_are_trimmed_codex_prompt`（重命名为统一语义），并增加内容断言。
- 失败验证命令：`cargo test -p vw-agent --test '' provider_returns_unified_prompt_for_all_models instructions_match_unified_prompt -- --nocapture`（以实现后的准确测试名为准；若模块内测则用 `cargo test -p vw-agent system_tests -- --nocapture` 过滤对应名）
- 预期失败原因：实现前旧常量/`PROMPT_*` 仍存在，或新测试名尚未编译；实现后应改为断言多模型同文。
- 通过验证命令：`cargo test -p vw-agent system:: -- --nocapture`
- 模拟策略：使用现有 `test_model` 构造多模型 id，不 mock 文件系统。

推荐测试名：

- `provider_returns_unified_prompt_for_all_models`
- `instructions_match_unified_prompt`
- `unified_prompt_declares_instruction_priority_and_general_assistant_role`

## 步骤

1. 编写上述失败测试：多模型 `provider` 返回相同单一 `&str`；`instructions()` 等于该正文 trim；断言关键中文/结构片段存在（指令优先级、`AGENTS.md`、代码与工作、默认工具仅作协议未覆盖时的回退）。
2. 运行失败验证，确认旧分流逻辑导致失败或编译失败符合预期。
3. 撰写 `unified.txt`（以现 `codex_header.txt` 为骨架精简重写），必须包含：
   - 通用助手身份（代码模式与工作模式皆可，不锁死“仅编码”）
   - `## 指令优先级`：用户本轮明确要求 > 已注入项目协议（`AGENTS.md` 等）> 本文件默认指引
   - `## 工具使用`：项目协议已规定导航/验证工作流时必须先遵循；仅协议未覆盖时才用专用 Read/Glob/Grep/apply_patch；Bash 用于终端与协议要求的 CLI（如索引工具）
   - 保留：编辑约束、Todo 跟踪、Git 卫生、前端任务（标明仅前端时适用）、最终答复风格
   - 删除或改写： exclusive “编码智能体 / 软件工程 CLI” 表述
4. 改 `system.rs`：单一 `PROMPT_UNIFIED = include_str!("prompt/unified.txt")`；删除各 `PROMPT_*`；`provider` 恒 `vec![PROMPT_UNIFIED]`；`instructions` 返回 `PROMPT_UNIFIED.trim()`；更新模块文档。
5. 删除旧按模型 txt（及 orphan）；保留 `max-steps.txt`。
6. 跑通过验证与相关测试。
