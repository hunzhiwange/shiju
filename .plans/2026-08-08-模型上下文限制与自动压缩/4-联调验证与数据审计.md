## 先写失败测试

1. 增加跨层 fixture：同一个未知自定义模型经过设置 patch、resolver 和 agent 后，限制为默认值，UI 使用率分母与运行时有效窗口一致。
2. 增加跨层 fixture：同一个显式配置模型经过保存、重新加载和下一轮会话请求后，限制和能力不变。
3. 增加 JSON 审计失败用例：任意模型的 `limit.context` 缺失/为 0、模态字段类型错误或文本模型缺少文本输入时测试失败。
4. 增加回归测试，确保已有 `/ui` 快照不重新携带原始 call records，避免本任务触发上下文治理时再次扩大 UI 请求体。

## 实现步骤

1. 将两份资产、共享解析器、桌面设置和 agent 运行时的字段命名与默认值统一；修复只影响测试 fixture 的不一致，不做无关格式化。
2. 更新模型详情/使用率展示，使其显示真实上下文限制、默认限制提示和输入使用率；展示逻辑使用有效输入窗口，不把累计输出 token 当成当前上下文窗口。
3. 用 `jq` 或现有 Rust 测试生成缺失项清单，逐项复核来源 URL、核对日期和模型用途；清单为空后再运行解析测试。
4. 检查现有 dirty worktree，确认只包含本任务允许的修改；保留其他任务已有改动，不使用 reset、checkout 或大范围格式化。
5. 执行聚焦测试和仓库要求的 clippy；如果发现无关既有编译错误，只记录文件与错误，不顺手修复。
