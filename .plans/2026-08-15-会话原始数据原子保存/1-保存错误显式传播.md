# 任务 1: 保存错误显式传播

批次：【批次 1】 无

状态：未开始

目的：让 UI 会话保存的数据库错误穿透 Gateway 和客户端，禁止 HTTP 200 假成功。

来源任务：无

预计会话范围：仅调整 Session UI 保存的返回类型和错误映射，不改变 raw 结构或流式协议，适合一个聚焦会话。

## 文件

- 修改：`crates/vw-agent/src/session/ui_store.rs`
- 修改：`crates/vw-agent/src/gateway/api/handlers/session/ui_ops.rs`
- 测试：`crates/vw-agent/src/gateway/api/handlers/session/ui_ops_tests.rs`
- 测试：`crates/vw-agent/src/session/ui_store_tests.rs`

## 上下文

- `run_project_operation` 当前用 `Option` 吞掉错误；`session_ui_save` 忽略该 `Option` 后固定返回 `true`。
- 新增仅供保存路径使用的 fallible API，返回 `anyhow::Result<PathBuf>`；不要求重写全部既有 Option 读取包装器。
- 缺少项目 scope、数据库连接失败和事务失败都必须成为 Gateway 非 2xx 错误。

## 测试计划

- 行为：底层 SessionStore 保存失败时，`session_ui_save` 返回错误且不返回 `true`。
- 失败验证测试：在 `ui_ops_tests.rs` 新增 `session_ui_save_propagates_session_store_failure`。
- 失败验证命令：`cargo test -p vw-agent session_ui_save_propagates_session_store_failure --lib`
- 预期失败原因：现有处理器丢弃 `save_session_ui_snapshot_scoped_for_tenant` 的 `None` 结果并返回成功。
- 通过验证命令：`cargo test -p vw-agent session_ui_save --lib`
- 模拟策略：使用测试数据库制造真实写入失败，不模拟 Gateway handler。

## 步骤

1. 为上述行为编写失败验证测试。
2. 运行失败验证命令并确认预期失败。
3. 为 UI 会话保存增加保留错误的 fallible 路径，并在 handler 中映射为 `ApiError`。
4. 保持旧的便捷 Option 包装器只服务未迁移调用点，禁止新 handler 使用它们。
5. 运行通过验证命令、相关 ui_store 测试及 clippy。

## 验证

- 预期：写入错误产生非成功结果；正常保存与 scope 隔离测试继续通过；clippy 无警告。
- 所需证据：新增测试先失败后通过、相关测试退出码 0、clippy 退出码 0、差异中无无关 Option API 重构。
