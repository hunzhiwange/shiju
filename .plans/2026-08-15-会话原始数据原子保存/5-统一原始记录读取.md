## 上下文

- 新路由使用 `session_id + turn_id + step_index`，客户端方法也必须要求 turn ID，禁止再以 session 内裸 step index 定位。
- 桌面 raw 缓存键改为稳定三元组；轨迹投影仍消费任务 2 重建后的完整 JSON，不自行拼第二套 raw。
- 当前这些桌面文件可能有用户未提交修改，执行前必须重读差异并只做最小合并。

## 测试计划

- 行为：同一会话两个 turn 都有 step 1 时，原始记录弹窗和轨迹分别显示各自内容，且返回 JSON 完全一致。
- 失败验证测试：新增 `llm_raw_endpoint_distinguishes_turns_with_same_step_index`、`trajectory_raw_cache_keys_include_turn_id`、`raw_modal_and_trajectory_share_reconstructed_payload`。
- 失败验证命令：`cargo test -p vw-agent llm_raw_endpoint_distinguishes_turns_with_same_step_index --lib`
- 预期失败原因：当前端点与桌面缓存都只用 `(session_id, step_index)`。
- 通过验证命令：`cargo test -p vw-agent llm_raw_endpoint --lib && cargo test -p vw-gateway-client session_step_llm_raw --lib && cargo test -p vw-desktop trajectory_raw --lib`
- 模拟策略：Gateway handler 使用真实 SessionStore fixture；桌面测试只替换 HTTP 边界，载荷使用真实重建 JSON。

## 步骤

1. 添加两个 turn 复用 step index 的 Gateway 失败测试。
2. 修改路由和客户端签名，强制传递 `turn_id`。
3. 将桌面 raw 索引、加载状态、错误状态和缓存改为稳定三元组。
4. 让原始记录弹窗和轨迹投影读取同一个缓存值，不复制或再次持久化。
5. 运行 Gateway、客户端、桌面聚焦测试与 clippy。
