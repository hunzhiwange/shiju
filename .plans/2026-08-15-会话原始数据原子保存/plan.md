# 会话原始数据原子保存计划

目标：会话步骤与 LLM 原始数据原子可见，同一轮公共上下文只存一次，任何持久化失败都明确返回。

范围：统一 Gateway 会话保存边界；为每个助手轮次引入稳定 `turn_id`；将公共 system、工具目录和初始消息与逐次 LLM 输入差量、输出分开存储；步骤仅引用所属轮次，工具耗时继续保存在步骤表；原始记录与轨迹读取同一份重建结果；修复 Gateway 与桌面端吞掉保存错误的问题。

范围外：不迁移旧 `session_step_llm_raw` 数据，不改变模型请求内容，不重做会话 UI，不处理与本缺陷无关的存储模块。

假设：处理器每次请求的 `step_index` 从零重新计数，不能单独作为会话级主键；Gateway 已预分配助手消息 ID，可作为稳定 `turn_id`；SQLite 与 PostgreSQL SessionStore 均支持事务；工具时间已由 `session_steps.tool_timings` 持久化。

## 设计决策

- 放弃“每步保存完整 messages”的现状：它重复增长中的上下文，且 `(session_id, step_index)` 会被后续轮次覆盖。
- 不采用每次重写一个巨大 turn JSON；选择一条 turn 公共上下文记录，加多条仅含输入差量和本轮输出的 round 记录。
- `turn_id + step_index` 标识真实 LLM 调用；同一轮工具调用不是同一请求，只共享上下文并追加工具结果差量。
- 会话快照、已完成步骤、turn 公共记录和 round 差量在同一 SessionStore 事务提交；提交失败不得返回成功或清除待提交数据。
- `查看原始记录` 与轨迹详情在读取边界重建既有完整 JSON 形状，避免 UI 持有第二份原始数据模型。

## 架构说明

- 处理器只产出类型化 raw 工件，不直接访问数据库；Gateway 以预分配助手消息 ID 聚合并交给会话保存端点。
- SessionStore 是 UI 会话与 raw 的唯一权威提交边界；消息键值存储仍是协议投影，但其失败必须显式暴露，不能伪装成功。
- 待提交 raw 只在 Gateway 内存中保留到事务确认；失败时保留以供同一会话下次保存重试，成功后按精确版本确认清理。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
