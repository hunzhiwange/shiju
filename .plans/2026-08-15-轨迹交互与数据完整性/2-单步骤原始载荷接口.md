# 任务 2: 单步骤原始载荷接口

批次：【批次 2】 依赖批次 1

状态：未开始

目的：让桌面按 session/step 精确读取 raw，避免一次补载步骤却读取整份会话和所有步骤原始数据。

来源任务：用户反馈 API 网关轨迹数据偶发缺失。

预计会话范围：新增一个只读 Gateway handler、路由和 client 调用，沿用现有 scope/tenant 隔离；不实现重试和 UI。

## 文件

- 修改：`crates/vw-agent/src/gateway/api/handlers/session.rs`
- 修改：`crates/vw-agent/src/gateway/api/handlers/session/ui_ops.rs`
- 测试：`crates/vw-agent/src/gateway/api/handlers/session/ui_ops_tests.rs`
- 修改：`crates/vw-gateway-client/src/client/session_api.rs`
- 测试：`crates/vw-gateway-client/src/client/session_api_tests.rs`

## 上下文

- 当前 `GatewayClient::session_step_llm_raw_get` 调用 `/session/{id}/ui`，加载整份 session 后从 map 提取一个 step。
- 新端点使用 `/v1/session/{session_id}/step/{step_index}/llm-raw`，必须复用 `resolve_scope_from_query`、tenant scope 和隔离数据库线程；不存在返回 JSON `null`，真实存储错误返回 5xx。

## 测试计划

- 行为：客户端读取一个步骤时只命中专用端点，并正确区分存在、不存在、跨 scope 和存储错误。
- 失败验证测试：新增 `session_step_llm_raw_get_reads_only_requested_step` 及 handler 的 scope/404 语义测试。
- 失败验证命令：`cargo test -p vw-gateway-client session_step_llm_raw_get_reads_only_requested_step --lib`
- 预期失败原因：客户端目前只请求完整 `/ui` 路由，mock server 不会收到专用路径。
- 通过验证命令：`cargo test -p vw-gateway-client session_step_llm_raw_get --lib`
- 模拟策略：handler 使用真实隔离 store；client 仅 mock HTTP 边界并断言方法、路径、查询参数和响应体。

## 步骤

1. 为 handler 和 client 写专用端点的失败测试。
2. 运行失败验证，确认 client 仍请求完整 UI 快照。
3. 实现按 tenant/scope 读取单步 raw 的 handler 并注册 GET 路由。
4. 将 client 方法改为直接调用专用端点，不再经过 `session_ui_get_with_raw`。
5. 运行两侧聚焦测试和全仓 clippy。

## 验证

- 运行：`cargo test -p vw-agent session_step_llm_raw --lib`
- 运行：`cargo test -p vw-gateway-client session_step_llm_raw_get --lib`
- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：目标步骤返回原 JSON；缺失为 `None`；scope 不串读；客户端不请求整份会话；clippy 零警告。
- 所需证据：失败测试先因路径不匹配失败；实现后两 crate 聚焦测试 0 失败；HTTP 请求记录只含目标 step；clippy 退出码 0。

## 完成

完成时 `session_api.rs` 的单步读取必须直达新路由，handler 必须通过现有租户和项目 scope 解析读取 `session_step_llm_raw`，不得退回全量会话扫描。
