# 任务 3: 轨迹原始数据有限重试

批次：【批次 3】 依赖批次 1,2

状态：未开始

目的：对刚完成但暂时返回空的步骤自动有限重试，不要求用户切回对话再重新进入轨迹。

来源任务：用户反馈最新轨迹偶发没有数据、历史稍后又出现。

预计会话范围：只修改桌面轨迹消息状态机、状态字段和状态提示；不修改后端存储、协议或视觉时间线。

## 上下文

- `AgentStepFinish` 已在轨迹模式下调用 `refresh_missing_raw_task`，但首次 `Ok(None)` 立即显示“重新进入轨迹重试”。
- 使用现有 `crate::app::message::after` 调度最多 3 次请求，首次立即执行，后两次分别延迟 300ms、900ms；`Ok(None)` 和请求错误都可进入下一次，session 切换、raw 已加载或 step 不再有效时取消后续动作，不新增配置项。

## 测试计划

- 行为：完成步骤首次返回空或请求错误时自动排队重试，成功后清除状态；三次仍失败才显示最后一次可恢复错误，过期 session 的重试不会污染当前会话。
- 失败验证测试：新增 `trajectory_raw_none_schedules_bounded_retry`、`trajectory_raw_retry_stops_after_success`、`trajectory_raw_retry_exhaustion_reports_error`。
- 失败验证命令：`cargo test -p vw-desktop trajectory_raw_none_schedules_bounded_retry --lib`
- 预期失败原因：当前 `Ok(None)` 直接写错误，不携带尝试次数，也不返回延迟 Task。
- 通过验证命令：`cargo test -p vw-desktop trajectory_raw_ --lib`
- 模拟策略：不等待真实时间；直接向 update 注入带 attempt 的消息并检查返回任务前后的状态集合，HTTP 由任务 2 的 client 测试覆盖。

## 步骤

1. 为第一次空响应、成功、耗尽和 stale session 写失败测试。
2. 运行失败验证确认现有状态机立即报错。
3. 给 raw 加载消息和加载状态加入有限 attempt；用 `after` 调度下一次精确 step 请求。
4. 成功、切换会话和不再缺失时清理 retry/loading/error；只有最后一次空响应或请求错误才显示最后错误。
5. 更新状态文案为自动重试语义，运行聚焦测试和全仓 clippy。

- 所需证据：失败验证先出现“未调度重试”；实现后聚焦测试 0 失败；状态集合无泄漏；clippy 退出码 0。

## 完成

完成时 `trajectory.rs` 应以固定、有限、可测试的重试状态机处理 `Ok(None)`；不得无限轮询、阻塞 UI 线程或把旧 session 数据写入当前视图。
