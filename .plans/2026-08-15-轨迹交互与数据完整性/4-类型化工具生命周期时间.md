# 任务 4: 类型化工具生命周期时间

批次：【批次 4】 依赖批次 1

状态：未开始

目的：为每个工具调用提供可信的开始/完成时间和所属 step，并通过 Gateway SSE 传到客户端。

来源任务：用户要求 Tools 色块按时间长短显示。

预计会话范围：实现 processor→gateway→gateway-client→desktop 消息入口的一个垂直协议切片；本任务只传输事件，不持久化到 session step，也不改轨迹 UI。

## 上下文

- `ToolEvent` 现有稳定 `call_id` 和 Start/Update/Complete，但无时间戳；Gateway 当前把它降级为 `chat.delta` 文本。
- 给事件增加 `occurred_ms`；Gateway 继续把旧格式文本追加到 `assistant_text` 以保持历史消息/工具卡不变，同时发送 `chat.tool` JSON。Gateway 在每个 `StepStart` 无条件记录当前 step_index，消息快照仍按原条件生成；工具事件读取该显式状态，不从时间或工具数组位置猜测。

## 测试计划

- 行为：工具开始和完成事件包含非递减时间、稳定 call_id 和当前 step_index；桌面仍收到等价工具文本，同时获得类型化生命周期消息。
- 失败验证测试：新增 `tool_stream_event_has_occurrence_time`、`gateway_tool_event_preserves_step_and_payload`、`normalize_chat_tool_event`、桌面 `chat_tool_event_keeps_legacy_tool_content`。
- 失败验证命令：`cargo test -p vw-agent gateway_tool_event_preserves_step_and_payload --lib`
- 预期失败原因：Gateway 当前只输出 `chat.delta`，协议中没有 occurred_ms、step_index 或工具 lifecycle 类型。
- 通过验证命令：`cargo test -p vw-gateway-client chat_tool_event --lib`
- 模拟策略：用固定构造的 ToolEvent 测试 gateway/client 边界；时间只断言存在和 start<=complete，不断言墙钟精确值。

## 步骤

1. 分别在 processor、gateway、client 和 desktop 边界写失败测试。
2. 运行失败验证确认工具事件被降级为普通 delta。
3. 给 ToolEvent 写入发生时间；让 patch recorder 即使没有 message ids 也记录 active step index，并保持快照 part 的原有条件。
4. Gateway 输出 `chat.tool`，保留对 `assistant_text` 的旧格式追加；client 新增封闭的 typed tool event 解析。
5. 桌面把 `chat.tool` 映射成专用 ChatMessage，同时复用旧工具文本更新路径，避免聊天 UI 回归。
6. 运行各层聚焦测试和全仓 clippy。

- 所需证据：失败测试先表明只有 delta；实现后各层测试 0 失败；start/complete call_id 和 step_index 一致；clippy 退出码 0。

## 完成

完成时 `chat.tool` 必须是带 step_index、call_id、name、kind、status、occurred_ms、payload 的类型化事件；聊天内容保持原有 `tool <name>\n<payload>\n` 语义。
