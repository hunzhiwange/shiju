# 任务 5: 工具时间持久化与轨迹投影

批次：【批次 5】 依赖批次 4

状态：未开始

目的：把工具生命周期合并进 session step，并让当前与历史轨迹按 call_id 读取真实工具耗时。

来源任务：用户要求历史轨迹也能显示 Tools 时间块。

预计会话范围：新增一个共享可序列化工具时间结构、桌面合并逻辑和轨迹投影映射；不实现工具栏或折叠 UI。

## 上下文

- 在 `ChatSessionStep` 增加 serde default 的 `tool_timings`，元素保存 call_id/name/started_ms/finished_ms；旧历史反序列化为空集合，不做迁移。
- Start 创建或更新同 call_id 记录，Update 不覆盖 start，Complete 填 finished_ms；乱序或重复事件幂等合并。投影按 raw tool call 的 call_id 关联，不按数组位置关联。

## 测试计划

- 行为：工具事件合并后随 session 快照序列化；重新加载历史后，匹配 call_id 的 Tool 记录得到 started/finished/duration，缺失或异常时间保持 Unavailable。
- 失败验证测试：新增 `chat_session_step_round_trips_tool_timings`、`tool_lifecycle_merges_idempotently`、`projection_uses_persisted_tool_timing_by_call_id`。
- 失败验证命令：`cargo test -p vw-desktop projection_uses_persisted_tool_timing_by_call_id --lib`
- 预期失败原因：`ChatSessionStep` 没有工具时间字段，投影生成 Tool 记录时起止时间均为 None。
- 通过验证命令：`cargo test -p vw-desktop tool_timing --lib`
- 模拟策略：使用序列化 round-trip 和纯状态更新；不 mock store，因为 `ChatSessionStep` 已由现有 session 保存路径持久化。

## 步骤

1. 为共享结构 round-trip、事件合并和投影映射写失败测试。
2. 运行失败验证确认 Tool 时长不可用。
3. 给 `ChatSessionStep` 增加默认空工具时间集合，并更新仓库内显式构造点。
4. 在 step 消息处理器按 session、step、call_id 幂等合并生命周期时间，并走现有 session 保存任务。
5. 投影按 call_id 关联 raw tool 记录；仅在 finished>=started 时计算 duration/tool_duration。
6. 运行共享和桌面聚焦测试及全仓 clippy。

## 验证

- 运行：`cargo test -p vw-shared tool_timings --lib`
- 运行：`cargo test -p vw-desktop tool_timing --lib`
- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：新旧 JSON 均可反序列化；重复/乱序事件不破坏首个 start；历史 round-trip 后 Tool 时长保持；clippy 零警告。
- 所需证据：失败验证先显示字段或时长缺失；实现后聚焦测试 0 失败；旧 fixture 无需迁移即可加载；clippy 退出码 0。

## 完成

完成时 `TrajectoryRecordKind::Tool` 的时间只来自相同 call_id 的持久化生命周期；未知、仅开始或结束早于开始的记录必须保持 `MetricAvailability::Unavailable`。
