# 可靠性配置接入计划

目标：删除三个未生效的回退与 Key 字段，让 Provider 重试参数真正控制模型请求，并在桌面帮助中说清每项配置影响的功能。

范围：修改 `ReliabilityConfig` 及其配置安全/校验调用；将 `provider_retries` 和 `provider_backoff_ms` 沿强类型会话请求传入 session processor，替换硬编码重试次数与退避；更新可靠性帮助和相邻测试。

范围外：不新增 Provider 回退、API Key 轮换、新配置开关或历史字段迁移。

假设：已持久化的三个旧字段可按用户要求直接废弃；Serde 加载时忽略它们，不保留兼容分支。当前工作树存在大量未完成改动，执行时必须保留重叠文件的用户变更。

## 设计决策

- Provider 重试次数表示“首次请求失败后额外重试次数”，因此总尝试次数为 `provider_retries + 1`。
- 以现有 `ReliabilityConfig` 作为强类型会话请求配置，不通过自由 JSON option 暗中传递全局配置。
- 模型请求重试使用配置的初始退避和指数退避，保留明确的最大等待上限；不变更“仅可重试瞬时错误”的分类规则。
- Channel 和 scheduler 已接入的字段保持现有运行逻辑，本次只补足说明和覆盖证据。

## 架构说明

- `vw-config-types` 是配置真值源；`vw-agent::session::processor::Request` 是各入口进入统一模型请求链的强类型边界。
- 桌面、Gateway、Channel、Task Plan 和 ACP 构造请求时都必须携带有效可靠性配置；不能只修一个 UI 入口。
- 开始修改前运行 `rustcodegraph sync`，并逐块检查已有 diff，避免覆盖用户在重叠文件中的工作。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
