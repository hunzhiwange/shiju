# 截图能力增强计划

目标：让代理能安全地捕获指定显示器或明确矩形区域，并将截图以可供模型视觉分析的受控图像引用返回。

范围：扩展 `screenshot` 的非交互式捕获参数和 macOS/Linux 命令构建；保留工作区与符号链接防护；让截图工具覆写 V2 `call`，以 `[IMAGE:data URI]` 交给既有多模态链路；为 browser 的 `computer_use` sidecar 传递同一组截图约束并验证请求。

范围外：不引入 Claude Code 私有依赖，不实现系统级鼠标键盘执行器，不新增远程截图服务，不支持 Windows，也不实现跨桌面环境的窗口枚举。

假设：`screenshot` 已由工具集注册；模型侧已识别 `[IMAGE:...]` 标记；macOS 使用 `screencapture`，Linux 仅在本机已安装的现有截图命令中选择可用者；sidecar 的实际服务由仓库外组件维护。

## 设计决策

- 选择扩展现有工具而非复制 Claude Code 的 Swift/Rust 原生模块：保持依赖小、跨平台失败路径明确。
- 选择 `display` 与显式矩形参数；交互式选择和前台窗口继续标记为需用户交互，不能作为自动化流程的默认路径。
- 选择复用既有 `[IMAGE:data URI]` 多模态通道，不扩大 `ToolResultContentDto` 协议。

## 架构说明

- `ScreenshotTool` 负责参数、路径、命令与图像引用；`Tool::call` 可覆写旧文本适配层。
- `ComputerUseClient` 仅验证、规范化并转发 sidecar 请求，仍由 `SecurityPolicy` 限制输出路径。
- 截图是可观察敏感内容的动作；保持自治检查、文件大小限制、超时与本地端点默认拒绝。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
