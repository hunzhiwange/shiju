# 任务 1: 共享活动请求

批次：【批次 1】 无

状态：未开始

目的：让 Iced 每次重建订阅时只复制活动请求引用，不再深复制完整 LLM 会话历史。

来源任务：无

预计会话范围：围绕 `AgentRequest` 的所有权迁移为 `Arc`，调整少量创建、读取和罕见修改调用者及其测试；不改变请求内容、哈希身份、队列或流重连语义。

## 上下文

- `SessionRuntimeState::active_agent_request` 当前保存值类型，`App::subscription` 在每次更新中调用 `.clone()`；请求的 `Hash`/`Eq` 已只使用 `id`。改为 `Arc<AgentRequest>`，创建时包裹一次，订阅用 `Arc::clone`，重置历史的唯一可变路径使用 `Arc::make_mut`。
- 保留 `session.rs` 中用户已有的异步 scoped 保存改动，不回退为同步网关调用。

## 测试计划

- 行为：多次收集活动订阅请求时共享同一请求和历史分配，同时请求 id/hash 身份与后台会话并存逻辑不变。
- 失败验证测试：在 `app_subscription_tests.rs` 新增 `subscription_request_collection_reuses_shared_request_allocation`，并更新现有活动/后台请求测试夹具。
- 失败验证命令：`cargo test -p vw-desktop subscription_request_collection_reuses_shared_request_allocation`
- 预期失败原因：当前 `active_agent_request` 和订阅收集结果是值类型，每次收集都会深复制历史，无法通过 `Arc::ptr_eq` 证明共享。
- 通过验证命令：`cargo test -p vw-desktop subscription_request_collection_reuses_shared_request_allocation && cargo test -p vw-desktop subscription_builds_agent_runtime_states`
- 模拟策略：使用真实 `App`、两个会话运行时和大历史请求；不启动网络流，只在 Iced 订阅构造边界验证共享所有权。

## 步骤

1. 提取只读的活动订阅请求收集函数，并先写共享分配失败测试。
2. 运行失败验证命令，确认值类型深复制导致测试失败或无法编译。
3. 将活动请求状态改为 `Arc<AgentRequest>`，调整创建、读取、take 和罕见写时复制路径。
4. 更新受影响测试夹具，验证前台与后台请求仍各自生成稳定订阅。
5. 运行聚焦测试和仓库 clippy，仅在保持通过时整理类型导入。

## 验证

- 运行：`cargo test -p vw-desktop subscription_request_collection_reuses_shared_request_allocation && cargo test -p vw-desktop subscription_builds_agent_runtime_states && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：两个测试退出码为 0；重复收集的相同请求满足 `Arc::ptr_eq`；clippy 无警告。
- 所需证据：失败测试的原始失败、通过后的测试摘要、受影响调用点审查清单、clippy 退出码 0。

## 完成

完成时应确认 `crates/vw-desktop/src/app/state/agent.rs` 的活动请求为共享不可变载荷，`app_subscription.rs` 不再深复制历史，`session.rs` 的重置路径只在必要时写时复制；不得改变请求 id 的订阅身份。
