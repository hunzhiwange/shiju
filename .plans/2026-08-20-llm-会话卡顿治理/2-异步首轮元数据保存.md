# 任务 2: 异步首轮元数据保存

批次：【批次 2】 依赖批次 1

状态：未开始

目的：确保创建首轮会话时先更新用户可见状态，再由后台任务保存 scoped 会话元数据。

来源任务：无

预计会话范围：审查并完成工作区现有的 `save_agent_session_scoped_task` 草案，只处理新会话元数据的网关保存时机，不改完整聊天快照协调器或网关 API。

## 文件

- 修改：`crates/vw-desktop/src/app/message/chat/session.rs`
- 测试：`crates/vw-desktop/src/app/message/chat/session_tests.rs`

## 上下文

- 原生路径曾在 Iced 更新调用栈中执行 `gateway_save_agent_session_scoped`，其内部 `block_on_gateway` 会同步等待 HTTP。当前未提交草案已统一使用 `gateway_save_agent_session_scoped_async` 和 `Task::perform`，该草案属于用户改动，必须保留并验证。

## 测试计划

- 行为：首轮发送立即把 user/assistant 占位消息写入 `App` 并进入 requesting 状态，scoped 元数据保存只表现为返回任务的一部分。
- 失败验证测试：完善 `session_tests.rs` 的 `start_new_session_appends_user_message_before_background_gateway_save`，验证状态已落地且返回任务包含后台保存单元。
- 失败验证命令：`cargo test -p vw-desktop start_new_session_appends_user_message_before_background_gateway_save`
- 预期失败原因：同步原生实现不会返回 scoped 保存任务，任务单元数量与异步行为断言不符。
- 通过验证命令：`cargo test -p vw-desktop start_new_session_appends_user_message_before_background_gateway_save`
- 模拟策略：使用真实 `App` 和本地任务构造，不执行任务、不访问网关；测试 Iced 更新边界的可观察状态。

## 步骤

1. 先审查用户现有差异，确认没有覆盖任务 1 的共享请求改动。
2. 运行失败验证；如草案已使测试通过，使用基线差异证明原实现会失败，并记录为现有草案验证而非伪造失败。
3. 保持 scoped 保存统一走异步函数，错误只通过现有 warning 和 `SessionSaveAck` 回到消息循环。
4. 检查首轮消息、requesting、会话 id 和任务单元断言。
5. 运行聚焦测试与仓库 clippy。

## 验证

- 运行：`cargo test -p vw-desktop start_new_session_appends_user_message_before_background_gateway_save && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：测试退出码为 0；首轮状态同步可见且保存任务异步；clippy 无警告。
- 所需证据：基线或原实现失败依据、通过测试摘要、`save_agent_session_scoped_task` 无同步 `block_on` 调用的差异审查、clippy 退出码 0。

## 完成

完成时 `crates/vw-desktop/src/app/message/chat/session.rs::save_agent_session_scoped_task` 必须在原生和 wasm 路径都返回异步任务，首轮发送不能等待网关元数据保存。
