# 任务 3: 保留相同历史界面状态

批次：【批次 3】 依赖批次 2

状态：未开始

目的：网关返回与当前可见历史相同的消息时，只补齐元数据，不重置滚动、虚拟列表和渲染缓存。

来源任务：无

预计会话范围：审查并完成现有 `SessionMessagesLoaded` 草案，限定在同一活动会话、角色和内容完全相同的刷新分支；不同历史仍走原有完整替换。

## 文件

- 修改：`crates/vw-desktop/src/app/message/project/session/lifecycle.rs`
- 测试：`crates/vw-desktop/src/app/message/project/session/lifecycle_tests.rs`

## 上下文

- 当前用户草案增加 `same_visible_history` 分支，保留 `chat_scroll_id`、turn focus、`active_session_view_state` 与 `chat_render_cache`，同时更新 message ids、usage、steps 和轨迹。必须验证排序后的网关消息与当前 chat 比较，且内容变化时不误用快速路径。

## 测试计划

- 行为：相同历史刷新保留 UI 状态；任一角色或内容变化仍替换历史并使旧 UI 缓存失效。
- 失败验证测试：保留 `session_messages_loaded_same_content_preserves_scroll_and_ui_cache`，新增 `session_messages_loaded_changed_content_replaces_history_and_invalidates_ui_cache`。
- 失败验证命令：`cargo test -p vw-desktop session_messages_loaded_same_content_preserves_scroll_and_ui_cache`
- 预期失败原因：原实现无条件生成新 scroll id、替换 chat 并使活动视图重新准备。
- 通过验证命令：`cargo test -p vw-desktop session_messages_loaded_same_content && cargo test -p vw-desktop session_messages_loaded_changed_content`
- 模拟策略：使用真实生命周期 reducer 和网关消息 DTO；不模拟 UI 组件，只验证状态机结果。

## 步骤

1. 先运行相同历史失败测试并记录旧行为。
2. 审查现有草案的比较时机、消息排序和 id 长度修正。
3. 补充内容变化反例，确保快速路径不吞掉真实更新。
4. 保持相同历史分支继续更新 usage、steps、message meta 和轨迹任务。
5. 运行聚焦测试与仓库 clippy。

## 验证

- 运行：`cargo test -p vw-desktop session_messages_loaded_same_content && cargo test -p vw-desktop session_messages_loaded_changed_content && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：相同历史测试保留所有 UI 标识；变化历史测试证明替换仍生效；clippy 无警告。
- 所需证据：旧实现失败、两个方向的通过测试摘要、快速路径字段更新清单、clippy 退出码 0。

## 完成

完成时 `lifecycle.rs` 只能在可见角色/内容逐项一致时保留 UI 状态；`chat_message_ids`、usage、steps 和消息元数据必须使用网关最新值。
