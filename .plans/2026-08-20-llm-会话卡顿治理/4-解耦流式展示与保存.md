# 任务 4: 解耦流式展示与保存

批次：【批次 4】 依赖批次 3

状态：未开始

目的：流式 delta 更新内存界面时不再每次克隆并保存完整会话，完整快照按会话去抖且终态强制保存。

来源任务：无

预计会话范围：增加一个固定的一秒保存去抖状态和消息，复用现有 `StreamSessionSaveCoordinator`；不改变界面增量间隔、网关终态持久化或会话文件格式。

## 上下文

- `finish_active_stream_tail_update` 当前每次调用 `load_session_or_default`，深复制 chat/ids/calls/steps 后立即 `save_session_task`。协调器只能合并已构造的快照，无法避免 UI 线程上的构造成本。
- 在 `SessionRuntimeState` 增加 `stream_save_flush_scheduled`；新增 `AgentStreamSessionSaveFlush(session_id)`，延迟到期时从最新状态构造一次快照。完成、取消、错误路径先清除标记并直接保存最终快照，迟到的定时消息必须无操作。

## 测试计划

- 行为：同一会话多个 delta 在一秒窗口内最多安排一个完整保存，终态总是保存包含最后 delta 的最新快照。
- 失败验证测试：在 `stream_events_tests.rs` 新增 `stream_deltas_debounce_full_session_save` 和 `stream_done_persists_latest_delta_and_cancels_debounce`。
- 失败验证命令：`cargo test -p vw-desktop stream_deltas_debounce_full_session_save`
- 预期失败原因：当前每次应用 delta 都立刻返回完整保存任务，没有独立保存调度状态。
- 通过验证命令：`cargo test -p vw-desktop stream_deltas_debounce_full_session_save && cargo test -p vw-desktop stream_done_persists_latest_delta_and_cancels_debounce`
- 模拟策略：使用现有 `with_save_session_hook` 只替换持久化外边界并记录快照；delta 合并、状态更新和终态 reducer 使用真实实现。

## 步骤

1. 编写多 delta 保存次数和终态最新内容失败测试。
2. 增加按 session 保存调度标记与延迟消息路由。
3. 从活动和后台增量应用路径移除即时完整快照构造，只安排一次保存刷新。
4. 在完成、取消、错误路径清除调度并同步构造最终快照交给现有后台保存任务。
5. 验证迟到保存消息不重复落盘，运行聚焦测试和仓库 clippy。

## 验证

- 运行：`cargo test -p vw-desktop stream_deltas_debounce_full_session_save && cargo test -p vw-desktop stream_done_persists_latest_delta_and_cancels_debounce && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：窗口内只调度一次保存；终态快照含最后 delta；协调器既有测试继续通过；clippy 无警告。
- 所需证据：失败时的重复保存信号、通过后的保存计数与快照内容、终态路径审查、clippy 退出码 0。

## 完成

完成时 `stream_events.rs` 的普通增量应用不得调用 `load_session_or_default` 构造完整保存对象；只有保存刷新或终态路径可以构造并提交完整快照。
