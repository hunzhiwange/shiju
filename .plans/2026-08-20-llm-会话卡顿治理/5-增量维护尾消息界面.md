# 任务 5: 增量维护尾消息界面

批次：【批次 5】 依赖批次 4

状态：未开始

目的：流式热路径只处理新增 delta，避免反复扫描和复制不断增长的完整 assistant 文本。

来源任务：无

预计会话范围：为每个会话维护最小的尾消息流状态，增量更新思考块开闭、计数和粗略高度，并限制 UI 预热只处理最新一代；不重写通用历史消息解析器。

## 上下文

- 当前一次活动 delta 会在 `update_think_timing_from_delta` 和 `chat::update` 两次调用 `split_think`，还会由高度估算和后台 `prepare_chat_ui_message_phase` 再解析完整文本。新增状态必须正确处理跨 delta 拆开的 `<think>`/`</think>` 标签，并在终态用通用解析结果校准。
- `ProjectMessage::SessionUiPrepared` 及其 lifecycle 处理需要携带尾消息代次；旧代次后台结果返回时不得覆盖新内容的缓存。

## 测试计划

- 行为：跨块思考标签、普通文本和工具块到达时，增量状态与最终 `split_think` 结果一致，且旧 UI 预热结果不会覆盖最新代次。
- 失败验证测试：新增 `stream_tail_state_handles_split_think_tags_from_deltas`、`stream_tail_height_uses_delta_without_full_message_scan`、`stale_stream_ui_phase_is_ignored`。
- 失败验证命令：`cargo test -p vw-desktop stream_tail_state_handles_split_think_tags_from_deltas`
- 预期失败原因：当前没有只接收 delta 的尾状态，思考信息只能从完整累计文本重新解析。
- 通过验证命令：`cargo test -p vw-desktop stream_tail_state_ && cargo test -p vw-desktop stale_stream_ui_phase_is_ignored`
- 模拟策略：对纯状态机使用真实字符串分块，对 UI 准备使用真实 `PreparedChatUiPhase`；只把后台调度边界表示为代次，不模拟解析器。

## 步骤

1. 用多种标签拆分位置编写增量状态失败测试，并以通用 `split_think` 作为最终语义对照。
2. 在会话运行时增加只保存必要游标、开闭状态、计数、粗略高度和预热代次的状态。
3. 让 delta 应用直接更新该状态；移除 `chat::update` 对流事件的第二次完整 `split_think`。
4. 将高度增长改为基于 delta 的增量估算，终态或非流式历史加载仍使用通用估算器校准。
5. 为 UI 预热结果增加代次校验，运行聚焦测试与仓库 clippy。

## 验证

- 运行：`cargo test -p vw-desktop stream_tail_state_ && cargo test -p vw-desktop stale_stream_ui_phase_is_ignored && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：所有标签分块得到一致状态；热路径辅助函数签名只接收 delta 与小状态；旧代次结果被拒绝；clippy 无警告。
- 所需证据：失败测试、分块矩阵通过摘要、热路径不再调用完整解析/估算函数的差异审查、clippy 退出码 0。

## 完成

完成时普通流式 delta 的同步路径不得扫描完整 assistant 内容；通用 `split_think` 和完整 UI 解析只用于终态校准、历史加载或后台最新代次准备。
