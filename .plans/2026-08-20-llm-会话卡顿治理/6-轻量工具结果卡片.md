# 任务 6: 轻量工具结果卡片

批次：【批次 6】 依赖批次 5

状态：未开始

目的：聊天主列表只渲染工具名称、摘要和详情入口，完整输出仅在用户打开详情弹窗后构建。

来源任务：无

预计会话范围：审查并完成工作区现有 `text_view` 草案，删除内联展开正文、滚动编辑器和右键正文路径；保留错误、权限、工作流预览和详情弹窗能力。

## 文件

- 修改：`crates/vw-desktop/src/app/components/chat_panel/tools/text_view.rs`
- 测试：`crates/vw-desktop/src/app/components/chat_panel/tools/text_view_tests.rs`

## 上下文

- 当前用户草案已移除 `chat_tool_expanded` 驱动的正文、长文本截断编辑器和内联复制按钮，并统一使用 `OpenToolDetail`。该草案必须与暗黑主题、错误标题、权限摘要和工作流预览现有行为一起验证。
- 中文标题继续使用默认字体；不得为中文错误标题引入等宽字体。

## 测试计划

- 行为：超大成功/错误工具输出在主列表只生成轻量卡片，详情按钮仍携带完整原始结果，问题工具和工作流预览保持原行为。
- 失败验证测试：新增 `text_tool_card_keeps_full_output_only_in_detail_action` 和 `text_tool_error_card_keeps_detail_entry_without_inline_editor`。
- 失败验证命令：`cargo test -p vw-desktop text_tool_card_keeps_full_output_only_in_detail_action`
- 预期失败原因：原实现会根据展开状态构建正文编辑器和滚动区域，无法证明主卡片不包含内联正文路径。
- 通过验证命令：`cargo test -p vw-desktop text_tool_card_ && cargo test -p vw-desktop text_tool_error_card_`
- 模拟策略：使用真实工具 JSON 和消息构造辅助函数；不渲染窗口，但需要额外执行现有非 ASCII/详情弹窗实际渲染路径检查。

## 步骤

1. 审查现有草案并先补齐详情动作与错误卡片失败测试。
2. 保持主卡片只包含 header/summary/detail，删除已无调用者的展开和内联编辑辅助代码。
3. 验证权限错误、普通错误、问题工具和工作流预览仍能进入正确详情或专用动作。
4. 通过桌面实际渲染路径打开含中文错误标题和大输出的详情弹窗，确认无 panic、布局与暗黑主题可读。
5. 运行聚焦测试与仓库 clippy。

## 验证

- 运行：`cargo test -p vw-desktop text_tool_card_ && cargo test -p vw-desktop text_tool_error_card_ && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：主卡片测试不触达内联编辑器；详情动作保留完整输出；实际渲染无 panic；clippy 无警告。
- 所需证据：失败/通过测试摘要、实际详情弹窗检查记录、移除无用辅助符号的差异、clippy 退出码 0。

## 完成

完成时 `text_view.rs::tool_text_view` 不得按输出长度创建正文 `text_editor` 或内联 `scrollable`；完整输出必须由现有工具详情弹窗按需展示。
