# 任务 7: 首增量立即贯通

批次：【批次 7】 依赖批次 6

状态：未开始

目的：模型产生的第一个非空文本或推理增量不等待服务端或桌面定时窗口，后续增量保持有界合并。

来源任务：无

预计会话范围：调整 `vw-agent` 的 LLM 增量合并器和桌面会话 delta 队列；依赖任务 4、5 已消除高频完整保存和全量解析，才把后续桌面合并间隔降到固定 50ms。

## 文件

- 修改：`crates/vw-agent/src/session/processor/llm_runner.rs`
- 修改：`crates/vw-desktop/src/app/message/chat/stream/stream_events.rs`
- 测试：`crates/vw-agent/src/session/processor/llm_runner_tests.rs`
- 测试：`crates/vw-desktop/src/app/message/chat/stream/stream_events_tests.rs`

## 上下文

- 服务端当前只在累计 1024 字符或某次事件到达时已超过 33ms 才刷新；首个小包可能等待下一事件。桌面活动会话当前固定等待 1 秒。首包应立即发出，后续服务端维持 33ms/1024，桌面维持 50ms；终态先冲刷 pending delta。

## 测试计划

- 行为：第一个普通文本和第一个推理增量立即触发 `StreamEvent::Delta`；桌面第一个活动会话 delta 立即进入 chat，后续连续 delta 被 50ms 窗口合并且终态不丢尾包。
- 失败验证测试：新增 `llm_stream_emits_first_text_delta_immediately`、`llm_stream_emits_first_reasoning_delta_immediately`、`active_stream_applies_first_delta_without_flush_timer` 和 `active_stream_terminal_flushes_pending_delta`。
- 失败验证命令：`cargo test -p vw-agent llm_stream_emits_first_text_delta_immediately && cargo test -p vw-desktop active_stream_applies_first_delta_without_flush_timer`
- 预期失败原因：两层现有逻辑都会先把首个小增量放入 pending 缓冲区。
- 通过验证命令：`cargo test -p vw-agent llm_stream_emits_first_ && cargo test -p vw-desktop active_stream_`
- 模拟策略：复用 LLM runner 的测试事件源，真实运行合并器；桌面使用真实 reducer 和可控消息任务，不访问网络。

## 步骤

1. 分别编写服务端文本、推理首包和桌面首包失败测试。
2. 在 LLM 合并器中显式跟踪各通道是否已发首包，首个非空块立即交给 `on_event`。
3. 在桌面 delta 队列中直接应用活动会话首包；后续使用 50ms 固定窗口，后台会话保持现有较低优先级策略。
4. 确认 Done、Error、Cancel 先冲刷 pending，且任务 4 的最终保存包含尾包。
5. 运行两个 crate 的聚焦测试与仓库 clippy。

## 验证

- 运行：`cargo test -p vw-agent llm_stream_emits_first_ && cargo test -p vw-desktop active_stream_ && cargo clippy --all-targets --all-features -- -D warnings`
- 预期：首个文本/推理/桌面 delta 均无需推进定时器即可观察；后续合并和终态尾包测试通过；clippy 无警告。
- 所需证据：四个测试的失败与通过摘要、首包路径日志顺序、终态内容断言、clippy 退出码 0。

## 完成

完成时首增量不得经过 `FLUSH_MIN_INTERVAL` 或 `ACTIVE_STREAM_DELTA_FLUSH_INTERVAL`；后续增量仍必须节流，不能退回逐 token 重排。
