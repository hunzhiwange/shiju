## 上下文

- `tool_icon`、`tool_verb`、`tool_icon_badge` 和 `tool_header_title` 已集中在 `tool_meta.rs`，别名先通过 `canonical_tool_name` 归一化。
- 新增 UI 层 `ToolVisualState` 与展示结果，覆盖 `waiting/queued`、`running`、`completed/success`、`error/failed/denied`、`cancelled` 和未知值；不得改变 `tool_parse.rs` 的协议解析。
- 复用现有 `Icon`：文件读取用 `FileText`、编辑用 `Pencil`、终端用 `Terminal`、搜索用 `Search`、网页用 `Globe`/`Link`、Agent 用 `Robot`、MCP 用 `Box`、状态用 `Clock`/`ArrowRepeat`/`Check`/`X`。

## 测试计划

- 行为：常见工具类型不再退化为同一箭头或文件图标，生命周期原始值稳定映射到状态图标、标签和色调，未知值为中性且不伪造完成。
- 失败验证测试：新增 `tool_icons_distinguish_common_activity_types`、`tool_visual_state_maps_all_supported_lifecycles`、`unknown_tool_visual_state_is_neutral`。
- 失败验证命令：`cargo test -p vw-desktop tool_icons_distinguish_common_activity_types`
- 预期失败原因：当前读取/写入共享 `ChevronRight`，且不存在统一生命周期展示模型。
- 通过验证命令：`cargo test -p vw-desktop tool_icons_distinguish_common_activity_types && cargo test -p vw-desktop tool_visual_state_ && cargo test -p vw-desktop unknown_tool_visual_state_`
- 模拟策略：直接输入真实工具名别名和协议已出现的状态字符串，不 mock 主题、协议或工具执行器。

## 步骤

1. 先写图标区分和生命周期映射失败测试，覆盖暗黑/明亮主题需要的色调分支。
2. 最小修改 `tool_icon` 的常见工具映射，保持别名一致和未知工具显式中性回退。
3. 新增 UI-only 生命周期枚举及纯映射函数，定义图标、简短中文标签、是否动画和主题色调。
4. 让 `tool_icon_badge` 可消费统一展示结果，但保持现有调用者在任务 2 前继续编译。
5. 运行聚焦测试与仓库 clippy，审查未引入 emoji、新依赖或协议变更。
