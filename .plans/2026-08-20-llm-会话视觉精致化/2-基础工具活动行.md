## 上下文

- `tool_header_title` 已被多数专用视图调用；本任务新增状态化入口，原布尔错误入口在任务 3 完成剩余迁移前继续服务真实调用者，之后删除。
- 头部固定结构为“20px 类型图标槽 + 动作标题 + 单行摘要 + 弹性空白 + 16px 状态槽 + 悬停详情入口”；状态槽存在时不得改变行高。
- 完成态静态且低对比；等待、运行、失败、取消必须保留区别；权限待确认继续使用现有权限徽标，不用普通等待态覆盖。
- 任务不得恢复性能计划已移除的内联大输出、文本编辑器或嵌套滚动区。

## 测试计划

- 行为：通用、Bash、连续命令、文件、配置和 LSP 视图在各生命周期构建一致头部，类型和状态可同时辨识，详情动作仍可触发。
- 失败验证测试：新增 `shared_tool_headers_build_for_all_lifecycle_states`、`bash_tool_header_uses_shared_type_and_status_slots`、`tool_header_keeps_permission_and_detail_actions`。
- 失败验证命令：`cargo test -p vw-desktop shared_tool_headers_build_for_all_lifecycle_states`
- 预期失败原因：现有标题 API 只接收错误布尔值，Bash 无类型图标，各视图无法表达等待、完成和取消。
- 通过验证命令：`cargo test -p vw-desktop shared_tool_headers_ && cargo test -p vw-desktop bash_tool_header_ && cargo test -p vw-desktop tool_header_keeps_`
- 模拟策略：使用真实 `tool <name>\n{json}` 载荷构建 Iced 元素；不 mock 工具状态，详情动作通过真实 `Message` 变体断言。

## 步骤

1. 先补共享头部、Bash 和权限/详情动作失败测试。
2. 将 `tool_header_title` 调整为消费任务 1 的展示结果，并保持固定类型与状态槽。
3. 逐一迁移通用、Bash、连续命令、文件、配置和 LSP 视图，只替换头部组合；未迁移专用视图继续走仍有真实调用者的旧入口。
4. 统一标题 13px、摘要 13px、图标光学居中和 4–8px 间距；路径/命令继续使用内容安全字体，中文标题不使用等宽字体。
5. 用 `cargo run -p vw-desktop --bin shi-ju` 打开包含中文摘要、长命令、文件搜索、等待、运行、完成和失败的实际会话，检查暗黑主题与悬停详情入口。
6. 运行聚焦测试与仓库 clippy，审查没有改动工具正文或执行行为。
