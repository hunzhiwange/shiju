## 上下文

- 助手消息当前无背景、用户消息使用轻量气泡；正文 15px、元信息 13px、行高 1.52，方向正确但表面宽度、块间距和元信息权重仍需统一。
- 保留助手文档式平面布局；用户气泡改为内容优先、最大宽度受控的表面，避免整行铺满。
- Markdown 解析和纯 ASCII 代码等宽字体策略必须保持；中文或混合代码块继续使用默认聊天字体。

## 测试计划

- 行为：用户与助手层级明显但不过度卡片化；标题、段落、列表、引用、代码、工具块和元信息形成稳定间距；操作按钮空闲时弱化、悬停时可见。
- 失败验证测试：新增 `message_visual_contract_keeps_assistant_flat_and_user_compact`、`markdown_visual_contract_preserves_readable_block_hierarchy`、`message_actions_remain_accessible_with_subtle_idle_style`。
- 失败验证命令：`cargo test -p vw-desktop message_visual_contract_keeps_assistant_flat_and_user_compact`
- 预期失败原因：当前用户 `bubble_inner` 固定 `Length::Fill`，无法证明内容宽度受控；视觉合同也未覆盖 Markdown 与操作按钮层级。
- 通过验证命令：`cargo test -p vw-desktop message_visual_contract_ && cargo test -p vw-desktop markdown_visual_contract_ && cargo test -p vw-desktop message_actions_remain_`
- 模拟策略：使用真实 `App`、中文/英文 Markdown、附件标记和消息角色构建 Iced 元素；不 mock 字体整形或消息动作。

## 步骤

1. 抽取可测试的消息 padding、宽度和表面样式合同，先写用户/助手差异失败测试。
2. 保持助手平面正文，将用户消息限制为内容优先的适度最大宽度、柔和圆角和无重阴影表面。
3. 调整正文、工具块、思考块、处理时长、元信息和 footer 的垂直节奏，减少重复分隔线与空白。
4. 收敛 Markdown 标题尺寸梯度、段落间距、列表缩进、引用条和代码块边框；不修改解析器和文本内容。
5. 弱化复制/分叉/重置按钮空闲色，保持悬停、按下、成功复制和键鼠交互清晰。
6. 用 `cargo run -p vw-desktop --bin shi-ju` 实际渲染含中文标题、混合代码块、长段落、嵌套列表、引用、附件和权限徽标的会话，检查暗黑/明亮主题。
7. 运行聚焦测试与仓库 clippy。
