# 任务 6: 会话外壳与视觉回归

批次：【批次 6】 依赖批次 5

状态：未开始

目的：统一消息列、状态行与输入卡片的阅读轴、边距和表面关系，并完成真实场景视觉回归。

## 上下文

- 聊天滚动内容当前水平填满后仅加 18px 边距；输入卡片也填满可用宽度，并使用默认 20px 圆角、12px 偏移和 32px 模糊阴影。
- 新增共享阅读列最大宽度，消息、空会话、状态与输入区使用同一中心线；窄窗口仍以 `Length::Fill` 和安全 padding 自适应。
- 主题皮肤的输入背景、边框与圆角覆盖继续优先，所有滚动条必须保持 4px。

## 测试计划

- 行为：宽屏会话形成居中且不过长的阅读列，窄屏无水平溢出；输入卡片与消息区连续而不过度悬浮，主题皮肤覆盖和 4px 滚动条不回归。
- 失败验证测试：新增 `conversation_shell_uses_shared_reading_column_width`、`input_panel_aligns_with_chat_column_on_wide_and_narrow_layouts`、`input_surface_shadow_is_subtle_and_skin_overrides_survive`。
- 失败验证命令：`cargo test -p vw-desktop conversation_shell_uses_shared_reading_column_width`
- 预期失败原因：当前消息与输入分别 `Length::Fill`，不存在共享最大宽度；默认输入阴影也高于目标视觉权重。
- 通过验证命令：`cargo test -p vw-desktop conversation_shell_ && cargo test -p vw-desktop input_panel_aligns_ && cargo test -p vw-desktop input_surface_shadow_`
- 模拟策略：使用真实 Iced 元素树、`Theme::Dark`/`Theme::Light` 和 `ChromeStyleOverrides`；不 mock 主题解析或输入交互。

## 步骤

1. 先写共享阅读列、宽窄布局和皮肤覆盖失败测试。
2. 在会话组件内定义一个有消息列和输入区真实调用者的阅读列宽度合同，居中包装消息内容与输入卡片。
3. 调整宽屏/窄屏 padding、底部状态与输入区间距，确保跳底按钮、问题导航、覆盖层锚点和滚动虚拟化不受影响。
4. 降低默认输入卡片阴影和边框对比，保持拖拽高亮、皮肤背景、皮肤边框和皮肤圆角覆盖。
5. 运行 `cargo run -p vw-desktop --bin shi-ju`，在暗黑、明亮、带聊天背景皮肤三种主题下检查空会话、短会话、长会话、运行中、等待权限、工具失败和窄窗口。
6. 检查所有滚动条仍为 4px，中文正文、工具摘要、动态状态、弹窗与输入区无字形整形 panic。
7. 运行聚焦测试与仓库 clippy，并审查最终差异没有改变业务消息或输入动作。

完成时消息、状态与输入区共享稳定阅读轴，主题皮肤和所有输入能力保持原行为；这是本计划的最终视觉回归门槛。
