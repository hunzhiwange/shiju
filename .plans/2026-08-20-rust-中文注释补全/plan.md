# Rust 中文注释补全计划

目标：为仓库中当前缺少中文注释的 Rust 文件补充准确、克制、可维护的中文说明，并保持运行时行为不变。

范围：覆盖审计命中的 1818 个 `.rs` 文件，其中生产文件 279 个、测试文件 1539 个，分布于 10 个 workspace crate；按 `agent_registry.rs` 的层次补充模块职责、公开 API 契约与必要的非显然逻辑说明。

范围外：不修改业务行为、测试断言、用户可见字符串、命名、模块结构、依赖、配置、品牌信息或已有中文注释文件。

假设：2026-08-20 工作树起点干净；`rg --files -g '*.rs'` 返回 3901 个文件，其中 2083 个已命中中文注释，1818 个未命中。目标清单固化在编号任务文件中，执行期间不因新增文件自动扩大范围。

## 设计决策

- 以 `crates/vw-acp/src/agent_registry.rs` 为风格基准：普通模块优先用 `//!` 说明职责与边界，公开项用 `///` 说明契约，复杂分支仅补充“为什么”。
- 测试文件说明覆盖行为、fixture 或边界意图，不逐句复述断言；通过 `include!` 拼接的片段使用普通 `//`，避免非法内部文档注释。
- 任务按互斥文件清单拆分；注释任务可并行，最终审计在全部注释任务完成后串行执行。

## 架构说明

- 保持现有 crate、模块、工厂连线和测试布局不变；注释必须基于实际调用者与相邻测试，不推测未来能力。
- 注释不得暴露密钥、令牌或敏感载荷；Iced 文件只改源码注释，不触碰字体或渲染字符串。

## 开发策略

- 本变更不改变行为，测试驱动开发不适用；以逐文件语义审阅、中文注释覆盖审计和差异审查作为主要证据。
- 每个注释任务只修改其固化清单，执行目标文件的聚焦静态检查，不并发运行 Cargo。
- 全部注释任务完成后执行 `cargo clippy --all-targets --all-features -- -D warnings`，并确认全仓库缺失清单归零。
