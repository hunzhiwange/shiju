# 工作流子任务状态与会话打开计划

目标：确保工作流子任务只更新运行时指定的任务文件，完成事件与验收状态一致，续轮获得已有证据，且子任务卡片可稳定打开对应会话。

范围：修正 `vw-agent` plan-run 执行/续轮提示中的规范化计划目录与任务文件路径；使 `SubtaskFinished.success` 反映编号任务文件完成契约；将子任务输出证据传给目标续轮；为桌面卡片携带确定会话目录并验证持久化会话可打开。

范围外：不迁移或删除旧的项目内 `.plans` 数据，不更改任务文件完成契约，不重设计通用会话导航或工作流卡片外观。

假设：`tasks.json` 与其所在用户级计划目录是当次 plan-run 的唯一调度事实来源；实际路径必须由运行时 home、构建对应的 `HOME_CONFIG_DIR_NAME` 和 task ID 动态解析，复现中的绝对路径只是样本；`run_session` 正常返回只表示会话结束，不能替代任务文件的状态与验证证据。

## 设计决策

- 选择在子任务和续轮提示中显式传入规范化绝对路径，不搜索、镜像或兼容写入项目内同名 `.plans`。
- 路径沿用 `plan_dir_abs(home, task_id)` 与 `task_plan_storage_dir(home)`：debug 构建使用 `.vibewindowdev`，release 构建使用 `.vibewindow`；禁止硬编码用户名、home、配置目录名、task ID 或复现项目路径。
- 不根据 LLM 自述自动伪造“已完成”；仍由现有完成契约检查状态和退出码证据。
- 续轮同时获得已有执行证据和待修正文件的绝对路径，避免重做已完成实现。

## 架构说明

- `task_plan_run::{prompts,goal,runner}` 负责路径、完成契约与续轮证据；桌面 `agent_stream` 产生卡片元数据，`workflow_view` 只消费会话 ID 和目录。
- 当前工作树已有 `workflow_view.rs`/`agent_stream.rs` 的卡片精简改动；实施时必须保留，仅追加会话导航所需的窄变更。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
