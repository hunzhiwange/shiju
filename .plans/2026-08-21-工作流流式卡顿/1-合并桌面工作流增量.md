# 任务 1: 合并桌面工作流增量

批次：【批次 1】 无

状态：执行中

目的：在 plan-run 增量进入 Iced 通道前合并连续文本，减少 UI 唤醒，同时保持事件顺序、终态冲刷和恢复游标正确。

来源任务：无

预计会话范围：修改桌面 agent stream 单一模块及其独立测试文件；不触碰当前已有未提交改动所在的聊天渲染和 session 生命周期文件，适合一个聚焦会话完成。

## 文件

- 修改：`crates/vw-desktop/src/app/impls/agent_stream.rs`
- 测试：`crates/vw-desktop/src/app/impls/agent_stream_tests.rs`

## 上下文

- `gateway_agent_stream` 在约 2030 行处理 `TaskPlanRunStreamEventDto`，当前每个 `SessionDelta` 都直接 `output.try_send(PlanRunSessionDelta)`。
- Iced 通道容量为 100；`last_forwarded_event_id` 决定 `GatewayReconnectState` 的恢复游标。
- 状态层 `queue_agent_session_delta` 的 50/100ms 合并发生得太晚，只减少内容应用次数，不减少原始 Iced 消息数量。
- 工作区已有聊天 UI 未提交修改属于用户改动，实施时必须保留且不得格式化或改写。

## 测试计划

- 行为：连续 plan-run 子会话 delta 在 UI 边界按 220ms、360 字符或 16KiB 硬上限合并，文本完整有序；生命周期/终态事件先冲刷缓存；只有成功转发的连续事件前缀才能推进恢复游标。
- 失败验证测试：在 `crates/vw-desktop/src/app/impls/agent_stream_tests.rs` 新增 `plan_run_delta_buffer_coalesces_before_ui_dispatch`、`plan_run_delta_buffer_flushes_before_lifecycle_event`、`plan_run_delta_buffer_preserves_cursor_on_backpressure`。
- 失败验证命令：`cargo test -p vw-desktop plan_run_delta_buffer --lib`
- 预期失败原因：当前没有进入 Iced 通道前的 plan-run 增量合并器，每个 `SessionDelta` 都独立发送，且高频 delta 仍使用 info 日志。
- 通过验证命令：`cargo test -p vw-desktop plan_run_delta_buffer --lib`
- 模拟策略：用确定性的同会话及交错多会话事件序列、显式时间点和容量受限的测试发送器模拟 SSE/UI 边界；不启动真实网关或窗口，验证实际输出消息、拼接文本、跨会话事件顺序和恢复游标。

## 步骤

1. 先编写三个失败测试：多条同会话及交错多会话 delta 合并成显著更少的 UI 消息且内容逐字一致、跨会话顺序不变；等待/终态事件之前冲刷对应增量；发送失败时游标不越过未成功交付的连续事件前缀。
2. 运行失败验证命令并确认失败来自缺少前置合并，而不是工作区现有改动或测试环境。
3. 在 `agent_stream.rs` 增加小型、有序且有界的 plan-run UI 增量合并状态，按 session 保存文本及事件 ID 范围，并提供 220ms 到期、360 字符软阈值、16KiB 硬上限及强制冲刷路径。
4. 将 plan-run SSE 读取与 UI 冲刷协调起来：短窗口到期时发送合并消息；任何非 delta 事件、流结束或重连前先按顺序冲刷；通道背压继续走显式停止/恢复逻辑。
5. 仅在合并消息成功进入 Iced 通道后更新 `last_forwarded_event_id`；确保重连重放不会丢文本，允许既有幂等路径处理重复事件。
6. 将逐条 `session_delta` 的 info 日志降为 debug，并记录合并条数/字符数；非 delta 生命周期及终态事件保留 info。
7. 运行聚焦测试，再运行仓库要求的 clippy；审查差异只包含本任务两个文件和计划执行产生的任务文件状态变化。

## 验证

- 预期：三个新增测试全部通过；连续 delta 的 UI 消息数小于输入事件数，拼接内容与输入完全一致，生命周期事件顺序和背压游标断言成立。
- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：退出码 0；如仅因无关的既有/其他 AI 改动失败，保留原始错误证据并将任务标为 `已完成，待回归`，不修改无关文件。
- 所需证据：失败测试的预期失败输出、聚焦测试退出码 0、clippy 退出码与错误归属、`git diff --check` 通过、最终差异确认未覆盖现有未提交聊天 UI 文件。
