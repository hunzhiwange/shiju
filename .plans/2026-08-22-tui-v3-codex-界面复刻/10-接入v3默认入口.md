## 上下文

- 当前入口：`crates/vw-cli/src/cli/interactive/mod.rs` 委托 `tui_v2::run_tui_v2`；终端初始化、raw mode、alternate screen 与 `/dev/tty` 处理在 `tui_v2/app.rs`。
- v3 bootstrap 只应选择 `TuiV3Surface`，并调用任务 2 得到的共享 app runner；不得复制 `GatewayUiRuntime`、`gateway_stream_request_from_state` 或 session restore。
- `tui_v2` 模块继续导出原入口用于回归或故障定位，但不作为默认 interactive 实现。
- 不新增 feature flag、环境变量或双写入口；切换点保持单一、显式、可回滚。

## 测试计划

- 行为：标准 interactive 路径委托 v3；gateway host、session seed、prompt submission、错误返回和最终打印结果与 v2 相同。
- 失败验证测试：新增 `run_interactive_delegates_to_standard_tui_v3_without_changing_final_output`、`tui_v3_entry_uses_shared_gateway_host`。
- 失败验证命令：`cargo test -p vw-cli run_interactive_delegates_to_standard_tui_v3_without_changing_final_output --lib`
- 预期失败原因：interactive 仍指向 `run_tui_v2`，且 `run_tui_v3` 尚不存在。
- 通过验证命令：`cargo test -p vw-cli run_interactive_delegates_to_standard_tui_v3_without_changing_final_output --lib`
- 模拟策略：延续 interactive 测试已有依赖注入，仅替代 runner；请求构造、错误类型和返回值使用真实类型。
