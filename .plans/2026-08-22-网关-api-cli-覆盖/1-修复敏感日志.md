# 任务 1: 修复 GatewayClient 敏感日志

批次：【批次 1】 依赖批次“无”

状态：未开始

目的：阻止认证、凭证和复杂请求体在 Gateway 客户端日志或错误文本中泄漏。

来源任务：无

预计会话范围：只收紧统一 HTTP 边界的日志与错误净化，不改变请求内容、返回类型或重试策略；这是后续凭证类 CLI 的安全前置。

## 文件

- 修改：`crates/vw-gateway-client/src/http.rs`
- 测试：`crates/vw-gateway-client/src/http_tests.rs`

## 上下文

- `http.rs::log_request` 当前会序列化完整 body，`response_error` 也会记录原始响应体。
- 保留 method、endpoint、path、状态码等诊断字段；敏感值和无界载荷不得进入 tracing。
- 不得记录 skey、token、password、credential、api_key 或原始业务载荷。

## 测试计划

- 行为：请求和失败响应经过统一净化后仍可诊断，但测试哨兵密钥不会出现在日志或返回错误中。
- 失败验证测试：`crates/vw-gateway-client/src/http_tests.rs` 中的 `gateway_http_logs_and_errors_redact_sensitive_payloads`
- 失败验证命令：`cargo test -p vw-gateway-client gateway_http_logs_and_errors_redact_sensitive_payloads --lib`
- 预期失败原因：现有实现会把测试请求体或响应体中的哨兵密钥原样写入捕获日志或错误文本。
- 通过验证命令：`cargo test -p vw-gateway-client gateway_http_logs_and_errors_redact_sensitive_payloads --lib`
- 模拟策略：使用本地 TCP 测试响应和 tracing 捕获层，只模拟 HTTP 边界，不模拟净化函数。

## 步骤

1. 先新增同时覆盖请求日志、非成功响应日志和返回错误的失败测试。
2. 实现集中、显式的字段净化与长度上限；日志只保留安全摘要。
3. 确认普通非敏感错误仍包含状态与可操作信息，重试判定文本保持稳定。
4. 运行聚焦测试和全仓库 clippy，审查没有新增原始 body 日志。

## 验证

- 运行：`cargo test -p vw-gateway-client gateway_http_logs_and_errors_redact_sensitive_payloads --lib`
- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：聚焦测试通过，哨兵值零泄漏，普通错误仍可诊断，clippy 退出码为 0。
- 所需证据：失败时捕获到哨兵值；通过后捕获日志与错误均不含哨兵值；测试 0 失败；clippy 0 警告。

`crates/vw-gateway-client/src/http.rs` 的统一日志边界完成净化，聚焦测试证明请求体与失败响应不会泄密。
