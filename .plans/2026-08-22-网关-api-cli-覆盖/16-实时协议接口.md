## 上下文

- 所有业务请求经 `GatewayClient`，CLI 只负责参数、输入、确认和输出。
- 该任务完成时须在中央 `ApiCommands` 注册一次；因共享注册文件，依赖前一批次完成。
- 当前工作树的无关改动必须原样保留。
- 包括 POST `/v1/agent`、POST `/v1/chat/completions`、GET `/v1/events`、`/v1/global/event`、`/v1/event`、scheduler events/stream、chat stream/stop、task-plan-run stream/stop、WebSocket chat。
- 流式命令默认 JSONL；Ctrl-C/服务端终止必须明确，stop 命令使用 request_id 并保持幂等响应。

## 测试计划

- 行为：各种实时协议保留事件顺序、认证/租户头和终止状态，非流式推理输出 JSON，stop 与连接操作受确认。
- 失败验证测试：`crates/vw-cli/src/handlers/api/realtime_tests.rs` 中的 `api_realtime_commands_cover_inference_sse_stop_and_websocket_protocols`
- 失败验证命令：`cargo test -p vw-cli api_realtime_commands_cover_inference_sse_stop_and_websocket_protocols --lib`
- 预期失败原因：CLI 没有统一实时命令，GatewayClient 也缺少部分 agent/OpenAI/event/WS 封装。
- 通过验证命令：`cargo test -p vw-cli api_realtime_commands_cover_inference_sse_stop_and_websocket_protocols --lib`
- 模拟策略：本地 HTTP、SSE 与 WebSocket 服务器验证真实 framing、headers、事件顺序和关闭码；不模拟模型。

## 步骤

1. 先分别写 JSON 推理、三类事件 SSE、两类可停止流、scheduler stream 和 WebSocket 失败测试。
