## 上下文

- 所有远程业务请求必须复用 `vw_gateway_client::GatewayClient`，不得在 CLI 中直接拼装 reqwest 请求。
- 保留现有顶层命令的本地语义；新增能力进入 `shiju api` 命名空间。
- 当前工作树有 SHIJU 与桌面未提交改动；不得覆盖或整理无关差异。
- 接口族包括 health、metrics、status、tools、mcp inspect、api-health、global health、models、path、vcs、command/agent/skill catalog 与 cli-tools。
- `/v1/metrics` 是文本响应，其余操作保持结构化 JSON；不得强行按 JSON 解码指标。

## 测试计划

- 行为：每个系统发现子命令使用正确方法、路径和租户头，文本指标与 JSON 响应按稳定格式输出。
- 失败验证测试：`crates/vw-cli/src/handlers/api/system_tests.rs` 中的 `api_system_commands_use_gateway_discovery_routes`
- 失败验证命令：`cargo test -p vw-cli api_system_commands_use_gateway_discovery_routes --lib`
- 预期失败原因：`ApiCommands` 尚无 system 接口族，GatewayClient 也缺少统一的系统 API 封装。
- 通过验证命令：`cargo test -p vw-cli api_system_commands_use_gateway_discovery_routes --lib`
- 模拟策略：使用逐请求本地 HTTP 服务器记录真实 method/path/headers，并返回最小合法 JSON 或 text。

## 步骤

1. 先为所有逻辑操作建立表驱动失败测试，明确 metrics 的文本分支。
2. 在 GatewayClient 新增窄的 system 方法，不暴露任意 path 请求器。
3. 新增 `api system` 子命令并统一交给共享输出器。
4. 验证错误状态不会被伪装为空结果，运行客户端测试、CLI 测试与 clippy。
