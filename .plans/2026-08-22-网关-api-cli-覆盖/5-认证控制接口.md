## 上下文

- 所有远程业务请求必须复用 `vw_gateway_client::GatewayClient`，不得在 CLI 中直接拼装 reqwest 请求。
- 保留现有顶层命令的本地语义；新增能力进入 `shiju api` 命名空间。
- 当前工作树有 SHIJU 与桌面未提交改动；不得覆盖或整理无关差异。
- 认证材料只能从 stdin/file/env 读取；不得作为 clap 的普通字符串参数或被日志输出。
- hook trust/revoke 与 dispose 都是副作用操作；dispose 还需打印精确租户/实例目标。

## 测试计划

- 行为：认证、OAuth、hook 和 dispose 命令命中正确路由，敏感输入不回显，所有危险操作无 `--yes` 时零请求。
- 失败验证测试：`crates/vw-cli/src/handlers/api/control_tests.rs` 中的 `api_control_commands_protect_credentials_and_destructive_actions`
- 失败验证命令：`cargo test -p vw-cli api_control_commands_protect_credentials_and_destructive_actions --lib`
- 预期失败原因：CLI 无该接口族，provider client 只覆盖列表，危险操作也没有统一确认路径。
- 通过验证命令：`cargo test -p vw-cli api_control_commands_protect_credentials_and_destructive_actions --lib`
- 模拟策略：本地 HTTP 服务器记录真实请求；用哨兵凭证检查 stdout/stderr/tracing 均不包含明文。

## 步骤
