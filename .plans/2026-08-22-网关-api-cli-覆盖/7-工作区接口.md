## 上下文

- 所有远程业务请求必须复用 `vw_gateway_client::GatewayClient`，不得在 CLI 中直接拼装 reqwest 请求。
- 保留现有顶层命令的本地语义；新增能力进入 `shiju api` 命名空间。
- 当前工作树有 SHIJU 与桌面未提交改动；不得覆盖或整理无关差异。
- 路径和搜索参数必须保持服务端约束，不在客户端扩大 allowed roots。
- write/move/copy/delete、git commit/command/merge 都有副作用；精确目标必须在确认信息中显示。

## 测试计划

- 行为：文件、搜索和 Git 命令准确转发路径与请求体，危险操作未确认时不访问 Gateway，服务端拒绝不会降级。
- 失败验证测试：`crates/vw-cli/src/handlers/api/workspace_tests.rs` 中的 `api_workspace_commands_preserve_paths_and_require_confirmation`
- 失败验证命令：`cargo test -p vw-cli api_workspace_commands_preserve_paths_and_require_confirmation --lib`
- 预期失败原因：现有 GatewayClient 仅供桌面/TUI 调用，CLI 无远程 workspace 接口族。
- 通过验证命令：`cargo test -p vw-cli api_workspace_commands_preserve_paths_and_require_confirmation --lib`
- 模拟策略：本地服务器断言 percent-encoding、query/body 和请求计数；不模拟文件系统或 Git 实现。
