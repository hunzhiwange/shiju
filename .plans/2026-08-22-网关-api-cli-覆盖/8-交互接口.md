## 上下文

- 所有远程业务请求必须复用 `vw_gateway_client::GatewayClient`，不得在 CLI 中直接拼装 reqwest 请求。
- 保留现有顶层命令的本地语义；新增能力进入 `shiju api` 命名空间。
- 当前工作树有 SHIJU 与桌面未提交改动；不得覆盖或整理无关差异。
- 审批回复和问题回复必须使用稳定 request_id；未知或空选项直接失败。
- PTY create/update/delete 及 connect 都可能影响远程进程；connect 不得静默回退为轮询。

## 测试计划

- 行为：权限、问题和 PTY 命令按真实协议工作，写操作受确认保护，PTY connect 正确转发租户与认证头。
- 失败验证测试：`crates/vw-cli/src/handlers/api/interactive_tests.rs` 中的 `api_interactive_commands_cover_permission_question_and_pty`
- 失败验证命令：`cargo test -p vw-cli api_interactive_commands_cover_permission_question_and_pty --lib`
- 预期失败原因：CLI 尚无该接口族，GatewayClient 也没有 PTY 生命周期封装。
- 通过验证命令：`cargo test -p vw-cli api_interactive_commands_cover_permission_question_and_pty --lib`
- 模拟策略：HTTP 路由使用本地服务器；WebSocket 使用本地握手服务器验证路径和请求头，不模拟 PTY 数据处理。
