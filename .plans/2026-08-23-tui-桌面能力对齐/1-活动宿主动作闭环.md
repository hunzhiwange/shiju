## 上下文

- 当前 `Queue` 会继续构造即时提交，第二次提交触发 fatal error；`ShowTranscript` 实际无效，`OpenExternalEditor` 明确报错。
- 当前取消只有本地 `AtomicBool`，需使用稳定 request ID 与 `GatewayClient::chat_stream_stop`，并保留显式失败反馈。

## 验证计划（仓库限制）

- 行为：活动流中排队不会二次提交；流结束后自动取队首；转录/外部编辑器可用；中断会停止对应服务端流且宿主继续运行。
- 失败验证测试：新增 `active_runner_executes_local_actions_and_drains_queue` 与 `interrupt_stops_the_matching_resumable_stream`。
- 失败验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 预期失败原因：测试引用当前不存在的宿主命令执行结果、可恢复流标识和排队排空入口。
- 通过验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 模拟策略：仅以本地 HTTP 测试服务记录 stream/stop 请求；真实执行 bridge、队列和 ChatWidget。
- 回归限制：未经用户明确授权不运行 `cargo test`；仅编译测试时将状态记为 `已完成，待回归`。

## 步骤

1. 添加覆盖活动流排队、正常结束排空、转录、外部编辑器和 request-scoped stop 的聚焦测试。
2. 运行失败验证命令，确认测试因缺少新宿主执行入口或流标识而失败，而非无关告警。
3. 为活动流保存稳定 request ID；把副作用结果作为事件送回主循环，错误写入 transcript，不退出 TUI。
4. 让 `Queue` 只进入本地队列，并在终态后提交一条；实现转录 pager 与现有外部编辑器安全入口。
5. 运行聚焦与全仓 Clippy；检查取消不扩大目录、权限或目标流范围。

- 所需证据：失败验证的缺失入口、通过后的 Clippy 退出码、stop 请求携带匹配 request ID、队列只提交一次、错误保留在 UI 的差异审查结果。
