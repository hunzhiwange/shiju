批次：【批次 2】 依赖批次 1

## 上下文

- `permission_list/reply`、`question_list/reply/reject`、`session_todo_get` 已在 Gateway client 中存在。
- 当前 `TaskStateChanged` 被直接忽略，且 `TuiControllerCommand::Overlay` 到达活动循环后会进入未支持分支。

## 验证计划（仓库限制）

- 行为：只同步当前会话的待处理请求；回复成功后清除对应 overlay，失败时保留请求并显示错误；未知/断连默认拒绝。
- 失败验证测试：新增 `task_state_change_refreshes_current_interactions`、`permission_and_question_replies_survive_gateway_failure`。
- 失败验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 预期失败原因：当前没有 interaction runtime、刷新事件或 overlay 命令执行结果类型。
- 通过验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 模拟策略：用本地 HTTP 服务返回真实 DTO；不模拟 bridge、状态 reducer 或安全决策。
- 回归限制：未经授权不运行 `cargo test`；只编译测试时使用 `已完成，待回归`。

## 步骤

1. 添加当前会话过滤、权限回复、问题回答/拒绝、待办刷新和失败保留的测试。
2. 运行失败验证命令，确认缺少 interaction runtime 和活动循环处理分支。
3. 在 Gateway runtime 增加最小交互 API 封装，并让 `TaskStateChanged` 触发异步刷新而不是 reducer 内发网络请求。
4. 将 DTO 转成既有 `PermissionQueue`、`UiQuestionOverlay`、`UiTodoOverlay` 和 `ChatWidget` 安全 overlay；仅成功响应后移除。
5. 运行聚焦与全仓 Clippy，审查请求 ID、会话 ID、目录与拒绝语义未被弱化。
