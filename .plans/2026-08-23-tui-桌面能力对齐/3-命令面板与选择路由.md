## 上下文

- `CommandPopup` 和 `ListSelectionView` 已能过滤并发出 `V3Action::Select`，但 `BottomPane` 没持有它们，bridge 又静默忽略所有 Select。
- 命令注册必须区分已接通、明确不可用和动态来源；不可把未知命令当普通提示发送。

## 验证计划（仓库限制）

- 行为：输入 `/` 展示命令；选择后由稳定 ID 路由；不可用项不可执行且显示原因；未知命令显式报错。
- 失败验证测试：新增 `slash_input_opens_and_filters_command_palette`、`selected_command_is_never_silently_ignored`。
- 失败验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 预期失败原因：ChatWidget 无通用选择 overlay，CLI 无命令目录和 Select 路由结果。
- 通过验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 模拟策略：本任务使用纯命令数据，不访问网络；业务处理器以显式 unavailable 返回占位，不产生副作用。
- 回归限制：未经授权不运行 `cargo test`；只编译测试时使用 `已完成，待回归`。

## 步骤

1. 添加命令弹层打开、过滤、禁用原因、稳定 ID 路由和未知命令拒绝测试。
2. 运行失败验证命令，确认活动 ChatWidget/bridge 缺少通用选择入口。
3. 将现有命令弹层接入 `BottomPane`，以 V3 纯数据公开通用选择 overlay，不让 `vw-tui` 持有 Gateway client。
4. 在 CLI 建立最小命令目录和类型化路由结果；先注册 help/status/exit 与后续任务所需命令 ID，不提前伪实现副作用。
5. 运行聚焦与全仓 Clippy，确认所有 Select surface 都显式匹配或返回可见错误。
