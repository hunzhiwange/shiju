## 上下文

- 当前启动逻辑只从 `session_ui_previews` 选最新会话；没有用户可见 picker。
- 切换必须先加载完整 snapshot，再一次性替换状态并重绑 runtime seed；加载失败不能清空现有消息、草稿或 scope。

## 验证计划（仓库限制）

- 行为：`/resume` 可搜索非归档会话并恢复；`/new` 创建并切换空会话；加载失败保持原状态和草稿。
- 失败验证测试：新增 `resume_switch_is_transactional`、`new_session_rebinds_runtime_after_create`。
- 失败验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 预期失败原因：runtime 缺显式列表/归档过滤/切换事务入口，命令路由没有会话选择结果。
- 通过验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 模拟策略：本地 HTTP 测试服务返回真实 `ChatSessionMeta` 与 `ChatSession`；不模拟状态替换。
- 回归限制：未经授权不运行 `cargo test`；只编译测试时使用 `已完成，待回归`。

## 步骤

1. 添加会话排序、归档过滤、成功切换、新建与加载失败回滚测试。
2. 运行失败验证命令，确认缺少事务切换入口。
3. 在 session runtime 封装列表、归档读取和完整快照加载；目录与会话 ID 继续由 Gateway 校验。
4. 使用任务 3 的选择 surface 接通 `/resume`、`/continue`、`/new`；只有完整加载成功后替换 state/widget/runtime seed。
5. 运行聚焦与全仓 Clippy，检查切换后历史、标题、scope、工作目录和草稿的一致性。
