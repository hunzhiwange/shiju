## 上下文

- Gateway client 已有 workflow、Cron 和 agent scheduler API；相应 TUI 模型当前没有活动调用者。
- 桌面端是 Gateway 读模型客户端；TUI 同样不得本地推导任务迁移、自动调度或伪造自由文本结构化任务。

- 行为：四类面板展示 Gateway canonical 状态；短控制只作用于可证明归属的稳定 ID；无归属操作禁用并说明原因。
- 失败验证测试：新增 `orchestration_panels_render_gateway_snapshots`、`orchestration_controls_require_owned_stable_ids`。
- 失败验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 预期失败原因：活动 runtime 没有 orchestration loader，面板模型无 CLI 路由或控制所有权检查。
- 通过验证命令：`cargo clippy -p vw-cli -p vw-tui --all-targets --all-features -- -D warnings`
- 模拟策略：本地 HTTP 测试服务提供真实 DTO；不模拟状态投影与 ownership 检查。
- 回归限制：未经授权不运行 `cargo test`；只编译测试时使用 `已完成，待回归`。

## 步骤

1. 添加工作流/Cron/Agent/后台任务快照、控制所有权和来源失败测试。
2. 运行失败验证命令，确认缺 orchestration runtime 和活动面板路由。
3. 封装只读列表与已存在的精确控制 API；保留 project/tenant scope，拒绝本地调度推演。

5. 运行聚焦与全仓 Clippy，检查稳定 ID、项目 scope、来源失败和禁用原因。
