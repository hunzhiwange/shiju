# vw-tui 中文注释补全计划

目标：为 `crates/vw-tui` 的 Rust 文件补充准确、克制、可维护的中文注释，完整保留原有英文注释，并保持行为不变。

范围：覆盖 `crates/vw-tui` 当前全部 374 个 Rust 文件，按互斥清单逐语义单元补充模块职责、公开 API 契约、原英文说明的中文对应、测试意图与必要的非显然逻辑说明。

范围外：不删除、翻译替换或改写原有英文注释；不修改代码行为、测试断言、用户可见字符串、命名、模块结构、依赖、配置、快照或非 Rust 文件。

假设：2026-08-23 审计时 `rg --files crates/vw-tui -g '*.rs'` 返回 374 个文件；`live_wrap.rs` 中“你/好”仅是英文注释里的示例字符，不算中文说明，因此全部文件均纳入任务清单。

## 设计决策

- 采用“保留英文、逐块相邻补充中文”的双语策略；每个原有英文注释块都要有语义等价的中文对应，英文原文不得删除、翻译后替换或改写。
- 禁止“一文件一行”的打卡式注释：按模块、关键类型/字段、跨模块 API、复杂状态转换、回退/安全/性能原因和测试行为组覆盖；文件行数阈值只作为最低防敷衍护栏，不代表完成。
- 以现有 `lib.rs`、`chatwidget.rs` 和 `bottom_pane/mod.rs` 的职责边界为依据：模块级说明职责，公开项说明契约，复杂分支只解释原因。
- 方案选择为按互斥领域文件清单并行处理，再串行统一审计；相比按文件逐项建任务，可控制任务数量，同时避免多人写同一文件。
- 测试文件只说明行为、fixture、快照或边界意图；通过 `include!`、`#[path]` 接入的片段使用在包含位置合法的注释形式。

## 架构说明

- `lib.rs` 是复制来源模块的最小 v3 编译壳；`ChatWidget` 只管理展示状态，`bottom_pane` 负责本地输入与页脚，运行时业务留在 crate 外部。
- 局部目录说明优先级更高；`bottom_pane/AGENTS.md` 要求状态机文档与 Enter、新行、粘贴突发及禁用语义保持同步。
- 注释不得暴露密钥、令牌或敏感载荷，不得把未激活、回退或只读展示路径描述成完整业务能力。

## 开发策略

- 本变更不改变行为，测试驱动开发不适用；以逐语义单元审阅、英文注释块逐块配对、分层中文注释密度、英文零删除和差异审查作为主要证据。
- 批次 1 的九个任务仅修改互斥文件清单，不运行 Cargo，避免并行争用构建资源。
- 批次 2 在全部注释任务完成后检查 374 个文件均有真实中文注释，并运行 `cargo clippy --all-targets --all-features -- -D warnings`。
