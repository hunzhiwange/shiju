# TUI @ 文件搜索计划

目标：让新版 TUI 在输入 `@` 时异步搜索当前工作目录文件，并支持键盘选择后插入相对路径提及。

范围：复用桌面端当前 `@token` 交互语义；在 `vw-tui` 内完成纯 UI 状态、弹窗和文本替换，在 `vw-cli` 宿主通过现有 Gateway 文件名搜索接口加载候选，并拒绝迟到结果覆盖当前查询。

范围外：不改桌面端行为，不新增文件索引协议，不加入拖放、行列定位卡片或目录专用交互，不重构通用补全框架。

假设：活动 TUI 由 `V3GatewayApp` 驱动，工作目录来自 `GatewayUiRuntime::directory()`；现有 `/v1/find/file` 接口可按目录返回相对路径，`FileSearchPopup` 与 `V3FileSearchMatch` 是尚未接线的展示边界。

## 设计决策

- 采用与桌面端一致的尾部 `@token` 字符策略和按键语义：`Up/Down` 导航、`Enter` 选择、`Esc` 关闭，选择结果替换当前 token 并补一个空格。
- UI 只发出查询数据并接收结果，不持有 Gateway 客户端；CLI 宿主负责异步请求、错误传递和查询代次校验。
- 使用现有文件名搜索接口，限定为文件结果和最多 20 条；不把内容搜索 `/v1/files/search` 误用于文件名补全。

## 架构说明

- `ChatComposer` 负责基于光标识别、替换可编辑 `@token`；`BottomPane` 负责单一弹窗、按键路由及查询变化动作。
- `GatewayV3Bridge` 将纯 `V3Action` 转成宿主命令；`ActiveRunner` 在线程中请求 Gateway，并只应用当前代次和当前查询的响应。
- `/` 命令面板与 `@` 文件面板互斥；迟到、失败和已关闭查询均不得修改草稿或重开弹窗。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
