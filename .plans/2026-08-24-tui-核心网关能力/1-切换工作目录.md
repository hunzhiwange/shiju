# 任务 1: 接通工作目录切换

批次：【批次 1】 依赖批次：无

状态：未开始

目的：让 `/cd <path>` 经 Gateway 项目解析后原子切换目录，并恢复或创建目标目录会话。

来源任务：无

预计会话范围：只处理目录切换的一条调用链；不增加额外目录授权、不创建项目、不改变 Gateway 的目录权限规则。

## 上下文

- `GatewayUiRuntime::resolve_project_directory_blocking` 与 `rebind_validated_directory` 已存在但没有活动命令调用者。
- 切换前必须拒绝活动 stream 和排队输入；`project_resolve` 使用 `create_if_missing=false`。
- 目标 runtime、会话、能力、集成与编排快照全部成功后才替换当前 app，失败保持原目录和草稿。

## 测试计划

- 行为：`/cd` 只切换到 Gateway 已解析且本地可规范化的目录，成功后绑定目标会话，任一失败不修改原状态。
- 失败验证测试：新增 `cd_command_routes_non_empty_path`、`cd_switch_commits_only_after_target_bootstrap`。
- 失败验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期失败原因：活动命令目录和 app 尚无 `ChangeDirectory` 路由与原子切换实现。
- 通过验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 模拟策略：使用现有本地 HTTP fixture 返回真实 `project_resolve`、session UI 和目录能力响应；不模拟 `V3GatewayApp`。

## 步骤

1. 添加命令语法、忙碌拒绝、成功提交和失败回滚测试。
2. 运行失败验证命令并确认缺失路由或 handler 导致失败。
3. 增加显式 `CommandRoute`，在临时 runtime 上完成项目解析、目录规范化和目标会话 bootstrap。
4. 原子替换 runtime/state/widget，保留草稿并刷新能力、集成、编排及交互请求。
5. 运行通过验证命令并审查没有 `create_if_missing=true` 或失败后半切换。

## 验证

- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：退出码 0；新增测试可编译；无 warning。
- 所需证据：失败编译指向缺失 `/cd` 路由；通过编译退出码 0；差异证明成功前不修改活动 runtime，错误可见且草稿保留。

## 完成

仅当 `/cd <path>` 可达 Gateway 项目解析、原子切换目标目录和会话，并覆盖忙碌、非法路径、未知项目和 bootstrap 失败后，任务可完成。
