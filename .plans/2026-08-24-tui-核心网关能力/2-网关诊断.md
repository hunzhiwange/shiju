## 上下文

- 使用 `GatewayClient::doctor_get`，不回退执行本地诊断命令。
- `ActiveRunner` 必须使用后台线程与带代次的 `HostMessage`，重复请求只展示最后一次结果。
- JSON 仅格式化允许展示的诊断字段，错误文本复用现有脱敏/截断规则。

## 测试计划

- 行为：`/doctor` 不启动聊天流、不阻塞事件循环，成功和失败均形成明确 transcript 条目。
- 失败验证测试：新增 `doctor_command_routes_to_gateway_diagnostics`、`runner_renders_latest_doctor_result`。
- 失败验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期失败原因：`CommandRoute::RunDoctor`、diagnostics runtime 和 host 完成消息尚不存在。
- 通过验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 模拟策略：HTTP fixture 返回真实 JSON 和错误状态；不模拟 transcript renderer。

## 步骤

1. 编写命令可达、非阻塞、迟到结果和错误展示测试。
2. 运行失败验证命令并确认缺失诊断路径。
3. 新增只读诊断 runtime，规范化并限制展示数据大小。
4. 在 runner 中启动后台请求并只接纳当前代次结果。
5. 运行通过验证命令并审查输出不包含认证头或原始敏感配置。
