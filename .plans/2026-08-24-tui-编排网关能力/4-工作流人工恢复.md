## 上下文

- 使用 `WorkflowPauseDto.form`、`actions` 和 `WorkflowResumeRequest`；form token 只存在运行时状态，不进入 transcript/session UI 持久化。
- 回复必须匹配当前 owned run ID 和当前 pause；取消只关闭本地表单，不伪造服务端恢复。
- `workflow_resume` 返回 `WorkflowRunResponse`，完成、再次暂停和错误都需统一投影并刷新所有权。

## 测试计划

- 行为：暂停表单可回答并恢复精确 owned run，过期/外部 token、重复回复和 session 切换后回复均被拒绝。
- 失败验证测试：新增 `workflow_pause_projects_typed_questions_without_persisting_token`、`workflow_resume_requires_current_owned_pause`。
- 失败验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期失败原因：当前状态无 Workflow pause ownership，问题回复只支持 Gateway question API。
- 通过验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 模拟策略：HTTP fixture 校验真实 resume body；表单转换和 reducer 使用真实类型。

## 步骤

1. 添加表单映射、token 非持久化、归属拒绝、成功和再次暂停测试。
2. 运行失败验证命令并确认缺失 Workflow pause 状态。
3. 新增最小 owned pause 状态和 typed overlay 映射，不复用普通 Gateway question request ID。
4. 调用 `workflow_resume`，按响应原子清理或替换 pause 所有权。
5. 运行通过验证命令并搜索确保 form token 不出现在日志、transcript 和 session snapshot。

## 验证

- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：退出码 0；测试编译；无 warning。
- 所需证据：失败/通过证据、resume body 精确匹配、过期回复零请求、token 非持久化搜索结果。

## 完成

仅当人工暂停可安全恢复同一 owned run，且 token 不持久化、不回显、不可重放后，任务可完成。
