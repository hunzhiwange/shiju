## 上下文

- 复用 `AgentSchedulerCommandKindDto` 与当前 `control_owned_task_blocking` 的 scope/ID 校验。
- 每种命令必须有显式 canonical 状态白名单；cancel/archive 需要 destructive 确认，其余也需确认但不标 destructive。
- Gateway 成功后重载 Scheduler snapshot；错误不得在本地推测目标状态。

## 测试计划

- 行为：六种命令只在当前任务 canonical 状态允许时发送，未知 ID、不允许转换、取消确认和 Gateway 失败均零本地状态提交。
- 失败验证测试：新增 `task_control_routes_supported_commands_only`、`task_control_enforces_canonical_transition_and_confirmation`。
- 失败验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期失败原因：当前 parser 只支持 cancel，model 只有 `supports_stop`。
- 通过验证命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 模拟策略：HTTP fixture 校验真实 scheduler command DTO；不模拟状态白名单。

## 步骤

1. 为每种 canonical 状态/命令组合、未知命令、确认与失败添加测试。
2. 运行失败验证命令并确认 parser/model 不支持新控制。
3. 用显式 match 定义允许动作，扩展命令与确认 intent。
4. 发送 Gateway command，成功后刷新 snapshot，失败保持旧状态。
5. 运行通过验证命令并审查范围中没有 promote/merge/move/Staff 分支。

## 验证

- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：退出码 0；测试编译；无 warning。
- 所需证据：失败/通过证据、每种命令精确 DTO、非法转换零请求、成功后刷新与失败不更新。

## 完成

仅当六种任务控制均有显式状态白名单、当前项目归属与确认，并保持高风险命令范围外后，任务可完成。
