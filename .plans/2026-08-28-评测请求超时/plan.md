# 评测请求超时计划

目标：将 Promptfoo coding 评测的单请求上限调整到足以覆盖正常的多步骤 Agent 任务。

范围：统一 Provider 默认值、coding/readonly 配置和 README 中的超时说明，并为配置解析增加回归测试。

范围外：不修改网关超时、Agent 执行策略或模型重试策略。

假设：日志已证明本次请求在约 4 分 34 秒后正常完成，180 秒上限是误报来源；15 分钟仍低于网关为 SSE 配置的 1 小时上限。

## 设计决策

- 统一使用 900000ms（15 分钟）作为评测单请求默认上限，保留环境变量和配置覆盖能力。
- 通过导出纯配置解析函数测试默认值与覆盖值，避免重新执行非确定性的真实模型请求。

## 架构说明

- 超时由 `evals/promptfoo/vibewindow-provider.mjs` 的 AbortController 控制，配置文件显式覆盖 Provider 默认值。
- 仅触及 Promptfoo 评测辅助代码；不改变产品网关行为。

## 开发策略

- 先增加默认值回归测试并确认失败，再做最小同步修改。
- 通过 Node 测试和 Promptfoo 配置/脚本检查验证，不运行完整评测作为单元回归替代。
