# 会话锁定 ACP 后端计划

目标：会话开始后锁定其 ACP 后端，并从聊天输入区移除全部历史重放策略按钮。

范围：修改桌面端会话运行时、ACP 选择消息处理和输入面板；空会话仍可选择 ACP 后端，已有消息、活动请求或排队请求的会话拒绝切换；移除“丢弃历史、摘要重放、全量重放、最近”及最近条数输入控件；补充相邻测试。

范围外：不改变任务看板、定时任务或员工配置中的 ACP 选择；不删除 ACP 历史策略的协议字段、配置解析、请求构造或后端兼容逻辑；不迁移已有配置。

假设：聊天输入面板是本需求所指功能入口；会话出现本地消息、活动请求或排队请求中的任一状态即视为已经开始，空白新会话仍允许选择并保存项目默认 ACP 后端。

## 设计决策

- 采用运行时统一判定并在消息处理层强制拒绝，避免仅靠禁用 UI 被陈旧事件或其它调用路径绕过。
- 已开始会话继续显示当前 ACP 标识，但选择器不可展开；拒绝事件使用现有 toast 反馈。
- 仅移除历史策略 UI，保留底层字段与默认值，避免扩大为协议兼容清理。

## 架构说明

- 会话状态判定放在 `session/runtime.rs`，供输入面板和消息处理复用。
- ACP 选择写入仍由 `message/chat/session.rs` 负责；输入面板只负责可交互状态和可见控件。
- UI 遵循暗色主题和现有输入面板样式，不引入新配置、trait 或依赖。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
