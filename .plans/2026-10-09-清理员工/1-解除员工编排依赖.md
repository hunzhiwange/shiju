# 任务 1: 解除员工编排依赖

批次：【批次 1】 无

状态：未开始

目的：让任务生命周期和项目唤醒不再读取 StaffConfig、员工分配或员工阶段动作。

来源任务：无

预计会话范围：聚焦调度器工作流回退、项目唤醒和命令入口，先切断员工层对核心派发的控制，为后续删除 Staff 类型提供稳定边界。

## 上下文

- `load_dispatch_workflow` 当前以 `workflow_snapshot_from_staff_config(StaffConfig::default())` 回退。
- `project_wake` 当前先执行员工自动分配/续跑，再派发任务；命令协议仍含 `AssignStaff` 和阶段动作。
- 工作流应来自已保存任务看板工作流；缺失时使用不依赖 Staff 的中性内建快照。
- 先用 RustCodeGraph 分析 `load_dispatch_workflow`、`project_wake` 及命令 DTO 的调用方和影响范围；提交时排除执行前已有的无关工作区改动。

## 测试计划

- 行为：没有 Staff 配置时，有限任务仍能按中性工作流进入本地调度；唤醒不再产生员工命令。
- 失败验证测试：新增 `dispatch_workflow_fallback_does_not_require_staff_config` 与 `project_wake_does_not_apply_staff_plan`。
- 失败验证命令：`cargo clippy -p vw-agent -p vw-api-types --all-targets --all-features -- -D warnings`
- 预期失败原因：新增断言要求的中性工作流和无员工唤醒路径尚不存在。
- 通过验证命令：`cargo clippy -p vw-agent -p vw-api-types --all-targets --all-features -- -D warnings`
- 模拟策略：使用现有临时调度存储和网关测试夹具，不模拟任务状态机。

## 步骤

1. 按 `./skills/rustcodegraph/SKILL.md` 检查索引并分析相关符号、调用链和受影响测试。
2. 添加工作流回退和项目唤醒不依赖 Staff 的失败验证。
3. 将内建工作流快照移到中性任务/生命周期模块，替换 Staff 回退。
4. 删除项目唤醒中的员工计划、员工命令和员工阶段能力分支。
5. 清理对应 API 命令 DTO、元数据投影和测试夹具。
6. 运行聚焦 clippy 并审查差异仅涉及员工编排解耦。
7. 按 `./skills/git-commit/SKILL.md` 仅提交本任务代码和测试变更。
