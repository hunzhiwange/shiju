# 任务 2: 本地执行器直连

批次：【批次 2】 依赖批次 1

状态：未开始

目的：让就绪任务直接由本地运行器认领和执行，消除派发阶段对 Worker 选择、控制器和 Worker 身份的依赖。

来源任务：无

预计会话范围：只重塑核心派发与本地 Run 生命周期；保留任务、Run、工作区、日志、产物和重试语义，不在本任务删除外围 API。

## 上下文

- `dispatch_task` 当前列举 Worker、评分、调用控制器、认领带 `worker_id` 的 Run，再决定 Local/Matrix target。
- `LocalAgentRunnerRequest`、工作区请求、执行请求和事件都携带 `WorkerName`。
- Run 的租约、attempt、heartbeat 仍有价值，只删除 Worker 所有权。
- 先用 RustCodeGraph 分析 `dispatch_task`、本地运行请求与 Run 存储映射的调用链和影响范围；提交时只包含本任务变更。

## 测试计划

- 行为：首个就绪有限任务无需 Worker 记录即可被本地执行器认领，Run 仍保持租约、状态迁移和重试字段。
- 失败验证测试：新增 `local_dispatch_claims_ready_task_without_worker_snapshot` 和 `run_lease_has_no_worker_identity`。
- 失败验证命令：`cargo clippy -p vw-agent -p vw-api-types --all-targets --all-features -- -D warnings`
- 预期失败原因：现有派发在 Worker 列表为空时返回 `None`，Run 请求仍要求 `worker_id`。
- 通过验证命令：`cargo clippy -p vw-agent -p vw-api-types --all-targets --all-features -- -D warnings`
- 模拟策略：仅模拟 `LocalAgentExecutor` 的工作区和代理执行边界；存储、状态迁移和租约使用真实实现。

## 步骤

1. 按 `./skills/rustcodegraph/SKILL.md` 检查索引并分析相关符号、调用链和受影响测试。
2. 添加无 Worker 快照仍可认领任务的失败验证。
3. 将派发收敛为就绪检查后直接构造本地运行请求。
4. 从 Run、运行请求、工作区请求、执行请求、日志和事件中删除 Worker 身份。
5. 同步 SQLite/Postgres schema 与映射；不编写旧数据迁移或兼容分支。
6. 删除 Worker 选择和控制器调用在本地路径中的使用，保持 Run 失败清理语义。
7. 运行聚焦 clippy，确认本地执行路径闭环。
8. 按 `./skills/git-commit/SKILL.md` 仅提交本任务代码和测试变更。
