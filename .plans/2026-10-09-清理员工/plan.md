# 清理员工与精简调度计划

目标：删除员工、Worker、Team 与全部 Matrix 能力，只保留任务、运行、依赖图与本地代理执行，显著降低配置和依赖复杂度。

范围：移除 Staff 配置、编排、API、CLI、桌面设置与任务看板员工模式；移除 Worker/Team 资源及持久化；删除 Matrix 聊天、task-pool、调度运行时、配置、feature 和全部 `matrix-sdk-*` 依赖；将任务派发、Run 与工作区执行收敛为单一本地路径。

范围外：保留有限任务、周期任务、Run、日志、产物、资源租约、普通任务依赖图及其它聊天通道；不迁移旧员工、Worker、Team 或 Matrix 配置数据。

假设：产品只需要当前进程内的本地代理执行；远程 Worker、Team DAG、员工岗位编排以及 Matrix 通信整体不再支持；旧配置字段和旧 API 可以直接删除，不要求兼容。

## 设计决策

- 选择“任务直接由本地运行器认领”，不保留可配置 Worker 或伪装的默认 Worker。
- Run 保留执行租约和重试信息，但删除 Worker 身份；工作区槽位继续由本地执行器管理。
- 删除 Matrix 的所有实现面和依赖，不保留禁用 feature、占位配置或拒绝型兼容路径。
- 删除 Team 资源和 `TeamDag` 任务类型；普通任务依赖继续使用现有 task graph。
- 不提供旧 Staff/Worker/Team 配置或数据库迁移逻辑。
- 每个任务开始前使用 `./skills/rustcodegraph/SKILL.md` 检查索引新鲜度并分析相关符号、调用链与影响范围；图未覆盖的配置、文档和未索引文件再使用 `rg`。
- 每个任务完成验证后使用 `./skills/git-commit/SKILL.md` 创建单一目的 Conventional Commit；只提交该任务变更，保留并排除执行前已有的无关工作区改动。

## 架构说明

- `agent_scheduler` 继续负责任务状态、依赖、Run、日志和产物；`runner/local.rs` 成为唯一执行入口。
- 网关只暴露任务、工作流、依赖图、Run、日志、产物和唤醒接口；桌面只展示普通任务看板和剩余聊天通道。
- 删除必须与模块导出、路由注册、配置序列化和相邻测试同步，避免留下隐藏配置面。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
- 仓库禁止默认运行 `cargo test`；各任务用负向源码检查和聚焦 `cargo clippy` 验证，最终执行规定的全量 clippy。
- Rust 代码导航、影响分析和受影响测试选择优先使用已有 RustCodeGraph 索引；索引不新鲜时先同步再据此决策。
- 提交是每个任务的完成条件之一；提交前必须复核 staged diff 与 `git diff --cached --check`，不得 push、amend 或捎带无关改动。
