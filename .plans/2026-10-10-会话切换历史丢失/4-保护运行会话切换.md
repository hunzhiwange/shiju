# 任务 4: 保护运行会话切换

批次：【批次 4】依赖批次：1、2、3

状态：未开始

目的：运行中会话切走后，后台增量或终态保存继续基于完整对话，切回时历史和消息 ID 不丢失。

来源任务：用户补充的运行会话切换缺失现象。

预计会话范围：只处理桌面热缓存、普通缓存和流事件交接；不修改冷打开、网关读取或存储事务保护。

## 上下文

- `finish_active_stream_tail_update` 删除普通聊天缓存；`stash_active_session_view` 热缓存插入成功时不建普通后备。后台增量从普通缓存缺失时的空列表续写，内容变化又使热缓存失效。`start` 原本会建普通缓存，故测试必须先模拟活跃流增量。

## 测试计划

- 行为：已有用户和助手历史、当前助手在生成时，切至另一会话；无论后台继续生成还是直接结束，再切回都保留旧消息、当前完整文本及对应 ID。轨迹原始步骤不被错误会话污染。
- 失败验证测试：新增 `running_session_switch_preserves_history_after_background_delta` 与 `running_session_switch_preserves_history_on_terminal_without_delta`。
- 失败验证命令：`cargo nextest run -p vw-desktop --lib -E 'test(running_session_switch_preserves_history_after_background_delta) | test(running_session_switch_preserves_history_on_terminal_without_delta)'`
- 预期失败原因：活跃增量清除普通缓存，热缓存成功插入后后台分支没有完整基线。
- 通过验证命令：同一聚焦命令，再运行 `cargo nextest run -p vw-desktop --lib -E 'test(background_stream_mutation_invalidates_cached_session_view) | test(inactive_stream_done_updates_cached_ids_and_marks_unseen_success) | test(open_requesting_session_prepares_restored_cached_state)'`。
- 模拟策略：直接驱动真实 `App` 的流事件和打开消息处理器；只把网关流内容作为确定性消息输入，不模拟两层缓存。

## 步骤

1. 写两条失败用例，先确认活跃增量删缓存，再切换、后台增量或终态、切回，记录消息内容与 ID 的失败断言。
2. 在热缓存移走完整聊天时保证后台事件拥有同版本续写基线；避免每条增量都复制整段旧历史，且不让过期热快照覆盖更新后的普通缓存。
3. 验证缓存容量拒绝、再次切换和终态持久化快照；保留原有轨迹步骤与原始载荷的会话归属。
4. 运行聚焦测试、相关旧测试和仓库 Clippy。
