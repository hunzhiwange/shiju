# 任务 6: 降低轨迹投影成本

批次：【批次 6】依赖批次：5

状态：未开始

目的：轨迹首次打开或原始载荷更新时，投影不对每个步骤重复扫描和复制累计历史。

来源任务：用户补充的轨迹卡顿。

预计会话范围：只优化纯投影算法，不修改视图布局、缓存生命周期或原始载荷保存。

## 文件

- 修改：`crates/vw-desktop/src/app/components/chat_panel/trajectory/projection.rs`
- 测试：`crates/vw-desktop/src/app/components/chat_panel/trajectory/projection_tests.rs`

## 上下文

- `project_trajectory` 的重复步骤索引检测对每个键再次扫描全部键；`ProjectionBuilder::project_messages` 每步 `clone_from(messages)`，而步骤原始 `messages` 常是累积数组。优化前先确认比较与记录去重语义。

## 验证计划

- 保持的行为：重复步骤索引、跨步骤增量、工具调用配对、稳定记录 ID 和原始详情与现状一致。
- 测试驱动开发不适用：目标是降低计算量，输出不变；使用现有投影测试和新增多步累积载荷等价测试，另用相同输入前后采样证实改善，不用单次毫秒阈值断言。
- 运行：`cargo nextest run -p vw-desktop --lib -E 'test(trajectory_projection_)'`。
- 模拟策略：使用真实 JSON 结构的累计步骤样本，不模拟比较函数。

## 步骤

1. 生成中等规模累计消息轨迹并记录投影基线，核对既有语义用例。
2. 用一次计数识别重复步骤索引；减少对完整历史 JSON 的无必要重复复制，同时保留前缀比较所需数据与记录细节。
3. 新增重复索引和累计消息稳定性的聚焦测试；相同输入复测，再运行 Clippy。

- 预期：所有投影语义测试通过；首次投影和变更后投影的重复扫描、复制热点下降；Clippy 无本次新增警告。
- 所需证据：前后采样或操作计数、测试和退出码、记录 ID/详情对比、已审查差异。
