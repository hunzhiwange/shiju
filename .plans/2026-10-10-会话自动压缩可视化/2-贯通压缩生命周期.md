# 任务 2: 贯通压缩生命周期

批次：【批次 2】 依赖批次 1

状态：未开始

目的：让自动压缩在开始和成功时产生类型化事件，并保证成功摘要进入安全、可恢复的会话历史。

来源任务：无

预计会话范围：聚焦处理器自动压缩路径、流事件及 Gateway 映射；不实现桌面样式。

## 文件

- 修改：`crates/vw-agent/src/session/processor/types.rs`
- 修改：`crates/vw-agent/src/session/processor/runner.rs`
- 修改：`crates/vw-agent/src/gateway/api/handlers/session/stream.rs`
- 测试：`crates/vw-agent/src/session/processor/runner_tests.rs`
- 测试：`crates/vw-agent/src/gateway/api/handlers/session/stream_tests.rs`

## 上下文

- 当前 `runner` 在预检或超长错误后调用临时摘要，但无 UI 事件；Gateway 的 `stream_payload_for_non_done_event` 负责把 `StreamEvent` 编码为 SSE/WS JSON。既有持久化压缩必须保持“摘要成功后再替换历史”的原子性。

## 测试计划

- 行为：自动压缩按“开始→成功→继续主请求”发出一次有序生命周期；摘要失败只有开始与错误，不发成功且保留历史。
- 失败验证测试：在处理器和 Gateway 测试中新增自动压缩事件顺序、JSON 类型与失败语义断言。
- 失败验证命令：`cargo test -p vw-agent compaction_lifecycle --lib`
- 预期失败原因：`StreamEvent` 尚无压缩生命周期变体，Gateway 也无对应协议负载。
- 通过验证命令：`cargo test -p vw-agent compaction_lifecycle --lib`
- 模拟策略：复用测试 LLM 流，仅模拟外部模型响应；会话替换和事件排序走真实代码。

## 步骤

1. 编写处理器开始、完成、失败顺序测试和 Gateway 编码测试。
2. 运行失败验证并记录缺失事件导致的失败。
3. 增加最小类型化事件，在两条自动压缩触发路径统一发出开始和成功事件。
4. 将事件映射为稳定的 Gateway 负载，并确保记录器及穷尽匹配同步更新。
5. 验证摘要失败不发完成、不破坏历史；运行聚焦测试和 Clippy。

## 验证

- 运行：`cargo test -p vw-agent compaction_lifecycle --lib`
- 运行：`cargo clippy --all-targets --all-features -- -D warnings`
- 预期：事件顺序、协议负载与失败原子性测试通过；Clippy 无警告。
- 所需证据：新增测试的预期失败、通过输出、事件 JSON 断言及 Clippy 退出码 0。

## 完成

处理器在自动摘要前后发出明确事件，Gateway 稳定编码；只有成功替换后才报告完成，失败保留原历史。
