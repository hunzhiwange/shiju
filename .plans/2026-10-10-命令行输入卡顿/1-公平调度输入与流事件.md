# 任务 1: 公平调度输入与流事件

批次：【批次 1】 无

状态：未开始

目的：让连续按键和突发 Gateway 消息都只能占用有界单轮预算，输入批量生效后再绘制一次。

来源任务：无

预计会话范围：只调整 CLI TUI 主循环与 runner 的调度边界，并在现有 runner 测试中验证公平性；不触碰渲染实现和 Gateway 协议。

## 文件

- 修改：`crates/vw-cli/src/cli/tui/app.rs`
- 测试：`crates/vw-cli/src/cli/tui/runner_tests.rs`

## 上下文

- `run_event_loop` 当前按 `runner.drain -> draw -> poll/read 一个事件` 循环；`drain_host_messages` 与 `drain_active_stream` 均循环到通道为空。
- 保留单线程终端所有权；预算应是内部常量，不新增用户配置。Resize、Paste、Mouse、覆盖层和退出动作语义必须保持。
- 编辑前使用 `./skills/rustcodegraph/SKILL.md`；先检查索引，再查询 `run_event_loop`、`drain_active_stream` 和调用影响。图未覆盖的测试夹具才使用 `rg`。

## 测试计划

- 行为：突发流消息超过单轮预算时仍留出下一轮处理输入的机会；一批已就绪按键可在一次绘制前全部更新草稿，并受上限约束。
- 失败验证测试：在 `runner_tests.rs` 增加 `active_runner_drain_yields_after_stream_budget`，并为从事件读取与动作执行中提取的可测批处理函数增加 `ready_key_burst_is_applied_before_next_frame`。
- 失败验证命令：`cargo test -p vw-cli cli::tui::runner_tests -- --nocapture`
- 预期失败原因：现有 drain 会清空整个通道，主循环每帧只读取一个终端事件，没有有界公平调度契约。
- 通过验证命令：`cargo test -p vw-cli cli::tui::runner_tests -- --nocapture`
- 模拟策略：使用现有本地 mpsc/Gateway fixture 和内存事件序列；不模拟网络时钟，不以易抖动的墙钟阈值断言。

## 步骤

1. 运行 `~/.rustcodegraph/bin/rustcodegraph status`、`~/.rustcodegraph/bin/rustcodegraph explore "run_event_loop drain_active_stream terminal input fairness"` 和 `~/.rustcodegraph/bin/rustcodegraph impact drain_active_stream --depth 2`，记录调用者与受影响测试。
2. 先新增失败测试，固定单轮流事件上限、输入批处理上限及顺序。
3. 运行失败验证命令并确认断言因现有无限 drain/单事件处理而失败。
4. 让 host/stream drain 返回是否仍可能有工作，并按常量预算停止；把终端事件处理整理为可测试的有界批处理，优先处理首个已读事件，再用零等待读取已就绪事件。
5. 主循环在一轮内执行有界后台工作、输入批处理和至多一次绘制；仅在无现成工作时使用等待，保持 resize 与外部编辑器恢复路径。
6. 运行聚焦测试，审查退出、提交、粘贴、鼠标和 transcript pager 路径未改变语义。
