批次：【批次 1】 无

状态：未开始

目的：避免每次输入重绘都克隆并重新测量完整聊天记录，使成本主要由可见视口决定。

来源任务：无

预计会话范围：只修改 `vw-tui` 的聊天记录布局缓存与渲染测试，保持 ChatWidget 公共接口、视觉结果和交互语义不变。

- 修改：`crates/vw-tui/src/chatwidget/rendering.rs`

- 测试：`crates/vw-tui/src/chatwidget/transcript_tests.rs`

## 上下文

- `committed_lines` 虽缓存每个 cell 的布局，但每帧仍克隆全部 `Line` 到新 Vec；`TranscriptAreaRenderable::render` 随后对完整文本执行 `line_count`，最后才滚动到视口。
- 缓存键必须继续包含宽度和语法主题 revision；历史变化、主题变化和宽度变化必须失效。鼠标选择依赖 `finish_render` 保存的可见缓冲内容。
- 编辑前使用 `./skills/rustcodegraph/SKILL.md` 查询 `committed_lines`、`TranscriptAreaRenderable`、调用者和影响测试；未索引快照再使用 `rg`。

## 测试计划

- 行为：超长历史在草稿逐字变化的连续帧中复用总高度，并只组装当前视口所需行；滚动、跟随底部、选择文本和现有快照保持一致。
- 失败验证测试：增加 `unchanged_long_transcript_reuses_layout_and_projects_only_viewport`，用测试专用计数记录布局构建与投影视图行数；扩展滚动测试覆盖顶部、中部和底部。
- 失败验证命令：`cargo test -p vw-tui --lib chatwidget::rendering::tests -- --nocapture && cargo test -p vw-tui --lib chatwidget::transcript::tests -- --nocapture`
- 预期失败原因：现有 API 每帧返回并克隆完整历史，无法证明视口有界投影。
- 通过验证命令：`cargo test -p vw-tui --lib chatwidget::rendering::tests -- --nocapture && cargo test -p vw-tui --lib chatwidget::transcript::tests -- --nocapture`
- 模拟策略：使用真实 HistoryCell、Ratatui Buffer 和 ChatWidget 渲染；测试计数仅暴露缓存构建/投影数量，不使用耗时阈值。

## 步骤

1. 运行 `~/.rustcodegraph/bin/rustcodegraph status`、`~/.rustcodegraph/bin/rustcodegraph explore "committed_lines TranscriptAreaRenderable render viewport"` 和 `~/.rustcodegraph/bin/rustcodegraph callers committed_lines --limit 30`，记录真实调用边界。
2. 新增长记录连续渲染和多位置滚动失败测试，确认完整行物化导致断言失败。
3. 运行失败验证命令并保存预期失败。
4. 将宽度相关缓存扩展为可查询总高度和行区间的布局；渲染先计算 scroll_top，再仅投影视口覆盖的行，避免复制完整历史。
5. 保持 active/live cell、分隔空行、滚动条长度、选择缓冲和 `transcript_lines` 导出接口的既有结果；仅优化主视口 render 路径。
6. 运行聚焦测试并审查既有快照没有非预期变化。

## 验证

- 运行：`cargo test -p vw-tui --lib chatwidget::rendering::tests -- --nocapture && cargo test -p vw-tui --lib chatwidget::transcript::tests -- --nocapture`

- 所需证据：RustCodeGraph 调用结果、新增测试先失败后通过、输出显示 0 failed；快照无需接受视觉变化；连续帧未重建历史布局且投影行数受视口高度约束。

`TranscriptState` 在宽度、主题和历史未变时复用布局，`TranscriptAreaRenderable` 只组装视口行；聚焦渲染测试通过且视觉快照不漂移后才能标记完成。
