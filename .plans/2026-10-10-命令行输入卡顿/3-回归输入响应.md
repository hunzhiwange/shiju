## 验证计划

- 行为：长记录和持续流输出期间快速输入不出现可感知的字符积压，滚动、粘贴、提交和退出仍正常。
- 聚焦验证命令：`cargo test -p vw-cli cli::tui::runner_tests -- --nocapture && cargo test -p vw-tui --lib chatwidget::rendering::tests -- --nocapture && cargo test -p vw-tui --lib chatwidget::transcript::tests -- --nocapture`
- 静态检查命令：`cargo clippy --all-targets --all-features -- -D warnings`
- 手工验证：启动 `shiju` TUI，恢复长会话；在流式输出期间连续快速输入至少 100 个字符并混合中文，检查回显连续、顺序正确、无成批追赶；再验证滚动、粘贴和提交。
- 预期：两组聚焦测试和 clippy 退出码均为 0；手工场景无字符丢失、乱序或明显积压。

## 步骤

1. 运行 `~/.rustcodegraph/bin/rustcodegraph sync`，再用 `git diff --name-only -- crates/vw-cli crates/vw-tui | ~/.rustcodegraph/bin/rustcodegraph affected --stdin --quiet` 检查影响范围。
2. 依次运行两组聚焦测试，记录测试数量、失败数量和退出码。
3. 执行长会话、流输出、快速中英文输入、滚动、粘贴、提交的手工检查。
4. 运行强制 clippy；仅修复本计划修改引入的错误或警告。
5. 审查 `git diff`，确认没有配置扩张、新依赖、桌面 UI 或 Gateway 协议变化。
6. 将 RustCodeGraph 影响结果、测试与 clippy 命令/退出码、手工场景结果和差异审查结论写入 `validation.md`；证据不完整时不得写成全部通过。
