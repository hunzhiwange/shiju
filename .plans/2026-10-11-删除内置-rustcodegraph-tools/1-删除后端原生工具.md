## 上下文

- `register_rustcodegraph_tool` 在默认与完整 toolset 中按索引状态动态注册 Tool；`runtime_capability_instructions` 还会注入原生 Tool 专用提示。
- 保留通用 Skill Tool、技能发现和显式技能加载；仅删除 `rustcodegraph_skill_available` 为原生 Tool 提示服务的参数链。
- Cargo crate 为 `vw-agent`，features 使用 `--all-features`；仓库禁止未授权运行 `cargo test`，因此测试过滤条件不适用，行为验收使用静态缺失检查与 `--all-targets` clippy。

## Cargo 共享槽位规则

1. 同一仓库的所有计划和任务共用仓库根目录下的 `target/rust-slot-1` 至 `target/rust-slot-10`，不得为任务、会话或计划另建构建目录，也不得按任务编号取模固定分配。
2. 每次构建/验证阶段开始前，创建仓库根目录下的 `target/rust-slot-locks`；依次用原子命令 `mkdir target/rust-slot-locks/slot-N.lock` 尝试领取槽位，`N` 为 1–10。仅 `mkdir` 成功者获得该槽位；这些相对路径命令从仓库根目录执行。
3. 领取成功后，在自己的锁目录中记录计划、任务、会话标识和持有进程 PID。同一槽位同时只允许一个持有者；已占用时尝试下一个，仅全部 10 个槽位都占用时等待并重试。
4. 将 `CARGO_TARGET_DIR` 设置为领取槽位的绝对路径，例如领取槽位 3 后，从仓库根目录执行 `export CARGO_TARGET_DIR="$PWD/target/rust-slot-3"`。示例编号不代表固定分配。
5. 所有 Cargo 构建、检查、测试以及调用 Cargo 的脚本和子进程均继承该设置，不得通过 `--target-dir` 或其他配置绕过槽位；生成的二进制也从该槽位定位。
6. 该阶段的 Cargo、脚本以及使用槽位产物的子进程全部结束后，删除自己写入的占用记录，并用 `rmdir` 释放自己的锁目录；保留槽位编译缓存供后续任务复用。
7. 正常结束、失败和中断均须清理自己的锁；在后台进程或其他使用槽位产物的进程仍运行时不得提前释放。规划清理步骤时覆盖这三种退出路径。
8. 遗留锁须先核实持有会话及相关进程已结束；无法确认则保持占用，不得删除其他活跃任务的锁、进程或缓存。
9. 生成或更新计划时，统一移除与这些规则冲突的单一 Rust 共享构建空间、逐任务独立目录和 Cargo 缓存全局独占窗口要求；仍须遵守源码文件占用、真实业务依赖和其他共享验证资源的互斥，不能仅因缓存分槽就把任务判定为可并行。
10. 最终验证记录包含实际槽位、绝对路径 `CARGO_TARGET_DIR`、确切命令、退出码和有效测试数量；Rust 代码修改后先运行 `cargo fmt --all`，再运行相应验证。编译成功或零测试不能替代行为验收证据。

## 验证计划

- 测试驱动开发不适用：本任务删除能力，且仓库明确禁止未授权运行 `cargo test`；使用删除前/后的静态命中差异与 clippy 编译全部测试目标作为验证。
- 行为：`vw-agent` 不再编译、注册或宣传名为 `rustcodegraph` 的内置 Tool。
- 失败验证：删除生产代码前，用 `rg` 记录原生 Tool 模块、注册函数、Cargo 依赖和 `## RustCodeGraph` 提示仍存在。
- 失败验证命令：`rg -n 'RustCodeGraphTool|register_rustcodegraph_tool|pub mod rustcodegraph|## RustCodeGraph|rustcodegraph = ' crates/vw-agent Cargo.toml`
- 预期失败原因：命令仍命中当前内置 Tool 实现及系统提示耦合。
- 通过验证命令：`cargo fmt --all && cargo clippy -p vw-agent --all-targets --all-features -- -D warnings`
- 模拟策略：不使用 mock；通过真实 toolset 编译路径与相邻测试目标的 clippy 检查类型和注册关系。

## 步骤

1. 记录原生 Tool 实现、注册、导出、依赖与专用提示的现有命中。
2. 删除 RustCodeGraph Tool 模块及描述文件，并移除 toolset 注册、公开导出和 Cargo 依赖。
3. 删除仅为原生 Tool 契约存在的提示词条件、参数传递和相邻断言，保留通用技能提示。
4. 更新 `Cargo.lock`，确认不再由工作区依赖引入 `rustcodegraph` crate。
5. 按槽位规则领取动态槽位、设置绝对 `CARGO_TARGET_DIR`，运行 `cargo fmt --all` 与目标 crate clippy；无论成功、失败或中断都在相关进程结束后释放自己的锁。
6. 审查差异并确认没有触碰通用工具安全策略；证据齐全后标记任务完成并使用 `$git-commit` 提交本任务变更。
