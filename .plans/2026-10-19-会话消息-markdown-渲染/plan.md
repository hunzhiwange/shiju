# 会话消息 Markdown 渲染计划

目标：完成态助手消息按 Markdown 排版显示，保留复制能力，并避免长回复或历史滚动卡顿。

范围：仅桌面会话中的助手正文，包括普通回复及穿插工具块后的文本块；调整现有 Markdown 展示路径、选择与复制衔接、对应测试和实际渲染验证。

范围外：用户消息、工具结果、思考块、输入编辑器、流式生成中的未完成文本，以及 Markdown 表格等目前解析器不支持的语法。

假设：`vw-desktop` 已缓存助手文本的 Markdown 块，但正常完成态优先渲染单一只读编辑器；消息气泡另有右键菜单和整条复制按钮。

## 设计决策

- 沿用 `message_view/markdown.rs` 的块级排版与缓存，不引入 WebView 或重型解析依赖。
- 当前单一编辑器能跨段选择，分块编辑器只能选单块。切换展示前须明确保留跨块选择的交互方案及其自动化、实际操作证据；不能仅靠整条复制按钮掩盖回归。
- 行内强调、代码与链接优先做到可读展示；受 Iced 选择能力限制的语法要有明确退化规则，不能让原始标记散落在正文。
- 复用现有消息块缓存和虚拟窗口，不在每次 `view` 调用中重新解析 Markdown、创建编辑器或扫描整段原文；大文本沿用安全分段与回退边界。

## 架构说明

- `session/chat_ui.rs` 建立 Markdown 块及只读编辑器缓存；`assistant_body.rs` 决定展示路径；`tool_text_support.rs` 与 `input/context_menus.rs` 读取选区并驱动右键菜单。
- `message_view.rs::chat_message_action_text` 为整条复制提供原始可见内容。保留 API 错误卡、流式预览与安全文本回退；非 ASCII 文本不能强制使用等宽字体。
- `chat_ui.rs::prune_chat_heavy_editor_caches` 清理远离窗口的 Markdown 编辑器，`ChatVirtualizer` 控制可见消息；新增渲染不能绕开这两个边界。

## 开发策略

- 对行为变化先增加失败测试，确认完成态正文展示和复制路径现状，再做最小改动。
- 使用既有测试模块覆盖不同消息形态、选区和回退；最终在明暗主题下走实际字形渲染路径，核对中文、代码和右键菜单。
- 比较改动前后的同机长消息渲染、历史滚动与缓存占用；聚焦验证缓存失效和窗口裁剪，发现明显回退时先修复再交付。
