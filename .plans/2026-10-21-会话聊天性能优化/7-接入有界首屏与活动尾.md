## 上下文

- 当前 `prepare_session_open`、UI store 和 Gateway helper 会物化完整 `ChatSession.messages`，并对完整会话计算 signature。
- 新打开流程先取 summary 与最新页；最新页成功即可解除 loading，calls/steps 等非首屏数据按现有真实需要单独延迟获取，不能重新捆回完整历史。
- App 保存任务 5 的 `PagedChatTimeline` 与 session generation。切换/重新打开会递增 generation，旧请求结果必须被拒绝。
- 活动 agent 回复以 overlay 叠加在已加载尾页；若页内已含同 key 条目则更新而非重复。
- 本任务暂不响应顶部加载；任务 8 再实现旧页请求和视觉锚点。

## Cargo 共享槽位规则（仅 Rust/Cargo 任务）

1. 同一仓库的所有计划和任务共用仓库根目录下的 `target/rust-slot-1` 至 `target/rust-slot-10`，不得为任务、会话或计划另建构建目录，也不得按任务编号取模固定分配。
2. 每次构建/验证阶段开始前，创建仓库根目录下的 `target/rust-slot-locks`；依次用原子命令 `mkdir target/rust-slot-locks/slot-N.lock` 尝试领取槽位，`N` 为 1–10。仅 `mkdir` 成功者获得该槽位；这些相对路径命令从仓库根目录执行。
3. 领取成功后，在自己的锁目录中记录计划、任务、会话标识和持有进程 PID。同一槽位同时只允许一个持有者；已占用时尝试下一个，仅全部 10 个槽位都占用时等待并重试。
4. 将 `CARGO_TARGET_DIR` 设置为领取槽位的绝对路径，例如领取槽位 3 后，从仓库根目录执行 `export CARGO_TARGET_DIR="$PWD/target/rust-slot-3"`。示例编号不代表固定分配。
5. 所有 Cargo 构建、检查、测试以及调用 Cargo 的脚本和子进程均继承该设置，不得通过 `--target-dir` 或其他配置绕过槽位；生成的二进制也从该槽位定位。
6. 该阶段的 Cargo、脚本以及使用槽位产物的子进程全部结束后，删除自己写入的占用记录，并用 `rmdir` 释放自己的锁目录；保留槽位编译缓存供后续任务复用。
7. 正常结束、失败和中断均须清理自己的锁；在后台进程或其他使用槽位产物的进程仍运行时不得提前释放。规划清理步骤时覆盖这三种退出路径。
8. 遗留锁须先核实持有会话及相关进程已结束；无法确认则保持占用，不得删除其他活跃任务的锁、进程或缓存。
9. 生成或更新计划时，统一移除与这些规则冲突的单一 Rust 共享构建空间、逐任务独立目录和 Cargo 缓存全局独占窗口要求；仍须遵守源码文件占用、真实业务依赖和其他共享验证资源的互斥，不能仅因缓存分槽就把任务判定为可并行。
10. 最终验证记录包含实际槽位、绝对路径 `CARGO_TARGET_DIR`、确切命令、退出码和有效测试数量；Rust 代码修改后先运行 `cargo fmt --all`，再运行相应验证。编译成功或零测试不能替代行为验收证据。

## 测试计划

- 行为：10,000 条后端历史的首次打开只请求/保存最新页，首屏可用后不等待完整历史，活动消息只合并一次，旧 generation 响应不污染新会话。
- 失败验证测试：`session_open_requests_summary_and_latest_page_only`、`session_open_becomes_ready_after_first_page`、`session_open_merges_active_overlay_once`、`session_open_rejects_stale_generation`。
- 失败验证命令：`cargo test -p vw-desktop session_open_requests_summary_and_latest_page_only -- --nocapture`
- 预期失败原因：当前 helper 调用完整 UI session 端点并将所有消息装入 `PreparedSessionOpen`。
- 通过验证命令：`cargo test -p vw-desktop session_open_page_ -- --nocapture && cargo test -p vw-desktop session_active_overlay_ -- --nocapture`
- 模拟策略：Gateway HTTP 边界使用仓库现有测试服务器，返回 10,000 条元数据但只传一页真实消息；App/session 状态和 overlay 使用真实结构，不 mock 合并算法。

## 步骤

1. 为请求顺序、首屏 ready、传输条数/字节和 generation 保护编写失败测试。
2. 为活动 overlay 的新增、重复恢复、完成态页面重叠编写失败测试。

5. 接入活动状态恢复和去重，确保第一页面到达即可显示。
6. 运行现有会话切换/打开回归、格式化和完整 clippy。
