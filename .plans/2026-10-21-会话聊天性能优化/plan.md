# 会话聊天性能优化

## 目标

- 让长会话滚动、输入、流式输出在 Iced 主线程上保持有界工作量，不随历史消息总量或流式正文累计长度线性退化。
- 保持现有 Markdown、自定义思考块、工具块、消息测量、滚动锚点与完成态缓存语义。
- 用确定性的工作量断言和真实渲染场景建立回归护栏；耗时数据仅作诊断，不设置脱离机器环境的脆弱阈值。

## 现状判断

VibeWindow 已有可视区虚拟化、Fenwick 高度索引、32 条消息分块预热和流式 delta 合并，因此瓶颈不是“没有虚拟列表”。主要热路径是：

```text
流式 delta（约每 50 ms）
  ├─ 克隆不断增长的 ChatMessage
  ├─ 后台重新解析完整正文并构造完整渲染缓存
  ├─ 缓存未及时命中时，view 主线程再次全量哈希/解析
  ├─ 同长度 sync_len 重建整棵高度索引
  └─ 分块缓存失效时可能克隆整段聊天历史
```

Rust 只能降低单次操作成本，不能消除错误的复杂度。当前单次增量仍可能产生 `O(历史消息数 + 当前回复字节数)` 工作，长会话和长回复会持续放大卡顿。

## Codex 对照结论

对照 `/Users/Shared/work/dir/data/codes/codex-main/codex-rs` 后，Codex TUI 使用 Ratatui，并非可直接复制的 Iced 实现；可迁移的是其工作量边界：

- `tui/src/streaming/controller.rs` 与 `streaming/render.rs` 将消息拆成不可变稳定区和可变尾，只重算尾部；完成时才做一次规范化全量渲染。
- `streaming/chunking.rs` 与 `commit_tick.rs` 使用积压感知的批处理和回压，而不是让每个 token 驱动完整 UI 工作。
- `frame_requester.rs` 合并重绘请求；布局缓存以 cell 身份、revision、宽度和主题版本显式失效。
- 已提交的历史内容进入稳定滚动区，活动消息只替换可见尾部。

## 方案选择

### 方案一：只增大流式合并间隔

实现简单，但只是降低触发频率；每次仍执行全量哈希、解析、克隆和索引重建，且会明显增加首字与工具状态延迟。不采用。

### 方案二：继续扩充现有全消息缓存

现有缓存已经覆盖完成态消息，但流式正文每次变化都会使基于全文哈希的缓存失效；增加更多同粒度缓存无法改变线性复杂度。不作为主方案。

### 方案三：稳定区/可变尾增量模型（采用）

保留 Iced、现有消息模型与完成态渲染结果，新增流式投影：稳定前缀只提交一次，可变尾在结构安全边界内重算；用消息 revision 和局部失效替代每帧全文哈希。高度索引同长度同步变为常量操作，分块预热只捕获请求范围。该方案直接消除已确认的四条历史/正文规模热路径。

## 目标架构

```text
Agent delta
  → StreamProjection（追加源文本、稳定边界、可变尾、revision）
      ├─ 稳定块：解析一次，后续复用
      ├─ 可变尾：仅尾部重新解析/测量
      └─ 完成：一次规范化全量校验与完成态缓存
  → ChatPanel view（借用 runtime + 显式 revision）
      ├─ 不在每帧克隆 SessionRuntimeState
      ├─ 不在流式缓存未命中时同步全量解析
      └─ 只更新活动消息高度
  → ChatVirtualizer（同长度不重建索引）
  → Chunk preparation（只快照请求的 32 条消息）
```

## 约束与边界

- 不更换 Iced，不引入重型依赖，不改变后端会话协议。
- 追加型 assistant 文本走增量路径；工具生命周期等替换型更新从最近稳定边界做有界重建，不能伪装成纯追加。
- 自定义 `<think>`、工具块、代码围栏和 UTF-8 边界未闭合时保留在可变尾，避免提前提交错误结构。
- 完成态必须与现有一次性 `build_render_cache_entry` 的可见结果一致。
- UI 验收覆盖暗黑主题、中文与动态文本的真实渲染路径，不对非 ASCII 内容使用等宽字体。

## 验收标准

- 1,000 条历史消息下，同长度流式高度更新不重建完整高度索引。
- 128 KiB 增长中回复的每次追加不再触发 UI 主线程全文哈希或全文解析；稳定前缀不重复解析。
- 流式期间不再每批克隆完整 `ChatMessage`，滚动分块预热最多复制请求分块内的消息。
- 完成态 Markdown、思考块、工具块、代码围栏和中文内容与当前规范化渲染一致。
- 聚焦测试、真实 Iced 渲染场景及 `cargo clippy --all-targets --all-features -- -D warnings` 通过。
