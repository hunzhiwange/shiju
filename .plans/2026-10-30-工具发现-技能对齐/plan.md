# 工具发现与技能对齐计划

目标：参考本地 Codex，使模型按需发现并加载工具，可靠获知、调用和恢复技能，统一主代理与子代理的实际请求行为。

范围：vw-agent 的工具目录、搜索工具、两条执行循环、技能目录与正文注入、main 默认技能、策略校验、压缩及恢复、供应商消息转换、聚焦回归和使用文档。保留现有工具标识与审批链。

范围外：Codex 云端技能服务、插件市场、代码执行模式、GUI 改版、自动安装技能、远端工具执行托管、原生 Responses tool_search 协议与外部 SDK 改造。

假设：当前存在 processor 与 core/tool_loop 两条实际执行链；MCP 已支持运行时注册，但模型工具规格整体发送。技能正文已有按需读取与恢复结构；main 的默认技能在 Gateway 分支遗漏传递。

## 设计决策

- 选客户端搜索：跨供应商、复用执行链；原生 Responses 搜索依赖 SDK，全文预加载浪费上下文。本次对齐行为，不宣称协议完全等同。
- MCP 延迟暴露，基础工具直接暴露；技能目录用 developer、正文用 user，权限始终重新校验。

## 架构说明

- 工具注册、授权、模型暴露分离，搜索只影响暴露，不能授予能力。
- 两条执行链复用目录及技能状态；恢复只存来源标识，读取时重验权限。
- 实际请求、上下文估算及压缩使用同一暴露集合。

## 开发策略

- 对行为变更先失败验证，再最小实现、通过验证与必要重构。
- 模型边界可脚本化，本地 MCP、文件和存储使用真实临时资源。
- 不执行全量单测、Makefile、wasm 检查或 fmt 检查模式；每次 Rust 修改先格式化并审查无关差异，再执行聚焦测试和规定的全目标 Clippy。
- 实现细节、任务顺序、批次和证据仅维护在编号任务及 prompt.md；本文件生成后只读。
