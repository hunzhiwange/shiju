# ACP 全量 CLI 模型来源计划

目标：22 个真实 CLI 默认使用客户端会话所选模型，并允许显式使用 CLI 本地配置；以逐项真实模型请求证据验收。

范围：完整 Provider/model 引用、四类模型协议中继、22 个 CLI 启动配置、必要适配器补丁、来源持久化和切模、桌面交互及全量验收。

范围外：重写 CLI 的 Agent 行为、绕过厂商权限、TLS 劫持、用其他 Agent 冒充原 CLI、自动回退账号、付费生产模型测试及仓库重品牌。

假设：本地配置指 CLI 执行主机；参考项目只对四项接管平台模型；公开资料尚不能证明五项上游入口，不能承诺仅靠本仓库达成 22/22。

## 设计决策

- 选择进程级配置覆盖与网关主机中继；直接分发上游密钥缺少统一撤销，全面 fork CLI 维护成本高。
- 保留原生 ACP；有实际缺口才修改适配器；上游缺口必须显式阻塞。

## 架构说明

- 先保留真实模型，再分派 ACP；复用低层 Provider 认证与转换，不重入会话工具循环。
- 原生配置隔离、令牌按会话绑定；模型来源不改变工具权限。

## 调查与契约

- 逐项证据：[cli-analysis.md](cli-analysis.md)，A 13 项、B 4 项、C 5 项；分类不是验收结果。
- 参考对比：[reference-comparison.md](reference-comparison.md)。Codex 配置已核对 OpenAI 官方文档；其他 CLI 只依据各自官方文档或源码。
- 新建 ACP 会话来源默认 `session_model`，可选 `cli_local`。来源变化新建会话，避免混用本机与托管状态；同来源切模空闲时原子重建。
- `auto` 在每个用户轮次开始解析为一个真实的非 ACP 模型，轮次内固定；不支持的模型能力在执行前报错。模型禁用、凭据撤销、转换不支持均不回退 CLI 账号。
- 本计划拟新增类型 `AcpModelSource`、运行时启动描述 `AcpLaunchProfile`；它们是后续任务定义，不声称已经存在。运行时秘密描述禁止通用 Serialize/Debug。
- 中继提供 Chat、Messages、Responses、Gemini 的必要接口；同协议优先透传，跨协议有显式能力边界。媒体生成、供应商托管工具及不可转换的思考签名不伪支持。
- 五项 C 的接管必须先证明上游入口；负向错误正确不算支持。A/B 也必须完成实际版本的离线模型请求证明。

## 开发策略

- 行为变更使用失败验证、通过验证、再重构；单元测试独立文件。
- 不改无关工作区变更，不新增重型代理依赖，优先复用 axum/reqwest/tokio/aisdk。
- 全仓 Clippy 必须执行；不运行无过滤全量 cargo test、wasm check、fmt check 或 Makefile。
- 当前只编写文档，不执行 Cargo；后续 Cargo 任务按各自完整槽位规则执行。
- 线性顺序、批次和复制提示以 prompt.md 为准；每个编号任务是进度来源，本文件生成后只读。
- 最终“全量支持”必须 22/22 同时具备客户端模型与本地来源的验证证据；有任一上游阻塞则整体仍未完成。
