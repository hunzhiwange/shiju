# 代码模式宿主计划

目标：提供受限 JavaScript exec/wait、异步工具桥接和会话隔离，接入动态工具发现与既有权限管线。

范围：独立 Rust V8 运行时与宿主进程、隔离执行单元、异步工具 Promise、元数据映射、嵌套搜索、输出和会话存储、exec/wait 接入、打包和故障恢复。依赖前两份计划。

范围外：不提供 Node/Deno 系统 API、任意模块导入、直接网络/文件访问；不实现图像生成辅助 API，不承诺全部 Codex 工具名兼容。

假设：Codex 使用独立 V8 宿主；本仓库没有等价 JavaScript 宿主。已有 Rhai 不具备所需 JavaScript 语义。

## 设计决策

- 比较 Node 子进程、轻量新引擎、V8 独立宿主；选择与参考一致的 V8。核心功能值得依赖，先验证构建可交付性。

## 架构说明

- JS 无系统 API，只能经工具桥接访问外部；每执行单元独立 isolate；租户会话隔离；取消回收子进程。

## 开发策略

- 对行为变更采用失败验证、通过验证、必要重构；新增测试在独立文件，优先真实执行器、临时数据库、真实进程和回环服务。
- 所有执行顺序与依赖见 prompt.md，完成状态仅记在编号任务文件。三个目录保守串行；单仓 cargo fmt --all 和全工作区 clippy 不与其它源码编辑并行。
- 禁止无过滤全量 cargo test、cargo fmt --all -- --check、WASM target 检查和 Makefile 命令。代码任务先格式化，再做聚焦验证及仓库要求的全目标全特性 clippy；审查并排除无关格式化差异。
- Rust 验证使用编号任务内的十槽规则；不得用编译成功或零测试代替行为通过。跨仓阶段分别领取对应仓库槽位。
- 当前工作区有其它任务的未提交改动；记录起点，只提交本任务实际变更，不修复无关编译故障。新 API 不要求兼容或迁移旧数据。
