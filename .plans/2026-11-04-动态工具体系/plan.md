# 动态工具体系计划

目标：将现有 MCP 按需发现扩展为通用、可替换、可恢复且不扩大权限的动态工具运行时。

范围：通用身份与暴露策略、授权搜索、版本目录、客户端工具回调、主循环和桌面处理器、MCP 通知衔接、SQLite/PostgreSQL 持久化、恢复与分叉、网关及客户端接口。

范围外：原生模型搜索协议与 Code Mode 分属相邻计划；不复制完整 Codex app-server，不迁移旧协议数据，不新增配置界面。

假设：现有 ToolDiscoverySession 为单轮快照，SessionToolset 固定；MCP 通知缓存、权限/审批/Hook 和两类循环已有实现。

## 设计决策

- 比较仅扩展 MCP 前缀、通用注册元数据、照搬 Codex 全服务；选择通用元数据，复用现有执行管线。

## 架构说明

- 稳定 ID 管授权；结构化身份管协议。目录和执行器同版本发布；当前请求固定快照；存储成功才发布。

## 开发策略

- 对行为变更采用失败验证、通过验证、必要重构；新增测试在独立文件，优先真实执行器、临时数据库、真实进程和回环服务。
- 所有执行顺序与依赖见 prompt.md，完成状态仅记在编号任务文件。三个目录保守串行；单仓 cargo fmt --all 和全工作区 clippy 不与其它源码编辑并行。
- 禁止无过滤全量 cargo test、cargo fmt --all -- --check、WASM target 检查和 Makefile 命令。代码任务先格式化，再做聚焦验证及仓库要求的全目标全特性 clippy；审查并排除无关格式化差异。
- Rust 验证使用编号任务内的十槽规则；不得用编译成功或零测试代替行为通过。跨仓阶段分别领取对应仓库槽位。
- 当前工作区有其它任务的未提交改动；记录起点，只提交本任务实际变更，不修复无关编译故障。新 API 不要求兼容或迁移旧数据。
