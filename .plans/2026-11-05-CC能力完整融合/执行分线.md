# CC 能力融合执行分线

按当前入口和任务卡调度。各目录的只读 `plan.md` 保留原架构与历史拆分依据，线性批次描述以重排后的 `prompt.md` 和任务卡为准。母任务编号仍对应原能力范围，子任务的完成、待回归和阻塞继续以编号卡和正式证据判断。缺失的已完成任务卡不重建。

## 首轮实施入口

三条线分别检查自己的外部产物。源码快照、执行主机、应用路径或配置事务已交付到所需接口时，即可推进使用这些接口的任务，无需等对应母能力完成全部桌面和平台验收。各线继续保留原验收标准。

| 实施线 | 入口 | 第一组可推进工作 | 保留的验收关口 |
| --- | --- | --- | --- |
| 常驻路由（母任务 8） | [常驻路由 prompt.md](../2026-11-05-常驻路由与完整协议适配/prompt.md) | 子任务 10 的控制 API 和 109 的授权事务准备可并行。子任务 8 的凭证实现已提交，生产联验等 36、86。 | 请求防护和凭证就绪后，子任务 86 才发布配置。转换按协议分开实施，实际数据面和 macOS 验收汇合。 |
| MCP（母任务 11） | [MCP prompt.md](../2026-11-05-MCP统一管理与应用分发/prompt.md) | 后端和前端来源盘点可并行。数据契约、校验和原生文件安全写入就绪后，应用适配器按两批实施，每批六项。 | 导入和分发汇合全部适配器；写入共用原生配置事务，凭据复用已有账号所有者。 |
| 外部会话（母任务 14） | [外部会话 prompt.md](../2026-11-05-跨应用会话浏览恢复与历史迁移/prompt.md) | 来源核对与公共数据合同完成后，按应用分批开发只读解析器。Claude、Codex 和 Pi 同一文件里的后续任务保留依赖。 | 受控来源读取汇合适配器；Codex 迁移和写入另等配置事务。 |

首轮把母计划的产物依赖写入 [母任务入口](prompt.md) 和各母任务卡，并重排上表三份子计划。其余子计划的内部批次仍按各自现有入口执行，复核相关任务卡的外部依赖后再启动。母任务 12、13、15 的独立候选分别是技能发现、模板校验和工作区记忆。项目组合的一键应用继续等待各分发接口，真实远端同步继续等待备份和恢复接口，删除旧路径和最终交付继续等待替代能力的验收。

## 并行实施与合入

1. 开工前核对任务卡状态、明确列出的直接依赖、生产接口及计划合入分支。依赖已删除的任务卡时查已有提交和正式证据。功能联调仍要求对应生产接口存在，不能用独立夹具代替。
2. 同批纯盘点任务可在文件互不重叠时共享工作区。同批 Rust 实现使用独立工作树，均从含已验收直接依赖的基线出发。执行计划时指定工作树模式，主调度从承载任务卡状态的集成工作区读取状态。无法隔离时在同一工作区顺次执行涉及共享 Rust 文件或全仓格式化的任务。
3. 适配器和聚焦测试按任务卡分属各文件。各工作树可先验证自己的最小模块接线。公共模块注册、路由表、SDK 导出、Cargo 清单及锁文件进入集成分支时逐项合入，以最新基线为准，只追加本任务所需入口。需要改变多条线的共享接口时，先确定单一负责任务并交付接口，再恢复依赖项。不得用整个文件覆盖其他任务的注册。
4. 合入前在原仓库的 `target/cc-plan-locks` 下以原子 `mkdir merge.lock` 领取合入窗口。持有者记录会话和 PID，检查集成分支及工作区冲突，只合入本任务提交并确认必要入口存在。代码和证据进入集成分支后，由任务原会话更新集成工作区的任务卡状态。合入与状态更新结束后释放自己的锁；等待期间继续在独立工作树实现或验证。遇到集成工作区未提交改动与本任务重叠时保留改动，登记冲突，先推进其他独立任务。
5. 各工作树继续使用原仓库根目录的 `target/rust-slot-locks` 和 `target/rust-slot-1` 至 `target/rust-slot-10`，Cargo 使用槽位的绝对路径。锁和缓存目录以原仓库为准，格式化、测试、Clippy 在任务工作树运行。适配器测试使用独立临时配置和动态端口。使用真实桌面、终端、账号或用户配置的验证，以同一目录下的 `macos-live.lock` 串行领取，仅在验证阶段占用。
6. 一个真实阻塞只挂起显式依赖它的任务。等待期间继续推进同批独立任务，或其他入口中已满足直接依赖的工作。最终回归在合入后的代码上执行，按任务原验收标准分别保留证据。
