# macOS替代验收与交付计划

目标：在 macOS 上逐项证明 CC Switch 能力已由识矩承接，并交付可复现证据与停用指南。

范围：来源映射复核、14 应用真实运行、API/SDK/执行端/Iced 链路、macOS 本机及远程网关、无 GUI、异常恢复、迁入同步、两种 macOS 架构包和交付文档。

范围外：Windows、Linux、WSL 验收；生产发布；重做前置能力；自动删除 CC Switch 或真实用户数据。

假设：来源快照固定为 ca58c0313360eae7c851fbd7553c1614c7af03e7。当前 vw-agent-apps 尚不存在；母任务 1–21 的完成证据是后续验收前提，不能将规划当作实现。

## 设计决策

- 采用按领域核证、按应用单场景实测；拒绝一次全量大验收或在验收中补齐整块能力。
- 仅 macOS；ARM64、x64 分列，缺机器或账号记未验证，不降低全覆盖门槛。

## 架构说明

- API 类型 → SDK → 网关 → 原生业务包 → 执行主机；Iced 不直写业务存储。
- 原始来源索引只读；证据保存在 docs/shiju/cc-macos-acceptance，测试账号与数据隔离。

## 开发策略

- 本计划以验收和文档为主，不修改生产代码；缺陷回交对应能力所有者，当前任务记录阻塞。
- 如另行获授权修改行为，先为单一缺陷编写真实失败验证，再做最小修复和通过验证；不能省略仓库检查。
- 证据须绑定产品树基线提交、工作区差异、产物哈希、macOS/架构和应用版本；旧证据必须复核适用性。
- 运行命令必须来自已交付契约，不推测未来 API、CLI 参数或测试名；映射准备任务登记确切重放步骤。
- 未实现、未验证、上游不支持分别列示，后者需要来源依据；非 macOS 记范围外，不计入通过数。
- 缺失真实上游时可用受控模型响应证明局部链路，但不能据此宣布真实账号/模型已通过。
- 每个会话只完成任务文件的一条验证故事；超过约 30 分钟的功能修复停止扩展并回交，不在此重建子系统。
