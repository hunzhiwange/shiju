# 余额套餐额度与查询脚本计划

目标：在 macOS 上通过网关、SDK 与 Iced 完整查询官方额度、余额、Coding Plan 和自定义脚本。

范围：母任务 7 的来源核对、账号定位、全部原生查询适配、脚本模板与隔离执行、缓存刷新、额度投影、API/SDK、桌面展示与 macOS 验收。

范围外：不改账号授权流程、请求路由执行、消费账单统计、用户旧数据迁移、发布源；不要求 Windows/Linux 验收。

假设：来源快照 ca58c0313360eae7c851fbd7553c1614c7af03e7、4.0.25；当前 vw-agent-apps 尚不存在，代码实施等待母任务 1–6 的相关交付。仅规划不能标记母任务完成。

## 设计决策

- 选原生适配器与受控 QuickJS；直接复用 Tauri 耦合重，全改 JS 会丢失原生能力，均不选。
- 缓存与调度归服务；客户端只展示，凭据不进入公开 DTO。

## 架构说明

- agent 执行上下文/存储 → apps 业务 → API 类型/SDK → Iced。
- 脚本不能绕过主机网络授权；官方、余额、估算、账单分开标识。只承诺 macOS 实测。

## 开发策略

- 行为变更先独立失败测试，再最小实现与通过验证；文档盘点以逐项清单验收。
- 编号任务每次只完成一个查询适配器或一个窄行为；全部串行，避免模块注册、路由、Cargo.lock 与格式化冲突。
- 新路径与测试名均为本计划拟新增定义，不宣称已存在；公共合同由前置任务落实，缺失依赖只在对应任务记录，不临时重建整个底座。
- Rust 修改先 cargo fmt --all，再过滤测试与 cargo clippy --all-targets --all-features -- -D warnings；不运行全量测试、wasm 检查、Makefile 或 fmt check。
- plan.md 生成后只读；进度与阻塞在编号文件，正式证据留 docs。外部账号缺失写未验证，不将替代 HTTP 测试当真实账号验收。
- 仅验收 macOS 当前主机架构，记录系统/架构/应用版本。真实数据库按底座已经交付的后端逐一验证，不新增数据库实现。
