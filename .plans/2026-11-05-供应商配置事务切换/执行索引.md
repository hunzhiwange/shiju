## 前置与落点

- 实施共同前置：母任务 1 的来源快照、母任务 2 的原生包/存储/API/权限/操作协议、母任务 3 的 14 应用注册均已验收。缺项只记录在正在执行的编号任务，不创造假接口。
- 编号任务列出的新文件是本计划设计落点，当前并不存在；任务 1 核对前置实际结构。若同职责模块已经交付，沿用并在当前任务记录映射，不另建第二套服务。
- 本计划固定 API 域与既有识矩 `/v1/provider` 区分为应用配置供应商领域；准确 URL/DTO/模块注册由任务 1 按母任务 2 实际契约确定。禁止直接把上游命令名做任意调用接口。
- 每个对外行为作为小型纵向任务同时接业务服务、强类型 DTO、鉴权 handler 与 SDK；内部补丁/事务任务由预览及应用适配调用，不为每个内部步骤增加公共后门。
- 凭据只在执行端持有；读响应、预览、差异、日志和失败详情一律脱敏。密钥保留/替换/清除必须是明确写入意图。
- 主机、租户、项目、账号隔离遵守母任务 2；同一物理文件写锁必须在不同调用上下文间共享。
- 母任务 5 拥有内建模型/预设知识，6 拥有托管账号与 OAuth，8 拥有代理协议，10 拥有聚合目录，15 拥有工作区，20 拥有全局导航与系统集成；本计划负责配置投影及已有账号引用。
- 后续母任务能力尚不存在时，用明确依赖响应和真实本机测试服务验证配置边界，不声称真实路由、聚合或托管登录已端到端通过；最终矩阵保留未验证交叉项。
- 不执行用户目录切换或清理。所有自动化测试使用临时 HOME/显式根目录、内存或临时数据库和测试端口；禁止测试读写真实 ~/.claude、~/.codex、~/.gemini 或生产钥匙串。

## 会话与验证

- 每任务只围绕标题行为。通常一次聚焦会话；遇到第二个独立行为则在当前任务记录阻塞，重新拆分，不默认扩大到其他任务。
- 每批仅一个任务；线性编号顺序执行。任意两批不并行，Cargo 槽位容量不是并行许可。
- 聚焦测试使用默认 features：现有 vw-api-types/vw-gateway-client 无 feature，vw-agent 使用其 Cargo.toml 默认集，vw-desktop 默认空集；不启额外 feature。vw-agent-apps 的真实 features 在任务 1 根据前置清单核定，默认 features，不自行新增。
- 每个 Rust 任务先 cargo fmt --all，再精确前缀过滤测试，最后全仓 cargo clippy --all-targets --all-features -- -D warnings。不运行无过滤全量 cargo test、fmt --check、wasm 检查或 Makefile。
- 必须有有效测试计数，零测试不通过；失败验证要命中业务断言，编译错误仅能说明测试接线未完成。测试文件独立于业务源码，通过现有模块注册方式纳入。
- UI 任务额外在 macOS 真实渲染明暗主题、中文、动态文案和长表单。记录截图与应用版本；构建 Element 不算字形/布局验收。已有 agent-profile-window 仅是隔离窗口模式参考，不直接用它冒充供应商界面验证。
- Rust 格式化引出的无关差异回退到本任务前状态，不覆盖用户既有修改。Clippy 既有无关错误仅交接，状态使用已完成，待回归并保留任务文件；缺真实前置则已阻塞。
- 已完成须当前红绿测试、确切命令/退出码/有效计数及 API/渲染证据。按 $git-commit 仅提交本任务实际变更，再在最终回复报告证据后删除任务文件；只有编号任务状态或删除不单独提交。
