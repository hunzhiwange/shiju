# 工作区记忆与应用专属设置计划

目标：完整融合 OpenClaw 工作区、每日记忆及专属配置和 Hermes 记忆、设置入口，仅验收 macOS。

范围：母任务 15 的逐命令归属、执行主机文件边界、配置分节原生化、权限 API、SDK、Iced 编辑搜索与系统入口；交叉能力复用前置领域并保留可追溯入口。

范围外：不实施母任务 1–14，不导入识矩全局记忆，不创建远程控制协议，不迁移旧数据库，不验收 Windows/Linux，不运行上游 Tauri。

假设：上游干净提交 ca58c0313360eae7c851fbd7553c1614c7af03e7、版本 4.0.25；当前 vw-agent-apps 未创建，母任务 1–14 的实施依赖须以实际交付证据确认。

## 设计决策

- 采用应用原生文件加网关领域 API；全局记忆导入会越域，通用命令转发会扩权，均不选。
- Hermes 深层设置沿用其 Web 面板，模型写入由供应商切换拥有；不另造配置编辑器。

## 架构说明

- agent-apps 执行业务；agent 校验权限和主机；API 类型→SDK→Iced。
- 复用前置路径解析、配置锁与原子写；目标主机路径不得回退本机。

## 开发策略

- 行为变更先失败验证，再最小实现和通过验证；无行为文档用清单审查。
- 每个任务只有一个主要验证故事。全部串行，批次与线性顺序见执行索引.md；不安排并行，避免入口、正式证据与 cargo fmt 全仓资源冲突。
- 来源映射.md 保存逐命令和文件归属，接口边界.md 定义本计划拟新增接口，不将尚未实现接口当作现状；任务 1 对前置实际合同复核后方可编码。
- Rust 修改先 cargo fmt --all，再精确过滤测试及 cargo clippy --all-targets --all-features -- -D warnings；禁止全量 cargo test、fmt check、wasm 检查及 Makefile。
- 仅 macOS 原生目标。UI 每项实际打开中文/长文本/暗黑弹窗验证字形整形与滚动，不能只构建 Element。其他平台保留源码但不宣称通过。
- 所有单元测试独立文件；正式证据保留在 docs/shiju/agent-apps/workspace-macos-acceptance.md，任务文件删除不丢证据。
- plan.md 生成后只读；本轮只规划，不更改母任务状态，不运行 Cargo，不领取槽位，不提交其他会话改动。
