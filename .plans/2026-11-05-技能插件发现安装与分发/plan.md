# 技能插件发现安装与分发计划

目标：融合技能发现、安装、更新、跨应用分发及 Claude 配置控制，经统一 API、SDK 和 Iced 提供，仅验收 macOS。

范围：仓库与市场搜索、技能 SSOT、Git/归档/本地与未托管导入、详情与哈希、应用绑定及复制/链接、冲突与备份恢复、目录迁移、取消进度、现有插件市场衔接及 TS 业务原生化。

范围外：Linux/Windows/wasm 验收、旧数据库迁入、重做 ACP 会话挂载、安装时执行脚本、重品牌、通用远程控制协议、修改只读母计划。

假设：上游干净提交 ca58c0313360eae7c851fbd7553c1614c7af03e7（4.0.25）；代码实施以各任务实际消费的业务包、执行端和配置接口为前置；来源盘点可先行。

## 设计决策

- 选原生服务融合现有市场；直接调用 Tauri 耦合 UI，另建市场会重复存储，均不选。
- 全局分发独立于 ACP；Claude 配置标记独立于插件包。只承诺 macOS。

## 架构说明

- agent-apps 管业务；agent 管存储/授权/执行端；api-types → SDK → Iced。
- 复用设置存储和应用根目录合同；所有写入防穿越、防越权，不扩大脚本权限。

## 开发策略

- 对会改变行为的代码，使用失败验证、通过验证、必要重构；测试独立文件，先证明真实失败。
- 每个会话限定一个行为、一个 API/SDK 小族或一个桌面操作；具体任务与依赖放编号文件，prompt.md 提供执行入口。
- 并行批次和直接产物依赖以 prompt.md 及编号任务卡为准。公共入口与共享证据按母计划执行分线逐项合入。
- 每个任务完成都需要新证据；Cargo 使用仓库十槽位。Rust 修改先 cargo fmt --all，再聚焦测试及 cargo clippy --all-targets --all-features -- -D warnings。
- 不运行无过滤全量测试、wasm 检查、Makefile 或 fmt check；本轮只有文档，不运行 Cargo。
- 首任务维护来源覆盖与前置合同；正式证据保留 docs/vibewindow/agent-apps/skills/，编号文件是唯一进度来源。生成子计划不代表母任务完成。
- plan.md 生成后只读；不覆盖现有 ACP/动态工具与其他会话改动，不自动写回母来源清单。
