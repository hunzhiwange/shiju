# 故障转移连通检测与诊断计划

目标：在识矩长期应用路由中融合安全故障转移与可取消诊断，打通 API、SDK 和 Iced，仅验收 macOS。

范围：备用队列及顺序、启停、熔断与恢复、单一重试预算、首字节/空闲/总超时、实际路由与失败原因、测速、可达性、模型/流式和 MCP 检测；保留账号及工具副作用边界。

范围外：Linux/Windows/wasm 验收、发布、历史库迁移、重建协议适配、账号授权与MCP配置分发；不在本轮实现代码。

假设：上游提交 ca58c0313360eae7c851fbd7553c1614c7af03e7 已核对；vw-agent-apps 尚未注册。母任务1–8按其契约交付后再接入运行链；提前规划不代表依赖已实现。

## 设计决策

- 选业务包加 agent 资源适配；整包Tauri迁移耦合高，桌面调度无法无窗口运行。
- 总尝试预算唯一；主动诊断不影响生产熔断。未证明可重放即拒绝重放。

## 架构说明

- 领域逻辑 → agent资源与权限 → API/SDK → Iced；复用长期路由与现有MCP底层。
- 队列持久化，健康和诊断短期有界；按租户/项目/主机/应用/供应商/账号隔离。

## 开发策略

- 对行为变更先写失败测试，再实现和通过验证；独立测试文件，精确过滤且非零测试。
- 每个任务只完成一个窄行为；来源、接口、依赖、批次与证据放编号文件及来源映射.md。本文件生成后只读。
- 线性执行，各批次一项，不安排并行；构建缓存分槽不代表源文件或真实窗口可并行。
- Rust修改后 cargo fmt --all、聚焦测试及 cargo clippy --all-targets --all-features -- -D warnings；仅macOS，不做全量测试或Makefile。
- 缺前置能力记录在当前任务，不以臆测接口实现替代；无关工作区变更不改、不提交。
