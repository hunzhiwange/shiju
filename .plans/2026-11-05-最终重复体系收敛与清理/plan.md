# 最终重复体系收敛与清理计划

目标：在前置融合能力已验收的基础上，逐领域收敛运行所有者与写入路径，完成 macOS 去重后验收。

范围：供应商、模型、账号、配置、MCP、技能/插件、提示词、会话、用量/价格、数据库、网络客户端、调度、事件、安装更新；代理边界、IPC、运行依赖、来源归档及 SDK/Iced 回归。

范围外：不补做母任务 1–20 的融合功能；不做 Windows/Linux、交叉编译、发布或全量单元测试；不强合不同职责的会话 relay，不替换仓库品牌。

假设：规划时 vw-agent-apps 尚未创建，母任务 21 未开始；来源清单主责 21 的文件、命令、事件均为零，必须交叉核对其他领域；既有工作区有无关未提交改动。

## 设计决策

- 比较全仓一次删除、长期双实现、按领域证据收敛；选择第三种，控制回滚范围。
- 仅 macOS 验收；前置未交付则登记依赖，不能据当前缺文件直接删除来源。

## 架构说明

- API 类型 → SDK → 网关 → 领域服务；桌面仅持有界面状态与本机系统动作。
- 单一所有者不等于单库、单客户端或单调度器；保留作用域和权限不同的边界。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构；先以真实调用链证明问题，再最小切换，最后删除失去调用者的副本。
- 已满足不变量的领域不制造失败或改动；给出当前行为、静态调用者和无需删除的证据即可。
- 每项仅收敛其领域已有等价路径，预计 20–40 分钟有效操作，首次构建等待另计。不能把补齐缺失业务塞进清理任务。
- 每项文件、符号、测试与回滚点写入独立正式证据文件；前置尚未交付的具体生产符号由执行时从真实代码绑定，禁止臆造新领域 API。
- 所有任务各占一个线性批次，编号即顺序。没有可并行批次：共享网关注册、SDK、清单及全仓格式化/Clippy 资源需要互斥；Cargo 分槽不能解除源码互斥。
- 只在编号文件记录任务状态或阻塞；本文件生成后只读。正式证据独立保留，不随完成任务文件删除。
- macOS 仅接受实际版本、真实操作和隔离数据证据；缺账号/设备/服务标未验证。无关既有编译错误不顺手修复。
