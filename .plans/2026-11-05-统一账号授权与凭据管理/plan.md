# 统一账号授权与凭据管理计划

目标：把七类账号授权与凭据管理拆成聚焦会话任务，交付隔离的主机业务、API、SDK 与 Iced 闭环，仅验收 macOS。

范围：Claude、Codex/ChatGPT、Copilot、xAI、Kimi、AGY、DSH 的真实来源授权方式，取消/到期、多账号、绑定/默认、登出/撤销、文件/钥匙串、刷新与跨进程轮换及脱敏。

范围外：Linux/Windows 验收、部署发布、旧结构迁移、Go 网关、新远程协议；模型与额度实现分别归母任务5、7，代理优化归8，系统通用交互归20。

假设：源提交 ca58c0313360eae7c851fbd7553c1614c7af03e7、版本4.0.25；当前 vw-agent-apps 未注册。母任务1–5及其契约交付前只可做文档；生成子计划不等于母任务6完成。

## 设计决策

- 选逐行为迁入原生包；整块搬迁会话过大，长期双写难一致，均不选。
- 全部串行；远端缺执行通道或回调不可达明确拒绝，不回退客户端。

## 架构说明

- 类型→SDK→Iced；Gateway鉴权→原生业务→授权执行主机。
- 复用已有存储与事务；秘密留主机，公开接口仅脱敏状态，租户头不是成员凭证。

## 开发策略

- 行为任务先独立失败测试，再最小实现、聚焦通过验证；真实文件、存储、进程和 HTTP，公网 OAuth 可受控替代。
- 一任务一个主要验证故事；具体文件、测试、线性批次与前置在编号文件，复制入口在 prompt.md。新增路径均为本计划拟建落点，不声称已存在。
- 来源和接口文档先固定支持矩阵与所有者；后续不得猜测前置接口已经交付。只有缺少真实依赖才记阻塞，不将计划存在等同于实现存在。
- Rust 修改先 cargo fmt --all，再聚焦测试与 cargo clippy --all-targets --all-features -- -D warnings；不执行无过滤全量 cargo test、wasm、Makefile 或 fmt check。
- 并发槽位仅用于构建缓存，不改变串行源码约束；格式化后审查并排除无关差异。
- 真实登录与桌面渲染另分会话，测试账号缺失的分支保留未验证，不能推断上游不支持。实际平台只验收当前 macOS，不追加跨平台工作。
- 本文件生成后只读；任务文件是进度来源，正式证据存 docs/vibewindow/agent-apps/auth/，不以删除文件推断完成。
