# 网关服务底座原生化计划

目标：将 CC 后端的共同底座接入原生 Rust 包和现有网关，以真实图标库读写证明 API、SDK、Iced 边界，仅验收 macOS。

范围：后端所有权与 TS 规则盘点；存储、认证、执行主机、任务/事件/分页/错误合同；原生图标库最小竖切和 macOS 无窗口/桌面验收。规则领域实现继续由母任务 3–20 承担。

范围外：不实现所有 CC 业务、不搬整库、不迁移用户旧数据、不改 Go 网关、不新建远程控制协议、不要求 Linux/Windows 验收。

假设：来源提交 ca58c0313360eae7c851fbd7553c1614c7af03e7，4.0.25；当前 vw-agent-apps 不存在。文档可提前执行；所有代码任务须等待母任务 1 的完整来源快照验收。用户明确本轮只验收 macOS。

## 设计决策

- 采用纯业务包加 agent 存储适配；整库抽离过大，反向依赖 agent 会成环，均不选。
- 图标库用现有双后端设置表；不运行 upstream，不建立第二数据库；领域迁移与底座证明分开。

## 架构说明

- vw-api-types → SDK；agent → vw-agent-apps 与现有存储；Iced 仅 SDK。
- 现有 Basic/租户头不等于成员授权；主机动作不得回退桌面本机。只承诺 macOS 实测。

## 开发策略

- 对行为变更先新增独立失败测试，再最小实现、聚焦通过验证；结构与盘点使用清单验收。
- 每项限定一个行为或固定来源文件组；详细文件、合同、批次、顺序与证据在编号文件和 prompt.md。
- 全部串行，每批一个任务，避免共享入口、Cargo.lock、格式化和测试资源冲突。共享槽位容量不代表这些任务可并行。
- 仅创建子计划不等于母任务完成。plan.md 生成后只读；执行进度/阻塞只写对应编号文件，长期交付证据留正式文档。
- Rust 修改先 cargo fmt --all，再聚焦测试和仓库要求的 Clippy；不做无过滤全量 cargo test、wasm 检查、Makefile 或 fmt check。
- macOS 同时验证真实 SQLite/PostgreSQL；没有 PostgreSQL 时记录阻塞，不接受 skip 或零测试。当前工作区其他改动不覆盖、不提交。
