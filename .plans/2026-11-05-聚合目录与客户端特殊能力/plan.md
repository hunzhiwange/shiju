# 聚合目录与客户端特殊能力计划

目标：把母任务 10 拆成短会话可完成的原生业务、网关、SDK 与 Iced 任务，仅在 macOS 验收。

范围：聚合成员与默认项、稳定模型标识与路由、Claude/Codex/Desktop 目录、Codex 子代理/审批/经典工具/客户端刷新、OMO/Slim、Pi/OMP 特殊目录、退出恢复与权限证据。

范围外：Linux/Windows 验收、应用安装器、通用供应商 CRUD、账号登录实现、通用模型元数据补全、MCP、任意命令执行及母能力 21 的去重。

假设：来源提交 ca58c0313360eae7c851fbd7553c1614c7af03e7，读取时工作区干净；vw-agent-apps 尚未注册。母能力 1–9 的已验收产物是实现前置条件，不能凭计划文件当作已交付代码。

## 设计决策

- 选择原生纯规则加现有事务/执行端，拒绝直接嵌入 Tauri 或桌面维护业务副本。
- 按源码纳入 Desktop 聚合；聚合拒绝故障转移。仅 macOS 验收，不删除其他平台代码。

## 架构说明

- vw-agent-apps 拥有规则；Gateway 管作用域和执行主机；SDK 是 Iced 唯一业务入口。
- 使用已有账号、事务与代理契约；聚合失败不回退错家；重启限确认后的托管 daemon。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构；测试放独立文件。
- 一个任务只处理一个规则族、一次窄接口接入或一个界面动作；建议每会话 20–45 分钟有效实现，编译等待另计，不把建议时长当作完成证据。
- 在实施步骤前规划失败验证命令和预期失败；将实现限制在测试证明的行为范围内。
- 测试真实配置、路由、存储和 HTTP；仅替代外部模型服务、时钟、进程表、危险重启边界。
- 所有批次串行，线性顺序及前置批次写在任务和 prompt.md；共享注册文件和 cargo fmt --all 会接触工作区，不以构建分槽推定可并行。
- 本目录只读架构指南不记录进度；任务状态只在编号任务维护，完成证据存 docs/shiju/agent-apps/aggregation/，不修改母 plan.md 或据此宣告母任务完成。
- 代码任务均在 macOS 原生目标以默认 features 执行明确过滤测试，再执行仓库规定的全 features Clippy；不运行全量单测、wasm、Makefile 或 fmt --check。
