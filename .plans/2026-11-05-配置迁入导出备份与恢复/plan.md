# 配置迁入导出备份与恢复计划

目标：将 CC Switch 数据显式迁入识矩唯一业务所有者，完成导入导出、备份恢复和原生桌面闭环，仅验收 macOS。

范围：来源识别与版本校验；供应商、MCP、技能、规则、组合、偏好、用量七类迁入；选择、冲突、幂等、取消与回滚；SQL及原生包；备份维护、恢复、保留、周期与分类；API、SDK、Iced。

范围外：不实现 WebDAV/S3 同步、不改 Go 网关、不搬真实用户数据、不接入 CC 更新源、不要求 Linux/Windows 验收、不重做前置领域能力。

假设：来源为 ca58c0313360eae7c851fbd7553c1614c7af03e7、4.0.25，源 schema 24；当前 vw-agent-apps 尚不存在。代码实施依赖母任务1–17交付；可先核对契约并登记缺项，不在单个会话重建底座。

## 设计决策

- 整库替换易跨越隔离边界，永久双库会多源；选择暂存解析后按领域迁入。
- 完整本机回退与可迁移导出分型；默认不跨设备复制凭据、绝对路径或系统集成。
- 共用既有身份、存储与任务协议；暂存旧 schema 仅作导入桥，不承担旧运行结构兼容。

## 架构说明

- API 类型 → SDK → Iced；网关鉴权 → 业务包 → 现有领域所有者。
- 执行主机处理目标数据；桌面仅选择/传输文件。写前回退、失败回滚，提交后投影失败显式报告。

## 开发策略

- 对行为变更先独立失败测试，再最小实现与聚焦通过验证；纯契约/覆盖盘点使用文档核对。
- 单项只含一个主要验收故事；预计约30–60分钟净实现，首次编译和前置等待另计。任务依赖缺失不吞并其他母任务。
- 所有任务按编号线性执行，每批一个任务，不安排并行。共享模块注册、路由、Cargo fmt和桌面验证资源均有冲突；共享槽位容量不改变执行顺序。
- 每项仅登记自己的证据；长期来源映射、契约与平台证据保留正式文档；进度/阻塞只在对应编号文件。plan.md只读，prompt.md不是进度源。
- 代码修改先cargo fmt --all，再聚焦测试及cargo clippy --all-targets --all-features -- -D warnings；不执行全量单元测试、fmt check、wasm检查或Makefile。
- 聚焦测试用各crate默认features，不假设新增feature；工作区Clippy使用全部features。当前尚未注册的业务包必须先确认前置交付，禁止以零测试作为通过。
- 仅macOS本机架构验收；不需其他平台或双架构设备。存储测试覆盖前置实际支持的后端；外部数据库缺失应登记未验证，不伪报通过。
- 所有fixture匿名，目录和数据库隔离；不得自动读取、迁移或破坏真实用户数据。系统HOME不得重设。工作区其他变更不覆盖、不提交。
