# 项目配置组合与一键应用计划

目标：在识矩通过 API、SDK 和 Iced 管理共享项目组合，按三个应用分组独立快照与应用，仅验收 macOS。

范围：组合创建、列表、改名、删除、重拍、当前标记、切换前自动保存、预览和四类配置应用；项目/租户/执行主机边界、逐项结果、并发与取消；来源到实现证据映射。

范围外：Windows/Linux 验收、旧库迁移、重做供应商事务或 MCP/Skills/提示词分发、独立远程协议、托盘整体重建与重品牌。

假设：来源为 CC Switch 4.0.25、ca58c0313360eae7c851fbd7553c1614c7af03e7。实际应用槽位分别等待供应商、MCP、技能和提示词接口。

## 设计决策

- 复用领域服务编排；复制四套写文件逻辑易分叉，整组强制回滚违背逐项结果，均不选。
- 三组独立、实体共享；部分失败显式状态，不把请求完成当全部应用成功。

## 架构说明

- api-types → SDK → Iced；agent 负责授权和存储适配，agent-apps 负责编排。
- 标记按租户/目标主机/应用组隔离；项目设置复用现有所有者，快照不存密钥。

## 开发策略

- 对会改变行为的代码，先失败验证，再最小实现、通过验证与必要重构；测试真实行为，独立测试文件。
- plan.md 生成后只读；顺序、批次及任务依赖见 prompt.md；来源与边界见来源映射.md。进度与阻塞只写对应任务文件。
- 并行批次和直接产物依赖以 prompt.md 及编号任务卡为准。公共入口与共享证据按母计划执行分线逐项合入。
- 每项只增加一类行为，通常约 30–60 分钟净实现；不含首次编译和等待依赖时间。发现多个独立问题时只解决当前行为所需部分，记录其余阻塞，不整块重写。
- 当前仅编写文档，不调用 Cargo。实施 Rust 任务须先 cargo fmt --all，执行有过滤测试，最后 cargo clippy --all-targets --all-features -- -D warnings。不跑全量 cargo test、fmt check、wasm 或 Makefile。
- 母任务维持未开始；子计划完成不等于功能完成。正式证据保存 docs/shiju/agent-apps/profile-macos-acceptance.md，不依赖被删除的任务文件。

实机验收由用户按`.plans/2026-11-05-CC能力完整融合/人工验收.md`人工完成。自动任务以聚焦测试、隔离夹具和命令输出为证据，无需启动真实桌面、使用真实账号、截图或录屏。
