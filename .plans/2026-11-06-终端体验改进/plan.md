# 终端体验改进计划

目标：代码模式与工作模式均可使用终端；默认字号 15px、行高舒适、拖拽容易，编辑器与终端可可靠切换输入焦点。

范围：桌面原生项目工作区的终端入口、布局、字体度量、面板高度拖动及编辑器焦点交接，复用现有终端生命周期与配置链。

范围外：浏览器端终端后端、Shell 能力扩展、新设置项、编辑器全面重构、无关供应商与文件树变更。

假设：“拖动条”指终端顶部高度分隔条，当前命中高度仅 1px；采用 8px 命中区。字号指字形真实尺寸；行高暂选字号的 1.4 倍，15px 对应约 21px，需实际渲染确认。默认值仅影响未配置字号的路径。

## 设计决策

- 工作模式复用现有底部终端，避免新增实例；不另建模式专属终端。
- 使用真实字号与固定行高比例，取代固定字号加缩放；暂不增加行高设置。
- 扩大分隔条命中区；焦点优先使用底层原生失焦接口，避免上层吞键绕过。

## 架构说明

- 入口由 top_bar/controls 与 view/panel/settings 连线；布局复用 bottom_panel。
- TerminalState、iced_term 与 CodeEditor 各自持有状态，应用 FocusArea 不等于控件焦点。
- 保持原生与 Web 能力边界及明暗主题一致。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前规划失败验证命令和预期失败。
- 将实施步骤限制在失败测试所证明的行为范围内。
- 测试真实行为，不验证模拟对象或实现细节。
