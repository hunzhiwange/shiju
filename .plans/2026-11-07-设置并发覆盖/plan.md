# 设置并发覆盖计划

目标：避免同租户不同设置并发 PATCH 丢更新，以及旧桌面系统设置快照覆盖编辑器新值。

范围：网关租户配置读改写边界；桌面系统设置旧调用者的字段补丁。来源为设置交互卡顿任务 4 的真实鉴权 HTTP 回读。

范围外：设置 UI 改版、请求去抖统一重构、安全策略调整。

假设：默认 features 的测试网关/SQLite 两轮共 40 次独立字段并发全部丢失一个值；旧快照确定顺序覆盖两次复现。生产构建和 PostgreSQL 尚需独立验证。

## 设计决策

- 服务端优先在存储边界实现原子更新；仅进程锁不能保护多进程写入，客户端排队也不能约束其他调用者。事务与条件写重试在任务 1 中依据现有数据库 API 收敛，不增加公开配置。
- 客户端只提交本次变更字段；保留原有默认值归一化、错误返回和鉴权。

## 架构说明

- 沿用 update_global_for_tenant → SystemConfigStore 及现有租户键；同时检查 SQLite/PostgreSQL，保持校验、密钥存储与缓存一致性。
- 桌面沿用 config_system_settings 的公共更新入口，不逐页复制网络实现。

## 开发策略

- 批次 1 → 批次 2，线性执行，不安排并行；第二批复用第一批真实网关回读证据。
- 先编写失败行为测试，再实现最小修复。同一命令取得红/绿证据。
- 详细复现与证据见 ../2026-11-07-设置交互卡顿/复测记录.md；本文件只读。
