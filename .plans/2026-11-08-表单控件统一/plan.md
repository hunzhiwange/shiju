# 表单控件统一计划

**目标**　让 Git「提交所选变更」及桌面端同类表单复用输入和单选控件，选择框与常规设置的「语言」一致。

**范围**　先统一公共文本输入和多行表单编辑器，接入 Git 提交表单。随后迁移工作流、专家中心、知识库的原生单选，以及系统配置、项目和任务配置弹窗中的普通输入。

**范围外**　Git 提交流程、配置数据、页面导航、命令输入、编辑器主体、带搜索或多选的专用菜单，以及表单呈现位置。

**假设**　当前常规设置「语言」是单选的外观与交互基准，自定义模型弹窗是输入基准。「提交所选变更」对应 Git 面板中的内嵌表单。参考 6435fcfda 中《系统配置与表单统一美化》的公共控件约定。

## 设计决策

- 逐处设置样式易遗漏，重写控件会扩大交互变更。继续使用 settings_select，并为 Iced 输入提供轻量构造函数，保留原生链式配置。

## 架构说明

- 公共入口留在 system_settings_common。字段值、消息、宽度和业务禁用条件由各调用方决定。专用控件沿用自身交互。

## 开发策略

- 先捕获真实视图的失败渲染、布局或事件断言，再验证修复。对仅去重的等价迁移运行现有交互测试，复核复用入口和实际渲染。
- 验收覆盖明暗主题、简体中文、繁体中文、英文与窄窗口。非 ASCII 使用默认字体。菜单滚动条宽 4px，两侧预留 7px。
- 保留选项顺序、值身份、回退、消息、输入遮罩、粘贴、保存与取消行为。图像与测试只用隔离配置和虚构数据。
- 各任务串行执行，顺序和依赖见 prompt.md。共享检出存在其它改动，实施和提交前按差异归属核对。
