# 任务 1　定义并实现共享审批边界

批次：【批次 1】无

状态：未开始

目的：为所有 ACP 后端建立工作区普通编辑免审批的公共契约，并用 Claude 的已验证原生控制跑通第一个实现。

来源任务：无。本对话的 ACP 双档权限需求。

预计会话范围：一个权限行为从可信会话授权映射到宿主边界。此任务完成公共策略、Claude 参考映射和可复用的测试入口，后端逐项适配及两档界面由后续任务承担。

## 上下文

桌面当前传入 `approve-reads` 或 `approve-all`，通用审批回调只免批读取。独立的 `fs/write_text_file` 已有直写分支，但现有路径校验只做词法归一。Claude 的 `sync_claude_access` 已支持确认后端模式，普通会话目前停在 `default`。完整授权必须绑定当前可信会话。桌面之外的授权由批次 4 接线，显式拒绝优先。

按无人值守方式执行：常规、可逆、低风险事项自行选择符合仓库约定的最佳可行方案，遇到问题先调查修复并继续；仅在关键歧义无法消除或确需新增授权时集中询问，记录决策和阻塞证据，不重复请求已有授权。

## Cargo 共享槽位规则

1. 同一仓库的所有计划和任务共用仓库根目录下的 `target/rust-slot-1` 至 `target/rust-slot-10`，不得为任务、会话或计划另建构建目录，也不得按任务编号取模固定分配。
2. 每次构建/验证阶段开始前，创建仓库根目录下的 `target/rust-slot-locks`；依次用原子命令 `mkdir target/rust-slot-locks/slot-N.lock` 尝试领取槽位，`N` 为 1–10。仅 `mkdir` 成功者获得该槽位；这些相对路径命令从仓库根目录执行。
3. 领取成功后，在自己的锁目录中记录计划、任务、会话标识和持有进程 PID。同一槽位同时只允许一个持有者；已占用时尝试下一个，仅全部 10 个槽位都占用时等待并重试。
4. 将 `CARGO_TARGET_DIR` 设置为领取槽位的绝对路径，例如领取槽位 3 后，从仓库根目录执行 `export CARGO_TARGET_DIR="$PWD/target/rust-slot-3"`。示例编号不代表固定分配。
5. 所有 Cargo 构建、检查、测试以及调用 Cargo 的脚本和子进程均继承该设置，不得通过 `--target-dir` 或其他配置绕过槽位；生成的二进制也从该槽位定位。
6. 该阶段的 Cargo、脚本以及使用槽位产物的子进程全部结束后，删除自己写入的占用记录，并用 `rmdir` 释放自己的锁目录；保留槽位编译缓存供后续任务复用。
7. 正常结束、失败和中断均须清理自己的锁；在后台进程或其他使用槽位产物的进程仍运行时不得提前释放。规划清理步骤时覆盖这三种退出路径。
8. 遗留锁须先核实持有会话及相关进程已结束；无法确认则保持占用，不得删除其他活跃任务的锁、进程或缓存。
9. 生成或更新计划时，统一移除与这些规则冲突的单一 Rust 共享构建空间、逐任务独立目录和 Cargo 缓存全局独占窗口要求；仍须遵守源码文件占用、真实业务依赖和其他共享验证资源的互斥，不能仅因缓存分槽就把任务判定为可并行。
10. 最终验证记录包含实际槽位、绝对路径 `CARGO_TARGET_DIR`、确切命令、退出码和有效测试数量；Rust 代码修改后先运行 `cargo fmt --all`，再运行相应验证。编译成功或零测试不能替代行为验收证据。

仓库另设 Cargo 中间产物目录。领取槽位后令 `CARGO_BUILD_BUILD_DIR="$CARGO_TARGET_DIR"`，与现有验收脚本一致。格式化前后审查差异，仅保留本任务需要的格式变更。

## 测试计划

- 行为：审批模式下，可信工作区普通文件的新建与修改可一次会话内连续完成，保护路径、越界、删除和命令仍受现有规则约束。
- 失败验证测试：在现有 RPC fixture 增加 `acp_desktop_approval_policy_allows_workspace_edits`，断言同轮连续两个安全编辑直接通过，且两次均未触发宿主弹窗。
- 失败验证命令：`cargo test -p vw-acp --lib acp_desktop_approval_policy_allows_workspace_edits -- --test-threads=1`。预期现有策略进入逐次确认。
- 通过验证命令：`cargo test -p vw-acp --lib acp_desktop_approval_policy_ -- --test-threads=1`，`cargo test -p vw-acp --lib acp_full_access_claude_ -- --test-threads=1`，`cargo test -p vw-agent --lib acp_desktop_approval_policy_ -- --test-threads=1`。使用各 crate 默认 features。
- 模拟策略：沿用真实 ACP JSON-RPC 测试连接，替换外部 CLI 身份及远端响应。路径、落盘和权限决策用临时目录实际验证。

## 步骤

1. 先添加失败测试并记录现有审批事件。分别测试 `session/request_permission` 和 `fs/write_text_file`。补齐非当前 ACP session、越界、目录符号链接、保护路径、未分类工具、删除及终端负例。
2. 从服务端已有可信桌面会话推导策略，检查请求身份、项目根目录及客户端缓存键。复用现有两档对外配置，内部权限表示无需暴露为第三档。
3. 在实际落盘路径执行工作区限制，绑定当前 ACP session。核对新文件的最近现存父目录及符号链接，并覆盖检查到落盘之间的路径替换。通用回调只在操作类型、全部目标及实际执行边界均可验证时返回单次允许。代理自报 `kind`、标题或路径字段不能单独充当授权证据；其余请求继续审批或拒绝。
4. Claude 复用已验证身份及模式回读。候选为 `acceptEdits`，但 SDK 也可能自动批准部分文件系统命令并跳过回调，须验证实际端到端边界；若宿主无法约束该原生模式，使用经验证的宿主路径，保留高风险限制。
5. 测试审批、完全访问、撤销后审批三段及恢复。显式拒绝、组织规则、流程确认继续优先；仅启用安全工作区编辑的变化。

## 验证

记录实现前失败和实现后通过。RPC 测试须证明工作区文件真实写入、边界外文件没有写入、完全访问仅来自当前授权且撤销不复用旧权限。运行 `cargo clippy --all-targets --all-features -- -D warnings`，保存有效测试数和退出码。
