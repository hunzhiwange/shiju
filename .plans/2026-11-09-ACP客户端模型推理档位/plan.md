# ACP 客户端模型推理档位计划

目标是让四个重点 ACP 的客户端模型按所选档位发出可验证的上游请求，先以 Codex 原生 Responses 跑通。

范围包括 Codex、OpenCode、Claude Code、GitHub Copilot，覆盖会话设档、受支持档位校验、桌面入口和真实 CLI 离线验收。Copilot 如仅支持启动设档，以新会话档位为验收边界。

范围外包括其余 ACP、通用跨协议推理翻译、Codex Chat 档位和线上账号调用。

假设采用仓库已验收的运行时和回环模型夹具。Claude 动态档位可能需要升级已审查版本，Copilot 启动参数对 BYOK 的效果须实测。

## 设计决策

- 采用适配器原生控制，按真实模型能力与已验证档位开放。统一在中继注入虽省适配，但会绕开适配器的推理状态和协议约束。
- 采用真实 CLI 加离线上游，直接比较出站字段。纯 ACP 回读适合检查控制状态，无法证明请求生效。

## 架构说明

- 沿用会话控制、模型目录、托管启动和模型中继。每个驱动负责自己的能力表达，绑定与权限校验继续生效。
- 核心证据是同一模型两档的请求路径、字段和值。仅保留脱敏投影。

## 开发策略

- 行为变更先做可复现的失败验证，再做最小实现和通过验证。
- 验证真实 CLI 与生产链路，仅用回环夹具替代上游模型服务。对照组保持来源、模型与协议一致。
- 保留无档位请求的现有行为。拒绝明确请求的未支持档位，保留此前确认值。
- 批次、可执行命令和交付证据见编号任务文件与执行提示词。
