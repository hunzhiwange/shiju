### 2. 系统外部协议

下面的 PowerShell 命令在当前用户下注册唯一测试协议，处理器只把收到的 URL 追加到临时文件。回环端口 `8765` 需空闲。Windows 注册结构参见 [Microsoft 的协议注册示例](https://learn.microsoft.com/en-us/windows/win32/shell/search-protocol)。

```powershell
$scheme = 'shiju-regression-' + [guid]::NewGuid().ToString('N')
$url = "${scheme}://local/synthetic?number=42"
$fixture = Join-Path $env:TEMP $scheme
$receiver = Join-Path $fixture 'receive.py'
$received = Join-Path $fixture 'received.txt'
$key = "HKCU:\Software\Classes\$scheme"
$commandKey = "$key\shell\open\command"
$python = (Get-Command python -CommandType Application).Source
New-Item -ItemType Directory -Path $fixture | Out-Null
@'
from pathlib import Path
import sys
with Path(sys.argv[1]).open('a', encoding='utf-8') as output:
    print(sys.argv[2], file=output)
'@ | Set-Content -Encoding utf8 $receiver
New-Item -Path $key | Out-Null
Set-Item -Path $key -Value "URL:$scheme"
New-ItemProperty -Path $key -Name 'URL Protocol' -Value '' | Out-Null
New-Item -Path $commandKey -Force | Out-Null
Set-Item -Path $commandKey -Value ('"{0}" "{1}" "{2}" "%1"' -f $python, $receiver, $received)
@"
<!doctype html><meta charset="utf-8"><title>Protocol regression</title>
<p><a href="$url">Same window</a></p>
<p><a href="$url" target="_blank">New window</a></p>
<p><a href="/child.html" target="_blank">Open test child</a></p>
<p><a href="${scheme}-missing://local/synthetic">Unregistered protocol</a></p>
<iframe src="/frame.html"></iframe>
"@ | Set-Content -Encoding utf8 (Join-Path $fixture 'index.html')
"<a href='$url'>Open from child</a>" | Set-Content -Encoding utf8 (Join-Path $fixture 'child.html')
"<a href='$url'>Open from frame</a><script>location.href='$url'</script>" |
    Set-Content -Encoding utf8 (Join-Path $fixture 'frame.html')
$server = Start-Process -FilePath $python -WorkingDirectory $fixture -PassThru `
    -ArgumentList '-m','http.server','8765','--bind','127.0.0.1'
& $env:VW_WEBVIEW_HELPER 'http://127.0.0.1:8765/' '--mode=window'
```

| 手动操作 | 预期结果 |
| --- | --- |
| 页面加载后等待，再点 iframe 中的协议链接 | 后台自动请求和子框架绕行都没有交接，接收文件无新增。 |
| 点 `Same window`，先取消，再点一次并确认 | 未确认和取消时均无新增。确认后只追加一行，内容与 `$url` 完全一致。当前网页仍可用。 |
| 点 `New window` 并确认 | 确认窗归属发起窗口，只追加一行。可在同一次确认未处理时重复触发，检查最多交接一次。 |
| 点 `Open test child`，在已打开的子窗点 `Open from child` | 确认窗归属子窗，父窗保持可用。取消无新增，确认只新增一行。 |
| 将 `$url` 粘贴到地址栏并回车，再用工具栏的外部打开操作复测 | 两个入口均需确认。取消无新增，确认一次只新增一行。 |
| 点 `Unregistered protocol` 并确认 | 显示无法打开或系统无处理程序的反馈，已注册处理器无新增。 |

在另一窗口可查看 `$fixture` 下的 `received.txt`，或关闭助手后用 `Get-Content $received` 检查。记下每步的新增行数，验证后清理本轮注册和文件。

### 4. MCP 桌面权限与隔离

**联网脚本。** 为回环 HTTPS 准备含 `IP:127.0.0.1` SAN 的服务器证书与私钥（PEM），签发测试 CA 须受当前 Windows 测试用户信任。已有测试证书时直接设置下方两个变量。否则在隔离测试账户中用 OpenSSL 生成短期证书，并仅信任本轮测试 CA。[Windows 当前用户证书导入](https://learn.microsoft.com/en-us/powershell/module/pki/import-certificate)

```powershell
$tlsDir = Join-Path $env:TEMP ('shiju-tls-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $tlsDir | Out-Null
Push-Location $tlsDir
try {
    openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 2 -keyout ca.key -out ca.pem `
        -subj '/CN=ShiJu Regression Local CA' -addext 'basicConstraints=critical,CA:TRUE' `
        -addext 'keyUsage=critical,keyCertSign,cRLSign'
    if ($LASTEXITCODE -ne 0) { throw 'CA generation failed' }
    openssl req -new -newkey rsa:2048 -nodes -keyout server.key -out server.csr -subj '/CN=127.0.0.1'
    if ($LASTEXITCODE -ne 0) { throw 'Server key generation failed' }
    @('subjectAltName=IP:127.0.0.1','basicConstraints=critical,CA:FALSE','extendedKeyUsage=serverAuth') |
        Set-Content -Encoding ascii server.ext
    openssl x509 -req -in server.csr -CA ca.pem -CAkey ca.key -CAcreateserial `
        -out server.pem -days 2 -sha256 -extfile server.ext
    if ($LASTEXITCODE -ne 0) { throw 'Server certificate signing failed' }
    openssl x509 -in ca.pem -outform DER -out ca.cer
    if ($LASTEXITCODE -ne 0) { throw 'CA conversion failed' }
    $testCa = Import-Certificate -FilePath (Join-Path $tlsDir 'ca.cer') -CertStoreLocation Cert:\CurrentUser\Root
} finally {
    Pop-Location
}
```

临时 `app.html` 使用 `https://127.0.0.1:9443/submit` 作为表单目的地。在保留证书环境变量的 PowerShell 中，先用下方命令启动该观察端点。端口 `9443` 需空闲。

```powershell
python -c "from http.server import HTTPServer, BaseHTTPRequestHandler; import os,ssl; s=HTTPServer(('127.0.0.1',9443),BaseHTTPRequestHandler); c=ssl.SSLContext(ssl.PROTOCOL_TLS_SERVER); c.load_cert_chain(os.environ['VW_MCP_TEST_CERT'],os.environ['VW_MCP_TEST_KEY']); s.socket=c.wrap_socket(s.socket,server_side=True); s.serve_forever()"
```

## 常驻采集页 · Windows 和 Linux

将以下内容存到空测试目录的 `media.html`，在该目录运行 `python -m http.server 8766 --bind 127.0.0.1`（Linux 用 `python3`）。在 ShiJu 内置浏览器打开 `http://127.0.0.1:8766/media.html`。先在主窗测试，关窗释放后重新打开，再点 `Open popup` 在子窗测试。`Start` 会让组合流持续到窗口关闭，便于观察指示器。用于拒绝或无设备检查时，页面直接显示浏览器返回的错误名。

```html
<!doctype html><meta charset="utf-8">
<button id="start">Start camera and microphone</button>
<a href="/media.html" target="_blank">Open popup</a>
<pre id="state"></pre>
<script>
document.querySelector('#start').onclick = async (event) => {
  event.target.disabled = true;
  try {
    window.testStream = await navigator.mediaDevices.getUserMedia({audio:true, video:true});
    document.querySelector('#state').textContent = window.testStream.getTracks()
      .map(track => `${track.kind}: ${track.readyState}`).join('\n');
  } catch (error) {
    document.querySelector('#state').textContent = error.name;
    event.target.disabled = false;
  }
};
</script>
```
