# 会话首轮提交与子会话导航计划

目标：首轮失败留在当前会话，首次成功提交后才登记并命名，子智能体和工作流子会话在 UI 中仅展示状态与详情。

范围：网关及本地会话存储、桌面、TUI、AgentTool、跨会话 SessionTool、工作流与计划运行、复用原生存储的通道入口。覆盖空白启动、首发失败、重试、失联后对账、迟到事件和标题竞争。

范围外：批量清理旧会话、第三方应用历史迁移、跨引擎恢复。已有会话的显式改名、分叉和会话权限继续按现有契约执行。

假设：“第一次返回”指首轮有效助手结果成功终止并落盘。连接建立、首个增量、工具启动、错误和取消都不触发。用户或工具给出的任务名可用于任务展示，执行会话首轮成功后才采用。正常的分叉与显式创建具名 API 资源沿用既有契约。

## 设计决策

- 客户端空白页保留草稿。运行需要稳定 ID 时，底层按作用域保留待提交记录。
- 统一在成功提交边界命名。保留失败诊断，禁止待提交记录进入历史。
- 子会话依真实来源限制导航，保留节点详情、进度与停止操作。

## 架构说明

- 复用 `Info`、SessionStore、网关终态及现有项目作用域。运行身份、历史可见性和标题分别管理。
- 桌面与 TUI 消费服务端提交结果。工作流和跨会话工具保留自己的任务编排。

## 开发策略

- 先用真实入口跑出预期失败，再实现最小修改并做聚焦验证。测试独立放置，模型等外部边界使用可控输出。
- 每批一个任务。共享会话合同、桌面状态及全仓格式化会产生交叉写入，按提示词顺序串行执行。
- 最后一批复跑跨入口回归，验证本地和网关模式。真实环境缺失时登记待回归及缺失证据。
