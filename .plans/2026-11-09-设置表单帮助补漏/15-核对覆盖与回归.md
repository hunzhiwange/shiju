## Cargo 共享槽位规则

1. 同一仓库的所有计划和任务共用仓库根目录下的 `target/rust-slot-1` 至 `target/rust-slot-10`，不得为任务、会话或计划另建构建目录，也不得按任务编号取模固定分配。
2. 每次构建/验证阶段开始前，创建仓库根目录下的 `target/rust-slot-locks`；依次用原子命令 `mkdir target/rust-slot-locks/slot-N.lock` 尝试领取槽位，`N` 为 1–10。仅 `mkdir` 成功者获得该槽位；这些相对路径命令从仓库根目录执行。
3. 领取成功后，在自己的锁目录中记录计划、任务、会话标识和持有进程 PID。同一槽位同时只允许一个持有者；已占用时尝试下一个，仅全部 10 个槽位都占用时等待并重试。
4. 将 `CARGO_TARGET_DIR` 设置为领取槽位的绝对路径，例如领取槽位 3 后，从仓库根目录执行 `export CARGO_TARGET_DIR="$PWD/target/rust-slot-3"`。示例编号不代表固定分配。
5. 所有 Cargo 构建、检查、测试以及调用 Cargo 的脚本和子进程均继承该设置，不得通过 `--target-dir` 或其他配置绕过槽位；生成的二进制也从该槽位定位。
6. 该阶段的 Cargo、脚本以及使用槽位产物的子进程全部结束后，删除自己写入的占用记录，并用 `rmdir` 释放自己的锁目录；保留槽位编译缓存供后续任务复用。
7. 正常结束、失败和中断均须清理自己的锁；在后台进程或其他使用槽位产物的进程仍运行时不得提前释放。规划清理步骤时覆盖这三种退出路径。
8. 遗留锁须先核实持有会话及相关进程已结束；无法确认则保持占用，不得删除其他活跃任务的锁、进程或缓存。
9. 生成或更新计划时，统一移除与这些规则冲突的单一 Rust 共享构建空间、逐任务独立目录和 Cargo 缓存全局独占窗口要求；仍须遵守源码文件占用、真实业务依赖和其他共享验证资源的互斥，不能仅因缓存分槽就把任务判定为可并行。
10. 最终验证记录包含实际槽位、绝对路径 `CARGO_TARGET_DIR`、确切命令、退出码和有效测试数量；Rust 代码修改后先运行 `cargo fmt --all`，再运行相应验证。编译成功或零测试不能替代行为验收证据。

## 验证计划

本批以覆盖复查与集成回归为主。若发现本轮回归，先在前序任务的独立测试文件加可复现的失败场景，再做局部修正。原推广覆盖范围内有可复现遗漏时，先分类，补上字段／分支验收并做局部修正。若明显超出一个会话，按模块追加可独立执行的补漏任务，并将发现的遗漏标为待覆盖。超出原推广范围的线索记录入口、文字及源码位置。

1. 在实际设置入口逐项核对终端与编辑器、内置主题编辑、提供商创建和编辑、模型三标签、多模态、智能体原生／ACP、通道海外／企业／实例／扫码，以及运行时、网络、记忆、Cron、自治、安全、MCP／ACP、插件和应用目录。记忆配置覆盖全部可达页签，记忆存储的三个分组和六个字段逐条列出。每条记录页面、字段、静态帮助或常驻理由和测试证据。
2. 对照原推广的其余设置和非设置入口。以 `rg -n 'settings_(group_heading|control_with_hint|responsive_row|row_layout)\('` 缩小候选，再检查自定义标题、说明文本和可达分支。命中只作线索，帮助已存在或确为必要提示的记下理由。从实际导航、内嵌页签与弹窗入口枚举可编辑表单，补查模块自有 `field_row`、`text_row`、`list_editor`、`text(description)` 及创建／编辑分叉。检查项目、知识库、专家中心、任务看板、工作流、书签、预览及 Git 提交的配置入口。逐项记录问号入口、必要常驻理由或不适用原因。仅有页面标题问号不能计为字段覆盖。
3. 默认 features 下执行 `cargo test -p vw-desktop --lib settings_help_gap_ -- --nocapture` 和 `cargo test -p vw-desktop --lib help_rollout_ -- --nocapture`。每个实施批次的补漏前缀至少一个有效场景，零失败。执行 `cargo test -p vw-desktop --lib system_settings_common::help -- --nocapture` 验证公共交互。
4. 在窄窗及普通宽度检查悬停、固定、跨行选取、右键菜单、Esc、页签切换、下拉菜单、滚动与搜索定位。复查明暗主题和简中、繁中、英文的实际渲染。检查帮助事件只携带静态文本，点击实际控件仍产生原消息。
5. 如有 Rust 修正，先运行 `cargo fmt --all`，重跑失败用例和上列回归。最终执行 `cargo clippy --all-targets --all-features -- -D warnings`，检查累计差异与 `git diff --check`。
