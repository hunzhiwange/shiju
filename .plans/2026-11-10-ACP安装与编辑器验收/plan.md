# ACP 安装与编辑器验收计划

目标：逐一验证识矩的 22 个内置 ACP 能否安装、连接并完成同一 Rue.js 编辑器需求，保留每项失败原因和复跑条件。

范围：本机 42617 网关、指定租户、Rue 仓库下各 ACP 的独立输出目录。每项分别记录安装、启动、指定模型请求和产物验收。自定义 ACP、其他平台、登录凭据配置、产品代码修复和替换模型不在范围内。

假设：未指定编辑器类型，统一按纯文本编辑器验收；输入、实时字数和刷新恢复为最小行为。仅替换输出路径，保持提示、模型与时限一致。

## 设计决策

- 从系统安装 API 走真实安装路径；对照现有安装状态，安装失败仍尝试现有可用运行时。
- 按 ACP 串行执行，先测已启用项；上一项阻塞不妨碍下一项。

## 架构说明

- 内置目录取自 vw-acp，安装走网关白名单，聊天绑定到各自 ACP 预设。逐项区分已安装、可连接、模型可用与实际写入。

## 开发策略

- 本轮不改识矩 Rust 源码，不调用 Cargo。用真实网关、外部 CLI、指定模型和浏览器验收；握手、终止事件或目录存在各自都不足以证明完成。
- 对外只报告脱敏结果，保留用户现有改动和原有权限，不替换账号或自动回退原生聊天。
