# Web 输入法通用桥接计划

目标：保留 Iced 与 winit，让标准输入控件在 Web 构建中共用中文输入法，无需逐页面接入。

范围：在本地 iced_winit 0.14.0 补丁中接收 DOM 组合输入并转为 Iced 标准 InputMethod 事件，沿用控件焦点、光标位置和安全输入用途；移除聊天专用桥接；补充真实浏览器验证。

范围外：替换 GUI 框架、升级 winit、修改业务表单样式、改造未接入 Iced 输入协议的第三方控件。

假设：标准 text_input、text_editor 及现有代码编辑器已使用 Iced 输入法协议；自定义控件仍需遵守同一协议。当前工作区其他任务的修改保持原样。

## 设计决策

- 选择补丁 iced_winit：改动集中且复用标准事件。补丁 winit 涉及更多平台后端；逐页桥接会重复业务逻辑，均不采用。
- Web DOM 桥接集中一个模块，按 Canvas 管理生命周期，不记录文本；原生平台保持上游路径。

## 架构说明

- 输入控件请求 InputMethod，运行时定位原生隐藏控件，组合文本及提交回到当前窗口标准事件队列。
- 焦点切换不得吞首字符或将未提交文本送给其他控件；销毁时解绑监听与清空临时文本。

## 开发策略

- 按批次 1 → 2 → 3 线性执行，禁止并行写入运行时和聊天输入相关文件。
- 先编写浏览器失败验证，再实现 DOM 桥接、接入运行时，最后移除旧路径并回归。
- 使用真实 Chromium DOM、组合事件与输入行为；Rust 验证领取共享槽位。仅执行聚焦测试，不运行全量 cargo test。
- 每个任务完成证据写入编号任务文件；本文件生成后只读。
