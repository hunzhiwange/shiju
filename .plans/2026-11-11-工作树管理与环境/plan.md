# 工作树管理与环境计划

目标：在 ShiJu 设置中提供工作树“常规 / 环境”页，统一托管工作树、聊天入口、恢复快照及安全清理。

范围：常规页的根目录、创建前获取更新、自动清理、保留数量、删除询问；按项目分组的托管列表、刷新、删除、原工作树新建聊天；环境页的项目选择、添加项目、初始化命令编辑；网关持久化、创建状态、快照恢复与清理确认闭环。

范围外：修改 Codex；重做任务池；旧数据格式迁移；自动接管第三方工作树；复刻未展示的环境高级能力；远程主机目录选择。

假设：截图环境页未展示编辑器，采用现有项目 commands.start 作为单项目初始化命令。空根目录沿用 task_worktrees_dir；保留数默认 15，fetch 默认关闭，自动清理及询问默认开启，询问开启时只提出清理建议，未经确认不删除。

## 设计决策

- 选择扩展现有网关与工作树模块；桌面直连 Git 会重复权限逻辑，独立新服务会增加持久化与连线成本。
- 采用截图交互及 ShiJu 原生控件，不移植 Codex 存储格式；新设置不迁移现有数据。

## 架构说明

- 网关管理生命周期、归属和恢复，Iced 复用设置控件与会话草稿入口。
- 以租户、项目、Git 身份判定归属；主工作区、外部工作树和任务池不参与自动清理。

## 开发策略

- 对会改变行为的代码，使用失败验证—通过验证—重构，测试放独立文件。
- 在编号任务实施前编写失败测试，任务内列出确切过滤命令，禁止零测试作为通过证据。
- 只实现失败测试证明的行为；使用临时真实 Git 仓库、本地 bare remote 和独立测试存储。
- 每次代码修改按任务规则领取 Cargo 槽位，运行 cargo fmt --all，审查并撤销仅由本次格式化产生的无关差异，再运行聚焦验证和规定的全特性 Clippy。
- 本轮仅创建计划，未修改产品代码、未运行 Cargo；计划文档做路径、覆盖、批次、提示词和槽位契约检查。
