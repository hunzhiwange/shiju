## 调查计划

1. 记录 git status，保留已有 staged、unstaged、untracked 变更。优先使用 skills/rustcodegraph/SKILL.md；图未覆盖或已变化处再用 rg。
2. 从 vw-desktop/Cargo.toml 逐层检查工作区依赖、lib/main 入口与模块 cfg，覆盖 vw-shared、vw-gateway-client、vw-provider-resolver、vw-config-types、vw-api-types 及其浏览器可达依赖；vendor 只读，服务端原生 crate 标为范围外。
3. 使用下面命令寻找显式路径及导入、别名、多行导入；追踪每个 Instant::now、SystemTime::now、elapsed、into_std/from_std 到真实类型。附带核查 std::thread::sleep、tokio::time 等邻近计时路径是否已有平台封装。Duration、UNIX_EPOCH 常量本身不作为缺陷。
4. 每项记录文件/符号、来源时钟、入口调用链、完整 cfg 证据、分类（确认风险/原生排除/已兼容/待证实）、对应验证场景；发现不相关的线程/文件系统问题仅列出范围外证据。
5. 核实 8 个工作流 ID 生成函数；agent_stream 的 last_flush 字段、new、should_flush 与 plan_run_delta_clock 当前均为 web_time，不能报告为未修复。
6. 已确认原生排除示例：state.rs 对 agent_apps_auth 的模块保护；message/mod.rs 对 skill_hub（含 connectors）的模块保护；models.rs 对 models_cache 的模块保护；启动计时与 LSP 的局部保护。父模块条件与调用点条件都要核查，不能只看命中行。
7. 将新增明确风险按相同时间 API 根因纳入后续任务可安全修复范围；若发现独立子系统问题，在审计中记录独立后续建议，不把后续窄任务扩大为重构。
