# ACP 缺失接入计划

目标：补齐参考项目有、当前 ShiJu 缺失的全部 ACP 接入，每个接入独立实施，沿用 Codex、Claude Code 的现有链路。

范围：固定参考源码快照中的第三方 ACP 目录、内嵌 Pi/Node.js 包 shiju-pi-cli，以及用户追加的 aionrs JSON Stream→ACP 桥接；覆盖官方目录、安装与发现、会话生命周期、权限、模型来源、MCP 与技能能力的真实支持及显式拒绝。具体差异见 `差异清单.md`，具体实施和进度只在编号任务文件。

范围外：Nanobot、Antigravity、OpenClaw Gateway 等独立非 ACP 引擎，原生引擎替换、使用 shiju-agent-cli 名称或别名、重品牌、无关重构、对外发布、既有 22 项的全面修复。

假设：用户所说“都要支持”指 ACP 接入范围；Kilo 与现有 kilocode 使用同一 @kilocode/cli，保留稳定 key。源码能力声明是调查入口，不能替代本仓库实测证据。

## 设计决策

- 选择逐接入复用现有链路；批量导入虽快但缺证据，重建通用注册框架改动大，均不采用。
- 共用注册及分派文件，全部串行；不复制参考项目数据库迁移。
- aionrs 非原生 ACP，复用现有服务端桥接 JSON Stream，不导入其引擎 crate。

## 架构说明

- vw-acp 注册、安装及协议；vw-agent 派生目录与模型/技能分派；桌面消费同一目录。
- 能力按真实握手和版本验证；权限默认拒绝，凭据隔离。

## 开发策略

- 对会改变行为的代码，使用失败验证-通过验证-重构。
- 在实施步骤前运行新增的行为测试，保留预期失败证据；实现范围限于对应接入。
- 单测验证真实注册/路由/序列化，只替代外部进程与网络边界；真实 CLI 验收独立记录。
- 沿用现有模型来源能力门控；上游不支持的功能明确拒绝，不制造 Codex/Claude 能力对等承诺。
- 不运行全量测试、fmt check、wasm check 或 Makefile。所有 Rust 任务执行规定 clippy；与本次无关的失败保留证据。
- 本轮只生成文档，不运行 Cargo；任务执行时遵守编号文件中的共享槽位规则。
