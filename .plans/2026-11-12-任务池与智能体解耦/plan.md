# 任务池与智能体解耦计划

目标：员工直接复用现有智能体；任务池只负责调度，非 Git 项目可运行任务；Git 与消息动作显式进入任务或工作流，worktree 按需创建。

范围：后端本地运行器、权限与目录占用、生命周期结果投影、任务工作流工具调用、桌面启动与员工展示，以及失去调用者的任务 worktree 池接口。保留现有普通 Git/worktree 工具、智能体配置与原生/ACP 执行链。完成标准包括非 Git 全链路运行、普通任务零隐式 Git/消息副作用、显式动作受权限约束、共享目录安全串行、员工与磁盘目录数量脱钩。

范围外：新增员工账户或执行引擎、新增消息渠道、自动发布与推送、全仓重构、旧数据迁移、自动删除用户现有 worktree 或未提交产物。

假设：沿用已注册项目与租户作用域，项目目录仍必须存在；员工是智能体定义的展示，每次任务产生独立 run/session。同一目录的普通任务先保守串行，不从自然语言猜测只读能力。现有配置与工作流允许显式选择原生或 ACP 后端。仓库存在其他会话修改，实施前重新核对差异和索引新鲜度。

## 设计决策

- 选择复用智能体与工具，移除默认 Git 生命周期。仅给池加开关仍保留耦合；另建通用员工/资源框架增加重复模型。两者均不采用。
- 消息、提交与合并必须显式配置；不以任务身份提升权限。

## 架构说明

- 任务池认领、排队、限流、依赖、重试与记录；运行器调用现有会话；任务/工作流调用工具。
- 项目目录与可选 worktree 资源分开记录。运行占用不等于 Git 槽位；安全边界由运行时维护。

## 开发策略

- 对行为变更使用失败验证—通过验证—重构；每份编号任务定义新增测试、预期失败和确切命令。
- 先使工作区契约不依赖 Git，再取消隐式收尾，随后完善权限、占用、显式工具和生命周期，最后切换桌面及清理旧池调用。
- 所有任务线性执行；批次顺序与文件归属见编号任务和 prompt.md。不安排并行：后端运行器、API 映射和桌面消息处理连续共享文件，缓存分槽不消除源码冲突。
- 测试使用真实临时目录、Git 仓库与本地持久化；仅模拟模型、ACP 协议对端或外部消息传输。不得向真实收件人发消息。
- Cargo 任务使用仓库共享槽位。代码修改后执行 cargo fmt --all，剔除其对无关文件的格式化；聚焦测试后运行 cargo clippy --all-targets --all-features -- -D warnings。禁止全量 cargo test、wasm 检查、fmt --check 和 Makefile 命令。
- plan.md 生成后只读；进度与阻塞只记录在对应编号任务。无需维持旧业务逻辑或迁移旧结构；不得借此删除已有数据或目录。
