## macOS 系统听写提示（用户追加要求）

- macOS 上在麦克风 tooltip 保留首行“听写”，追加：“也可使用 macOS 系统听写：将光标放入输入框，按系统设置的听写快捷键（如连按两次 Fn/地球仪键）。可在‘系统设置 → 键盘 → 听写’中开启或修改。”
- 强调系统听写可用于支持文本输入的可编辑输入框，不局限于会话输入区；本轮采用一个可发现的统一提示，不在每个表单旁重复加说明，不承诺密码、只读或所有自绘控件必然支持。
- 这是对系统能力的使用提示，不替代现有应用内听写。只有用户点击应用麦克风才进入应用录音链路；不要拦截 Fn、改系统快捷键、自动启用系统听写或触发额外权限请求。
- 仅 macOS 显示系统提示，其它平台仍显示原“听写”；Fn/地球仪快捷键因用户配置和键盘而异，不写死“按一次 Fn 即启动”。中文提示使用默认字体；如图标字体不含地球仪字符，使用“地球仪键”文字。
- 来源：[Apple：在 Mac 上听写信息和文稿](https://support.apple.com/zh-cn/guide/mac-help/mh40584/27/mac/27)、[Apple：键盘设置](https://support.apple.com/zh-cn/guide/mac-help/kbdm162/27/mac/27)。这仅核实系统用法；自绘 Iced 输入框仍需任务4验证真实文字插入。
- 在 voice_controls_tests.rs 增加 `voice_ui_primary_macos_dictation_hint_is_platform_scoped`，复用本任务红绿命令；通过实际 tooltip 内容/平台条件验证，不只匹配源码。先证明原提示缺少这段说明，再实现。非 macOS 分支至少审查编译条件，未运行平台不可写成实测通过。

## Cargo 共享槽位规则

1. 从仓库根目录直接使用已存在的 `python3 scripts/cargo_slot.py <命令及参数>`；入口自动领取或核验继承 `target/rust-slot-1` 至 `rust-slot-20`，不要在外层再手工领取第二个槽位。
2. 同一开发阶段将顺序原生检查放在一次入口调用中，持续复用缓存。例如 `python3 scripts/cargo_slot.py sh -c 'cargo check -p vw-desktop --lib && cargo clippy --all-targets --all-features -- -D warnings'`；实际 crate、features 与聚焦命令以本任务下文为准。下文裸 Cargo 表示入口内部命令，不表示允许绕过入口。
3. `CARGO_TARGET_DIR` 与 `CARGO_BUILD_BUILD_DIR` 由入口设置为同一槽位绝对路径，子脚本继承，不另建构建目录、不覆盖已领取路径、不执行 clean。任务涉及的二进制从该槽位定位。
4. 入口持有锁直到自有前台子进程组停止；常驻测试或应用存活期间不能提前释放。不启动脱离前台进程组的后台任务，不删除其它会话的锁、进程或缓存。正常、失败及中断退出后保留缓存。
5. 槽位只隔离缓存，不解除本任务的源码、任务依赖及验收资源互斥；20 个槽位不代表应并发运行 20 个重型构建。遵守现有批次与串行约定。
6. 完成时记录实际槽位、两个绝对目录、确切原生验证命令、退出码和有效测试数量。原生聚焦测试、整仓 `cargo clippy --all-targets --all-features -- -D warnings` 及要求的真实渲染、授权、音频与实机验收继续执行；零测试和热更新通过不能替代完成验收。
