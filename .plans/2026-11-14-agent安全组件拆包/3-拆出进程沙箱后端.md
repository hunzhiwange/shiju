## 具体实施

1. 确认外部/上一个任务完成，保存来源测试名、cfg、ignore 与本次开始时 Git 差异，核对生产调用者与工厂引用。
2. 建立包及 workspace member，agent 使用 `path = "../libs/process-sandbox"` 的正式依赖；如果原模块受 feature/平台限制，依赖保持等价 optional/target 条件，不扩大默认能力。
3. 先移 Sandbox/NoopSandbox 再整体移四种实现。原 agent traits/后端入口重导出；detect::create_sandbox 及其配置选择顺序留在 agent。保留 agent 原 sandbox-bubblewrap/sandbox-landlock，并转发到新包同名 feature；landlock 依赖随实现迁移，agent 中若无其它使用再移除。
4. 搬迁相邻测试及私有辅助结构，只调整跨包路径；不把私有函数普遍改 pub。不需要新包里的测试继续依赖 agent；无法切断时保留证据并停止扩大搬迁。
5. 在本任务调用方测试文件新增一个 `process_sandbox_production_boundary`：显式将旧入口对象借用/赋值为新包公开类型或 trait，并通过原入口执行一个真实本地行为。无可用类型的纯路径 API 以普通仓库/linked worktree 的实际结果断言验证；不写仅比较字符串名称的空测试。
6. 按下列顺序验证，审查新包 `cargo tree` 及生产函数体的 rename diff，交接提交与当前结果。

## 验证计划

结构迁移不改变业务行为，人为制造红灯不适用。优先迁移既有行为测试，测试数量以执行前清单和平台 cfg 为准；迁出后不能通过减断言或保留重复副本凑数量。边界测试使用临时数据和真实本地实现；网络/系统边界规则见专属约束。

```sh
cargo test -j 1 -p process-sandbox --lib traits:: &&
cargo test -j 1 -p process-sandbox --lib docker:: &&
cargo test -j 1 -p process-sandbox --features sandbox-bubblewrap --lib bubblewrap:: &&
cargo test -j 1 -p process-sandbox --features sandbox-landlock --lib landlock:: &&
cargo test -j 1 -p vw-agent --features sandbox-bubblewrap,sandbox-landlock --lib security::detect:: &&
cargo test -j 1 -p vw-agent --lib package_boundaries::process_sandbox_tests:: &&
cargo tree -p process-sandbox -e normal
```

预期：traits 1、docker 17、bubblewrap 9、landlock 静态 8（受平台 cfg 影响）、agent detect 9 个测试集合保留；每族有效数大于零；新边界测试 1 个有效通过。所有必要命令退出 0、failed=0。新包单测编译过同一目标不重复 check；agent 边界测试同时编译直接调用者。此阶段不运行整仓检查。

所需证据：原/新测试清单映射及实际有效数、失败/ignored/内部跳过情况、生产依赖接线与树、旧入口类型身份或实际路径行为、迁移函数体无语义变化、槽位双路径/退出码/进程收尾。统一回归由总计划 D 承接，不在本任务重复。

## 专属约束

firejail 保留 Linux-only 模块门禁；在 Linux 再运行 `cargo test -j 1 -p process-sandbox --lib firejail::`（6 个静态测试）。Linux Landlock/进程隔离实测缺少环境时记录具体验收缺口，不能用 macOS fallback 代替；现有隔离参数/默认拒绝/Unsupported 分支不变。边界测试使用 NoopSandbox 对 std::process::Command 的包装，不启动用户命令。
