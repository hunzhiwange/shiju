## 具体实施

1. 确认外部/上一个任务完成，保存来源测试名、cfg、ignore 与本次开始时 Git 差异，核对生产调用者与工厂引用。
2. 建立包及 workspace member，agent 使用 `path = "../libs/project-storage-paths"` 的正式依赖；如果原模块受 feature/平台限制，依赖保持等价 optional/target 条件，不扩大默认能力。
3. 移动 paths 实现，Git 发现改用 git_discovery::git_repository::discover；project_data_dir、project_data_dir_best_effort、workspace_data_dir 由 pub(crate) 改为 pub，仅因多个真实后端跨包调用；其它内部函数仍私有。旧 agent memory::paths 保持 crate 内模块可见性并重导出。
4. 搬迁相邻测试及私有辅助结构，只调整跨包路径；不把私有函数普遍改 pub。不需要新包里的测试继续依赖 agent；无法切断时保留证据并停止扩大搬迁。
5. 在本任务调用方测试文件新增一个 `project_storage_paths_production_boundary`：显式将旧入口对象借用/赋值为新包公开类型或 trait，并通过原入口执行一个真实本地行为。无可用类型的纯路径 API 以普通仓库/linked worktree 的实际结果断言验证；不写仅比较字符串名称的空测试。
6. 按下列顺序验证，审查新包 `cargo tree` 及生产函数体的 rename diff，交接提交与当前结果。

## 验证计划

结构迁移不改变业务行为，人为制造红灯不适用。优先迁移既有行为测试，测试数量以执行前清单和平台 cfg 为准；迁出后不能通过减断言或保留重复副本凑数量。边界测试使用临时数据和真实本地实现；网络/系统边界规则见专属约束。

```sh
cargo test -j 1 -p project-storage-paths --lib paths:: &&
cargo test -j 1 -p vw-agent --lib package_boundaries::project_storage_paths_tests:: &&
cargo tree -p project-storage-paths -e normal
```

预期：原 15 个路径测试保留并通过，project/workspace 作用域、common git dir 哈希、临时目录回退不变；新边界测试 1 个有效通过。所有必要命令退出 0、failed=0。新包单测编译过同一目标不重复 check；agent 边界测试同时编译直接调用者。此阶段不运行整仓检查。

所需证据：原/新测试清单映射及实际有效数、失败/ignored/内部跳过情况、生产依赖接线与树、旧入口类型身份或实际路径行为、迁移函数体无语义变化、槽位双路径/退出码/进程收尾。统一回归由总计划 D 承接，不在本任务重复。

## 专属约束

不得把用户存储目录改到工作区或包目录，禁止因拆包读写真实用户数据。环境变量和非 WASM/WASM 分支照搬；新增边界测试使用临时 linked worktree，仅比较派生结果。
