# vw-agent 大规模拆包总计划

目标：正式迁出 13 个生产包，使路径基础、安全组件、记忆后端获得独立测试边界，缩小 vw-agent 的业务实现范围。

范围：三个独立工作计划共 13 个迁移任务，另设一个统一集成任务。新包统一放在 `crates/libs/<通用包名>/`。现有四包基础计划是前置阶段，不重复迁移、不修改其只读计划。

范围外：不整体拆 gateway、session、channels、tools；不改模型协议、业务配置、权限、SQL schema、存储布局或算法；不拆全局数据库、日志、健康状态及 HTTP embedding/Qdrant 客户端。

假设：前置 `.plans/2026-11-14-基础能力拆包` 当前仅有计划、尚未执行；新计划开始前需有其完成证据。未提交修改保留。没有承诺一次拆完全部 vw-agent，也不以包数量保证编译耗时下降。

## 设计决策

按路径、安全、记忆分三份计划；保留 agent 工厂与旧入口，优先搬生产实现。相比整体搬大目录可避免依赖环；相比只拆算法，覆盖更多实际后端。

## 架构说明

agent → 后端 → memory-types/路径包/算法包；路径包 → git-discovery；安全包不依赖 agent。允许已有配置类型包作为叶子依赖，禁止依赖 agent/shared/desktop。

## 开发策略

- 每个任务迁移一个已有领域组件；只有边界所需的路径、可见性和依赖接线调整，不同时重写业务实现。
- 不改行为，TDD 人为红灯不适用；移动原测试、核对集合、新增少量跨包类型身份及实际调用测试。若必须改变行为，则先新增证明问题的定向失败测试，再实现；不得顺手扩大迁移范围。
- 前置完成与每次移交使用提交号、当前测试输出及依赖树证据，不能因目录存在就视为完成。编号文件被删除后依赖提交/聊天交接核验，不依赖已删除任务文件获取规则。
- 配置、provider 工厂、代理 HTTP 客户端、初始化顺序继续由 agent 负责；不以新抽象或回调把 agent 反向塞进新包。
- Codex 的可借鉴点是 trait/协议和实现的单向依赖，不是照抄同名目录；本计划不改上层业务 API 和平台语义。

- 每任务保留原测试及有效过滤条件，在该任务完成必要新包单测、直接调用方边界测试。预期数量以执行前快照为准，本文静态测试数不是运行证据。
- 所有新包必须从 agent 的生产清单接入，而非仅 dev-dependency；原实现文件迁走，不留下两套代码。每任务执行 `cargo tree -p <本任务包名> -e normal`（包名取该任务声明的字面值），审查依赖方向和必要特性。

### Rust/Cargo 专用资源规则

- 按用户技能及 .plans 的现行覆盖规则直接使用原生 Cargo，不使用旧包装脚本或 Relax。所有下列任务命令在仓库根目录、已领取槽位的同一前台阶段执行，不是孤立 shell 命令。
- Rust 会话上限 3、混合语言总上限 5；本组任务实际逐个串行，跨计划也不重叠写共享清单。高内存编译同仓库串行排队，命令 `-j 1` 不替代跨进程排队，也不保证降低单个 rustc 峰值。
- 动态从 target/rust-slot-1 至 rust-slot-10 领取共享缓存；原子 mkdir target/rust-slot-locks/slot-N.lock 成功才持有，全部占用则等待。不新增第 11 个槽位、不按任务号固定槽位、不创建任务缓存、不删除未知/他人锁。
- 锁记录覆盖整个编译阶段的真实持有进程 PID 和任务标识，禁止短命 shell PID；继承前核实持有者是当前进程或存活祖先进程，锁与路径对应。同阶段顺序命令复用槽位。
- CARGO_TARGET_DIR 与 CARGO_BUILD_BUILD_DIR 都指向同一槽位绝对路径，Cargo 和子进程继承，不用别名/参数覆盖。保留缓存，不改 profile、features、工具链或 codegen 来规避验证；本任务明确迁移的原 feature 转发除外。
- 记录句柄、入口 PID/进程组、实际槽位、双绝对路径、完整命令、退出码及有效测试数；零测试、旧输出或仅编译成功不算行为通过。前一步成功后才能运行下一条，使用 && 或显式退出码判断。
- 正常/失败/取消后先停止并确认自有 Cargo、rustc、链接器及产物使用进程退出，再释放自有锁。通过原句柄停止；必要时核对归属后有界等待、终止自有进程组，不按名字批量杀进程、不移除 Cargo 缓存锁。未确认清理则保留占用和具体证据，清理前不重试或并发启动替代检查。
