# vw-shared 全面拆分计划

目标：将共享协议、纯工具与磁盘/网络实现拆为职责明确的库，保留现有协议及公开入口。

范围：审计见 audit.md；执行卡覆盖整个 vw-shared，包括测试、资源、feature、消费者及发布接线。来源是系统底层全面拆分任务23，本次只生成实施计划，代码拆分尚未执行。

范围外：业务功能调整、依赖升级、Cargo.lock 修改、动态验证。

## 设计决策

选择独立职责库而非整体搬 shared 或只拆文件；纯协议先于存储服务。provider 的原始与运行时模型保留两个真实结构；不合并同名 Model。过大模块在职责库内分文件，见专属卡边界，禁止新建 common/core 聚合库。

- 新库均位于 crates/libs/<任务声明库名>，Cargo.toml、src/lib.rs，沿用当前 0.6.0/edition 2024/MIT；不得依赖 vw-shared。依赖箭头及逐文件归属见 audit.md。
- 每卡先读取本文件，再使用 /Users/xiangmin/.codex/skills/do-task-plans/SKILL.md；导航使用 skills/rustcodegraph/SKILL.md，图不可用或未覆盖时使用 rg。无须通过入口 prompt 才能取得规则。
- plan.md 生成后只读，不更新进度、不清理；prompt.md 为固定历史入口。所有任务按编号单任务串行批次执行，前置卡代码必须已落地，删除的卡不可重复执行。公共清单和消费者均有写冲突。
- 常规可逆决策自主完成，先查调用者、别名及工厂，保持错误、安全、序列化和平台行为；不新增猜测配置/trait，不覆盖他人改动。关键歧义查证后仍无法解决才集中询问，局部阻塞继续独立部分。

- 配置子计划尚未实施，其候选接口不能写成现有 API；本计划 local-app-auth 以实际路径函数为准，不强制阻塞于整个配置计划。

## 开发与静态审查规则

用户明确覆盖技能默认验证流程：只写代码，不执行任何 Cargo 命令（包括 metadata/fmt）、单元测试、脚本测试或实机；不运行间接调用 Cargo 的脚本、不建索引或领取槽位。TDD 不适用于本次保持行为迁移，迁移现有测试源码并记录未来验收。Cargo.lock 留以后授权统一生成。

允许 rg、文件读取、git diff --check 与 git diff --stat，只能报告静态证据，不能宣称编译或测试通过。以后统一验证另行授权，按仓库 cargo_slot 规则串行，覆盖所有新库/消费者、现有定向行为、平台与 wasm 条件路径；本计划不添加验证执行任务。
