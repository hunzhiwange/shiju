# 代理底层拆包计划

目标：从 vw-agent 抽取依赖闭合的小型库，降低单个 crate 的修改与测试影响范围。

范围：参考 crates/libs/content-guard/Cargo.toml 的独立包结构，拆出标志、纯算法、观测、异步工具、路径、日志、事件、权限、安全审计、数据库和协议模型。原业务调用点直接接线；共享类型只有一个所有者。

范围外：新增功能、数据库迁移、发布、性能承诺，以及 gateway/channels/session/tools 等大型应用层整体搬迁；后续根据本轮边界再规划。

假设：本轮是纯结构重构；不改变序列化、权限、运行状态和外部协议。独立拆包有利于隔离编译，但实际耗时收益留统一验收测量。

## 设计决策

- 选择按依赖闭包拆库；整目录平移容易形成环，全部塞入 shared 会形成新大包。
- 先零依赖叶子，再组合基础设施；保留实际应用适配，不新增通用 trait 或开关。

## 架构说明

- 新库位于 crates/libs，沿用 0.6.0、2024、MIT 与 doctest=false；仅声明真实依赖。
- 依赖方向：应用 → 基础设施 → 契约/纯算法；新包不得依赖 vw-agent。

## 开发策略

- 用户明确覆盖默认测试流程：本轮只写代码，不执行任何 Cargo 相关命令、单元测试、实机测试或程序启动，包括 metadata、generate-lockfile、check、test、fmt、clippy、dev-test。
- 不新增行为，不要求红灯测试；只搬迁既有测试源码及必要导入，不执行，不额外编写测试。遇到行为变化先收窄到等价搬迁。
- 当前只生成计划，不实现拆包。执行任务时先查实际源码、调用点和测试布局，再做最小修改。

## 公共执行约定

- 每任务先读本文件及编号任务；本文件与 prompt.md 生成后只读，不写进度或清理。
- 执行技能：`/Users/xiangmin/.codex/skills/do-task-plans/SKILL.md`。用户本次禁止验证、写完删除任务的要求优先于技能及仓库默认规则。
- 无人值守执行常规可逆决策；先查证再决策，记录影响后续的假设，不为常规命名或导入反复询问。局部阻塞调查根因，继续独立工作，不扩展功能。
- 全部在仓库根目录执行。线性顺序为任务 1 至 22；每任务独占一个批次。虽有算法独立，共享 Cargo.toml、vw-agent 清单与入口文件，故无并行批次。
- 新包加入根 Cargo.toml members，在 vw-agent/Cargo.toml 添加路径和版本依赖；保持平台 cfg、optional/default/features 转发，不复制整个 vw-agent 依赖表。
- 直接更新仓库内真实调用者；原模块有大量调用时可作为单一实现的薄转发入口，不新增兼容逻辑或双实现。app.rs 只保留既有路径映射。
- 私有函数、pub(crate)、测试辅助、include!/include_str! 资源路径逐项检查，不能通过扩大所有成员可见性解决。单元测试保持独立文件，迁移后不能反向依赖应用。
- git 工作区已有无关变更及任务删除，全部保留；禁止覆盖、暂存或提交它们。

## 公共验证与资源规则

- 完成证据仅为当前差异审阅、依赖和引用静态检查；不表示编译成功、测试通过或发布可用。统一验证由用户以后单独发起，本计划不设自动测试收尾任务。
- 允许文本检索、文件读取、清单编辑与 `git diff --check`；后者仅检查补丁空白。rg 的零匹配退出码 1 为预期信号。
- 不运行 Cargo 包装脚本，不手工修改 Cargo.lock 伪造解析结果；清单变更引起的锁文件更新明确留统一验收处理。
- 将每包原测试目标、已有测试文件、特性/平台组合和待验证行为记入代码提交正文，任务删除后仍能追溯；不运行命令收集测试列表。
- 将来获授权启动 Rust 验证时，按仓库 scripts/cargo_slot.py 入口串行执行重型编译、保留缓存并释放自有锁；本轮不领取槽位或启动编译。

## 公共收尾规则

- 状态为未开始、已完成、已阻塞；本计划“已完成”仅指代码编写与静态审阅完成，全部编译和行为验收仍未进行，不以待回归保留已写完任务。
- 代码接线完整、静态差异审阅完成后使用 `$git-commit` 技能仅提交本任务代码及必要文档；提交正文说明“未运行 Cargo、单元测试及实机测试，待统一验收”，附迁移映射、待验行为与依赖。
- 同一代码提交包含对应编号任务文件删除；写完即删除，不等待未来测试。plan.md 与 prompt.md 保留，已删除入口表示代码已交付，不表示验证通过。
- 阻塞或提交失败则保留编号任务，写明原因、已尝试路径与未完成接线；存在实际变更按提交技能提交可保存部分，不空提交。不创建任务状态或删除专用提交。
- 当前计划生成阶段保留全部编号文件；未来逐任务执行才删除。最终回复简短说明变更和下一步。
