# 命令行底层拆分计划

目标：从 vw-cli 按依赖由轻到重拆出职责明确的库，缩小单包源码和测试编译边界。

范围：本轮覆盖 crates/vw-cli 的全部现有职责并继续拆分首轮领域库，新增库放 crates/libs，参照 content-guard 的独立清单与显式模块组织；包括调用接线、现有测试源码迁移和依赖收敛。

范围外：不拆 vw-agent/vw-tui 内部，不重品牌，不新增功能，不进行任何构建、测试或实机验收。

假设：本轮仅生成计划，后续独立会话实施；源码搬迁保持行为，不能保证传递依赖或总构建时间立刻下降。

## 设计决策

- 选择领域库逐层搬迁；只拆文件无法缩小包边界，一次整体拆包风险过大。
- 参照 content-guard 的轻依赖模式，不照搬其 regex/serde 依赖。
- 模型与编辑器作为内聚单元，先解反向依赖，再迁包。

## 最终依赖边界

- vw-cli → cli-bootstrap → cli-command-schema、各领域命令库及 cli-agent-session；bootstrap 是唯一进程初始化与分发层。
- cli-gateway-commands → cli-api-workspace/session/automation/system → cli-api-core → vw-gateway-client。core 不包含顶层命令枚举。
- cli-interaction → cli-gateway-session/automation/workspace/capabilities → cli-gateway-transport → 现有网关客户端；cli-gateway-runtime 完成迁移后删除。
- cli-interaction → cli-interaction-state → cli-interaction-model；编辑模型、状态不依赖启动、分发或本地代理装配。
- cli-agent-session → cli-interaction、cli-workspace-git、vw-agent；终端基础、记录渲染与 stdio 继续独立。
- API/运行服务先拆共享核心，再拆消费者；各任务均更新真实消费者，不用临时空库占位。

## 架构说明

- 入口 → 本地会话/交互运行 → 网关适配/状态 → 模型；记录渲染 → 终端基础。
- 远程命令库直接使用网关客户端；所有新库禁止反向依赖 vw-cli。

- 本轮为结构重构，保持算法、CLI 参数、错误、序列化及权限行为，不规划行为变化，不使用测试驱动开发。
