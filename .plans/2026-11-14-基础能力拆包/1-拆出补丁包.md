# 任务 1：拆出补丁包

先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

批次：【批次 1】依赖：无；后续线性顺序为 2 → 3 → 4 → 5，无并行任务。

状态：未开始

目的：将生产补丁解析、替换、预览和应用实现迁入 `crates/libs/patch`，保持原调用方行为。

来源任务：无。

预计会话范围：一个已有自包含模块及其测试，外部依赖仅 serde、serde_json 和测试 tempfile。

## 文件

- 新建：`crates/libs/patch/Cargo.toml`、`src/lib.rs`（相对该新包）；库根声明 `pub mod patch`。
- 移动：`crates/vw-shared/src/patch/` 中实现与四组测试到 `crates/libs/patch/src/patch/`，保留原内部模块层级。
- 修改：根 `Cargo.toml`、`Cargo.lock`、`crates/vw-shared/Cargo.toml`、`crates/vw-shared/src/patch/mod.rs`。
- 新建调用方测试：`crates/vw-shared/src/patch/reexport_tests.rs`，从旧 mod.rs 以 cfg(test) 声明。
- 阅读：`crates/vw-agent/src/patch/mod.rs`、`crates/vw-agent/src/tools/apply_patch/`，不迁移工具策略。

## 上下文

agent 已通过 `pub use vw_shared::patch::*` 使用共享实现。新库保留内部 patch 模块，使原测试 `crate::patch` 路径成立；旧 shared 模块只重导出 `::patch::patch::*`，避免包名与模块名歧义。

## 验证计划

纯结构迁移，不改变行为，TDD 红灯不适用。迁移前保存四组原测试名及源码差异基线；静态计数共 76 个普通 test 属性，执行时核对有效测试数并解释任何差异。原测试不删、不改断言，保留真实临时文件测试。

新增 1 个 `patch_reexport_preserves_types_and_file_application`：将旧入口解析出的 Hunk 明确赋给新包类型，使用旧入口将补丁应用到临时目录并核对内容，证明同一类型及真实接线。

## 步骤

1. 核对来源没有新增业务依赖和他人未提交修改，记录原 API、测试集合、直接调用者。
2. 创建 package `patch`（0.6.0、2024、MIT、doctest=false），运行依赖沿用 shared 的 serde/serde_json 版本，dev-dependency tempfile=3；加入 workspace member `crates/libs/patch`。
3. 原样移动四组实现/测试，旧 mod.rs 改为重导出及调用方测试声明。shared 添加 `patch = { path = "../libs/patch", version = "0.6.0" }`，不移除 shared 中仍被其它模块使用的依赖。
4. 增加上述调用方测试；用 `git diff --find-renames` 核对业务函数体未变，仅修正文档中失效的 crate 路径。
5. 执行下列顺序命令，Cargo 只更新与本任务有关的 lock hunk，不升级无关依赖。完成后按公共规则移交。

## 验证

同一持有槽位的前台阶段顺序运行：

```sh
cargo test -j 1 -p patch --lib patch:: &&
cargo test -j 1 -p vw-shared --lib patch::reexport_tests:: &&
cargo test -j 1 -p vw-agent --lib tools::apply_patch::tests::
```

预期：新包迁移测试 76 个通过；shared 新测试 1 个通过；agent 工具测试有效数大于零且 failed=0。三条命令均退出 0；新包无 vw-* 依赖。最后一条已编译 agent lib-test，不再额外 check 同一目标。

所需证据：源码迁移差异、测试名称清单与数量、实际槽位/双路径、三条命令退出码和输出、lock hunk 审查。记录首次构建是否命中缓存及测试耗时，只作观察，不宣称因果加速；统一回归由任务 5 承接。
