先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

批次：【批次 3】依赖：任务 2 完成；线性顺序 1 → 2 → 3 → 4 → 5，无并行任务。

状态：未开始

目的：将敏感内容泄漏和提示攻击的纯检测实现迁入生产包 content-guard，保持检测及处置结果。

来源任务：无。

预计会话范围：两个职责相近、无业务运行时依赖的检测模块，共 17 个原测试；不迁移 semantic_guard 或任何执行策略。

## 文件

- 新建：`crates/libs/content-guard/Cargo.toml`、`src/lib.rs`，声明 `pub mod leak_detector` 和 `pub mod prompt_guard`。
- 移动：`crates/vw-agent/src/security/leak_detector.rs`、`leak_detector_tests.rs`、`prompt_guard.rs`、`prompt_guard_tests.rs` 到新包 `src/`。
- 修改：根 `Cargo.toml`、`Cargo.lock`、`crates/vw-agent/Cargo.toml`；原两个生产文件改为仅重导出及测试声明。
- 新建：`crates/vw-agent/src/security/leak_detector_reexport_tests.rs`、`prompt_guard_reexport_tests.rs`。
- 阅读：`crates/vw-agent/src/security/mod.rs` 及其检测调用者。

## 上下文

新包仅依赖 regex=1、serde=1（derive）；模块各自的 OnceLock 正则缓存只保留一份。域名匹配已独立，不让其引入 regex；本包不依赖 domain-matcher。

## 验证计划

结构迁移，TDD 红灯不适用。原 leak_detector_tests 的 8 个测试、prompt_guard_tests 的 9 个测试均原样迁移。不得更改阈值、模式、默认值、脱敏占位符、错误回退或动作语义。

调用方各新增 1 个测试：`leak_detector_reexport_preserves_identity_and_redaction`、`prompt_guard_reexport_preserves_identity_and_decision`。将旧 API 生成的结果显式赋给新包枚举，核对敏感字符串被识别/脱敏以及严格配置拒绝已知注入。仅使用测试 fixture，不读取真实密钥，不记录真实内容。

## 步骤

1. 核对任务 2 的证据、17 个原测试及 agent 原 security 根部的公开导出。
2. 创建新包、加入 `crates/libs/content-guard` workspace member；agent 添加 `content-guard = { path = "../libs/content-guard", version = "0.6.0" }`。
3. 移动四个来源文件，保留原测试相对路径；agent 旧文件重导出新包对应模块，保持 LeakResult、GuardResult、GuardAction 等为同一类型。
4. 增加两个独立测试文件，挂载为各旧模块下 `reexport_tests`；原安全规则/工厂接线不动。
5. 逐模块运行原测试、调用方测试；不要为消除既有文档或 lint 问题扩大行为修改。

```sh
cargo test -j 1 -p content-guard --lib prompt_guard:: &&
cargo test -j 1 -p vw-agent --lib security::leak_detector::reexport_tests:: &&
cargo test -j 1 -p vw-agent --lib security::prompt_guard::reexport_tests::
```

预期：分别通过 8、9、1、1 个测试，failed=0，四条退出码为 0。新包没有 agent、shared、网络、数据库或密钥持久化依赖。

所需证据：17 个原测试的集合一致性、新输出及两个跨包枚举身份验证、正则/阈值/动作代码无语义变化的差异审查；统一回归由任务 5 承接。
