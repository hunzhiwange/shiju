# 基础能力拆包计划

目标：正式迁出四个低耦合生产包，使其可独立测试，业务行为和现有调用路径不变。

范围：将补丁处理、域名匹配、内容安全检测、记忆分块与向量算法分别迁入 `crates/libs/patch`、`crates/libs/domain-matcher`、`crates/libs/content-guard`、`crates/libs/memory-algorithms`，完成生产依赖接线、测试迁移和调用方验证。

范围外：不调整 gateway/session/tools 的架构，不拆数据库、完整 memory、health、UI；不改变策略、算法、数据格式、配置、工具链或构建 profile；不新增通用拆包框架。

假设：当前分支及未提交工作继续保留；这是正式生产迁移，不是复制代码做演示。行数及测试数仅来自静态阅读，执行时以当前源码与实际测试输出为准。

## 设计决策

采用 `crates/libs/` 归组、通用包名。相比根目录平铺更清晰；相比合成一个基础大包保留独立测试边界；暂不搬迁其它 crate。

## 架构说明

应用 → 原模块导出 → 基础包。基础包不得依赖任何 `vw-*` 包，也不得相互依赖；仅保留必要外部依赖。原接口重导出同一类型，不复制实现。

| 包名 | 生产来源 | 必要依赖 | 对外模块 |
| --- | --- | --- | --- |
| patch | vw-shared/src/patch | serde（derive）、serde_json；测试 tempfile | patch |
| domain-matcher | vw-agent/src/security/domain_matcher | anyhow | domain_matcher |
| content-guard | vw-agent/src/security/leak_detector.rs、prompt_guard.rs | regex、serde（derive） | leak_detector、prompt_guard |
| memory-algorithms | vw-agent/src/memory/chunker、vector | 标准库 | chunker、vector |

路径来源均以 `crates/` 为前缀。新包沿用现有 edition 2024、MIT、仓库版本 0.6.0；库禁用 doctest，保留必要且准确的 API 文档。新包没有平台特性开关，不为未来用途增加抽象。health 因依赖 vw-shared 的运行标识计算而排除；skillforge 因未找到生产调用而排除。

## 开发策略

- 四个迁移各为一个聚焦任务，最后单独进行集成审查与公共检查；具体顺序及批次由编号文件和 prompt.md 声明。
- 本次不改行为，不要求人为制造业务红灯；复用原行为测试、增加少量跨包类型与旧入口验证，以生产接线和测试集合一致性验收。
- 实现必须移动代码而非保留两套实现，不借拆包修复原有算法或安全规则；若出现必须改行为的问题，先记录并停止该迁移扩大范围，继续不受影响工作。
- 新包测试能够独立运行是直接收益；上层变更仍可能触发重编译，不以包数量或代码行数承诺性能。

### Rust/Cargo 专用规则

- 根据用户提供的技能及 .plans/AGENTS.md 的现行覆盖规则，直接使用原生 Cargo；不使用旧 cargo_slot.py、Relax 或新包装脚本。这不是修改根仓库的构建配置。
- Rust 活动会话上限 3，混合语言总会话上限 5；本计划因共享清单实际串行。任意大型 Rust 编译在同仓库排队，槽位数量不等于编译预算；命令使用 `-j 1`，它也不能限制其它 Cargo 进程。
- 动态从 `target/rust-slot-1` 至 `target/rust-slot-10` 领取共享缓存，原子 `mkdir target/rust-slot-locks/slot-N.lock` 成功才持有；全部占用则等待。不新增第 11 个槽位、不固定任务槽位、不创建任务缓存，不删除未知或他人锁。
- 锁内记录覆盖整个验证阶段的真实持有进程 PID 和任务标识，不能记录即将退出的短命 shell PID；同阶段顺序验证在同一前台会话复用槽位。继承时核实锁的持有 PID 属于当前进程或存活祖先进程，并核对路径，不借用其它任务的槽位。
- `CARGO_TARGET_DIR`、`CARGO_BUILD_BUILD_DIR` 均设置为同一槽位的绝对路径，Cargo 及子进程继承，不通过别名或参数覆盖。以下任务命令均在已领取、已设置环境的前台会话执行，不是另开孤立进程执行。
- 保留所有缓存；不改 features、profile、工具链或 codegen 来规避编译成本。顺序命令前一步成功才能继续，使用 `&&` 或显式退出码判断。
- 记录运行句柄、入口 PID/进程组、实际槽位、双缓存路径、确切命令、退出码及有效测试数。零测试、旧结果或只编译成功均不算行为通过。
- 正常结束、失败或取消，先通过原句柄停止并确认自有 Cargo/rustc/链接器及产物使用进程退出，再释放自有锁；有界等待后仍存活，核实归属再终止自有进程组，不按进程名批量杀进程。未知归属保持占用并记录，不宣称已清理。清理前不重试、不手工移除 Cargo 锁。
