# 桌面全域拆包计划

目标：在首期底层拆包之后继续覆盖全部桌面子系统，使 vw-desktop 收敛为启动、窗口生命周期和跨域装配壳。

范围：本计划通过《源码归属清单》覆盖当前 src 下全部 2148 个 Rust 文件；业务、视图、局部消息、局部状态及测试源码均有归属。包括工作流、任务执行、设置、会话和平台服务。

范围外：改变产品行为、协议迁移、重品牌、发布，以及当前阶段任何编译或运行验收。

假设：这是首期的后续计划，先执行 `.plans/2026-11-14-桌面底层拆包/prompt.md` 的 15 项。旧 plan.md/prompt.md 保持只读；旧计划所说的 UI 范围外仅适用于首期，本计划接续覆盖。当前快照只提供静态依据，实施时重新读取源码。

## 设计决策

- 选择逐域、逐片提取，按低依赖到业务再装配推进；不把整个 app 搬到 desktop-core，也不为每个文件创建 crate。
- 不预设量化提速或行数指标；完成依据是职责与依赖边界、业务源码归属、实际调用接线和删除重复实现。

## 架构说明

- 基础数据/本机服务 → 控件 → 领域状态及局部更新/视图 → 桌面壳，箭头表达被上层依赖的顺序。
- 新库不依赖 vw-desktop；同域切片共用一个库，禁止按切片编号建包。

## 开发策略

只做结构迁移。每片先读取实现、父模块、工厂/路由、调用者与相邻测试，再收敛输入输出，移动并接线。保留所有现有行为、失败检查、cfg 和资源生命周期。不是运行测试驱动开发：用户明确要求不运行 Cargo、不运行单元或实机测试，代码交付后删除任务，未来统一验收。

## 公共执行约定

- 执行技能 `/Users/xiangmin/.codex/skills/do-task-plans/SKILL.md`；用户明确覆盖其任务内测试要求与未运行测试就保留任务的默认规则。本计划只生成任务，不在规划阶段实现代码。
- 本文件和 prompt.md 生成后只读；状态、调整与阻塞仅记编号文件。范围清单是生成时基线，后续用提交历史追踪移动，不要求更新历史清单。
- 常规可逆决策自主选择符合现有模式的最小方案；必要相邻适配可做，禁止顺便改变行为、增加能力或覆盖已有改动。先查源码，真正无法解决的关键歧义再集中询问。
- 从仓库根目录执行。遵守仓库 rustcodegraph 技能，查询不可用或图未覆盖时回退 rg；本阶段不运行可能触发工具链的索引刷新。已有用户变更须原样保留，尤其用量中心、Cargo.lock 及其他并行工作。
- 首期任务全部代码交付后开始本计划。后续任务按编号严格串行，每任务独占一个批次，依赖前一项；未完成的业务依赖不可因编号任务文件删除而猜测完成，核对提交与实际导出。共享清单、App 状态和消息入口频繁修改，故无并行实现批次。
- 新包均放 `crates/libs/<包名>`；参照 content-guard 的最小 Cargo.toml、0.6.0、edition 2024、MIT、doctest=false。先检查包是否存在，已存在则扩展，不复制重建。每片同步 workspace、桌面/真实调用库的 path/version 依赖与模块声明。
- 每片只移动所列生产源码及关联测试；可以修改实际调用点与最小共享类型，不能把下一个切片的实现整段搬进来。未迁移调用通过旧模块窄重导出/适配保持连线。引用尚未迁移的实现时，先提取最小必要依赖闭包到正确所有者，再移动本片；记录调整，不建立反向依赖或空壳伪实现。

## 全域边界规则

- App 只在桌面壳拥有，不把它复制到新库，不定义包含全部字段的 AppContext，也不通过 trait/dyn/闭包集合隐藏全局访问。
- 领域库拥有自己真实使用的状态、局部 Message、视图与 update。原 `impl App` 中的业务方法先变为本领域函数；壳保留委派。跨 crate 不能为外部 App 写 inherent impl。
- UI 组件返回 `Element<本域消息>`，壳使用 map 包装；异步任务返回本域消息，由壳 Task::map。跨域打开项目、标签、文件等动作使用按真实调用定义的小型枚举结果，由壳按原有顺序处理。不创建通用事件总线或万能服务容器。
- 本领域 view 只接收本领域状态和实际需要的只读参数，避免传完整 App。借用型参数优先，不能为解耦每帧深拷贝全部会话或账号数据；不能修改异步 Send/生命周期约束绕过所有权。
- 一个共享类型只有一个实际所有者。优先复用 vw-config-types、vw-api-types、vw-shared、vw-provider-resolver；渲染缓存与渲染 key 同属聊天视图库，业务会话库不能反向要求视图；必要时将纯业务投影与渲染缓存分开。
- 设置按功能域拆库；不能出现装下所有设置的巨型 settings 实现包。每域包含局部状态/更新/视图，设置壳只组合。供应商应用适配和模型路由配置职责分开。
- 小共享控件用泛型局部消息，既有样式、弹窗布局、toast、4px 滚动条与两侧留白不变；中文不使用等宽字体。本阶段不运行实际渲染，必须明确这一验收尚未完成。
- 原生系统 API 保留主线程约束、权限请求时机、取消和清理；不扩大网络/目录/命令白名单。账号脱敏、租户隔离、迟到响应拒绝、录音文件描述符保护、安装回滚不可弱化。
- 平台实现与依赖 cfg 同步移动；不能把 cpal/git2/objc2 等变成 wasm 无条件依赖。资源使用路径、include 宏、build.rs、Info.plist 与自定义窗口入口都要静态追踪。测试保持独立文件，不移除断言；跨 crate 测试私有访问重新按模块正确注册，不把测试支持函数暴露为生产 API。

## 公共验证与资源规则

- 用户明确禁止本阶段一切 Cargo 命令，包括 metadata/tree/check/test/build/fmt/clippy、别名、cargo_slot 包装和脚本间接启动。也不运行单元测试、原生窗口、实机测试、基准、安装、下载、CI 或发布。
- 允许编辑 Cargo.toml，禁止自动刷新或手改 Cargo.lock。不能换 rustc 或其他执行器变相验证；不启动编译、不领取缓存槽位、不清缓存。
- 当前仅源码阅读、rg、Git 差异审阅与轻量文档清单检查。每任务都提供运行目录及静态命令；必须明确这些不能证明编译、行为、渲染或性能通过。
- 以后统一验收需新的授权；届时遵守仓库 scripts/cargo_slot.py 20 槽位、同阶段复用、高内存编译串行与子进程收尾，不采用技能参考中的手工 10 槽位规则。此处不授权自动执行后续验收。
- 后续验收顺序：更新锁文件与依赖解析 → 按受影响库和桌面目标检查 → 迁移后的定向单元测试 → 跨域集成 → 平台/权限/窗口实际渲染。公共检查合并，不默认运行全量测试。

## 公共收尾规则

- 状态只用未开始、已完成、已阻塞、待回归。这里“已完成”只表示代码交付与静态审阅，不表示运行验收通过。
- 有实际变更时必须使用 `/Users/xiangmin/.codex/skills/git-commit/SKILL.md` 仅提交本任务变更；中文提交说明中列旧新路径/符号、最终测试入口、静态证据和“未运行 Cargo、单元及实机测试，待统一验收”。不混入用户改动，不创建空提交。
- 代码完成、静态证据完整且提交成功后删除对应编号任务文件，不因统一验收未执行而保留；删除可纳入同任务提交修订，不为纯任务删除单独提交。真实实现阻塞或提交失败必须保留任务并记录原因，不能把尚未完成实现说成以后测试。
- plan.md、prompt.md、源码归属清单.md 保留。最后收口任务写正式验收交接文档，引用提交历史恢复已删除编号任务的具体范围。

## 最终壳边界

允许保留：main/lib、App 的领域状态组合、顶层消息枚举与分派、Iced 应用入口和窗口生命周期、资源打包接线、显式验收入口。只有这些组合代码可留桌面；不得保留配置算法、网关业务、领域视图、存储、领域 update 或大段派生计算。根验收入口可以留，但测试业务主体应随领域迁移。没有出现于当前快照的新文件必须在最终收口检查中重新归属。
