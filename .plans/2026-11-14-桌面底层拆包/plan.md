# 桌面底层拆包计划

目标：从 vw-desktop 依赖较少的底层能力开始提取独立库，减少单包源码与测试目标耦合。

范围：差异文本、主题模型与存储、预览、文件索引、录音存储、音频后端、权限、Git 与 LSP；包含清单接线、调用适配和已有测试源码迁移。本轮只生成计划。

范围外：界面组件、App/Message 大状态拆包、工作流业务、发布、锁文件刷新及本阶段全部运行验收。

假设：以当前工作区为基线；用户已有未提交改动继续保留。包数量按稳定职责划分，不以每文件一个包为目标。源码规模降低不等于已测得编译提速。

## 设计决策

- 选择叶子库逐步提取；只做桌面内部文件拆分不能缩小 crate 编译边界；整包搬迁会保留耦合。
- 参考 content-guard 的小清单与独立 src/lib.rs 模式，沿用 0.6.0、edition 2024、MIT、doctest=false。

## 架构说明

- 桌面 → 领域库 → 现有基础库；新库禁止反向依赖 vw-desktop。
- 路径选择、Iced 状态与本地化留桌面；平台 cfg、安全检查和资源生命周期原样保留。

## 开发策略

这是结构迁移，不计划行为变化。先读实现、调用者和相邻测试，再移动与接线，禁止趁机重构或修复历史行为。测试源码随职责迁移，不新增无关测试。本阶段不采用运行失败测试的流程，依据是用户明确要求只写代码、以后统一验收。

## 公共执行约定

- 每个任务先读本文件与自身编号任务。本文件生成后只读，不记录状态；prompt.md 仅为入口且保持原样。
- 执行技能：`/Users/xiangmin/.codex/skills/do-task-plans/SKILL.md`。本计划明确用户覆盖：跳过该技能要求的任务内运行测试和保留待回归任务规则，以本计划的代码完成收尾为准。
- 常规、可逆事项自主决策；先查仓库事实。必要相邻适配可做，禁止扩展功能、覆盖他人改动或降低安全边界。确实阻塞时记录已尝试路径并继续独立工作，不把无人值守当作新增授权。
- 优先读取仓库 rustcodegraph 技能；索引不可用或未覆盖时用 rg。规划时 status 返回 7988 文件，explore 长时间无结果，已中断并回退源码读取；不初始化或刷新索引来绕过命令禁令。
- 新库放 `crates/libs/<包名>/`，最小 Cargo.toml、src/lib.rs、独立测试文件。新包名为本计划拟定目标，实施前检查是否已存在，禁止覆盖已有包。
- 每项移动同时更新根 Cargo.toml workspace members、桌面 Cargo.toml path/version 依赖、旧模块门面和实际调用点。保留现有依赖 features 与 target cfg，禁止复制桌面整张依赖表。
- 跨 crate 只公开实际调用所需符号；原 pub(crate) 不可机械保留，也不可整体升级全部符号为 pub。保留测试隔离与测试进程锁语义，不用 cfg(test) 暴露项支撑生产调用。
- 所有任务按编号串行，每任务一个批次，依赖前一任务；没有可并行实现批次。共享两张 Cargo.toml 与入口文件，串行避免接线覆盖。优先级按依赖闭包与安全耦合评估，无运行测量排名。

## 公共验证与资源规则

- 用户明确覆盖仓库/技能默认测试规则：整个实施阶段禁止任何 Cargo 命令（包括 metadata、tree、check、test、build、fmt、clippy、别名及包装脚本间接调用），不跑单元测试、实机测试、窗口探针、基准、安装或发布。
- 可以读取、编辑 Cargo.toml；不自动生成或手改 Cargo.lock，不运行 CI，不推送触发外部验收。锁文件更新留给后续统一验收。
- 只进行源码审阅、rg 搜索与 git diff 轻量检查，不使用其他编译器或运行器替代被禁止的验收。不声称编译、行为或性能已通过。
- Rust 专用资源约定：本阶段不启动编译，因此不领取缓存槽位。以后用户单独授权验收后遵守仓库 scripts/cargo_slot.py、20 槽位、同阶段复用、高内存编译串行及自有进程收尾约定；技能参考的手工 10 槽位不适用。当前计划不授权以后自动执行验收。
- 每项任务需要：迁移文件清单、旧新符号映射、调用者搜索、cfg/依赖/测试注册审阅及 git diff --check 结果。这些只能证明代码交付，不能代替编译或测试证据。
- 统一验收由后续独立任务处理：先刷新锁文件，检查新增库与桌面目标，再运行迁移后的定向测试与桌面集成，最后按平台验收音频权限、Git、LSP 和原生窗口。不默认全量测试。

## 公共收尾规则

- 状态只用未开始、已完成、已阻塞、待回归。本计划的“已完成”仅表示代码与静态审阅完成，明确不表示运行验收通过。
- 每项有实际变更时使用 `/Users/xiangmin/.codex/skills/git-commit/SKILL.md` 中文提交，仅提交自身变更；提交信息写明“未运行 Cargo、单元及实机测试，待统一验收”。不提交已有无关改动，不创建空提交。
- 代码完成且静态证据齐全后，先提交实际变更，再删除对应编号任务文件；不因尚未运行测试保留任务。删除可随本任务提交修订收纳，不为纯状态/删除单独创建提交。
- 真实代码阻塞或提交失败保留编号任务文件，记录原因、静态证据和已尝试方案，不能因不跑测试而掩盖实现未完成。
- plan.md 与 prompt.md 永久保留。编号文件删除后，以 Git 历史与提交信息恢复迁移内容、测试入口及未验收说明；最后的收尾任务另写统一验收文档，防止删除任务丢失验收范围。
