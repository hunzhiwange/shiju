# 系统底层全面拆分计划

目标：从 vw-webview 开始，按依赖由小到大提取职责单一的底层库，降低单包开发与测试耦合。

范围：先完整拆分 vw-webview，再覆盖其余 11 个顶层包的领域边界审计与实施子计划；已有 crates/libs 的库优先复用。此目录替代旧 WebView 12 任务入口，旧目录只作历史参考，不交叉执行。

范围外：业务功能变更、重品牌、依赖升级、未经边界审计直接搬迁其他大包、任何构建测试或实机验收。

假设：保持当前启动参数、二进制名、IPC、页面脚本和安全策略的既有行为；以当前 0.6.0、edition 2024、MIT 小库模式为基础。拆包改善编译边界的收益尚未测量。

## 设计决策

- 选择按职责拆 crate；仅拆文件不能隔离编译，按操作系统拆 crate 会重复平台连线。
- 纯库先行，平台及运行时后置；共享清单有写冲突，全部采用单任务串行批次。
- 本轮仅计划，不实施代码。未来执行按用户明确要求只写代码，不运行验证。

## 架构说明

- WebView 不再汇聚为 platform 大库；按纯数据、纯资源、独立原生能力、视图和运行时分层，依赖方向以每张任务卡为准。
- 箭头表示从基础到上层；下层不得反向依赖 vw-webview 或运行时，纯库不得引入 tao/wry/GTK/ObjC/Windows。
- 目标库统一位于 crates/libs/webview-*，各自有 Cargo.toml、src/lib.rs；只公开实际跨 crate 使用的符号，测试独立文件。

## 开发策略

本轮为保持行为的结构迁移，不做新功能或安全语义调整。按用户明确覆盖要求，不执行测试驱动流程，不新增测试运行要求；保留并迁移既有测试源码和断言，未来统一验证。发现疑似既有缺陷记录证据，不借拆分修复业务行为。

## 公共执行约定

- 每个任务先读本文件和任务卡，确认前置任务已经代码落地。本文件生成后只读，不更新进度、不删除；prompt.md 仅作为固定入口索引。
- 使用 /Users/xiangmin/.codex/skills/do-task-plans/SKILL.md 执行。用户本次“不进行任何 Cargo 相关、不运行测试、只写代码、写完删除任务”的要求覆盖技能及仓库默认定向测试、实机验证和未验证不得删除的要求。
- 常规、可逆决策自主完成；先搜索真实调用者、工厂接线和相邻测试。保持单向依赖，不新增推测 trait、配置和特性开关。局部问题先调查，在范围内修复必要接线；无法消除的关键歧义或授权问题才集中询问，不将沉默视为批准。
- 工作目录为仓库根。导航优先 skills/rustcodegraph/SKILL.md；索引查询不可用时回退 rg 和读取源码，不启动 Cargo 建索引。本次 status 有索引，explore 未及时返回已取消，以下边界依据源码补充核对。
- 不覆盖工作区已有变更，尤其 Cargo.lock 及其他包的修改。实现中准确记录迁移、静态审查证据、依赖变化和未验证项。
- 每次新增库都同步根 Cargo.toml 的 members、直接消费者的路径依赖及源代码调用，版本引用匹配现有模式。平台依赖原样保留 target cfg 和 features；不把平台依赖放进纯库。

## 公共验证与资源规则

- 严禁运行任何 Cargo 命令（含 metadata、check、test、fmt、clippy、run、generate-lockfile），也不通过脚本间接运行。不执行单元测试、脚本测试、GUI、截图或实机验证，不领构建槽位、不启动构建子进程。
- 允许读取和修改 Cargo.toml 作为拆包必要代码配置；这不授权执行 Cargo。Cargo.lock 不手工生成或更新，留待用户以后统一验证时生成。
- 仅做静态差异审查：git diff --check、git diff --stat，以及各任务指定的 rg 搜索、清单与 include_str!/模块路径人工核对。rg 无匹配可能返回 1，按搜索目的判读，不能作为编译或测试通过证据。
- Rust 后续验证另行授权，届时按仓库有效 Cargo 槽位协议串行执行。本计划不包含验证执行任务，也不自动触发统一回归。
- 后续统一验收须覆盖本计划全部新库及原二进制的编译/已有定向测试、跨库 IPC 和资源、macOS/Windows/Linux 条件分支、Cookie 保密、MCP CSP/nonce/表单撤销、弹窗析构与权限拒绝。未执行项一律写“未验证”。

## 公共收尾规则

- 状态只用未开始、已完成、已阻塞、待回归。本计划“已完成”仅表示代码及静态审查完成，不表示编译、测试、性能或实机通过；不因用户明确延后验证而标为阻塞。
- 有实现变更时使用 /Users/xiangmin/.codex/skills/git-commit/SKILL.md 提交，仅包含本任务代码及配置，中文提交说明明确“未运行 Cargo、测试及实机验证”。提交失败保留任务卡并记录原因；无实现变更不创建空提交。
- 代码迁移完成、调用接线和静态差异审查完成并提交后，删除对应编号任务文件。最终回复报告实现及未验证情况；plan.md、prompt.md 保留，已删除卡的入口视为历史索引，不重复执行。
- 合理调查仍无法落地则标已阻塞，保留卡并记录已做修改、尝试、所需输入；实际变更先按上条提交。不能以静态审查代替或宣称动态验证成功。

## 全面拆分边界

- “尽可能全部”指全部既有职责都有归属，不是每个函数建库；一个库只承载一个领域，不以 core/common/platform 命名兜底新增无关功能。
- WebView 采用 19 个职责库，按任务卡串行实现；原 vw-webview 只保留二进制入口及分派，不以转移成新的巨大 runtime 文件作为完成。
- 其余 11 个顶层包均有后续计划任务。尚未逐符号审计的大包不伪造可立即搬迁的接口；先按既有模块划分领域并生成完整编号实施卡，再由实施入口串行推进。后续计划继续继承本次禁用 Cargo/测试/实机和代码完成删卡约定。
- 全仓候选顺序来自当前路径依赖：config-types → shared → api-types → provider-resolver → gateway-client → acp → agent-apps → agent → tui → desktop → cli。WebView 先行是用户指定起点；同层先处理已确认外依赖更少的模块，不能只按文件数决定顺序。
- 领域间存在双向引用时，先下沉两侧真实共享的数据契约，再搬服务实现；不允许基础领域回依赖原聚合包，也不通过全局注册器或动态分派掩盖环。
- 原包可暂作仅含组装及导出的门面；所有内部消费者切到实际职责库，不能因门面继续拉入全部依赖而宣称隔离完成。是否删除门面须核对发布和外部入口，不能擅自破坏发布接口。
- 后续领域子计划的成功证据包括所有源文件归属表、跨包调用与依赖表、保留门面理由；保留内容逐项说明为何必须与事件循环、状态或公开发布边界共同存在。
