# 终端全量拆包计划

目标：在首轮底层拆包后继续覆盖全部已启用 TUI 职责，使 vw-tui 最终只保留公共重导出与必要集成测试入口。

范围：输入组合器、底部面板、通用选择器、审批和问答覆盖层、转录/执行/队列状态、聊天装配、引导、分页器、终端循环及 surface；审计全部剩余实际模块。

范围外：其他系统包的全面拆分、功能变化、启用未编译复制代码、Cargo、测试、实机验收。

假设：第一阶段 16 项实施任务先全部完成。本阶段是用户扩大范围后的独立追加计划，不改写第一阶段只读计划；第一阶段暂时保留的上层模块在本阶段继续提取。

## 设计决策

- 首轮只拆底层不足以达到用户“尽可能全部拆分”的目标。本阶段把上层真实模块纳入，vw-tui 只作为既有消费入口。
- 选择按真实类型所有者与职责拆包；只拆文件仍共享编译目标，每个 impl 单独成包则无法遵守 Rust 固有方法所有权。ChatWidget 的固有方法整体留在最终 tui-chat 内，独立状态先向下抽离。
- 提取已有 BottomPaneView 协议，不创造通用插件框架；问答弹层依赖组合器，组合器不能依赖弹层；底部面板不反向依赖 ChatWidget。

## 架构说明

- 低层继续使用首轮 tui-contracts/text/input/theme/render/highlight/markdown/stream/clipboard/terminal/cells。
- 本轮依赖方向：widgets → composer/pickers/popups → overlays/bottom-pane → chat；独立 transcript/exec-state/chat-state 仅依赖已有底层，surface 独立。
- BottomPaneView 与 ViewCompletion 属于 widgets；MentionBinding、UserMessage、V3ChatStatus 按纯数据依赖归入已有 contracts。禁止复制定义绕开类型所有权。

## 公共验证与资源规则

- 禁止所有 Cargo 命令及间接启动 Cargo 的脚本、索引初始化/同步，禁止运行任何测试、实机渲染或 TUI；禁止新增测试。只迁移并接线既有测试和资源。
- 禁止修改或生成 Cargo.lock。当前已有无关变更必须隔离。
- 只做 rg 搜索、文件读取、git diff --check 及静态差异/依赖审阅。静态证据不代表编译、行为、性能或跨平台验证通过。
- 无自动回归任务；未来用户统一授权验收时，按仓库 cargo_slot.py 入口串行执行必要 Rust 验证，当前不生成运行指令。
- 不承诺所有包都达到某个虚构行数；以闭合职责与编译依赖隔离为目标，过大时仅按真实独立数据所有者继续提取，禁止制造没有真实调用者的抽象。
