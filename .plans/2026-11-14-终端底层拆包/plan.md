# 终端底层拆包计划

目标：从 vw-tui 提取低依赖底层库，缩小修改与测试所需的编译单元，保留上层交互装配。

范围：仅拆分 crates/vw-tui 的实际启用模块及直接调用接线。新库放在 crates/libs/，参考 content-guard 的独立包清单、明确版本、最少依赖及 doctest=false；保留各来源许可证。

范围外：其他系统底层的实际拆分、功能开发、重品牌、发布、构建、测试及实机验收。

假设：以当前 src/lib.rs、显式 path 和子模块声明为事实；目录中的复制源码不等于正在编译的代码。下游主要消费者为 vw-cli。

## 设计决策

- 选择按职责抽 crate：相比只拆文件能隔离编译；相比每文件一包可减少碎片。共享清单写入多，全部串行。
- 用户明确要求仅写代码：本计划覆盖技能及仓库默认的任务内运行验证要求，统一验收另行授权。

## 架构说明

- 依赖从装配层指向底层，禁止新库反向依赖 vw-tui。
- vw-tui 保留 ChatWidget、底部面板、审批交互、surface 和运行循环；原有真实调用入口通过同一类型重导出维持接线，不新增旧数据迁移逻辑。

## 开发策略

- 只做等价移动、可见性调整、导入和清单接线，不改变行为，不引入新 trait、配置或重型依赖。
- 不使用失败测试驱动：本阶段禁止新增及运行测试；现有测试代码、快照及 fixture 随所属模块迁移，保留以后统一验收能力。
- 测试模块若与业务内联，搬迁时独立存放；不重写断言，不扩大到未启用的复制模块。
- 提取前核对完整模块树、所有 crate/self/super 引用、宏、include_str、相对资源、条件编译和测试专用依赖。现有索引的通用符号 used-by 存在同名噪声，必须结合路径和文本搜索核对。

## 公共执行约定

- 每个任务先读本文件及自身任务文件。本文件与 prompt.md 生成后只读，不更新进度、不清理。
- 执行技能：/Users/xiangmin/.codex/skills/do-task-plans/SKILL.md。其默认验证流程以本计划用户明确约束为准。
- 无人值守执行常规可逆决策，优先沿用现有模式。先调查局部阻塞，继续独立工作；仅关键目标歧义或新增授权才集中询问。
- 工作目录为 /Users/xiangmin/worker/code/shiju。线性顺序为任务编号升序，每批一个任务；批次 N 依赖批次 N-1，禁止并行修改公共清单和接线。
- 当前工作区已有无关修改，包括 Cargo.lock；仅处理本任务文件，不能覆盖、暂存或提交他人变更。
- 新库版本 0.6.0、edition 2024，许可证按来源保留，依赖版本/特性沿用原清单。每次新增库同步根 Cargo.toml 显式 members 与 vw-tui 路径依赖，不集中拖到最后接线。
- 每次只移动闭合职责。用普通 pub 暴露真实跨 crate 调用所需项，其他项保留私有；禁止批量公开所有内部字段。
- 不因测试可见性引入生产反向依赖：跨层断言留在上层现有测试入口；底层自有测试移入底层独立测试文件。
- 每个任务重新搜索实际模块声明，不能按整个目录直接搬走。路径属性、重导出和文件名变更均需核对消费者；必要相邻改动限定于完成当前接线。

## 公共验证与资源规则

- 本计划及执行阶段禁止任何 Cargo 命令，包括 metadata、check、test、fmt、clippy、generate-lockfile，以及会间接启动 Cargo 的脚本、IDE 构建或 RustCodeGraph 索引初始化/同步。
- 禁止单元、集成、快照、实机、真实渲染测试，不启动 TUI，不新增测试；只保留并接线已有测试源码。
- 允许只读搜索、清单文本审阅、git diff --check 和 git diff 静态审阅。它们不代表编译、行为或性能通过。
- 不生成或手工修改 Cargo.lock。以后统一验收时再更新锁文件；现阶段禁止使用 --locked 是否可用作为完成要求。
- 不承诺拆包即减少最终链接时间；收益目标是缩小各底层库的修改与聚焦测试边界，性能留待统一验收。
