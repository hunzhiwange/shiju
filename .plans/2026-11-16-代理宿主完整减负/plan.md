# 代理宿主完整减负计划

目标：一次覆盖 vw-agent 全部残留职责，把领域实现、领域测试及夹具归还真正所有者，宿主仅留启动组合和具体宿主端口。

范围：当前 crates/vw-agent/src 全部 1381 个 Rust 文件、135228 行；每个文件在 scope.json 唯一归属，另追踪由宿主跨目录挂载的测试。覆盖网关、会话、工具、插件、通道、执行循环和其余适配层。

范围外：删除功能、重品牌、改变权限及协议、Desktop 拆分、为行数修改注释或格式、发布。

假设：沿用用户本聊天“只写代码，不运行任何 Cargo、实机和单元测试，完成后删任务，未来统一验证”的约束；本计划中的命令仅供未来验证使用，不构成本次执行授权。

## 设计决策

- 选择现有领域库持有完整职责，宿主保留具体装配。继续只迁少量测试收益不足；把整个宿主改名为新单体只改变统计，不采用。
- 测试占据主要残留；整组迁移领域测试，同时下沉残留业务分支、消除过量转发。真实宿主验收保留必要边界断言，不复制全套宿主状态。

## 架构说明

领域库使用既有输入类型及 Host 端口；宿主实现具体权限、当前租户和外部生命周期。禁止反向依赖 vw-agent、path/include 加载宿主源码或把 App/AppState 克隆进领域库。

## 整轮成功标准

- 当前135228行按 baseline.json 同路径、splitlines口径核对；最终宿主 Rust 物理源码不高于35000行，净减至少100228行。此为整轮硬验收，不能把建议值当成已达成；不能为达标删除覆盖或业务。
- 生产逻辑单独报告：文件名排除 test 的粗分仅作导航，必须逐项识别 cfg(test)、测试夹具、文档、转发和真实生产分支。迁出的生产符号必须由真实调用者引用，不能仅增加另一份算法。
- scope.json 每个原始文件都须有迁出目标或具体保留职责；保留项给出符号、原因及行数。不得以“宿主耦合”四字整体保留一个大测试文件；先拆出领域断言，只保留真实边界。
- 新旧测试逐项映射，不删除场景、不用模拟端口冒充真实鉴权/文件访问验收。物理路径变化、测试编译归属、依赖方向和构建耗时分别报告；未运行时不宣称编译收益。
- 一次执行入口覆盖所有工作，不能完成首批小样本便终止。最后收口仍超额则任务保持已阻塞，列出缺口，不宣称整个目标完成。

## 开发策略

这是保持行为的职责迁移，沿用原断言，不人为制造失败。发现必须改变行为时先写对应失败用例代码、隔离范围并记录预期失败；本次不运行，后续验证阶段取得红绿证据后才能声称行为验收。
每项任务处理完整文件族和真实入口，不再按2～4条测试设完成边界。源文件已是转发时，直接使用真实领域入口承接其完整测试，必要宿主调用用薄契约覆盖。

## 通用迁移动作

1. 读本任务来源及直接夹具，建立每个生产符号和每条用例的“实际所有者→目标→宿主保留原因”映射。读取任务1中本领域跨目录挂载并承接同一职责，不能漏掉宿主外部path测试。
2. 将仍处在宿主的策略判断、请求转换、生命周期局部算法接回已有领域入口；真实租户、权限、外部资源生命周期仍由具体宿主端口注入。只为当前真实调用补充必要输入/端口，不能为了测试暴露私有实现或增加通用Host框架。
3. 已有领域入口足够时直接迁整组测试、最小真实存储/临时目录夹具和必要dev依赖；通过本库自己的测试模块注册。原测试需真实宿主时分离领域断言，保留能证明宿主实际接线的薄测试。不能把原文件拷到libs又让宿主继续path加载。
4. 进程级OnceLock、环境变量、当前租户和全局配置必须沿用本库已有隔离方式；复用真实存储，mock仅限清晰的宿主/外部服务端口。不能拷完整App/AppState、不能在测试中重写算法。
5. 删除已经由领域承接的原定义、无调用转发文件、旧mod/path及专用夹具/import；保留公共使用者实际需要的薄re-export，更新直接调用者避免层层转发。保留所有安全、取消、失败与事件顺序断言。
6. 接线和静态审查在本任务内闭合；与其它任务共用父模块、清单只排队最小补丁。本任务不能修改scope中其他任务源文件，跨所有者缺口记录具体符号请求原任务处理。
