## fixture、资源与隔离

私有 Fixture、local_user、certificates、client、receive、read 和 DocumentApproval 保持原文件。Fixture 以 libc::geteuid 生成用户，创建独立 RwLock 策略、启用 Word，创建 runtime 并 bind_office。pair 写真实 WordDocument Allow，按 office_owner 批准一次性配对 token，发送 word/document_id/Untitled/capabilities 并断言 paired；request 从该 owner 的真实 sessions 读取 generation。call 走 execute_tool_from_registry 与 chat ToolUseContext。

certificates 使用 OnceLock<TempDir>，目录0700、证书/私钥0600；运行时调用 openssl req 生成一天有效的 localhost 自签名证书，客户端显式信任该证书并检查 localhost；固定允许 Origin=https://localhost:3000，实际服务端地址来自 transport.address()。临时目录负责清理。无需真实 Office、外网或物理音频；需 openssl 和本地 TLS/socket 支持。本轮未运行这些资源路径，不记录私钥或 token。

receive 超时3秒；拒绝后无派发检查20ms；断线最多100次轮询、每次5ms。异步 responder 通过 join 等待；abort token 来自 tokio-util。没有修改环境变量或显式环境锁。factory 用临时 workspace/config 和进程级 shared runtime，是保留宿主的重要原因，后续验证须关注并行共享状态，不据静态阅读声称隔离已验证。
