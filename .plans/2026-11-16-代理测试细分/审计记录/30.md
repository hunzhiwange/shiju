## 保留理由、断言与资源

provider_tests 的前三项分别验证真实配置中空供应商的设置/运行时差异、远程发现与配置模型合并、内置 API 继承，经过 ensure_host/load_state_impl 的实际宿主目录读取。
unknown_model、cross_layer_fixture、explicit_model_capabilities 三项验证配置装配与 model-state 的默认限制及显式能力契约；cross_layer_explicit_model 项额外调用 session::llm::model_limit_for_request，验证下一次请求元数据。custom_provider_reasoning 项校验真实目录 shiju/token-plan 推理选项及覆盖保留。
四项 provider_catalog 分别验证真实配置存储故障时保留 Configuration 错误来源并恢复、CONFIG_READ_BOUNDARY 下单快照一致性、禁用/删除后缓存撤销、同项目路径跨 tenant 与工作线程 task-local 恢复隔离。
这些行为保留真实 Host，不引入假宿主或库到应用的反向依赖。全部断言和函数体原样保留。

provider_tests 原有 EnvGuard/Drop、TempDir、global_async_env_lock、HOME/VIBEWINDOW_CONFIG_DIR/VIBEWINDOW_WORKSPACE 环境恢复保持不变；模型发现使用 localhost TcpListener、读取超时及 server.join，agent_env::provide_with 显式提供启动快照。两个 include_str 相对路径仍解析至 crates/libs/model-state/assets/provider/cross_layer_{unknown,explicit}_model.json（新旧目录到 crates 均为三级），资源不复制。

model_catalog_tests 七项保留理由与断言依次为：
- keeps_selected_deployment：真实 AppProviderStore/GlobalDatabase 重开 SQLite 后保留 deployment、alias、runtime identity 与内置目录。
- respects_native_default：真实 tenant 配置与 SQLite 的原生默认模型优先级。
- uses_only_exact_host_and_endpoint：deployment 的 host/endpoint 精确隔离，不匹配配置明确失败。
- refreshes_after_commit_without_reconfiguring：SQLite 提交、重命名和删除立即影响目录缓存；解绑后恢复配置模型。
- preserves_declared_metadata：SQLite provenance 与模型限制、输入输出模态、tool/reasoning 能力投影。
- keeps_gateway_picker_in_tenant：真实认证 gateway/provider_list 与 tenant picker，展示名、默认、连接状态、runtime key 隔离。
- rejects_gateway_image_before_ocr：真实 gateway/session 执行门禁；上游调用数为0、明确 image 错误、无 Delta。

Fixture 的 tenant/deployment/database、run_isolated 的子进程精确全名过滤、env_clear、独立 HOME/TMPDIR/配置/工作目录、60秒超时和 kill_on_drop 均不变；gateway/upstream 的 abort/await 释放断言原样保留。module_path 未变，子进程过滤全名保持有效设计。
