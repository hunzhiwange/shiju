# 桌面宿主减负适中拆分计划

目标：以单会话可完成的一组相关行为为单位，将 `vw-desktop` 的领域实现和测试归回已有库。

范围：基于原计划重新限定具名用例；每项含必要夹具、注册、宿主接线与定向验证，不把这些必需步骤拆成多个交接任务。本目录是唯一执行入口；旧版计划已按用户要求删除。

范围外：一次迁完大文件、清空宿主、重写 App/AppState、改业务行为、全仓测试与新建测试基础设施。

假设：源码会继续演进，任务先核对指定用例仍存在且注册有效；源码中的未挂载文件不计迁移收益。

## 设计决策

- 采用一组相关行为的粒度，通常2～4条现有测试；需要取消协作等复杂夹具的场景可单列。拒绝按整领域迁移，也不把每条简单测试拆成任务。
- 优先复用领域入口；独立移出的断言与必须保留的宿主交互分别记录，不能靠搬路径或删除覆盖达标。

## 架构说明

- 领域持有算法、局部输入和独立测试；宿主保留装配、真实权限及跨系统交互。
- 不反向引用宿主源码，不为测试暴露额外生产接口，不复制完整宿主夹具。

## 开发策略与会话边界

- 每项任务只阅读指定测试、直接夹具、领域入口及注册链；禁止为一项迁移通读整个宿主、全部计划或所有测试。
- 通常涉及1个来源测试文件、1个领域测试模块和必要父模块，约3～6个文件；最多一个局部夹具适配决策。行数只是审查信号，不用凑指标削减断言。
- 先确认已有接口足以承接；若发现需要新增跨系统端口、移动大段生产状态或连带迁移另一组行为，先记录具体依赖，不在本会话扩为领域重构。能独立闭合的部分完成实现、接线与必要测试；未完成部分明确阻塞，不冒充任务完成。
- 保持行为的迁移先跑原用例，不人为制造红灯；实际行为变化必须先写失败测试，并取得同一过滤命令的失败与通过证据。
- 编译等待不等于任务复杂度；仅验证阶段排队，运行输出保存证据文件，阅读摘要及相关错误，不反复读大量无关日志。不能保证绝不发生上下文压缩，但不将跨领域探索或无边界修复塞进一个任务。
- 归属审计与公共 Clippy 分成两个编号任务，审计只修迁移清单/挂载缺口；公共检查仅修本计划引入的窄问题，遇到超范围错误保留证据，不扩成全仓修复。

- 已确认 `app/message/chat/processing_timing_tests.rs` 仅一行领域归属说明，本轮不再规划计时测试迁移，审计时记为已迁出、不重复计收益。UI 迁移沿用真实 UserInterface 事件、布局、绘制和字体整形，中文动态文本及明暗主题均需无 panic；保持统一控件和滚动间距。

### Rust 专用规则

- 仓库 AGENTS.md 与 scripts/BUILDING.md 优先于技能参考中的通用裸 Cargo 和10槽位示例：统一用 `python3 scripts/cargo_slot.py <前台命令>`，自动领取 rust-slot-1 至20；同阶段顺序命令用一次入口和 `sh -c '命令 && 命令'` 复用双缓存路径，不手工 mkdir 领锁、不覆盖环境、不清缓存。
- 高内存 Cargo 编译只在验证阶段串行排队；缓存容量不代表编译并行预算。必要时原生命令加 `-j 1`；不因此增加实现依赖。此次模块、签名及依赖接线变化以原生定向 Cargo 验证，不要求 Relax 探针。
- 保持前台进程组；记录入口句柄、槽位、CARGO_TARGET_DIR 和 CARGO_BUILD_BUILD_DIR。取消或超时先停止自有进程组，核实 Cargo/rustc/链接器子进程退出再释放自有锁；不得批量杀进程或删除他人锁。
- 定向测试已编译同一目标不重复 check；否则只检查受影响包的 lib 或具体 bin。仅格式化本次修改文件。不默认运行全量 cargo test、workspace build、全仓 fmt、wasm 或 Makefile。
- 统一回归只补跨任务接线和必要公共检查；`python3 scripts/cargo_slot.py cargo clippy --all-targets --all-features -- -D warnings` 合并执行一次。不机械重跑未受后续改动影响的测试。既有无关失败如实记录，不扩展范围。
