# 桌面测试拆分计划

目标：完整核对并迁移桌面局部测试，宿主保留有明确依据的装配契约。

范围：30 项领域任务覆盖当前 467 个含测试源码文件、3508 项测试属性；另 1 项验收此前已迁移的3项测试，1项最终核对。明细见 inventory.md 和 inventory.json。

范围外：agent/tui、认证模块修复、产品功能、新建总测试库、重新生产拆包及发布。

假设：清单为创建时的源码快照，文本属性数不代表 cfg 激活数量或编译耗时。其他会话新增项在最终核对时补登记。

## 设计决策

- 按实际领域划分任务，不按测试数量机械切片，不安排批次或执行分组。
- 直接搬文件不能隔离宿主 lib-test；采用已有领域库承载局部行为，宿主保留跨域状态投影与消息映射。
- 一个领域内按行为族逐步迁移并即时定向验证，不把必要验证积压到最终核对。

## 架构说明

- 清单候选库来自相邻生产文件导入，执行时按真实调用确认；不因构造 App 一律保留、不因有小库强迁装配。
- 复用已有状态及动作，不复制 App、不增加无调用者抽象。保持权限、主题、平台与外部副作用语义。

## 开发策略

- 纯迁移对照原函数、断言、cfg、资源和 fixture，无需人为红灯。行为变化先在编号任务登记真实失败场景、红绿命令及预期失败再实施。
- 使用真实局部状态，只模拟明确的外部边界。原有中文整形、明暗主题及交互继续真实验证，不降为仅构造 Element。

- 本计划创建只做路径、入口和差异轻量检查。执行时每任务完成必要定向测试，实际 ran > 0、failed = 0、退出 0 才算通过；零测试、仅编译或旧结果不算通过。

### Rust 专用规则

- 仓库规则优先于技能参考：macOS/Linux 使用 `python3 scripts/cargo_slot.py` 包住原生 Cargo，单次 `-j 1`。同阶段顺序命令用一次入口及 `&&` 连接，禁止脱离前台进程组的后台任务，不新增包装设施或常驻探针。
- 脚本已存在，原子领取 target/rust-slot-1 至 rust-slot-20，记录真实存活 PID，设置 CARGO_TARGET_DIR 与 CARGO_BUILD_BUILD_DIR 为同一槽位绝对路径。嵌套只继承当前或祖先 PID 核验过的锁，不覆盖缓存路径、不抢他人锁，不手工建立短命 PID 槽位。
- 高内存 Rust 编译仅在验证阶段串行排队；缓存容量不决定任务批次或会话数。保留增量缓存，不清缓存、不改工具链、profile 或 features 提速。
- 记录句柄、PID/PGID、槽位、双缓存路径、命令、退出码与有效数量。取消先停自有进程组，等待并确认 Cargo/rustc/链接器均退出后释放自有锁；不按名称批量杀进程、不删除他人锁。正常退出亦确认清理。
- 模块归属、签名、trait、宏与依赖改变必须原生定向验证；不以 Relax verdict 替代。具体用法参见 scripts/BUILDING.md。
