## 文件与上下文

- 检查和按需修改：`crates/vw-agent/src/lib.rs`、`crates/vw-agent/src/tools/mod.rs`、`crates/vw-agent/src/gateway/`、`crates/vw-agent/src/session/`、`crates/vw-agent/src/plugins/` 及其它被入口实际引用的测试模块。
- 目标为 `crates/libs/` 中生产实现所属的现有 agent、session、tool、gateway 等库；具体路径和测试依赖由执行者确认后记录，非创建新包清单。
- 已核查 `crates/libs/tool-mcp/src/mcp_tool_tests.rs` 存在，部分测试由宿主 tools 模块通过路径引入；这只是审计示例，不能推断整份测试都可直接迁移。
- 本任务拥有代理侧父模块、所属库测试接线与依赖调整；排除 desktop 和 tui 领域修改。

## 主要拆分逻辑

1. 从 Cargo 目标和模块树建立实际编译测试清单，包含 cfg、path、include、测试辅助、fixture、资源和宏；按被测生产符号的所有者判定，不按文件名分类。
2. 分成库内局部行为、公开跨库契约、宿主装配行为。局部行为迁入所属库独立测试文件；公开契约复用合适目标；宿主保留真实路由、运行时、权限及通道组装验证。
3. 移除纯测试对宿主重导出路径的依赖，以所属库和底层类型直接接线。只为真实调用者提取必要窄接口，不扩大生产可见性来迁测试、不让库反向依赖 vw-agent。
4. 源文件物理移动和编译归属同时迁移：目标库引入测试、完善 dev-dependencies，删除主包引入，迁移资源路径；不复制断言或保留双份执行。
5. 无法局部化的测试记录具体宿主依赖及保留理由；不得把全部遗留笼统标成集成测试。共享测试夹具按真实使用最小提取，不建巨型测试支持库。
6. 审计 CI 是否能发现迁入库的 lib 测试，记录已有工作流覆盖证据；若发现必要接线缺口，在本任务中最小修复并协调共享文件写入。

## 验证计划

纯测试归属重构不改变行为，不新增人为红灯；迁移前记录原测试全名与覆盖断言，迁移后逐项映射到目标，解释合并或必要改名。具体迁移由本任务决定，因此必须先将选定的目标包、过滤条件和预期数量写入本文件再运行，不能把示例当完整验收。

已确认可用的审计及宿主保留测试示例：

```sh
rg -n '#\[path|include!|mod .*test' crates/vw-agent/src/tools/mod.rs
python3 scripts/cargo_slot.py cargo test -j 1 -p vw-agent --lib plugin_install_dir_uses_config_parent
```

- 新归属库的每个迁移行为族使用同样槽位入口运行原生 Cargo，指定实际包、--lib 和有效过滤条件；保留宿主行为变更处也必须定向测试。
- 若迁移涉及生产接线且宿主目标未被测试编译覆盖，运行 `python3 scripts/cargo_slot.py cargo check -j 1 -p vw-agent --lib`。
- 需要行为变化时，先记录对应实际失败测试和红绿命令，按公共策略执行。
- 模拟仅用于真实外部网络、进程等边界，保留错误、取消、租户、权限和资源释放语义。

## 验收证据

提交中保留原测试到新包/模块/测试名映射、宿主残留及逐项理由、前后实际主包测试源码规模和测试数量口径。每个迁移族 ran > 0、failed = 0、退出码为 0，原断言覆盖无静默丢失；主包不再引入已迁测试。记录独立小库测试不需要编译 vw-agent lib-test 的输出证据，不承诺无测量的耗时比例。全量扫描只用于清单，不触发全量测试。
