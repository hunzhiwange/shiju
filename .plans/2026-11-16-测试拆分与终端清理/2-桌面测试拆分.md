# 任务 2：vw-desktop 测试拆分

先阅读并遵守 [公共执行规则](plan.md)。

批次：【批次 1】；依赖：无。推荐按编号阅读，可与任务 1、3 独立实施。

状态：未开始

目的：使桌面局部行为测试随现有 desktop 库编译，减少 App 全局构造导致的宿主测试耦合。

来源任务：用户本轮要求；不重复已有桌面生产拆包。

预计会话范围：一个桌面测试归属入口，执行者决定具体行为族和迁移顺序；优先已拆出的实现，再最小收窄确实阻挡测试迁移的接口，不扩成整套 App 重构。

## 文件与上下文

- 宿主入口：`crates/vw-desktop/src/lib.rs`、`crates/vw-desktop/src/app/mod.rs`，以及 app/components、app/message、app/state 和 apps/workflow 中实际引入的测试。
- 审计示例：`crates/vw-desktop/src/app/components/system_settings_providers/custom_model_modal_tests.rs` 构造 App；`crates/vw-desktop/src/app/message/tests.rs` 验证任务包装行为。
- 目标是现有 `crates/libs/desktop-*` 及其实际领域依赖；具体文件、目标及测试名由本任务核实后登记，不预设新的大测试库。
- 本任务拥有 desktop 宿主、其领域库的必要接口、父模块、dev-dependencies 和调用者接线；排除 agent、tui 内部迁移。

## 主要拆分逻辑

1. 从目标及模块树核查生产与测试归属，区分局部模型/更新/视图行为和真实跨功能装配验证，建立含资源与 cfg 的映射。
2. 对已属于小库的能力，直接迁测试和最小 fixture，移除宿主路径依赖；目标库独立引入测试，宿主删除旧引入。
3. 对只为测试局部控件却构造 App 的场景，核对生产调用者，将必要状态和消息映射收窄到已有组件接口。复用现有局部状态，不新建复制 App 的状态容器、不以泛型/trait 堆叠掩盖依赖。
4. 全局导航、跨域消息、窗口生命周期等真实宿主行为保留少量契约测试；公开接口集成目标仅在不触发禁止的应用构建且确有必要时采用，不能单纯把所有测试塞进另一个目标。
5. 同步迁移资源、快照和 fixture，保持原始断言、主题和平台语义；不按名称删“重复测试”。CI 发现范围由本任务核对并负责必要接线。

## 验证计划

行为保持不变的迁移采用前后覆盖对照，无需人为失败测试。若接口调整改变真实行为，实施前在本文件写明实际失败用例与红绿命令。各行为族确定后，先登记实际目标库、过滤条件及预期数量，再做原生定向验证。

已确认的宿主保留验证示例：

```sh
python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --lib spawn_blocking_opt_
python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --lib overlays_return_base_add_modal_and_edit_modal
```

示例过滤对应当前源码；若其被迁移，使用确认后的实际小库命令替换并保留映射，不把旧宿主零测试记为成功。第一项当前预期 3 个测试，第二项当前预期 1 个，执行前复核最新树。

- 每个迁移族验证所属小库；受接口变化影响的宿主调用路径保留定向验证。宿主目标未被有效测试编译时运行 `python3 scripts/cargo_slot.py cargo check -j 1 -p vw-desktop --lib`。
- 优先真实局部状态和消息断言；只模拟外部服务。UI 修改仍遵守统一控件、暗黑主题与字体约束，避免改变渲染；确涉字体时验证真实字形整形路径，不启动截图验收。

## 验收证据

保留原测试到目标包/测试名映射及 fixture 去向、保留宿主的逐项原因、前后主包实际测试源码规模和数量口径。每族有效测试数 > 0、failed = 0、退出码 0；迁入库独立运行不编译 vw-desktop lib-test，主包不重复引入。所有触及的生产调用者完成接线且行为保持，不能仅完成文件搬移。
