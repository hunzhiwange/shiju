# Tokio 最小复现计划

目标：将 ShiJu 桌面触发的生命周期校验缺陷整理成可独立分享的安全测试 demo，证明 Relax 修复前失败、修复后通过。

范围：在 ShiJu tools 下新增独立、仅依赖标准库的测试包和说明，复用 Relax 两个指定提交已有测试，记录三方对照证据。

范围外：不修改 ShiJu 业务代码、启动脚本、补丁和 vendor；不重新修复 Relax，不启动桌面，不处理其他兼容问题；不推送、不改写 Git 历史。

假设：本次是在 shiju 中准备小型复现材料；已有安全测试就是可复用 demo，不再抄入整个 Tokio。旧版可执行文件存在，但来源仍需核验。

## 设计决策

- 整体 ShiJu 复现依赖多；仅给补丁缺乏运行入口。选择独立 std 测试包，保留两个生命周期边界。
- 单文件便于移植，独立 Cargo 包便于普通开发者运行；采用独立包与独立测试文件，不接入主 workspace。

## 架构说明

- Link 关联类型归一化后，ShardedListItem 方法比较仍须保留 impl 头的隐含生命周期约束。
- 两个提交分别负责实现修复和测试去除 unsafe；无需再次制作相同修复。

## 开发策略

- 先复用安全测试取得失败证据，再整理测试包并重复定向验证。
- 只验证已有缺陷，不修改编译器制造红灯，不以 demo 通过推断完整桌面可用。

### Rust 专用规则

- ShiJu 中 Cargo 验证按本仓库 AGENTS.md 使用 `python3 scripts/cargo_slot.py`，其规则覆盖技能通用缓存规则；该入口已核验存在，动态领取 1–20 槽位，设置两个 Cargo 缓存路径并核验继承所有权。同阶段顺序命令复用槽位，不手工创建其它缓存池。
- 大型编译串行排队，内存紧张时 Cargo 使用 `-j 1`；等待只约束验证，不扩大任务依赖。不清缓存，不改变 profile 或工具链。
- 本任务预期复用 Relax 现有可执行文件，无需编译 Relax。任何额外构建先证明必要性并遵守其 release 构建约定，不修改当前源码来制作旧二进制。
- 运行器显式指定同一 checkout 的 RELAX_STD；三方测试不得误复用代码缓存。原生对照由独立 Cargo 测试包运行，不把 rs 文件检查当业务 crate 验收。
- 记录入口句柄、PID/进程组、槽位及两个绝对缓存路径；取消时停止并确认自有 Cargo/rustc/链接器和测试进程退出再释放自有槽位，保留缓存，不碰其他任务进程或锁。
- 失败后不无条件启动后续重型检查；旧版本预期失败作为独立取证步骤处理。记录退出码、实际测试数、失败阶段和新输出，零测试不算通过。
