# ACP 原生工具与 MCP 共存计划

目标：在原权限允许时，内置 ACP 适配器能在同一挂载会话声明并执行原生工具和 MCP 工具。

范围：按审计矩阵的 41 个注册 key 分卡。已知裁剪逐个整改，已共存逐个复验，缺证项先定位首个断点。另设验收口径和收口任务。

范围外：新增平台或传输支持、扩大工具权限、升级上游版本、发布制品。

假设：固定版本和支持平台以当前受管合约及实测为准。注册项存在并不代表当前主机可获取或运行对应制品。

## 设计决策

- 保留原生发现及审批路径，定点去掉旧验收裁剪。确需桥接时按工具所有权分派，并沿原审批通道执行。
- 从[审计矩阵](../../docs/dev/acp/mcp-policy-audit/README.md)复核基线，再用当前入口和制品取证。

## 架构说明

- 项目选择进入 session-engine 的服务投影，经 acp-client 发给适配器。受管安装与模型驱动仍验证入口及摘要。
- 保留显式会话名单、逐服务名单、拒绝优先、沙箱和撤权。对无法执行的名单或传输继续显式拒绝。

## 开发策略

- 行为变化先在现有探针或相邻测试加失败用例，使用同一命令取得修复前后证据。使用真实固定适配器和只读服务，回环模型仅负责发出确定调用并观察续轮。
- 已共存项以复验取证为主。发现适配器自身缺陷时，仅修本项能隔离的根因并补红绿证据。确认共享根因时，由最终集成任务负责共享实现和受影响项复跑，相关任务保留待回归及失败证据。
- 每项用独立临时工作区及私有配置验证无挂载、挂载、撤除后的新会话。挂载轮执行一个获准的官方只读工具及一个 MCP 工具，记录真实服务、调用 ID、成功输出和模型续轮。另验证可执行的显式拒绝、取消及支持的 load/resume。记录实际版本、入口、摘要、平台及权限模式。回环和真实模型分开标注。
- 测试只使用本地只读数据和回环服务。保留源文件和用户配置。平台制品、授权环境或凭据缺失时写明已尝试路径和可复验入口。历史、静态或替代平台证据分别记录。

## 公共执行约定

- 用已核实的 `/Users/xiangmin/.codex/skills/do-task-plans/SKILL.md` 执行。先读本计划、仓库 AGENTS.md 与编号任务。Rust 路径先用仓库 RustCodeGraph 技能导航。本文件只读。
- 从当前仓库根目录、当前分支执行，不创建 worktree。任务会话负责自身接线、验证、提交和任务卡清理。主调度只派发、等待和核对状态。
- 同批次各适配器只写独立报告及专属路径，固定制品安装使用私有缓存及临时目录。已知五项行为整改可能同时更新受管合约与摘要，按批次依次写入。其他适配器若发现必须更新公共文件，记录根因及证据，由收口任务落地并协调复跑。Git 暂存及提交串行，仅提交本任务变更。
- 常规可逆事项自行处理。遇到故障先追查根因并尝试等效验证，继续不受影响的工作。遇到关键授权或外部依赖缺失时记录证据。已有授权内运行，未获授权的真实模型调用、平台实机操作或发布留待明确授权。

## 公共验证与资源规则

- 适配器复验从本卡链接的固定版入口、现有探针和共存验收说明执行。保留对应历史验收文档，新增独立的共存回执。安装和运行所需的环境值从实际受审制品、当前会话租户和已授权回环入口取得，禁止沿用历史文档中的账号、端口、凭据或权限设置。
- 走本地网关时，每轮独立执行 `curl -fsS -N --max-time 300 -H @"$ACP_HEADERS" -H "Content-Type: application/json" --data-binary @"$ACP_REQUEST" "$ACP_GATEWAY/v1/chat/stream" > "$ACP_TRACE"`。四个变量按共存验收说明生成。直接 ACP 探针复用各适配器对应模型协议和回环模型。
- 定向测试在对应任务执行。全量测试、桌面编译、全仓格式及 lint 不作为默认验收。公共检查由收口任务执行一次，同一目标已有成功编译证据时不重复 check。
- Rust/Cargo 仅在执行阶段获明确验证授权时运行。按仓库约定用 `python3 scripts/cargo_slot.py cargo test -j 1 …`，自动领取并复用共享槽位及双缓存路径。重型编译仅在构建阶段串行。记录槽位、双路径、命令、退出码和非零有效测试数。失败或取消先结束自有进程并确认退出，再释放槽位，保留缓存。顺序命令在前一步成功后继续。

## 公共收尾规则

- 状态使用 `未开始`、`已完成`、`已阻塞`、`待回归`。获得当前验收证据并提交后删除已完成任务卡。
- 客观阻塞保留任务卡，记录失败、尝试、输入和复验命令。实现完成且仅剩无关回归，或已将共享验证失败交给明确的集成任务时，记为待回归。
- 有实际变更的已完成、已阻塞和待回归任务均先用 `$git-commit` 提交自身文件。仅任务卡状态变化或删除无需提交，不创建空提交。无权执行的检查如实记录。
