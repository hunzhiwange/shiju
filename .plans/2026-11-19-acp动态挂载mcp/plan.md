# ACP 动态挂载 MCP 计划

目标：让每个内置 ACP 用同一条 RueJS 任务验证模型能发现、调用动态挂载的 RustCodeGraph，并读回结果。

范围：按 `acp-agent-registry` 的 41 个内置注册 key 每项建一份任务。Codex 补跑复杂任务并复核基线，其余 40 个分别验证及适配。别名沿用原 key。每项保留自己的证据与限制。

范围外：聊天 HTTP API 的按请求选择字段、已连接会话热插拔、代理配置迁移、RueJS 编辑器和其他代码修改。

假设：复用已有阿里租户与模型。当前安装、配置和外部模型可用性由各任务实际核对。多步任务已有索引覆盖，Codex 的真实通过证据目前来自单次查询。

## 设计决策

沿用宿主配置解析和 ACP 建会话传参。优先原生支持，其次使用已有受管适配入口。外部限制无法安全解除时保留明确拒绝。未完成任务使用新版统一提示和指定模型，以目标 MCP 的真实执行及回传判定。

## 架构说明

宿主 `.vwacprc.json` 由 `mcp-client` 和 `session-engine::acp_defaults` 解析，经 `llm-runtime` 传给 ACP 新会话。代理须把工具交给模型并完成续轮。保留已有租户、审批、传输和凭据边界。

## 开发策略

- 先核对版本、`initialize` 能力、真实的 `session/new.params.mcpServers`、代理工具发现、模型侧工具定义、调用和结果回传，定位第一处断点。
- 原样通过时只记录证据。行为有缺口时，先用同一验收请求记录可复现失败，再在受影响边界加会失败的定向断言，做最小修复并用相同命令取得通过证据。断言覆盖动态选中、调用结果和移除后的隔离，避免只断言配置被接收。
- 先比较原生挂载、现有受管会话转换及上游升级的可行性。转换必须保留会话、租户、权限、撤销和进程生命周期。若版本或授权无法满足，记录阻塞，保留失效关闭。回环模型可定位工具声明、调用和结果，最终仍需指定真实模型。
- 新会话挂载使用请求独立的 ACP 会话。若代理支持 `load/resume` 且修改了该边界，额外验证重新入场时工具集和原有权限；不借用同一连接验证热插拔。

## 公共执行约定

- 先阅读本计划和编号文件，使用已存在的 `$do-task-plans`（`~/.codex/skills/do-task-plans/SKILL.md`）。整体计划和入口提示生成后只读。进度、阻塞和待跑命令记在对应编号文件。
- 编号是推荐顺序。批次 1 的任务互不依赖。批次 2 至 4 约束 DimCode、Dirac、Nova、siGit 对 `acp-client/src/client/protocol.rs` 中 `validate_mcp_contract` 的潜在同函数修改，前一项收尾后即可进场，前项阻塞不影响后一项的独立调查。编译排队只约束验证。
- 各任务会话负责实现、必要接线、验证、独立证据、提交和自身任务文件清理。主调度会话只派发、等待、判定及恢复。每项写自己后端的验收记录，新版验收入口见本计划。若经复现发现确需改公共文件且无预定写入顺序，先完成本项独立工作，定位实际冲突后与当前写入方依次落地；不得覆盖未提交改动。各自提交落实并核对自己负责的接线。
- 当前目录和分支执行。未经明确要求不创建或切换分支，不创建 Git worktree。不 push、改写历史、重启用户网关或变更真实租户的全局配置。Git 暂存和提交避免与其他任务并发操作同一个索引。
- 在授权内自主处理缺依赖、进程失败和小范围设计选择。先调查并尝试等效路径，局部阻塞时推进独立工作。遇到必须新增授权或原目标有关键歧义时才集中确认，保留未通过证据。
- 受管补丁修改限目标适配器及其版本/摘要键，同一共享清单按后端 hunk 提交。更新补丁后验证仓库所安装的是当前受审入口。禁止全局安装用户 MCP、扩大权限、向 ACP 或 MCP 子进程传入上游真实凭据、伪造登录或更换真实验收模型。

## 统一验收合同

2026-11-19 起，所有尚保留编号任务文件的后端按本节复验。编号文件中的历史结果保留当时的判据与结论。历史记录里的“零额外工具”“精确标记”“零工具失败”及原提示哈希不作为后续验收前置条件。

- 优先使用原版 ACP 的会话级 MCP。官方内置工具可按现有权限正常声明和执行。禁止为通过验收新增 MCP-only 补丁、全会话工具白名单或禁用内置工具。服务级显式名单、审批、沙箱、宿主拒绝和会话隔离继续生效。确有 MCP 转发、执行或结果回传缺口时，只修复已证实的缺口。
- 无挂载、挂载、撤除各开一个新会话，三轮使用下方同一提示和指定模型。前后对照核对本次服务没有注册、没有成功执行且没有返回结果。若模型提及服务、尝试调用未挂载工具而被正常拒绝、使用官方工具或附加说明，记录为诊断。无需固定答复字串。若无法观测工具目录，核对实发会话配置及服务侧启动、连接或分派证据，不能仅依据模型自述判断。
- 挂载轮要求来自 `ruejs_graph_probe` 的 `rustcodegraph_query`、`rustcodegraph_callers`、`rustcodegraph_node` 各至少实际成功一次。记录服务身份、调用和完成、原始 MCP 结果以及回传模型的证据，答复须能对应真实结果。官方工具和其他按策略授权的工具调用不构成失败。已恢复的参数错误或按原权限拒绝的辅助工具调用如实记录。目标调用未成功、结果未回传、未授权执行、撤除泄漏或会话未正常完成，仍不通过。
- 优先使用真实 RustCodeGraph 的 stdio 入口。原生只支持远程传输时，用能保留审批及会话边界的兼容入口转发到同一真实服务。记录传输、版本、提交或构建摘要、新会话 ID、HTTP 状态、SSE 终态、UI summary 的绑定及权限、ACP options 的选模结果。聊天流须有正常的 `chat.done`，无终止会话的推理、中继或协议错误。断线按原请求和游标续传。回环模型结果可以作为诊断，真实模型三轮仍须有闭环证据。
- 优先复核已有证据。若同一受验入口及实际配置的历史三轮记录已覆盖新版条件，可据证据重判。若旧记录使用仅为验收设置的 MCP-only 或全会话白名单，补验默认共存路径。实际路径、权限或证据有变化时只补缺项。旧补丁涉及正式审批、传输或隔离修复时，根据实际缺口保留相应逻辑。结果写入任务原有验收记录。

## 复用步骤

1. 在仓库根目录核对绝对路径 `/Users/xiangmin/.rustcodegraph/bin/rustcodegraph` 与 RueJS 源码 `/Users/xiangmin/worker/code/ruejs`。用 `umask 077` 和 `mktemp -d` 创建私有验收目录，把源码复制到子目录 `ruejs`，排除 `.git`、`node_modules`、`target`、`.rustcodegraph`、`.vwacprc.json`、`.vibewindow.json`、`.codex`、本地密钥与环境文件。在副本执行 `/Users/xiangmin/.rustcodegraph/bin/rustcodegraph init -i`，确认索引命中 `createRueSiteApp`。为对比同时记录 RueJS 分支、提交及实际索引的关键文件位置，源码差异导致行号变化时据实注明。
2. 用已有受审二进制启动独立网关，源码修复后按需用 `python3 scripts/cargo_slot.py cargo build -j 1 --locked -p vw-cli --bin shiju` 获取产物。网关用该 `shiju` 执行 `--config-dir "$probe_dir/config" gateway --host 127.0.0.1 --port 0`，以私有 `VIBEWINDOW_TEST_HOME="$probe_dir/home"` 隔离数据。启动日志确认实际端口，读取 `/v1/health`。只在私有实例从现有已授权凭据来源准备租户 `10001 / 100010005` 的同一提供商及模型并启用目标预设，凭据留在本机受控存储，禁止打印、提交或传给 MCP 子进程。目标模型先用 `GET /v1/config` 和选模结果核对，能力端点仅用于诊断。若私有实例无法使用授权，保留独立证据并标阻塞，已有用户实例可在预设已启用且不需变更时使用私有项目副本走同等验收。
3. 复制上文新版复用请求的完整 `curl`，使用编号文件中的 `agent` 值，把目录头、请求体 cwd 及 MCP 参数路径一起改为该副本，用实际回环端口。按三轮验收。在副本中放置文档给出的 `.vwacprc.json` 打开挂载，第三轮前移除本任务添加的条目。保留 SSE 和响应头，依据 `x-vw-session-id` 用同一租户及目录头查询 `/v1/session/{id}/ui/summary` 和 `/v1/session/{id}/acp-options`。结束确认自有服务、进程和端口清理，原 RueJS 与代理全局配置未改。
4. 检查本任务证据与差异后提交。按新版合同重判有证据的历史场景并补齐缺项。遇到影响已完成适配的公共修改，只由该修改的实施任务补跑受影响路径。

## Rust 专用验证与资源规则

- 仓库 `AGENTS.md` 优先。Rust 定向命令统一从仓库根运行 `python3 scripts/cargo_slot.py cargo …`，使用项目已有缓存和动态锁，不新增池、包装器或固定编号。脚本维护 `CARGO_TARGET_DIR`、`CARGO_BUILD_BUILD_DIR` 及锁的归属，需跨多条顺序命令或继续使用产物时由入口持有同一槽位直到结束。确认产物和子进程不再使用后释放自有锁，保留缓存。
- 同仓 Rust 重型编译串行。内存紧张用 `-j 1`，不重复重启或额外开替代重型进程。记录槽位、两个缓存路径、命令、退出码和有效测试数。测试已编译同一目标就省略 check。取消或失败先收尾自有进程组，核查 Cargo、rustc、链接器和运行产物的子进程退出，再重试。不接触其他任务的锁或进程。
- 只运行受影响包和目标、具体过滤用例。正反行为都要有证据，零测试和仅编译不算通过。禁止默认全量测试、workspace 构建、全特性 Clippy、桌面编译、全仓格式检查和 Makefile 验证。格式化只限实际改动文件，文档使用 `git diff --check` 和轻量格式或结构校验。

## 公共收尾规则

- 编号任务状态限 `未开始`、`已完成`、`已阻塞`、`待回归`。三轮证据及必要定向验证齐全才记 `已完成`，汇报证据后删除对应编号文件。真实失败或能力受限记 `已阻塞` 并保留具体原因、尝试和依赖；实现已完成但无关因素阻塞必需验证时记 `待回归`，保留当前结果和复跑命令。
- `已完成`、`已阻塞`、`待回归` 都需先通过 `$git-commit` 提交本任务的实际改动，注明验证范围和限制，排除他人和同时运行的任务。仅有编号文件状态更新或删除时不建专用或空提交。提交失败时保留编号文件并如实记录。
