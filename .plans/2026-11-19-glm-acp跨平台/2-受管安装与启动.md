# 任务 2 · 受管安装与启动

先阅读并遵守 [公共执行规则](plan.md)。

批次：1，依赖无。

状态：未开始

目的：支持六个平台冷安装、发现并执行经过摘要校验的 GLM 入口。

## 文件与步骤

- 负责 `crates/libs/acp-agent-registry/src/{managed_runtime.rs,managed_runtime_tests.rs,install.rs}` 与 `managed_runtime/install.py`，需要时补齐 `crates/libs/acp-client/src/client/process.rs` 的 GLM 启动转换和直接测试。GLM 合同的补丁摘要由任务 1 维护。
- 先用现有固定合同复现非 macOS arm64 走全局 npm 回退，Windows 无 Unix 扩展名入口和 `patch` 的问题分别实测。参考现有 Python 应用器。保留 npm 完整性、原文件、补丁文件、阶段目录和最终制品校验。仅对 GLM 放宽平台安装门禁。安装失败按原门禁报错。
- 确定受审入口到实际 Node 启动的绑定。Windows 优先使用解析出的可信 Node 与已校验的 JS 路径分参数执行，验证路径包含空格、非 ASCII 和 npm shim 时的行为。校验必须覆盖实际执行文件及固定参数，不能只信文件名或任意 `.cmd`。确认兼容 ACP stdio、进程终止和重复安装。沿用已有可用的 Python、Node/npm 发现及启动模式，避免全局安装依赖。
- 独立测试写入现有测试文件，新增过滤前缀 `glm_managed_runtime_`。覆盖成功冷装、注册表选择、入口实际可启动、摘要破坏或入口重定向被拒绝，以及失败阶段可安全重试。

## 验证

macOS/Linux 从仓库根运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p acp-agent-registry --lib glm_managed_runtime_`。Windows 使用公共槽位约定运行对应 `cargo test -j 1 -p acp-agent-registry --lib glm_managed_runtime_`。红测记录原回退或入口解析失败。绿测须从受管根启动该版本并完成 ACP 初始化，篡改无法通过。若改 ACP 进程派发，新增同前缀测试并用同入口运行 `cargo test -j 1 -p acp-client --lib glm_managed_runtime_`。
