# 第三方会话改版计划

类型为 ShiJu 原生桌面软件的会话管理页。

目标是升级「第三方智能 → 会话」的应用选择器、会话列表和阅读器，让浏览、查找、恢复和导出更顺手。

范围包括截图 1–11 覆盖的应用筛选、搜索与分组、列表菜单、记录位置、恢复与复制、阅读工具栏、对话目录和执行过程。第三方「应用」目录仍由相邻的第三方应用列表计划负责。

## 设计决策

参考本地 CC Switch 的功能布局和交互密度，使用 ShiJu 的间距、主题、图标和原生控件形成自己的视觉样式。保留现有的侧栏和授权项目/主机上下文。原生 Iced 可复用现有操作和窗口行为，WebView 方案会引入另一套 UI 与桥接，采用 Iced。

参考基线为 `/Users/xiangmin/worker/code/cc-switch` 的 `ca58c031` 及用户的 11 张截图。查阅 `src/components/sessions/` 和 `reader/` 的控件与状态。参考仓库代码为 MIT，品牌资产逐项看来源，优先用 ShiJu 已有图标。截图中的聊天内容只是样例。借鉴 design-taste-frontend 的对齐、阅读层级、真实品牌标识、可读文案和状态反馈。使用原生渲染验收。

## 架构说明

`third_party_settings.rs` 路由至 `third_party_resources::sessions`，再进入 `desktop-apps-ui` 外部会话模块。目录、阅读流、来源、恢复、导出和删除继续走现有网关能力与授权。应用计数来自授权目录快照。以身份、作用域及代次隔离异步结果。

## 公共执行约定

- 执行前阅读仓库 AGENTS.md 和对应编号任务，在当前分支和工作目录使用 `/Users/xiangmin/.codex/skills/do-task-plans/SKILL.md`。常规可逆决策自行处理并记录依据，遇阻先排查根因和合法替代路径，继续独立工作。关键歧义或新增授权集中提出。维护 `plan.md` 和 `prompt.md` 为只读参考。
- 编号任务自行完成所需接线、验证、暂存、提交和任务文件收尾。调度只负责派发、等待、判定与恢复。按编号任务声明的文件归属写入，共享 Git 索引串行操作，排除无关改动。
- 用 Iced 系统设置控件、主题与 toast，表单按 AGENTS.md 参考统一设置与自定义模型弹窗。检查悬停、焦点、选中、禁用和破坏性动作。列表与阅读区滚动条 4px、两侧预留 7px。菜单、弹窗和图片浮层关闭前拦截后层输入。中文与可能含非 ASCII 的路径使用安全字体，等宽内容与中文标签分控件。
- 继续核验完整会话身份、项目、实例、主机、授权与异步代次。命令让授权主机生成，Finder 仍需同机授权，原有删除确认和批量限制继续生效。真实日志、命令、路径、凭据及会话内容用合成数据替代后再采证。

## 公共验证与资源规则

- 本次计划只做文档检查。执行阶段有明确测试授权后再跑编号任务中的定向命令，桌面编译和实机验证按 AGENTS.md 的授权执行。行为变更先新增独立失败用例，再定向复跑，布局优先用原生画面和交互路径采证。记录退出码、测试数及未运行项目。
- 从仓库根目录调用 `python3 scripts/cargo_slot.py`。脚本管理 20 个动态独占槽位、继承复用、持有者校验与清理，两个 Cargo 缓存目录使用同一绝对槽位。高内存编译串行，只约束编译阶段。内存紧张用 `-j 1`，保留缓存，记录槽位与两条缓存路径。
- 使用前台运行句柄管理自有进程组，失败、取消或超时后先核实并收尾自有 Cargo、rustc 与链接进程，再考虑重试。公共回归只补跨任务路径，避免重复检查已编译且未受后续影响的相同目标。格式化仅限修改文件。

## 公共收尾规则

- 状态使用 `未开始`、`已完成`、`待回归`、`已阻塞`。编号文件记录失败证据和未获授权或尚未执行的检查。有当前验收证据后标为已完成并删除编号任务文件。实现完成但客观条件阻止验证时保留文件并标为待回归。排障后仍无法实施时保留文件并标为已阻塞。
- 执行编号任务有实际变更时，三种收尾状态均先用 `$git-commit` 提交任务相关变更，提交说明如实注明验证和遗留项。任务状态更新或任务文件清理自身不产生专门提交。提交失败保留任务文件和证据。
