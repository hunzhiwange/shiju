# 任务 3 · 跨应用矩阵与绑定

先阅读 [公共执行规则](plan.md)。

批次：【批次 2】依赖任务 1、2

状态：未开始

目的为交付第三方 MCP 主列表和可验证的单格、整行、整列发布。

## 文件

- 新建 `crates/libs/desktop-settings-mcp/src/management_bindings/matrix.rs` 和相邻独立测试文件。在 `management_bindings.rs` 内注册，独立验证后交给任务 7 组合。
- 修改 `crates/libs/desktop-settings-mcp/src/{management_bindings,management_bindings_update,distribution}.rs`，复用 `host_module_24_tests/bindings_controller.rs` 的用例基础。桌面调用由任务 7 接线。

## 步骤

1. 按 `UnifiedMcpPanel.tsx`、`AppMatrix.tsx` 与图 1 排列为固定搜索工具栏、名称主列、应用图标与启用数、尾部编辑和行菜单。匹配 ID、显示名及任务 2 的安全命令或地址摘要。显示过滤计数，提供初次加载、空目录、无结果和错误状态。
2. 列顺序核对参考的 Claude Code、Codex、Gemini CLI、Grok Build、OpenCode、Hermes、Pi、MiniMax Code、Kimi Code、DeepSeek Harness、Antigravity、Oh My Pi。按现有应用显示偏好过滤展示，隐藏只影响展示。结合网关能力、传输与可信安装显示可用性。多个安装必须明确选中实例或独立显示子列。没有可信实例时给出原因。
3. 为单格直接提交指定记录与目标，避免依赖全局选择。整行支持启用及关闭，整列只作用于当前筛选结果。按真实 scope、目标和接口批量上限分发。撤销只对已提交的差量基于当前修订反向提交，并提示中途冲突。
4. 用一致列宽对齐表头和数据。窄窗让矩阵独立横滚，保留整行可读与可操作。将期望值、原生写入中、完成、失败和上次观察区别呈现。重试依据原失败的目标及修订。
5. 交付窄的矩阵动作类型、可见筛选记录和可信目标投影，任务 7 映射应用图标及表单、行菜单、顶栏动作。应用目录页由同日独立计划负责。

## 验证

- 在相邻独立用例新增 `third_party_mcp_matrix_`。失败阶段先覆盖单格误用全局选择、列操作越过搜索过滤、同应用多实例串写和失败被误标为已同步。
- 失败及通过均运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p desktop-settings-mcp --lib third_party_mcp_matrix_`。使用合成目录和受控 SDK 结果，确认有效用例数和每项选中目标。
