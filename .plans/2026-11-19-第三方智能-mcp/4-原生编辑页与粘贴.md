## 步骤

1. 参考 `McpFormModal.tsx`、`formBits.tsx`、`mcpDraft.ts`。布局为返回与标题、正文滚动、固定取消与保存。正文依次放模板、粘贴、名称、表单／JSON、连接方式、目标应用、折叠说明。复用现有五个网关模板。
2. 支持 JSON 单定义、`mcpServers`、Codex TOML `mcp_servers` 和 OpenCode local/remote。复用现有深链或原生解析中的纯转换逻辑时保留来源边界。单条填入草稿，多条先列出新项、同名和无效项，再明确选择跳过或按修订更新。粘贴不触发连接、存盘或本地命令。
3. stdio 提供命令、独立参数行、环境项及工作目录。HTTP/SSE 提供地址和请求头。表单与 JSON 往返保持顺序、空格及凭据引用。无效 JSON 保留草稿并标位置。已有私有连接按现有替换语义提示，使用清空的替换表单，不预填伪造数据。
4. 说明区显示显示名、描述、标签、主页、文档与可公开的连接摘要，接任务 2 的元数据更新。编辑 ID 锁定。对真实可写目标提供双列品牌多选，解释不支持传输或未安装。新增默认全不勾选，编辑使用当前期望值。以任务 1 的可信目标来源独立构建列表。
5. 先保存定义再按返回修订分发勾选差量，明确已有启用目标的重发范围。使用现有 SDK 分发契约，逐项报告部分失败并提供失败目标重试。保存成功后保留记录引用，重试不重复创建。连接改动无有效目标时仍可单独保存。

## 验证

- 新增 `third_party_mcp_form_` 前缀测试。先覆盖 TOML/OpenCode 解析缺失与保存后目标差量未逐项结算，再补 JSON 往返、遮罩、同名冲突、传输变化及部分失败重试。
- 失败和通过均运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p desktop-settings-mcp --lib third_party_mcp_form_`。使用合成配置与现有控制器测试夹具，记录有效测试数。
