# 任务 5 · 应用导入与结果

先阅读 [公共执行规则](plan.md)。

批次：【批次 2】依赖任务 1

状态：未开始

目的为交付图 2 的应用导入、冲突反馈与来源明细。

## 文件

- 修改 `crates/libs/desktop-settings-mcp/src/{management_import,management_import_update,import}.rs` 及 `src/host_module_24_tests/import_controller.rs`。
- 修改 `crates/vw-desktop/src/app/{components/system_settings_mcp_import,message/settings/mcp_management_import}.rs`。复用 `crates/libs/agent-app-services/src/mcp/import.rs` 和网关现有原生预览、导入入口。

## 步骤

1. 顶栏「从应用导入」打开确认面板，列出当前执行主机上可用的可信应用实例。允许选择全部可导入来源或单独实例，逐个沿用现有网关预览、凭据与明确确认。维持浏览预览时只读。
2. 保持网关已有槽位语义。区分新建、已有同定义绑定、禁用来源、冲突、未读到、无配置和失败。同名有差异时保留既有目录定义并报告，避免用界面默认覆盖。不默认把项目级配置或插件自带 MCP 纳入用户级扫描。
3. 提供「导入完成」弹层，列出新增数、绑定变更数、跳过及失败。折叠的「读取了哪些文件」基于真实来源报告。仅展示既有适配器已确认的文件名或路径模式，并标明是位置说明。没有可信路径信息时只显示应用和实例，不把参考图的路径当成当前已读文件。
4. 匹配作用域和实例后汇总结果。部分失败只重试失败来源，保留先前成功。完成后刷新目录，切页后旧结果不盖住新页面。保持任务 1 迁来的 MCP 深链显式确认。

## 验证

- 新增 `third_party_mcp_import_` 前缀测试。失败阶段应发现只处理单来源或无法保留部分结果。通过阶段验证没有明确确认就无写入、合成配置中的秘密不会进入结果，以及同名冲突无覆盖。
- 失败和通过均运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p desktop-settings-mcp --lib third_party_mcp_import_`。使用受控预览及导入结果，记录实际用例数。
