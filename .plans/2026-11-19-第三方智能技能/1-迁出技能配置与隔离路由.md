# 任务 1　迁出技能配置与隔离路由

先阅读并遵守 [公共执行规则](plan.md)。

批次为 1，依赖无。状态为 `未开始`。

目的为让第三方技能通过现有独立路由访问，原生技能目录与设置继续使用各自入口。来源为用户的迁出要求。会话负责导航与弹层所有权。

## 文件

- 修改 `crates/libs/desktop-settings-skills/src/{page,third_party}.rs`，以及 `crates/vw-desktop/src/app/components/{system_settings_skills,third_party_settings,system_settings_search}.rs`。
- 修改 `crates/vw-desktop/src/app/skill_link_preview.rs` 与 `crates/vw-desktop/src/app/components/third_party_settings_integration_tests.rs`。

## 步骤

1. 从 `page::view` 移出外部仓库、Claude 配置、市场、更新、安装、导入、任务、绑定、存储、备份操作。保留原生技能目录、发现顺序、系统配置、原生帮助、创建、启停与插件入口。
2. 在 `third_party_settings::navigate` 以项目和主机初始化 Skills，取消 `apps_catalog.expanded` 作为目录入口前提。旧绑定按显式应用实例校验，页面消息携带原作用域。注册第三方专用覆盖层并保留原生技能覆盖层的独立调用。开放现有第三方 Claude 配置入口并随页面生命周期关闭。
3. 调整搜索关键词及技能链接确认的交接顺序，先进入正确路由再打开仓库预览；预览失败保持可重试，保留确认后才写入的语义。主机／项目切换、离开页面、关闭设置时清理瞬态状态，保持后台写入原作用域。给后续任务交付 `third_party::State/Message` 的页面级作用域接口。
4. 核对相关调用者与现有搜索、光栅化用例。作用域由当前 gateway context 和真实 project ID 组成，路径只作 UI 上下文校验。

## 验证

在集成测试文件新增 `third_party_skills_navigation_` 前缀用例，断言无预选应用可进入、从技能链接命中对应覆盖层、旧上下文事件被丢弃，及第三方与原生搜索各命中自己的页面。失败和通过均用 `python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --lib third_party_skills_navigation_`，以旧入口依赖选中应用或弹层路由错误为预期失败。取得非零用例且全部通过后交付批次 2。
