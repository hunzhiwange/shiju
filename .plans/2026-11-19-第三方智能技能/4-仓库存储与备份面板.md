# 任务 4　仓库、存储与备份面板

先阅读并遵守 [公共执行规则](plan.md)。

批次为 2，依赖任务 1。同批可与任务 2、3 并行。状态为 `未开始`。

目的为重做辅助面板及保留真实管理能力。来源为附图 4、6、7 和 CC Switch 的 `RepoManagerPanel.tsx`、`SkillsStorageSheet.tsx`、`SkillRestoreDialog.tsx`。本会话负责面板内部及已有消息适配。

## 文件

- 修改 `crates/libs/desktop-settings-skills/src/{repo_modal,storage_modal,backup_modal}.rs`、`src/update/{repo_modal,storage_modal}.rs` 和对应三个桌面组件适配文件 `crates/vw-desktop/src/app/components/system_settings_skills/{repo_modal,storage_modal,backup_modal}.rs`。
- 测试写入同包既有 `storage_modal_tests.rs`，新增 `repo_modal_tests.rs` 与各自父文件内测试注册。

## 步骤

1. 仓库管理使用右侧面板，支持 `owner/name` 或 GitHub URL、分支、启停、打开来源和删除确认。输入错误定位到字段。保留配置版本，按发现报告显示真实数量或读取失败，实现无计数时的明确状态。通知任务 5 在仓库写入之后刷新页面来源；确认前不写入。
2. 存储与同步弹层展示当前执行主机的真实技能根路径，区分运行时目录与通用目录，说明部分应用直接读取通用目录的影响。沿用现有位置迁移、同步模式版本化更新与立即重同步。展示已读数量与部分失败，迁移前确认，失败不把候选位置渲染成当前值。打开目录仍遵守本机和路径校验。
3. 恢复弹层区分加载、失败、没有备份和已选备份，展示名称及可读日期。恢复应用目标由当前安装实例确认，沿用已捕获作用域和版本。删除备份移到明确确认步骤。确认完成后由任务 5 刷新库存和备份状态。
4. 避免跨任务写入发现工作页和共享导航。通过现有面板入口与回读适配，向任务 5 提供面板状态和刷新时点。

## 验证

在独立用例定义 `third_party_skills_panels_` 前缀，验证新增接受的仓库输入形态、恶意或无效 URL 被拒绝、相同位置不触发迁移与错误回读保留权威位置。用 `python3 scripts/cargo_slot.py cargo test -j 1 -p desktop-settings-skills --lib third_party_skills_panels_` 取得预期失败与改后有效通过数。复核存储和备份实操继续走既有作用域和授权入口。面板布局归任务 5。
