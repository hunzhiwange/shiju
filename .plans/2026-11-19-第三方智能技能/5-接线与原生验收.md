# 任务 5　接线与原生验收

先阅读并遵守 [公共执行规则](plan.md)。

批次为 3，依赖任务 2、3、4。状态为 `未开始`。

目的为交付可从桌面入口完整操作的 Skills 页。来源为全部八张图。会话拥有最后的共享文件接线、集成修复与渲染验收。

## 文件

- 修改 `crates/vw-desktop/src/app/components/{mod,third_party_settings,third_party_settings_integration_tests,system_settings_skills}.rs`，以及 `crates/vw-desktop/src/app/message/settings/skills.rs` 中与第三方任务完成和覆盖层相关的接线。
- 如需移除被替代的市场弹层，仅清理已经无调用者的适配模块。保留原生技能与插件模块边界。

## 步骤

1. 注册页面桥接模块，组装工作页、添加菜单、更多菜单、仓库面板及弹层。更多菜单提供仓库、存储与同步、备份、更新或任务、Claude 配置入口。发现页「安装到」位于工具栏，恢复复用同作用域的目标选择并在提交前可见。收起或离开时清理弹层和临时选择。
2. 结合同一作用域的安装、导入、绑定、更新、卸载、仓库修改和恢复终态刷新相关数据。加测迟到回包无权改变新页面，部分成功不重复提交。使用隔离项目、临时执行目录与受控仓库夹具，禁止操作个人技能目录。
3. 在既有 tiny-skia 光栅化测试方式上扩展新页面和弹层，实际加载 CJK 字体。截图覆盖明暗主题、1280×900 和 800×720，检查固定工具栏、标题和脚注、弹窗居中或仓库靠右、焦点、滚动及鼠标事件不透传。验收需要原生交互时使用已授权桌面客户端及隔离网关环境，记录实测、截图和未覆盖项。
4. 回归原生技能配置、插件入口和技能链接跳转。对照八图核对真实空态、失败提示、来源和应用列表，使用 ShiJu 样式检查，不要求 Web 像素复刻。

## 验证

在集成测试文件先加 `third_party_skills_acceptance_` 用例，至少覆盖添加菜单三个分支、安装终态后的权威刷新、失效响应以及覆盖层阻止底层按钮触发。改前预期菜单和状态更新连接缺失。失败和通过均运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --lib third_party_skills_acceptance_`，确认有效测试数及零失败。对已完成且后续相关代码发生变化的旧用例，用 `python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --lib third_party_task_08_` 补导航与渲染回归。原生验收报告覆盖八图，明确 ZIP 使用预授权来源、真实网关批准的应用及未实测路径。
