# 第三方智能技能改版计划

类型为 ShiJu Iced 原生桌面工作页。

目标是将第三方技能管理集中到「第三方智能 → Skills」，完善已安装、发现、导入和多应用分发流程。

范围包括八张附图中的帮助、空态、已安装表、发现与来源筛选、仓库管理、应用选择、存储与同步、备份恢复，以及「添加 Skill」菜单。迁出原生技能配置中的第三方入口，并保留第三方更新、卸载、任务和 Claude 配置。

范围外包括独立的「应用」目录和「提示词」改版、自动执行技能、跨主机汇总、客户端任意路径授权与安装数据迁移。

假设使用点击进入 Skills 时的当前执行主机与项目，页面无需侧栏预选应用。应用选择以当前主机目录、网关能力及真实安装实例为准。ZIP 采用现有预授权文件标识，远端能力按现有网关反馈呈现。具体限制见任务 3。

## 设计决策

- 原页面继续叠加按钮的改动小，但跨应用流程仍割裂。移植 Web 页面需要第二套 UI。选择改造现有 Skills 路由，沿用 ShiJu Iced 组件。
- 本地 `cc-switch` 提交 `ca58c031` 的 `src/components/skills/` 和八张截图提供布局密度、控件层级与交互顺序。使用 ShiJu 的主题、文案与组件实现。

## 架构说明

- `ThirdPartyPage::Skills` 承载页面和弹层。复用 `desktop-settings-skills` 领域 reducer、网关 SDK 与执行主机安装记录。Iced 负责展示与操作编排；原生技能配置仍由自身目录和设置驱动。
- 捕获网关、租户、项目、主机、导航代次和请求代次。允许后台任务完成，旧响应不得修改新上下文的展示。应用目标按安装实例校验。

## 公共执行约定

- 每个任务先读本计划与自身编号文件，并使用 `/Users/xiangmin/.codex/skills/do-task-plans/SKILL.md`。本计划与入口提示生成后只读。编号任务负责实现、共享接线、验证、提交和自身任务文件清理。调度会话仅派发、等待、判定和恢复。
- 当前工作目录及分支内执行，保留既有差异。若「第三方应用列表」或「第三方智能提示词」也在实施，共用的 `third_party_settings.rs` 与集成测试按实际修改段落交接，保留彼此路由。两套其它计划均不构成前置依赖。
- 常规可逆选择自主处理，记录影响后续执行的假设。先查根因再在已授权范围内修复；仍受阻时继续独立部分。仅在关键歧义或确需新授权时询问。保护令牌、原始路径与网关权限，不加旁路。
- 使用原生工作页的设计原则落实固定工具栏、等宽边距、清晰列表、真实应用标识、必要提示与明确操作反馈。采用 ShiJu 明暗色、原生按钮和焦点反馈。网页英雄区、着色器和浏览器检查器没有适用的 Iced 运行面。
- 表单参考 `system_settings_common/` 和 `system_settings_providers/custom_model_modal.rs`。使用统一输入、多选和弹层控件，4px 滚动条、两侧各 7px 留白，固定标题及页脚。遮罩阻止向底层透传，中文走已加载的 CJK 字体。应用图标复用 `desktop_settings_apps::system_settings_apps::list::brand_icon`，品牌名使用目录数据。

## 公共验证与资源规则

- 本轮创建计划只做静态检查。执行计划时按仓库授权运行编号中的定向命令。行为改动先写独立用例并取得预期失败，再实施并确认实际测试数。纯视觉通过原生渲染与交互验收。未授权运行的测试或客户端构建如实记入编号文件。
- Rust 验证从仓库根通过 `python3 scripts/cargo_slot.py cargo ...` 执行。仓库现有脚本统一领取并复用共享槽位，继承两条绝对缓存路径，通过槽位所有权和进程组完成清理；源码显示共享槽位范围为 1–20。编译阶段串行，单次 `-j 1`，保留缓存。取消后等待自有进程组退出和脚本释放锁，再重试。记录槽位、缓存路径、命令、退出码、有效测试数与失败数。
- 禁止默认跑全量测试、workspace 构建和全仓格式检查。已编译成功的同目标无需再 check。格式化限改动文件。最终回归只补跨任务接线及受影响的实际渲染。高内存编译排队不改变实现批次。

## 公共收尾规则

- 使用 `未开始`、`已完成`、`待回归`、`已阻塞` 四种状态，状态及验证证据仅写对应编号文件。
- 已获本任务全部验收证据后报告结果并清理对应编号文件。实现完成但受外部条件限制无法验收时保留文件并标为 `待回归`。排障后仍无法进行核心工作时标为 `已阻塞`，记录原因、已尝试路径和下一步所需条件。
- 编号任务按执行收尾约定使用 `git-commit`，仅提交本任务实际改动，暂存及提交按顺序执行。上述三种收尾状态均如实记录验证情况和未完成项。仅有编号文件状态变动或删除时无需空提交。提交失败则保留编号文件及证据。
