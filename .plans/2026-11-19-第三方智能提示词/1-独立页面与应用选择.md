# 任务 1 · 独立页面与应用选择

先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

批次为 1，依赖无。状态为未开始。来源为截图 1、2。

目的为从第三方智能侧栏和应用详情进入同一提示词工作页，提供带品牌图标和当前选择标记的应用菜单。

## 文件

- 接线 `crates/libs/desktop-ui-controls/src/settings_navigation.rs`，`crates/vw-desktop/src/app/components/third_party_settings.rs`、`third_party_resources.rs`、`system_settings_apps/details.rs`、`system_settings_apps/mod.rs` 及 `crates/vw-desktop/src/app/message/settings/apps_catalog.rs`。
- 页面桥接 `crates/vw-desktop/src/app/components/system_settings_prompts/list.rs`，复用 `crates/libs/desktop-settings-apps/src/system_settings_apps/list.rs` 的 `brand_icon`。
- 验证 `crates/vw-desktop/src/app/components/third_party_settings_integration_tests.rs`。

## 步骤

1. 将「提示词」接入 `ThirdPartyPage::ALL`、侧栏图标、独立窗口、设置搜索及 `navigate`。应用详情改为跳到提示词页并传入应用身份，移走详情展开即加载提示词的触发点，保留项目配置查询。调通正常页面路由后挂载现有 `prompts::list::view`，供任务 2 替换版式。
2. 在桌面桥接层用当前目录生成菜单，仅展示具备实际支持和授权的应用。布局为图标、名称、可用时显示条数、选中对勾。菜单有可滚动最大高度，窄窗可完整选择。当前作用域的已加载列表提供实际条数，未知行留空。列表读取可触发首次导入，从现有单应用 `Event::Open` 进入即可。
3. Claude Desktop 提供明确的 Claude Code 跳转，OpenClaw 指向工作区入口。保留 Pi 专属操作。空目录、失败、正在加载、切换项目或执行主机均有各自状态，旧响应不可恢复旧应用。写入或编辑期间依照现有状态阻止切换。
4. 在提示词页宿主接好 Pi 模板、文件和复制等现有弹层，核对 `system_settings_apps::view_overlays` 与 `prompts::list::view` 的现有职责，保证只挂载一次。

## 验证

- 在集成测试文件增加 `third_party_prompts_entry_and_scope`。先证明应用详情跳转、侧栏和当前作用域校验无法通过，再核对同入口、选中、目录无可用应用和切换后拒绝旧结果。沿用现有隔离 fixture 和子进程约定。
- 获授权后在改版前后运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --bin shi-ju third_party_prompts_entry_and_scope`。前置失败应来自缺少页面或错误作用域，完成要求有真实测试执行和零失败。实机确认窄窗菜单可滚动，关闭遮罩时底层无误触。
