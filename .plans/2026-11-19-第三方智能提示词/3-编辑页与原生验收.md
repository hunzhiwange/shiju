# 任务 3 · 编辑页与原生验收

先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

批次为 3，依赖任务 2 的列表入口和固定页面内容区。本任务最终修改此前由任务 2 持有的列表和更新文件。状态为未开始。来源为截图 4 和五种页面状态的串联。

目的为把新增和编辑改为原生页内表单，验证完整读写路径与主题渲染。

## 文件

- 修改 `crates/libs/desktop-settings-skills/src/prompts/editor.rs`、`list.rs`、`update.rs` 及确有接线变化的 `crates/vw-desktop/src/app/components/system_settings_prompts/editor.rs`。
- 补充 `crates/vw-desktop/src/app/components/third_party_settings_integration_tests.rs` 的原生渲染 fixture 与编辑回归。

## 步骤

1. 将独立提示词页内容切换为页内编辑态，固定头部和底部动作。顶部返回及标题包含当前应用，正文区使用可伸展的 Markdown 编辑器，内容区域有限时只滚动其内。名称必填、说明可选，右下显示 Unicode 字符数与 UTF-8 字节数，保留 MCode 32768 字节规则。参考 `desktop-settings-providers/src/custom_model_modal.rs` 及共享设置控件。仍为弹窗的辅助功能继续使用共享遮罩和卡片。
2. 复用 `Draft`、`Edit`、`CloseEditor`、`Save`、`Saved`；保存中锁定重复提交与离开编辑，失败保留正文及各字段，成功返回列表并刷新实际状态。编辑期间后台动作不接收点击。保留 Pi、Hermes 的特定生效提示。核对名称校验、中文计数及快照冲突反馈。
3. 在原生验收中走完进入、切换应用、创建、搜索、编辑、启用、停用、复制、导入、删除及撤销。使用临时隔离目标或现有真实 fixture，避免改动用户默认指令文件。覆盖文件缺失、无条目、有条目、远端路径和特殊应用。保存两套主题下的空态、应用列表、页面菜单、编辑、有条目菜单截图，宽度参考现有 800×720 与 1280×900 fixture。

## 验证

- 在集成测试独立文件增加 `third_party_prompts_editor_flow`，令旧界面在页内进入／返回或必填反馈断言上失败。实现后验证编辑态、中文字符和字节、错误保留与成功返回，并用 `third_party_task_08_pages_rasterize_in_both_themes` 补齐带中文的提示词加载态、列表和编辑态的实际光栅化。
- 获授权后前后运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --bin shi-ju third_party_prompts_editor_flow`，并在最终改动后运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p vw-desktop --bin shi-ju third_party_task_08_pages_rasterize_in_both_themes`。确认 fixture 子进程实际执行并零失败。原生点击验收另记录视口、主题及文件状态截图。
