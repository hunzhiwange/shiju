# 第三方智能提示词改版计划

类型为原生桌面开发工具。主要操作为添加提示词。

目标是把第三方应用提示词从详情中的纵向按钮堆叠升级为可切换应用、可搜索和可编辑的独立工作页。

范围包括应用选择、文件状态、空态、列表、操作菜单和新增／编辑表单，保留本机与远端导入、同步、撤销、跨应用复制及专属入口。

范围外包括应用安装管理页、服务端协议和存储迁移、跨主机汇总及新增应用支持。现有「第三方应用列表」计划管理安装目录，本计划管理提示词。

假设应用选择沿用当前执行主机的目录和可见性规则。当前应用优先沿用有效选择，其次选择目录里第一个可管理应用。

## 设计决策

- 参照五张截图及本地 CC Switch 的提示词交互。CC Switch 检查基线为 `ca58c031`，根目录 LICENSE 与 package.json 均声明 MIT。以原生 Iced 组件实现界面，使用识矩主题和已有品牌图标。设计技能中的网站脚手架与浏览器门禁适用于 HTML，本计划的验收覆盖 Iced 实际渲染。
- 对比在每个详情加折叠区、由详情跳转独立页、移植 Web 前端。选择独立原生页，兼顾跨应用切换、稳定视口及现有详情入口。

## 公共验证与资源规则

- 从仓库根目录执行。未获明确验证授权时做差异和路径检查，在编号文件记录测试、桌面编译和实机验收未运行的情况。获得授权后按编号任务定向运行，确认实际测试数；同一目标已由定向测试成功编译时省略重复 check。格式化只涉及修改文件；集成回归补跨任务链路。
- Rust 专用规则以仓库 `scripts/cargo_slot.py` 为入口，重型 Cargo 调用串行。该脚本动态领取 1–10 号共享槽位，通过锁核验持有 PID 并把 `CARGO_TARGET_DIR` 与 `CARGO_BUILD_BUILD_DIR` 指向同一绝对槽位目录。复用同阶段槽位，避免固定分配、自建缓存或覆盖路径。单次 Cargo 用 `-j 1`。资源排队只约束验证。
- 记录入口句柄、槽位、缓存路径、命令、退出码、实际运行数和失败数。遇到取消或超时，先收尾自有进程组及仍使用产物的子进程，确认退出后才释放锁并重试；保留缓存与他人进程。原生窗口的运行和系统授权沿用仓库文档。

## 公共收尾规则

- 状态为「未开始」「已完成」「待回归」或「已阻塞」。以当前验证证据判定完成，汇报证据后删除相应编号文件。实现完成但验收未运行或因外部原因失败时标「待回归」。排障后仍无法实施时标「已阻塞」。后两者保留编号文件，注明失败证据、尝试、所需输入及回归命令。
- 三种收尾状态下，只要存在本任务实际变更，都先用 `$git-commit` 仅提交本任务改动，并如实记录验证情况。只有编号文件状态或删除时不创建专用提交。提交失败保留文件和证据。
