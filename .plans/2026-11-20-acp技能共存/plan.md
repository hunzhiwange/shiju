# ACP 会话技能与原生技能共存计划

目标是让 Codex 之外的每个内置 ACP 在同一会话发现并按需读取 ShiJu 挂载技能和原生技能，同时可使用已授权的 MCP 与现有模型来源。

范围以 `crates/libs/acp-agent-registry/src/agent_registry.rs` 的 41 个正式注册 key 为准。每个非 Codex key 一项，共 40 项。别名沿相同后端验证。已有挂载的适配器补共存，未接通的适配器补真实接入与验收。

范围外包括 Codex 重做、用户自定义后端、技能市场及 UI 改版、发布和未要求的跨平台移植。

假设第一轮以各卡列出的当前受审发行物及可运行平台为准。历史 22 项技能清单仅供定位，旧结论需结合现行制品复验。仅已核实的模型来源和权限模式能作为完成证据。

## 设计决策

- 优先追加原生会话发现根或已审插件。只有缺少此入口才评估受管补丁。拼接正文和把技能伪装为 MCP 均无法通过验收。
- [Codex 实测](../../docs/dev/acp/ACP验收.md#codex-acp-技能与-mcp-共存)提供验收口径。各供应商沿用自己的原生加载接口、模型协议和审批路径。

## 架构说明

- `session-engine::acp_defaults::apply_agent_defaults` 解析受信选择，`SessionSkillView` 提供按租户、项目、会话绑定的目录视图。适配器扫描器或 ACP 已审扩展注册该视图。
- `session/new.mcpServers` 及受管中继保留现有权限边界。技能目录发现不授予写入、执行、联网或访问其它租户来源的权限。

## 开发策略

- 先读本卡的受管合约、MCP 回执和扫描器或启动驱动。对照同制品原生目录和网关投影，定位首个行为差异。区分旧版或被替换制品、选模失败、策略拒绝和技能发现问题。
- 行为变化先以本卡真实进程探针获取预期失败。保留无挂载基线可运行，确认挂载拒绝、原生技能消失、目录或工具缺失发生在指定断点。使用相同探针取通过证据。已有正确行为时保留基线通过，补缺失的验收和回执。
- 仅将供应商模型响应替换为回环夹具。始终运行实际网关、受审 ACP、原生技能读取和 MCP。夹具只根据实际模型请求中的目录和工具发出调用，随机正文和附件不会预置进提示或夹具响应，三个不同的返回值须通过调用 ID 出现在模型续轮。
- 基线、挂载、撤除三轮独立创建会话。三轮都要读到原生技能正文，只有挂载轮读到选中的 ShiJu 技能和试验 MCP 返回值。核对 MCP 审计计数为 0、1、0、三个独立会话 ID、每轮一个 `chat.done` 和零 `chat.error`，重读绑定的后端、模型来源和权限状态。另在挂载轮对同一只读 MCP 做一次拒绝对照，确认无下游执行。
- 使用不同私有目录布置原生技能、选中技能与非选中 ShiJu 技能。三轮同时查目录、调用结果、首次模型请求无技能正文、撤除或跨会话后不可发现旧视图。保留显式策略、沙箱和原生禁用配置。同名技能按原生受审优先级处理，若无法保证可区分则明确拒绝歧义。已有跨进程恢复能力且修改该路径时再验证保存、恢复和撤除，无热切换承诺。

## 公共执行约定

- 从仓库根在当前工作目录及当前分支执行。先读仓库 `AGENTS.md`、本计划及编号任务，使用已安装的 `$do-task-plans` 技能。代码导航优先仓库 RustCodeGraph 技能。本计划与入口提示生成后只读。
- 每个编号任务负责自身代码、接线、制品合约、测试、验收、回执、提交及清理。共享验收入口由任务 1 实现与验证。其他任务拥有自己的探针配置及回执，适配器需要修改通用接线时自行完成与验证。主调度只负责派发、等待、状态判定及恢复。
- 单适配器按 `prompt.md` 推荐顺序推进。任务 1 后，已有挂载组逐项更新共享受管安装产物校验或共享技能发布清单。缺口组逐项写入 `skill_mounts/mod.rs` 的同一能力分派，部分同时更新安装校验。批次约束共享文件的写入次序和当前工作区验证，前一适配器的功能不是后一适配器的产品依赖。共享文件上一项完成提交或保留并交代阻塞后，再接续公共修改。只暂存及提交本项差异。
- 常规可逆选择自主处理，记录实际假设。遇到已有制品、文档、命令或网络问题先排查并尝试同等的受审路径，继续独立工作。只有会改变验收目标或需要新增授权时再询问。固定入口确实没有安全原生路径时，保留能力门禁和任务卡，说明上游能力、发行制品或授权的具体阻塞。
- 保留用户配置、正式租户和已有工作区差异。验收使用新建 0700 私有目录、独立网关和签名或摘要受审制品。由探针生成项目和租户配置，不沿用历史账号、端口、令牌或完全访问选择。现有受审模式要求特定授权时只在已有授权内复验，禁止为过验收扩大权限。禁止回显原始凭据、关闭审批、发布或更换用户实际安装。
- 每个任务在 `docs/dev/acp/skill-coexistence/<key>.md` 写独立回执。记录实际版本、平台、入口摘要、模型来源、审批结果、三轮与拒绝对照的可审计结果及缺项。仅当固定制品或已发布能力发生变化才更新相应现行清单条目。历史回执保留原样。

## 公共验证与资源规则

- 任务 1 建立 `scripts/verify_acp_skill_coexistence.py` 以及 `scripts/acp_skill_coexistence/` 下的供应商探针。每卡只调用自己的 key。运行器从项目根调用 `scripts/acp_mount_integration.py` 的只读 MCP 或复用其现有 HTTP/SSE 处理器。模型探针对实际请求校验技能目录、工具协议和调用 ID，提交报告只保留脱敏证据。只有三轮及权限对照均成功、记录非零有效回合才退出 0。保留失败阶段摘要和首个断点。
- Rust 定向单测限受影响包和目标。网关编译和随后验收复用同一个槽位。无代码差异且已取得本次三轮证据时无需再编译。统一回归只补受后续共享改动影响的行为，归属修改该公共路径的编号任务，复用既有受影响探针，不机械重跑已覆盖且未受影响的项。
- 禁止默认全量测试、桌面构建、全仓 lint 和 fmt。实际授权与仓库约定优先。计划创建阶段只做静态覆盖和路径校验。

### Rust 专用规则

- 从仓库根执行仓库规定的 `python3 scripts/cargo_slot.py cargo ...`。需要同时使用新构建产物时由槽位入口执行该卡的前台顺序命令，槽内原生 Cargo 使用 `--locked -j 1`，前一步成功才运行下一步。
- 共享池范围以仓库脚本为准，当前为 `target/rust-slot-1` 至 `target/rust-slot-20`。入口原子领取 `target/rust-slot-locks/slot-N.lock`，记录真实 PID 和所有权。同阶段按入口校验继承复用，`CARGO_TARGET_DIR` 与 `CARGO_BUILD_BUILD_DIR` 指向同一绝对槽位。禁止挪用槽位、改 profile、清缓存或覆盖 target-dir。重型编译仅在验证阶段串行。
- 正常、失败或取消时通过原运行句柄停止自有进程组并确认 Cargo、rustc、链接器及槽位产物使用者退出，再由槽位入口释放锁，保留缓存。归属未知的锁或进程保持原状。长构建检查 CPU 时间及编译输出，避免重复启动。记录槽位、双路径、退出码和非零有效测试或实际会话数。已成功编译的同目标无需重复 check。

## 公共收尾规则

- 仅使用 `未开始`、`已完成`、`已阻塞`、`待回归`。状态和未完成项仅写对应编号文件。
- 符合本卡验收后记录证据，标记为 `已完成` 并按提交规则收尾，随后删除对应编号文件。
- 已穷尽受审路径仍遇核心阻塞时保留任务卡，记录实际失败、已尝试路径、未执行检查及继续所需输入。实现完成且仅受无关原因阻止回归时可记 `待回归`，保留卡及确切复验命令。历史证据、零测试和初始化成功均不能代替当前功能通过。
- `已完成`、`已阻塞` 和 `待回归` 只要有实际改动，均须使用 `$git-commit` 技能按任务提交并如实说明结果。仅任务文件状态变化或删除时不创建空提交。提交失败保留卡并记录证据。
