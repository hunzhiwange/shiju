# 任务 6 · 跨进程、桌面与部署验收

先阅读并遵守 [公共执行规则](plan.md)。

批次【批次 4】 · 依赖任务 5 及此前接线  
状态为 `未开始`。

目的为验证现有 ShiJu 聊天到真实 Rust 子进程和云端契约的接线，并取得授权实机证据。任务负责跨模块接线缺口和发布说明。

## 文件

- 新建 `crates/vw-cli/tests/employee_acp_roundtrip.rs`，为 `crates/vw-cli/Cargo.toml` 接入 `employee-acp-test-support` 测试构建能力，沿子命令所需依赖传递到客户端。
- 新建 `docs/shiju/数字员工-ACP-接入与验收.md`，按需在 `docs/shiju/ACP-对外接入.md` 增加入口链接。
- 核对 `.github/workflows/release.yml` 对 `vw-cli` 的既有发布路径。使用同一个 `shiju` 二进制交付子命令。

## 步骤

1. 从正常聊天网关路由用真实 ACP 宿主启动实际 `shiju employee-acp` 子进程。用 Cargo integration test 提供的 `CARGO_BIN_EXE_shiju` 定位二进制。对产品 HTTP 使用可控回环服务，使用 `employee-acp-test-support` 限定回环 fixture 入口，普通发布关闭该能力。以回环 fixture 截获产品协议、身份和轮次，保留真实子进程、stdio、会话持久化及停止路径。
2. 覆盖私有及共享多轮、关闭重开、同一用户的员工目标绑定、双用户共享历史隔离、撤权后的重开及取消后新一轮。加一组失败注入，例如首条有效响应丢失，要求留在既有业务会话并复用提交键。确认事件只进入员工会话产品路径，实际产品测试核对 Task 与 Attempt 新增均为零。
3. 在确认授权并取得已部署新 API、迁移和别名修复的可写测试环境后，用已有桌面客户端运行真实聊天。需要私有和共享员工 ID、共享员工的实际 QwenPaw 镜像版本、两个授权用户及一个未授权或异公司用户。两授权账号同时发自己的标记，下一轮只复述本账号的标记。各类别完成两轮和重开，取消结果、晚到回包与下一轮一并复核。
4. 文档记录用户如何从员工列表开聊、原 ShiJu 发布产物中子命令的位置、目标版本与鉴权前置。区分 ACP 最终正文、逐段正文及产品确认取消与 Worker 中止。含真实账号、凭据、消息、云端标识的原始记录留在受控临时位置，交付使用脱敏结果。

## 测试计划与验收

- 失败与通过命令均为 `python3 scripts/cargo_slot.py cargo test -j 1 -p vw-cli --features employee-acp-test-support --test employee_acp_roundtrip`。先用受控断线、错绑定或签名账号变更证明测试拒绝把错误结果算作通过，再恢复正常路径，记录前后退出码和具名测试结果。桌面发布二进制检查仅在用户明确授权后运行 `python3 scripts/cargo_slot.py cargo build -j 1 -p vw-desktop --bin shi-ju`，并以真实聊天和实际视觉结果验收。已通过定向测试按受影响项重跑。
- 必须区分隔离回环、模拟 Worker 和目标部署三类证据。若缺少可信 HTTPS 环境、网关权限、测试账号、Worker 或构建授权，完成能够独立执行的验证，将对应实机项保留为阻塞。写明可复验的桌面入口及最少外部输入。
