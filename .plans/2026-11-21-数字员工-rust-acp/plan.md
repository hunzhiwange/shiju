# 数字员工 Rust ACP 接入计划

目标是在 ShiJu 选中有权访问的数字员工后，用现有聊天窗口完成多轮、重开和停止。用户沿用 ShiJu 登录。

范围包括 Rust 本地 ACP 子命令、内置后端、账号与员工绑定、私有和共享会话，以及真实链路验收。首版使用桌面本机网关、纯文本和一条最终正文。范围外包括远程 ACP 服务、第三方客户端、派工、模型配置、附件、工具回调及旧 Go 桥接的状态迁移。

假设验收环境已部署 Agent Cloud 会话接口、数据库迁移和 Matrix 别名修复。网关对登录凭据和这些新路由的实际授权是验收前置，采用现有员工页面的用户凭据链验证。

## 设计决策

Rust 子命令 `shiju employee-acp` 随现有 CLI 发布，通过 stdio 接入现有 ACP 宿主。桌面直接接 HTTP 会增加客户端会话实现，远程 ACP 会增加部署和传输适配。采用内置 ACP。

## 架构说明

桌面员工页进入原聊天 → ShiJu 本机网关启动受控 ACP 子命令 → 可信 HTTPS 网关 → Agent Cloud。业务历史和取消状态由云端保存，ShiJu 沿用现有会话和 UI 投影。

## 依赖与共同契约

- 工作目录为 `/Users/xiangmin/worker/code/shiju`。服务端参考 [OpenAPI](../../../shiju-agent-cloud/api/openapi.yaml#L259)、[会话规范](../../../shiju-agent-cloud/openspec/specs/conversation-messaging/spec.md)和[既有桥接行为](../../../shiju-agent-cloud/control-plane/cmd/employee-acp/README.md)。服务端基础提交为 `e7fdf74` 和 `095ec8c`。旧计划的[实机证据](../../../shiju-agent-cloud/.plans/2026-11-21-员工对话-acp/4-acp-桌面联调与验收.md)作为前置参考，部署状态单独核实。
- 使用一个内置 backend key `employee-acp` 和 profile `acp-employee-acp`。首条请求沿现有聊天选项提交受限 `employee_target` 对象，包含 `employee_id` 和 `kind`（`private` 或 `shared`）。网关按已认证用户创建或检查会话绑定。后续请求取服务端绑定，重复传入目标必须一致。
- 子命令启动参数固定为 `--employee-id`、`--employee-kind`、`--state-dir` 和 `--account-scope`。账号范围值由宿主从已验证身份派生，仅供本地状态隔离。进程私有环境键 `SHIJU_EMPLOYEE_ACP_CREDENTIAL` 承载请求期凭据。配套宿主固定 Agent Cloud 来源，桥接向产品网关发送该用户支持的凭据头。产品网关负责权限和租户注入。
- ACP v1 提供 `initialize`、`session/new`、`session/load`、`session/list`、`session/prompt`、`session/cancel` 和最终正文通知。以 [ACP 会话建立](https://agentclientprotocol.com/protocol/v1/session-setup)、[会话列表](https://agentclientprotocol.com/protocol/v1/session-list)及[交互与取消](https://agentclientprotocol.com/protocol/v1/prompt-turn)为协议参考。先验证锁定 SDK 可用的能力特性。
- [网关用户作用域](../2026-11-21-网关用户作用域/plan.md)是任务 4 的外部接线条件。检查当前分支上认证后的用户作用域、会话读写及停止授权。若其实现尚待验，先完成独立代码，取得相关用户隔离证据后才接入员工凭据和会话。账号切换、登出和凭据更新须使旧进程及请求失效，并保持同一已验证身份重登录后的历史可恢复。
- 桌面现有员工页面使用登录态派生的 `X-Api-Key`，既有 Go 桥接使用用户 Bearer。任务 1 以现有桌面账号链实现受控客户端，任务 6 核对实际产品网关允许所选凭据访问新路由。若需增加网关授权或外部部署，由已授权环境提供。按可信服务边界排障。

## 开发策略

- 每个行为先写具名失败测试，再实现并复验。用真实 ACP 宿主、stdio 子进程和 HTTP 请求。隔离用例在外部云端或 Worker 边界用可控替身，实机证据单独记录。
- 任务 1 和 3 可独立实现。任务 2 接任务 1 的类型与调用，任务 4 接任务 3 的内置后端策略。任务 5 连接桌面选择与正常聊天入口，任务 6 负责跨进程、桌面和部署验收。
- 任务 4 维护网关聊天请求、绑定和身份接线。任务 5 维护桌面入口和调用方。任务 6 维护跨边界联调与发布说明。各任务直接完成所需父模块、清单和接线。若依赖变更导致 `Cargo.lock` 等共享文件需串行写入，由涉及任务依次读回并提交自身改动。
