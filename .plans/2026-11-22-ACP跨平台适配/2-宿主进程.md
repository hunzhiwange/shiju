目的：用现有 ACP 宿主保证 Linux 上能按原始参数启动、取消并收尾。

## 文件与范围

## 上下文

Linux 启动沿用现有命令解析与自有进程组语义。

## 实施

1. 对照安装、ACP 会话与终端入口，保留 argv、cwd 和环境边界。覆盖原生可执行文件、受信 npm shim、带空格/中文路径、无 Node 或命令不存在。优先直接启动受审 JS 入口。
2. 查取消或掉线后子进程、stdio 和资源清理。沿用自有进程组语义，传递独立参数，确保无关进程不受影响。
3. 为 Linux 补参数传递和进程组清理的回归测试源码。ACP 子进程集成边界由任务 49 汇总。

## GNU 宿主 stdio 隔离

提交：`461697328`。

- 任务 4 与任务 48 接口为 `acp_host_io::isolated_stdio::spawn_isolated_stdio(&Path, &[OsString]) -> io::Result<IsolatedStdio>`，仅在 GNU x86_64 和 AArch64 编译。调用者先按现有策略选定和审查绝对 ELF 路径，再一次性取 `take_stdin`、`take_stdout`、`take_stderr`。用应用协议确认就绪，用 `wait` 收集退出，用 `cancel` 结束并回收监督进程。丢弃句柄也会触发取消。Bubblewrap 设置错误体现为 stderr 及非零退出，调用者须按失败关闭。Relay 可经经过授权的 stdio 消息传递，子进程不接收 host 地址和继承环境。
- legacy Bubblewrap 包装用 PATH 找 bwrap，挂宿主 `/tmp` 且丢失原命令的 env/cwd，Landlock 现有规则没有网络隔离。新增独立策略使用系统 `/usr/bin/bwrap`、新用户/PID/网络/IPC/UTS 命名空间、只读入口副本、逐文件挂载固定 GNU 运行库、专用 tmpfs HOME/cwd 和 seccomp。子进程没有宿主项目、用户 HOME、设备目录、procfs 或宿主 socket。通过 CLOEXEC 关闭继承描述符，取消覆盖启动阶段和 PID 命名空间内自行脱离进程组的后代。无宽松回退。现有适配器和公开能力门控维持原状。[Bubblewrap 选项与生命周期实现](https://raw.githubusercontent.com/containers/bubblewrap/main/bubblewrap.c)
- 当前范围是固定原生 ELF 和 stdio，不提供脚本解释器、私有动态库、项目挂载或网络例外。需其他依赖的适配器继续沿其任务卡保留受管门控。
- 静态 Rust 语法和差异检查通过。获授权后在 GNU amd64 与 arm64 各执行 `python3 scripts/cargo_slot.py cargo test -j 1 -p acp-host-io --lib acp_platform_isolated_stdio`，预期命中 2 项且零失败，另保留上列两条定向命令。真实进程用例主动检查凭据替身、环境、临时目录、IPv4/IPv6 回环、Unix socket 及取消后的 stdout/stderr EOF。宿主需支持 Linux 5.11+ 的 `close_range(CLOSE_RANGE_CLOEXEC)`、非 setuid Bubblewrap、用户命名空间及 seccomp；Docker 本身须允许创建这些命名空间。运行能力未验证，本任务保持待回归。


## VT Code 私有 Unix relay 候选

提交：`a76413a61`。

- 供任务 48 产品接线调用的入口为 `acp_host_io::isolated_stdio::spawn_isolated_stdio_with_unix_relay(&Path, &[OsString], &Path) -> io::Result<IsolatedStdio>`。请求方负责审查固定 ELF、创建并持有专属 Unix stream listener、控制 relay 的模型/MCP 授权。socket 要求请求目录模式 `0700`、socket 模式 `0600`，且均由宿主有效用户持有。套接字使用 `O_PATH|O_NOFOLLOW` 固定，挂到 `ISOLATED_UNIX_RELAY_SOCKET`（`/run/shiju/relay.sock`）。对 patched-engine 请求使用 `ISOLATED_UNIX_RELAY_WORKSPACE`（`/tmp/work`），入口设置 VT Code 补丁所需的固定非密钥启动标记。
- 工作区是空的只读 tmpfs，私有 HOME 和临时空间与宿主继续隔离。只增加文件系统 Unix stream 连接，仍禁止 IP、监听、新 Unix socket 对、关联描述符传递及 io_uring。没有映射实时工程、用户配置、其它文件或 socket。缺失、软链、权限不合的 socket 在构建命令前拒绝。Bubblewrap 设置失败通过 stderr 和非零退出返回，调用方使用协议确认就绪。取消与原 stdio 共用监督句柄及进程回收，不提供宽松回退。[Bubblewrap 0.10 的文件描述符挂载](https://raw.githubusercontent.com/containers/bubblewrap/v0.10.0/bubblewrap.c) [Linux 对路径与抽象 Unix socket 的查找](https://raw.githubusercontent.com/torvalds/linux/master/net/unix/af_unix.c)
- 静态 Rust 语法和定向差异检查通过。获授权后在 GNU amd64 与 arm64 非 root 环境运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p acp-host-io --lib acp_platform_isolated_unix_relay`，预期命中 2 项且零失败。真实 ELF 夹具检查请求 socket HTTP 往返、其它 Unix socket 与 IP 回环不可达、描述符接收拒绝、工作区写入拒绝及取消后的管道 EOF。新增前置为非 setuid Bubblewrap 0.10+ 的 `--ro-bind-fd`，其余沿用上节。保留旧 stdio 定向命令以覆盖无 socket 路线。
