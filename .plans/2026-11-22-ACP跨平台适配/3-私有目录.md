# 任务 3 适配私有配置与模型中继隔离

先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

批次：【批次 1】 依赖：无

状态：待回归

来源任务：无

目的：让受管 ACP 在 Linux x64 和 ARM64 上拥有可验证的私有配置和状态目录。

## 文件与范围

修改 `crates/libs/llm-runtime/src/acp/model_source/{profile.rs,profile_tests.rs,gateway.rs,gateway_tests.rs}`。

## 上下文

沿用已有 Unix 私有状态目录和回环模型中继。

## 实施

1. 复用 Linux 私有目录校验，覆盖临时目录与持久历史、创建中断、不安全父目录、符号链接和复用时权限变化。验证所有者及私有权限。
2. 保留会话级模型绑定和回环鉴权。凭据不进入 argv、公共日志或用户真实配置。撤销先关闭访问，再清理自有目录。
3. 提供可由现有驱动调用的验证路径，按任务 48 的接线约定交付。平台测试源码必须断言实际权限失败关闭。

## 验证

- 先写独立回归测试，使用 `acp_platform_private_profile` 作为测试名或前缀。旧行为预期失败点为受管目录被平台门控拒绝，或不安全目录未被拒绝。
- 后续在 Linux Docker 容器内使用同一红绿命令 `python3 scripts/cargo_slot.py cargo test -j 1 -p llm-runtime --lib acp_platform_private_profile`。仅列为后续命令，本轮不执行。绿灯要求命中本任务测试且零失败。
- 本轮静态逐项检查测试断言、调用者接线及本任务差异。记录受影响目标和待运行项。

## 交付记录

- `prepare_profile` 继续通过 `AcpLaunchProfile::new_for_agent` 创建临时目录。Linux 创建前验证绝对路径上的祖先，拒绝符号链接、非受信所有者及可由其他用户写入的非 sticky 目录。根用户或当前有效用户所有的 sticky 祖先允许系统 `/tmp`。实际临时目录和历史子目录验证有效用户所有及 `0700`，配置文件验证有效用户所有及 `0600`。写入配置前重新验证目录。
- Claude 驱动继续通过 `claude_state_directory` 进入现有历史路径。半成品命名空间经校验后可继续创建会话目录，权限变化或链接替换时拒绝。普通状态根允许安全的非私有目录，承载历史的命名空间和会话目录均须私有。
- `configure_profile` 启动现有 OpenClaw `OwnedGateway` 时先检查回环地址。配置释放先撤销会话绑定并释放中继，再终止自有 Gateway，最后释放临时文件。原有会话鉴权、参数检查及产品能力门控沿用现有入口。
- 任务 48 接线输入为现有 `prepare_profile`、`configure_profile` 和 Claude 的 `claude_state_directory`。其他驱动自建 Linux 持久目录时可使用 `profile::verify_linux_directory_tree` 校验父路径，再校验其专有目录的所有者和私有权限。两个平台测试文件已由现有单元测试模块加载，无共享文件接线变更。
- 已静态核对五个 `acp_platform_private_profile` 测试、现有调用者与任务差异。旧实现的预期失败点包括接受不安全的 TMPDIR 或状态根、目录权限变化后仍发布配置、接受非回环 Gateway 地址。
- 受影响目标为 `llm-runtime --lib`。Linux GNU x64 与 ARM64 的编译和测试均未执行。后续在对应架构 Docker 容器内以非 root 用户运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p llm-runtime --lib acp_platform_private_profile`，每种架构应命中五个测试且零失败。
