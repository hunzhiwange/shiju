# 任务 38 适配 pi

先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

批次：【批次 3】 依赖：批次 1、2

状态：已阻塞

来源任务：无

目的：完成 pi 的 Linux x64 和 ARM64 的运行契约。

## 文件与范围

- 候选落点为 `crates/libs/llm-runtime/src/acp/model_source/drivers/pi.rs`、`crates/libs/llm-runtime/src/acp/skill_mounts/pi.rs`、`patches/acp-model-source/pi`。只改该 key 独占文件、受管补丁和独立测试。宿主共享注册、父模块、安装脚本和能力接线由任务 48 写入。
- 新建或复用该 key 的独立测试文件。若驱动没有独占测试入口，在 `crates/libs/llm-runtime/src/acp/acceptance_support/` 新建 `platform_pi_tests.rs`，由任务 48 负责测试模块注册。现有证据见 `docs/dev/acp/mcp-acceptance/pi.md`、`docs/dev/acp/skill-coexistence/pi.md`。

## 上下文

审计基线版本为 pi-acp 0.0.22 / Pi 0.73.1。MCP 现状｜原版保存列表，但 RPC 不注册到目录。模型来源现状｜原版有配置选模；受审适配器和引擎；通用，挂载依赖 Darwin 沙箱，Windows ACL 拒绝。原生工具现状｜原生 active tools 在普通与挂载均保留；显式外部名单拒绝优先；原生编辑/命令仍需宿主门禁。详见审计矩阵。 [MCP 策略审计](../../docs/dev/acp/mcp-policy-audit/README.md)

## 实施

先读取任务 7–9 中适用的固定制品、SDK 隔离或已有受管移植做法。选择与该适配器相匹配的路径，沿用相同的接线交付字段。

1. 梳理当前 Darwin 沙箱的每一项约束。Linux 挂载需要可验证的等价约束，缺失时保持挂载拒绝。
2. 对两个 Linux 架构核对上游制品、固定入口、安装依赖与可验证身份。优先用原生入口，其次移植该 key 的现有受管补丁或已有宿主桥。
3. 通过该适配器实际入口实现指定本机模型、原生工具和 MCP、会话外挂 MCP、两类技能及宿主审批，按公共规则处理撤销及恢复。复用已完成的宿主模块。保留普通 cli_local 路径。发现上游能力或发行物缺失时继续其它组合，记明失败点，维持拒绝。
4. 向任务 48 给出逐目标版本及制品、确切注册点、能力判定、安装参数、测试入口与未解决限制，写入本编号文件的交付记录。只读审查现有 Apple Silicon 分支，保留其已支持行为。任务 49 使用这份结果入账。

## 交付记录

- GNU x64 和 GNU ARM64 使用同一份 pi-acp 0.0.22 原包 `pi-acp/dist/index.js` 与 Pi 0.73.1 `@mariozechner/pi-coding-agent/dist/cli.js`。核对了两个上游 npm 归档的 SHA-512、入口的 SHA-256、bin 映射和无 OS/CPU 限定的清单。适配器原包仍只保存 MCP 列表，不能作为受管入口使用。源锁和补丁摘要见 [Linux 制品清单](../../patches/acp-model-source/pi/linux.json)。[适配器 npm 清单](https://registry.npmjs.org/pi-acp/0.0.22) · [引擎 npm 清单](https://registry.npmjs.org/@mariozechner%2fpi-coding-agent/0.73.1) · [固定源码与锁](https://github.com/svkozak/pi-acp/tree/8be5f22769f71d759aa48d798416c56e8be101ef)
- GNU x64 从固定源码锁选用 `@esbuild/linux-x64@0.27.2`，归档 SHA-512 与清单一致，构建用 ELF64 machine 为 62。GNU ARM64 选用 `@esbuild/linux-arm64@0.27.2`，归档 SHA-512 与清单一致，构建用 ELF64 machine 为 183。两者均只读取归档，未执行构建器。两个目标各缺受管适配器 Linux 构建输出、运行依赖锁及隔离回执，不能把原包摘要或 Darwin v4 摘要登记成 Linux 受管输出。
- Darwin v4 的 RPC 子进程使用收窄的环境和私有 HOME/TMPDIR，读系统依赖、固定入口和模块、工作区及宿主选中技能，排除工作区 `.git`、`.env`、`.vwacprc.json` 和未选中的 `.shiju/skills`。写入仅允许当前私有模型状态、会话历史和 `/dev/null`，禁止派生进程及任意执行，只允许连接所绑定的回环模型端口。保留原生 `read`，关闭自动扩展和自动技能扫描，通过固定解析器显式追加项目技能和选中技能，原生同名优先。适配器父进程与单操作 MCP runner 分离。runner 使用固定命令、无额外环境、只读工作区及独立可写 scratch，禁止网络和派生进程。宿主批准受当前调用 ID、工具和实参约束，恢复按当前 MCP 集合重建目录。现有 Darwin arm64 路径未改。
- Linux 隔离缺口在两个目标相同。现有 Bubblewrap 包装隔离整个网络命名空间，没有保留指定宿主回环模型端口的合同，且绑定宿主 `/tmp`。现有 Landlock 包装提供宽泛的工作区读写和文件执行权限。两者均没有此 RPC 所需的完整文件、进程和定向网络边界，也没有现有 Cortex runner 的 Linux 等价入口。Pi 的受管 MCP 发现有 Darwin 判定，Cortex runner 直接启动 `/usr/bin/sandbox-exec`。现有受限档只暴露原生读，Linux 尚无原生写入、编辑、命令的逐次宿主批准入口。上游也没有原生 MCP 注册和审计落点。两架构的宿主受限模式、原生与外挂工具、同会话撤除及恢复仍缺完整实现。新增 `skill_mounts/pi.rs::configure` 对 Linux 已选技能显式失败，无选择仍走既有配置，普通 `cli_local` 保留。
- 任务 48 接线点。稳定 key `pi`。目标版本目录作为 `pi-0.0.22-model-source-linux-v1` 的候选，见清单。建立隔离和固定产物后，从 `managed_runtime.rs::installed_directory`、`install`、`reviewed_agent_command` 与 `verify_reviewed_agent_executable` 接入对应目标。入口为安装树的 `node_modules/pi-acp/dist/index.js`，参数为空，引擎为同树的 `node_modules/@mariozechner/pi-coding-agent/dist/cli.js`。构建输入为 Node 22 或 24、npm、Git、目标 esbuild 可选包，按现有安装方式核对源码锁，`git apply --unidiff-zero`、`npm ci --ignore-scripts`、`npm run build`。固定运行时树及其依赖，校验源归档、引擎、产物和配套文件的目标摘要，将实测且审查后的安装相对路径及摘要填入目标的 `managed_files`。外挂 stdio runner 还需 Python 3 及有效 Linux 隔离入口。不能直接复用 Darwin runner 或把未打补丁的普通入口发布为受管能力。
- 能力接线涉及 `model_source/drivers/mod.rs::capabilities`、`request.rs::do_stream_request_acp`、`skill_mounts/mod.rs::validate` 及 `acp-client/src/client/process.rs` 的受限启动验证。继续使用 `model_source/drivers/pi.rs::configure` 的 OpenAI Chat Completions 回环模型和私有状态，在新建及恢复时核验当前权限、启用工具、有效审批和制品身份。当前子模块只允许 Darwin arm64 的 `session_model + ApproveReads` 例外，保持 Linux 能力关闭。共享校验目前仍接受 `validate("pi", true)`，任务 48 须接入目标判定并同步已有测试预期。保留当前生产 scanner 的拒绝，直至有等价生产实现和平台证据。
- 测试已挂入独占的 `skill_mounts/pi_tests.rs`，无需共享模块注册。后续在各架构执行原定命令，预期命中一个负向 scanner 测试及一个显式忽略的真实网关测试。旧源码会先尝试验证缺失的受管入口，无法得到新增的 Linux 隔离拒绝。网关测试须在审查过的 Linux 安装、受限接线和明确运行授权具备后，设置 `SHIJU_ACP_PI_GATEWAY_BIN` 及指向私有测试制品的 `VIBEWINDOW_CONFIG_DIR`，同命令追加 `-- --include-ignored`。沿正常网关验证固定版本、协议、两类技能及原生读、外挂 MCP 同 ID 续轮、拒绝和撤除阶段的零下游调用。现有探针的四阶段使用不同会话，故不构成 Linux 同会话恢复、取消或原生 MCP 证据。当前端到端红灯先停在缺少受管 Linux 摘要，再由真实网关受限能力门控阻断。
- 静态核对了上游制品和补丁摘要、Linux ELF 架构、旧路由、测试断言、Rust 格式解析、Python 语法、JSON 与定向差异。两架构均未运行 Cargo、Docker、安装、构建或网关，无红绿退出码及实际测试计数。

## 续审

- **普通 `cli_local`，GNU x64 与 ARM64 均待回归。** 两个固定 npm 包作为正常 PATH 发现的真实供应商入口。新增 `acp_platform_pi_contract_native`，从私有 npm prefix 校验两个实际入口和软件包身份，以隔离 HOME 和配置目录通过 `resolve_agent_spec("pi")` 和 `AcpClient::create_session` 建连并关闭。测试不消耗模型或账号。后续在目标容器用私有 prefix 安装固定 `pi-acp@0.0.22` 和 `@mariozechner/pi-coding-agent@0.73.1`（`npm install --global --prefix "$PI_TEST_PREFIX" --ignore-scripts --no-audit --no-fund`），设 `SHIJU_ACP_PI_NATIVE_PREFIX` 后执行 `python3 scripts/cargo_slot.py cargo test -j 1 -p llm-runtime --lib acp_platform_pi_contract_native -- --ignored`。这是对已配齐两个固定包的普通入口回归。当前产品 npm 回退只安装适配器，供应商 Pi 引擎仍须另行安装，现有回退不作为固定受管安装证据。
- **指定模型，不带外挂，GNU x64 与 ARM64。** 核对共享生产 `prepare_profile` 和 `drivers::launch_route` 后，Pi 的 Chat Completions 协议和私有选模配置可复用。独占 `drivers/pi.rs::configure` 现在要求 Linux 引擎在经验证适配器的同一安装树内，拒绝重定向和 PATH 回退。普通 CLI 及 Darwin 路径维持原选择。显式全访问组合可复用固定源补丁，但仍需任务 48 发布并核验该目标的受管入口和运行依赖，且不构成宿主逐次授权。已修正网关测试按公开选项读回断言带 provider 前缀的模型 ID。
- **受限启动、两类技能、会话 MCP、恢复和撤权，两个 GNU 目标仍阻塞。** 复查常用替代路径。OpenClaw 和 Hermes 的受限启动仍是 Darwin 路径。DeepAgents 的 Linux 客户端只消费宿主回环投影，不能提供下游进程隔离。现有 `mimo_mcp::prepare` 仍只允许 Darwin arm64，批准记录按工具名、参数和租约消费，无调用 ID。Pi 在 ACP 回调完成后执行 stdio，现有 Cortex helper 也只能用 Seatbelt。直接接入 HTTP、移植仅客户端或让原版适配器忽略 MCP 都无法兑现当前审批和恢复合同。
- **共享失败关闭接线。** 当前批次 4 的 `validate_linux_session_mcp` 和客户端新建、加载、恢复前的检查接了 `linux_native_only`，Pi 当前不在名单。原版收到会话 MCP 会保存但不注册，生产路径需要按 key 配置显式拒绝新建及恢复携带的非空挂载，不能依赖供应商忽略请求。此项由任务 48 在共享分派和客户端完成。任务 38 的 Linux 技能 scanner 拒绝以及已有限制模式门控继续有效。
- **外部输入。** 受限组合需要两目标可审查的 Linux 沙箱或隔离执行制品，RPC 仅能接专用模型端点，MCP stdio 不联网且无派生，受控工具按调用 ID 消费有效批准并跟随新建、恢复、取消或撤除的租约。原生 MCP 还需上游可审查的注册与执行前授权接口，或有相同语义并支持原生与会话来源区分的宿主实现。固定 Pi 0.73.1 的本机扩展入口只具备通用工具注册，固定适配器也未消费原生 MCP 定义。完整合同保留已阻塞。此次只检查断言、源码、清单路径、Rust 格式和定向差异，未运行 Cargo、Docker、安装或握手。
- 续审实际提交 `2a00f6db5`，仅包含 Pi 模型驱动和独占测试。任务 48 可沿本卡登记的普通与受管入口分别复核。
