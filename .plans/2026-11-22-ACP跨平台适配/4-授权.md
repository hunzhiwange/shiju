目的：在 Linux 保持原生及外挂调用的权限边界和可观察审批。

## 文件与范围

修改 `crates/libs/acp-host-io/src/permissions.rs`、`permission_prompt.rs` 及独立测试，`crates/libs/llm-runtime/src/acp/approval.rs` 与 `scripts/verify_acp_approval.py` 的共用契约。任务 48 负责适配器专属接线。

## 上下文

保留 ACP 请求审批及各供应商显式模式。上游固定权限模式不能证明实际执行经过宿主审批。

## 实施

1. 检查批准一次、拒绝、用户取消、超时、断线、撤权及重放。将批准绑定原会话、提示轮、调用 ID、来源、工具与实参。无明确批准或原生执行无法经现有策略约束时拒绝。
2. 区分官方及外挂同名工具、原生静态 MCP 与会话挂载，保留租户/项目隔离。外部调用未进入执行器作为拒绝断言。
3. 提供 Linux 文件路径与终端命令的审批样本。检查 headless 路径不会自动允许，不通过放宽权限实现共存。

宿主审批和会话接口专属红绿测试另用 `python3 scripts/cargo_slot.py cargo test -j 1 -p llm-runtime --lib acp_platform_approval_binding`。旧实现预期在来源或参数变更的重放样例失败，绿灯须命中用例且零失败。

## 实施及静态证据

- 宿主拒绝有歧义的 ACP 选项 ID 和断开的终端确认输入。一次确认只用于当前提示轮的原始 ACP 请求；活跃轮记录已请求确认的调用 ID，拒绝同 ID 的重发、换参及换来源。异步应答返回后复查原会话和提示轮，提示轮撤销后取消待处理确认。交互等待上限为 300 秒。
- 受管 MCP 在发放授权时要求显式宿主同意，消费时校验宿主目录中的工具身份、完整实参、原提示轮及原启动租约。授权消费一次且最多保留 15 秒。终端确认使用结构化的命令、参数及 cwd；环境覆盖只显示变量名。
- Linux 网关 fixture 观察 headless、全权限撤销和跨项目交互的文件、终端副作用。并行会话只允许其中一个会话以一次性批准创建终端标记；跨 ACP 会话的终端请求须失败。普通工作区文件仍走现有宿主工作区策略。
- 任务 48 接线约束：保留原生的现行门控。供应商须提供可校验的来源及目录映射；MCP 标准执行帧目前没有 ACP 调用 ID，现有 relay 按原提示轮、选定服务/工具及精确实参消费，未证明供应商能传递执行端的调用 ID。原生静态 MCP 无法用这个 relay 的授权作为执行证明。不能通过受管执行入口约束的 Linux 组合继续拒绝。
- 已通过限定路径的 `git diff --check`、修改 Rust 文件的 rustfmt 语法解析和 Python AST 解析。静态复核涵盖审批拒绝、取消、超时、旧回调、跨会话、改参、来源变化，以及执行前消费边界。旧实现的红灯由同 ID 再次进入受管授权、过期回调仍返回允许、无换行终端应答被接受和同 ID 拒绝选择被误分类触发；未执行红绿测试。
