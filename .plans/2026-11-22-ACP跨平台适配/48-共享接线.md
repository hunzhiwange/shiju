# 任务 48 接通注册、安装、能力与策略入口

先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

批次：【批次 4】 依赖：批次 2、3

状态：未开始

来源任务：无

目的：将 41 个适配器的实现接回现有产品入口。

## 文件与范围

集中写入 `crates/libs/acp-agent-registry/src/{agent_registry.rs,managed_runtime.rs,managed_runtime/install.py,managed_runtime/contracts.json}`、`crates/libs/config-acp-install/src/lib.rs`、`crates/libs/acp-client/src/client/process.rs`、`crates/libs/llm-runtime/src/acp/{request.rs,model_source/drivers/mod.rs,skill_mounts/mod.rs,acceptance_support}` 和必要的权限父模块。接线边界从各 key 编号文件取证。

## 实施

1. 按四目标接注册表、显式安装器和制品身份验证。审查固定版本与平台架构。共享表出现不同平台摘要时，扩展现有契约而不改 key。
2. 审查正常启动、恢复、重启和挂载都经过对应能力及权限检查。接通各任务新测试入口。界面和网关继续消费现有能力状态。未知目标、制品不匹配与缺少审批时保留拒绝。
3. 对未原生验证目标保持现有对外门控。将可通过后续目标验收进入的路径接至真实运行分支，测试从该分支验证，不增用户生产绕过开关。分别记录接线、验证门槛和具体阻塞。

## 验证

- 先补 `acp_platform_registry_contract` 和 `acp_platform_dispatch_contract`。旧接线会选错平台制品、漏注册或让未授权能力进入执行。
- 后续按顺序运行 `python3 scripts/cargo_slot.py cargo test -j 1 -p acp-agent-registry --lib acp_platform_registry_contract` 和 `python3 scripts/cargo_slot.py cargo test -j 1 -p llm-runtime --lib acp_platform_dispatch_contract`。每个过滤均须命中本任务测试，绿灯零失败。
- 本轮从注册入口逐 key 核对正常配置、会话和选项 API，记录缺口。
