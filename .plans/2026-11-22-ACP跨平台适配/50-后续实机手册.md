先阅读并遵守 [公共执行规则](plan.md)，再执行本任务。

目的：提供以后没有常驻实体机时可执行的验收路线。

## 文件与范围

新建 `docs/dev/acp/platform-verification.md`。只编写手册。任务 49 独占集成脚本及覆盖账本。

## 实施

1. 首轮采用 Linux x64 和原生 Windows x64 虚拟机或 GitHub 托管 runner，先验 Codex、Claude、GLM，再扩四目标和其余 key。公开仓库可查 [GitHub 托管 runner](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) 的 x64 和 ARM64 标签。按仓库访问权限、配额和目标 CPU 确认可用性。无可用托管机时采用匹配架构的自托管 VM 或云 VM。页中写明 WSL 与 Linux 容器证据覆盖范围。
2. 按已存在脚本参数和任务 48 的接线记录，给出各平台的环境准备、隔离目录、回环替身、目标 CLI 及固定适配器、后续模型和授权验收的命令。验 Windows 路径、DACL、重解析点、安装与进程清理。验 Linux 文件权限、进程组及各架构制品。
3. 用一次性私有工作区、无真实钥匙的回环任务起步。真实本地推理可在目标 VM 运行轻量模型，或使用已授权同机/私有网络的专用服务并记录部署位置。真上游账号、凭据、费用或远端执行需另授权。无凭据的 CI 不接触账号或生产网络。
4. 补后续启用步骤。对应四目标的证据通过后，按 key、架构与具体能力更新任务 48 的门控及公开支持表，再执行该目标的定向回归。
5. 分别记录运行日志、实际进程架构、模型协议与同 ID 续轮、两类技能、审批记录、拒绝零执行、撤除和进程清理。写清每类证据能支持哪个能力以及解除哪个门控。

## 验证

静态核对 runner 依据、四目标、三组优先适配器、命令参数及证据字段。目录、命令和引用应与仓库当前入口一致。此任务仅交付手册，不预约环境、不运行远端流程。
