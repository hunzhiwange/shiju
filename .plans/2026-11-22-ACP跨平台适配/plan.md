# ACP 跨平台适配计划

目标：让 41 个内置 ACP 在 Windows、Linux 使用本机模型、原生工具和外挂 MCP、原生和外挂技能，并执行宿主授权。

范围：覆盖 Windows MSVC、Linux GNU 的 x64、ARM64。以网关正常入口串起安装、发现、聊天、恢复与取消。指定模型沿用 `session_model`，必须覆盖实际本机推理端点采用的协议及工具续轮，保留 `cli_local` 原生账号和模型路径。覆盖原生工具、智能体既有 MCP、会话外挂 MCP、原生技能及外挂技能的共存、撤除和拒绝。

范围外：本轮只交付代码及测试源码。实机、远端 CI、真实模型、打包、发布另行授权。本轮不编译、不跑测试、不安装上游运行时。

假设：将“授权”理解为宿主对文件、命令和工具调用的权限申请、批准、拒绝、取消及撤销。以现有审计的 41 个小写 key 为基线。支持目标是四个 OS/架构组合，缺少合法上游制品时保持该组合阻塞。

## 设计决策

- 复用原生 ACP。缺功能时优先移植现有受管补丁，其次使用已有宿主桥。全量重写适配器难保留原生行为和权限。无法安全实现时显式阻塞该项。

## 架构说明

- 安装契约与运行入口分层。模型走私有配置、中继和选模驱动。MCP、技能和授权沿现有会话隔离、权限及撤权路径。

## 开发策略

- 行为修改先补预期在旧源码失败的定向测试，再实现。当前授权下静态走查红灯断言及接线，记录命令为未执行。只有后续获得运行授权才收集红绿结果。
- 测试通过真实生产入口和可观察副作用判断。替身只模拟外部模型协议、外部 ACP/MCP 或审批应答边界，不在替身中预置生产代码应实现的路由。
- 四目标逐项检查安装与启动、原生模型、指定本机模型、原生工具和 MCP、外挂 MCP、原生技能、外挂技能、授权。实现证据包含入口、制品来源及固定版本、测试入口和限制。普通启动可用时保留，某项能力缺失时显式反馈，禁止静默回退为默认云模型或扩大权限。
- 能力发布依赖实际实现条件、已审版本、平台制品与验证证据。无平台运行证据时在支持矩阵标为待回归，保留现有对外门控及 macOS 路径。单个平台、单个架构或单个传输的结果不外推。

## 公共执行约定

- 独立执行入口为 `$do-task-plans`。任务只读本文件及自身文件即可开始。任务会话负责自身代码、接线、证据、提交和收尾。主调度会话只派发、等待、判定及恢复。
- 在仓库根目录和当前分支工作，不切分支或建 worktree。先读现有实现、调用者和相邻测试。沿用已有模块。遵守仓库 AGENTS.md。保护既有未提交修改，暂存和提交只包含本任务。共享文件由编号任务指定负责人，避免并行改写。适配器任务以各自源码、补丁及测试为边界，共享接线按后续集成任务的写入约定处理。
- 按无人值守方式执行。常规可逆选择自行决定并记录。先定位根因、尝试可行替代并继续独立工作。有实质范围变化、无法消除的关键歧义或新增授权需求时集中询问。缺上游制品、合法源码、协议能力或安全等价实现时记录依据及影响组合。
- 保留默认拒绝及租户、项目、会话、提示和工具调用边界。不改用户真实配置、不读取或迁移真实凭据，不给外挂脚本提升权限。无审批能力、明示拒绝、审批过期和状态不安全均应失败关闭。请求撤除后旧 MCP、技能、临时凭据及审批不可复用。
- 进度、阻塞、交给后续任务的精确接线输入及未运行命令只写对应编号文件。只读保留本文件和入口文件。

## 公共验证与资源规则

- 本轮允许静态检查和定向差异检查。各任务在仓库根目录执行 `git diff --check -- <本任务路径>`；同时审查新增文件及已暂存差异，确认没有无关修改和敏感数据。测试命令仅作为后续授权后的执行入口。本轮的公共验收使用覆盖账本对照注册表，检查每个能力都有代码证据或具体阻塞。
- 若后续获准执行，单任务只跑受影响的定向测试，记录退出码、实际命中数、失败数和证据。统一回归只补跨任务集成。既有通过且未受影响的目标不重复检查，同目标测试已编译则不再 check。禁止把全量构建、测试、全特性 lint 和桌面构建加入默认流程。
- Rust 后续验证按仓库优先规则从仓库根目录使用 `python3 scripts/cargo_slot.py cargo test -j 1 ...`，复用脚本管理的共享槽位，不复制通用技能的手动槽位规则。两套 Cargo 目录指向同一绝对槽位，复用受脚本校验的持有者与锁。重型编译只在验证阶段排队。记录实际槽位、命令、退出码和测试数。前台执行，取消或超时先通过原句柄收尾自有 Cargo、rustc、链接器及使用产物的进程，核对退出后释放自有锁，保留缓存，不清理他人的锁或进程。

## 公共收尾规则

- 状态只用 `未开始`、`已完成`、`已阻塞`、`待回归`。行为实现经静态审查但测试或目标平台未运行，标记待回归。存在实质实现缺口，标记已阻塞并列出尝试、影响和所需输入。两者保留编号文件。这些状态均可向后续集成任务交付独立可用的代码，不要求集成任务假装全部能力通过。
- 具备该任务要求的当前证据才标记已完成，报告证据并删除编号文件。只涉及静态产物的任务按自身静态验收标准收尾。
- 实际执行编号任务时，有本任务代码、配置、测试或文档变更，三种收尾状态均须先使用 `$git-commit` 提交本任务变更，如实写明待验证或阻塞。排除其他任务和已有工作区修改。仅状态变化或任务文件删除不提交。失败则保留文件记录证据。
