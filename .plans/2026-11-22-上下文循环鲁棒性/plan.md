# LLM 上下文循环鲁棒性计划

**目标**　上下文超限或流中断后，ShiJu 能从已确认的模型步骤继续，保留工具执行证据，并在重启后恢复一致的模型历史。

**范围**　Gateway 有工具聊天的单步恢复与请求预算，桌面原生会话的压缩边界与检查点，原生流终止判定和摘要安装条件，以及跨边界的定向回归。

**范围外**　ACP 远端历史治理、供应商协议改造、异步压缩、全库历史迁移及跨进程工具恰好执行一次。

**假设**　以本地 Codex 源码为设计参考。使用脚本化模型和本地持久化夹具验证，无需在线模型凭据或启动桌面。外部工具已产生副作用但尚无可确认结果时终止自动恢复。

## 设计决策

- 整轮失败时停止重放可先止损，单步恢复能继续任务。使用单步恢复。
- 摘要加最新用户消息占用较少。选择摘要加有界结构化后缀，保留当前任务证据。
- 部分流内容可展示。明确完成后才执行工具或提交摘要。

## 架构说明

沿用 Gateway 工具循环、桌面会话运行器、共享预算和追加式检查点。绑定同一模型步骤的工具目录、调用身份、结果和重试状态。沿用现有租户、项目、审批及工具暴露边界。

## 开发策略

- 对行为变更先添加失败测试，再实施和运行相同过滤条件。失败验证应到达预期断言，编译失败和零测试不算证据。
- 通过真实入口验证可观察行为。只替换外部模型、外部副作用或不确定的流时序，沿用仓库夹具。
- 一个编号任务对应一个会话和一项验收行为。先建立安全边界，再接入续跑能力。各入口由各自的回归任务验证。准确顺序与写入依赖见编号文件及入口列表。

## 公共执行约定

- 任务会话负责自身实现、宿主接线、验证、暂存、提交及编号文件收尾。主调度只派发、等待、判定状态和恢复执行。
- 执行入口为 $do-task-plans。从对应编号文件开始，确认依赖已经交付。此计划和入口文件生成后只读。
- 在当前工作目录和分支完成。仅编辑任务负责的文件。共享文件的写入顺序见编号任务。Git 暂存和提交串行，由各任务自行完成。已有工作区修改按文件和差异块隔离。
- 常规、可逆、低风险决定按现有模式自主处理，记录影响后续任务的假设和依据。先排查根因，尝试已有等效路径，继续独立部分。只有核心验收歧义或新增授权无法从上下文解决时才集中询问。
- 仅在对应编号文件记录状态、具体阻塞、证据和待运行命令。保持权限范围，沿用输出脱敏，不记录完整工具载荷供排障。

## 公共验证与资源规则

- 当前计划创建只做文档检查。后续实施接受本计划时，在仓库根目录运行各任务列出的受影响目标和有效过滤条件。同一目标已通过编译则省略重复 check。
- 统一回归只验证跨任务行为，不重复未受后续修改影响的已通过测试。按仓库约定执行修改文件的局部格式检查，省略全仓格式检查、全量测试、workspace 构建、全特性 Clippy、桌面编译及 Makefile。
- Rust 验证使用仓库已有的 `python3 scripts/cargo_slot.py cargo test -j 1 …`。脚本动态领取仓库现有共享槽位 `target/rust-slot-1` 至 `target/rust-slot-20`，以原子目录锁和持有进程记录所有权，同时设置 `CARGO_TARGET_DIR` 和 `CARGO_BUILD_BUILD_DIR`。可继承经校验的自有槽位。复用缓存，保留锁由脚本管理，禁止擅自清除他人进程、锁和缓存。
- 高内存 Cargo 验证跨任务排队，独立实现仍可并行。记录命令句柄、槽位、两个缓存路径、退出码和有效测试数。取消或超时时通过原句柄停止脚本，确认自有 Cargo、rustc 和链接器均退出、脚本释放自有锁后再重试。仅在确认归属后对自有进程组有界终止。各定向命令依序运行，当前命令失败时先诊断。

## 公共收尾规则

- 状态仅用 `未开始`、`已完成`、`已阻塞`、`待回归`。
- 当前定向证据满足验收后标记 `已完成`，在最终回复中报告证据并删除对应编号任务文件。
- 排障和替代路径仍无法解阻时标记 `已阻塞`。实现完成但因无关原因缺验证时标记 `待回归`。两种状态均保留编号文件，记录所需输入、排障结果和复验命令。
- 上述三种收尾状态如有本任务实际代码、测试、配置或文档变更，先使用 $git-commit 提交本任务实际变更，如实注明验证结果及未完成项，再结束会话或清理编号文件。只暂存归属本任务的差异。仅状态更新或清理任务文件时不单独提交。提交失败则保留任务文件并记录证据。
