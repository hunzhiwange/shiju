# 2. 网关交接与执行

批次 2。依赖任务 1。遵循 [公共约定](plan.md)。

- 统一 `gateway-agent-scheduler/src/store_routes.rs` 创建与 `task-scheduler/src/task_board.rs` 移动入口的步骤进入规则。重复写入同一步骤、单纯排序或修改普通属性不得重复交接。
- 成员交接只改变负责人。智能体交接设置实际执行目标并使任务进入队列，沿用项目并发、容量、依赖和阻塞限制。用网关现有身份解析入口核验成员与智能体。
- `task-scheduler/src/lifecycle_bridge.rs`、`engine/dispatch.rs` 和 `runner/local.rs` 分离运行状态和步骤 key。执行成功、失败、回收及重试更新运行，保留当前步骤。步骤说明传入执行器。向当前运行提供受项目和步骤约束的移动动作，过期运行无法覆盖人工移动。
- 检查项目切换、创建和移动分别在哪些情况下需要触发交接。SQLite 和 PostgreSQL 对重复请求、同任务并发和在途执行采用一致行为。

验收需证明进入智能体步骤只产生一次运行，结束留在原步骤，移动到人工步骤后不派发。执行前先调整相邻的真实存储和网关测试。授权后用 `python3 scripts/cargo_slot.py cargo test -j 1 -p task-scheduler --lib local_runner` 定向验证执行，网关侧单独运行新增交接测试。

成员交接接线待确认身份来源。当前任务网关可解析项目作用域。仓库的 [网关契约](../../docs/shiju/apps/usage/contract.md) 要求用可信项目上下文证明成员权限。
