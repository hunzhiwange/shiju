# 工作流步骤交接

任务进入工作流步骤时，网关按步骤配置保留负责人、交给成员或交给智能体。成员或负责当前步骤的智能体明确更新任务状态。一次执行结束只记录执行结果。

状态库保存稳定 key、显示名称和四个进度分类。工作流保存有序步骤和进入规则。智能体步骤可保存工作说明、完成目标、退回目标。完成或退回时更新看板状态，目标步骤的进入规则随后生效。

以步骤规则作为新的工作流契约。旧语义角色及自动结果转移没有转换或回退路径。保留现有任务和运行记录，按新契约重新配置工作流。

## 架构

看板步骤与调度器运行状态分别保存。沿用网关的工作流 CRUD、任务写入口、项目调度锁和运行记录。接受交接前检查任务、项目、负责人及运行归属。持久化一步交接后再唤醒自动派发。

## 公共执行约定

- 各任务负责所属实现、完整接线和验证。遵循 AGENTS.md，保留工作区其他变更。
- 常规可逆决策自行推进。关键授权未明确时先做独立工作。局部故障按现有 API 和存储路径排查。
- 用户授权后执行定向行为验证，确认有效测试数量。Rust 调用 `python3 scripts/cargo_slot.py cargo test -j 1`，重型目标串行并复用槽位。取消时从原入口退出并清理自有进程。未授权时做差异及语法检查。仅格式化修改文件。
- 如分会话执行读取 do-task-plans。未获提交授权时保留工作区差异。各任务记录验证证据或明确标为待回归或已阻塞。
