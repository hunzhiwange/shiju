# 计划执行约定

适用于本目录下全部计划、任务卡及执行入口。按用户 2026-11-13 的要求，取消全量构建和截图验证；历史执行记录保留，仅作为历史证据。

- 不执行 workspace 全量构建，不为验收单独构建 CLI、桌面程序、安装包或新增原生验收窗口；不通过脚本、`cargo run`、`cargo test --test` 等入口间接进行上述构建。
- 不启动 GUI 来采集、保存、查看或对比验收截图，不运行专门的截图/逐帧绘制验收 harness，不新增截图工具或截图产物要求。用户提供的参考图及产品截图/屏幕采集功能需求仍保留。
- 用与本次改动相关的聚焦行为测试、状态/消息断言、必要的布局检查及差异审查验证；优先复用既有测试。纯文档任务仅做引用、命令和格式核对，不调用 Cargo。
- Rust 代码变更遵守本目录的定向验证规则及 [Rust 项目覆盖规则](references/rust.md)；不额外增加全量构建或全量测试。涉及字体的修改仍检查实际字形整形路径，可复用不采集截图的聚焦验证。
- 下级任务中遗留的全量构建、原生截图和图像验收步骤及对应完成门槛取消。以本约定及聚焦验证结果收尾，不因缺少这些产物阻塞或重复回归，也不得把未执行的步骤记为通过。
- 原有已执行命令、截图路径及结果不改写为新结果。任务编号、依赖及入口路径保持稳定。

## 2026-11-14 验证范围修正

- 开发阶段完成必要定向单元测试及受影响目标的基础检查，不把单元测试统一延后。优先复用现有测试，确认有效测试数、退出码和结果；纯文档任务不调用 Cargo。
- 取消逐任务 workspace 构建、全目标全特性 Clippy、全仓格式检查和全量测试要求。统一回归只补跨任务集成和公共检查，整仓 Clippy 合并一次，不机械重跑未受后续修改影响的已通过单元测试。
- 串行限制仅针对同仓库 Rust 重型编译，复用现有缓存；其它语言的普通定向测试不套用此限制。Rust 必要测试成本高时排队完成，不能仅因此标待回归。
- 必要定向验证通过后按原任务规则收尾；仅剩具体集成待验收项或客观外部阻塞时保留待回归和证据。历史已执行证据保持原样，不把未运行记为通过；plan.md、prompt.md 的编号、依赖与入口保持稳定。
