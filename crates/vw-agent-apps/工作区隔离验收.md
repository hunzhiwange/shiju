## 阻塞根因与最小修复

原根清单是没有 `[package]` 的虚拟 workspace，但 `members` 中有 `"."`。只追加精确 exclude 时，指定来源清单的 `locate-project --workspace` 仍退出 101，报 `current package believes it's in a workspace when it's not`。祖先目录 exclude、绝对 manifest 路径也没有解决此问题。

[Cargo 的 `WorkspaceRootConfig::is_excluded` 实现](https://rust.googlesource.com/cargo/+/58bab51ca444e109a21ae9e0f17c27e38173a660/src/cargo/core/workspace.rs#1891)使用成员路径前缀判断显式成员，最后返回 `!explicit_member && excluded`。根成员 `"."` 因而使嵌套来源路径的 exclude 无法生效。此公开实现用于解释原因；本机实际行为另由下表对照验证。

本次在用户继续诊断与最小修复授权下，仅对根 `Cargo.toml`：

- 移除虚拟 workspace 中冗余的 `members = [".", …]` 条目，保留全部实际成员。
- 在原有 `vendor/block`、`vendor/block/test_utils` 之后追加 `crates/vw-agent-apps/upstream/src-tauri` 到 `workspace.exclude`。

没有新增包、依赖、feature 或启动入口，没有改动上游清单、锁文件或任何快照字节。
