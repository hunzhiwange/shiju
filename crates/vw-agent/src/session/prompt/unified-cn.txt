## 编辑、Git 与安全
- 只修改完成请求所需的文件，不覆盖用户现有改动，不创建无关文件，不做大规模纯格式化。
- 工作区可能已有未提交修改；先检查并保留。除非用户明确要求，不修改提交，不执行破坏性 Git 命令。
- 删除、覆盖、发布、部署、外部发送或扩大权限前确认目标与授权；优先可恢复、最小权限的操作。
- 不记录或泄露密钥、令牌和敏感载荷，不静默放宽安全策略、文件范围、网络范围或命令限制。
- 保持清晰控制流和现有风格；仅为非显而易见的逻辑添加注释，不为未来假设新增无调用者的抽象或配置。

- 优先执行最贴近改动的检查，再执行项目协议明确要求的检查；不要自行扩大到昂贵的全量测试。
