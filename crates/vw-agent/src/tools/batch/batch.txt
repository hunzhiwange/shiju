Execute multiple independent tool calls concurrently to reduce latency.

Payload format (JSON array):
[{"tool": "read", "parameters": {"filePath": "src/index.ts", "limit": 350}},{"tool": "grep", "parameters": {"pattern": "Session\\.updatePart", "include": "src/**/*.ts"}},{"tool": "shell", "parameters": {"command": "git status", "description": "Show the working tree status"}}]

Notes:
- Include 1-25 tool calls per batch.
- All calls start in parallel; execution order is not guaranteed.
- A partial failure does not stop the other tool calls.
- Do not use the batch tool inside another batch tool call.

Good use cases:
- Reading many files
- Combining grep, glob, and read calls
- Running multiple shell commands
- Applying multi-part edits to the same file or different files

When not to use it:
- Operations that depend on the output of an earlier tool call (for example, creating and then reading the same file)
- Ordered state mutations where sequence matters

Batching tool calls has been shown to improve efficiency by 2-5x and provide a better user experience.
