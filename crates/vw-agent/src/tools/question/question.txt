Use this tool to ask the user multiple-choice questions during execution. This lets you:
1. Gather user preferences or requirements.
2. Clarify ambiguous instructions.
3. Obtain decisions between implementation approaches.
4. Present clearly comparable directions to the user.

Usage:
- `questions` accepts at most 4 questions, and each question accepts at most 4 `options`. Question text and option labels must each be unique within their respective scope.
- Custom answers are allowed by default. Enabling `custom` automatically provides a custom input, so do not manually add a fallback option such as "Other."
- Use `multiSelect: true` to allow multiple selections; the legacy `multiple` field remains supported.
- If you recommend a specific option, place it first and append " (Recommended)" to its label.
- When users need to compare concrete artifacts, options may include an optional `preview` field, such as a UI sketch, code snippet, or configuration example. Use previews only for single-choice questions.
- Tool results include `questions`, `answers` indexed by question text, and optional `annotations`.
- In plan mode, use this tool to clarify requirements or choose between approaches. Do not use it to ask whether to begin executing the plan; use `plan_exit` instead.
