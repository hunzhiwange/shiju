Execute shell commands in a specified working directory, with timeout controls and sandbox isolation.

Parameters:
- `command` (required): The command to execute.
- `description` (required): Describe what the command does in 5-10 words.
- `timeout` (optional): Optional positive execution deadline in milliseconds; no default deadline.
- `workdir` (optional): Working directory; prefer this parameter over `cd`.
- `approved` (optional): Set true only after actual user approval of this command; never self-authorize.

Security restrictions:
- Commands run in the working-directory sandbox.
- Only permitted paths are accessible.
- Environment variables are filtered through an allowlist.
- Dangerous commands require user confirmation.

Recommended usage:
- Use the glob/grep tools instead of `find`/`grep` commands.
- Use the file_edit tool instead of `sed`/`awk` commands.
- Use the file_read tool instead of `cat`/`head`/`tail` commands.
- Use the file_write tool instead of `echo > file` commands.

Process sessions:
- For ordinary commands, omit `yield_time_ms`. Bash waits up to 30000 ms for completion and returns as soon as the command exits. Set a shorter wait (250–30000 ms) only when intentionally returning early. The optional `timeout` sets the command's execution deadline.
- Use terminal results directly. Call `bash_wait` only when the latest result has `state=running`, including when `success=true` and output is empty. Keep the same `process_id` and pass `next_cursor` as `cursor`.
- Use `bash_cancel` only when there is a reason to stop the command, such as a user request. It terminates the process tree. Handles belong to the trusted tenant, workspace and session. No stdin or PTY is supported.
