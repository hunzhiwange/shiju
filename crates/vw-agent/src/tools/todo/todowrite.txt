Use this tool to create and manage a structured task list for the current coding session. It helps you track progress, organize complex tasks, and show the user that you are being thorough.
It also helps the user understand both the progress of individual tasks and the overall request.

## When to use this tool
Use this tool by default unless the request is an especially simple question-and-answer task. Use it proactively in these situations:

1. Complex multi-step tasks - When a task requires three or more distinct steps or operations.
2. Non-trivial, complex tasks - Tasks that require careful planning or multiple operations.
3. The user explicitly requests a to-do list - When the user directly asks you to use one.
4. The user provides multiple tasks - When the user gives you a list of things to do, either numbered or comma-separated.
5. After receiving new instructions - Immediately capture the user's requirements as to-do items. Edit the list whenever new information appears.
6. After completing a task - Mark it completed and add any new follow-up tasks.
7. When you begin a new task, mark its to-do item as in progress. Ideally, only one item should be in progress at any time. Do not start a new task before completing the current one.
8. Coding, fixing, refactoring, research followed by implementation, and other non-Q&A tasks - Write the to-do list before acting, and do not end the turn until every item is complete.

## When not to use this tool

Skip this tool only in these situations:
1. Especially simple questions or single-step information queries.
2. Tasks for which tracking provides no organizational benefit.
3. Tasks that can be completed in fewer than three trivial steps.
4. Requests that are purely conversational or informational.

Note: If you only need to answer one trivial question, do not use this tool. Once you create a to-do list, you must continue checking and updating it until every item is complete so that you do not exit accidentally.

## Task status and management

1. **Task statuses**: Use these statuses to track progress:
   - pending: The task has not started.
   - in_progress: The task is currently being worked on (limited to one at a time).
   - completed: The task completed successfully.
   - cancelled: The task is no longer needed.

## Updating existing tasks (important)

When `merge: true`, this tool merges the supplied `todos` into the current session's task list:
- It first matches and updates items by `id`.
- If the `id` is missing or cannot be matched, it attempts to match and update by `content`, allowing you to update a status by repeating the content.

Example: Mark a task as in progress or completed without knowing its id:

/todowrite {"todos":[{"content":"Implement batch tool-call output","status":"in_progress"}],"merge":true}
/todowrite {"todos":[{"content":"Implement batch tool-call output","status":"completed"}],"merge":true}

2. **Task management**:
   - Update task statuses in real time while working.
   - Mark each task completed immediately after finishing it; do not complete tasks in bulk.
   - Only one task may be `in_progress` at any time.
   - Complete the current task before starting a new one.
   - Cancel tasks that are no longer relevant.

3. **Task decomposition**:
   - Create specific, actionable items.
   - Break complex tasks into smaller, manageable steps.
   - Use clear, descriptive task names.

When in doubt, use this tool. Proactive task management demonstrates care and helps ensure that you complete every requirement successfully.
