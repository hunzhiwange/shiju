Create or update the current session's task list. Each item has an id, content, status, and priority.

Arguments and update rules:
- Always supply a `todos` array. Status must be pending, in_progress, completed, or cancelled. Priority must be low, medium, or high; new items default to pending and medium.
- Create a list with `merge:false`, short task descriptions, and distinct stable ids. This REPLACES the entire list: omitted tasks are removed. Use replacement only for initial creation or intentional replanning, preserving retained tasks and their ids.
- For later updates, use `merge:true` and send ONLY changed items and fields. Prefer an existing id plus status; omit content and priority when unchanged. Omitted tasks and fields are preserved.
- If the current id is unknown, use TodoRead to recover it. Content can also locate an item, but when supplied it is matched before id: do not send another task's content with an id.
- To add an item with merge:true, supply a new distinct id and content. An unmatched id without content does not create a task; do not invent ids for status updates.
- Use actual tool calls with JSON arguments, not slash commands or JSON printed in ordinary text. Check the result; a failed call does not update the list.

Examples (arguments to TodoWrite):
Create: {"merge":false,"todos":[{"id":"1","content":"Inspect relevant code","status":"in_progress"},{"id":"2","content":"Implement and verify fix","status":"pending"}]}
Advance: {"merge":true,"todos":[{"id":"1","status":"completed"},{"id":"2","status":"in_progress"}]}
Finish: {"merge":true,"todos":[{"id":"2","status":"completed"}]}

Keep at most one item in_progress. Mark completed only when the work and necessary verification actually succeeded. Leave blocked work unfinished and report the blocker; cancel only work that is no longer required. Never mark unfinished work completed just to end a turn.
