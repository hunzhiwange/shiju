# Relax 常驻测试与策略优化

2026-11-13，延续月亮组件实测。Relax 的实际收益来自保持测试进程常驻：修改真实控件或事件接线后直接重跑断言，省去每次编辑的完整 lib-test 代码生成。本轮已把这条路径接入仓库开发入口。

## 新入口

```sh
# 当前仓库已实测通过的语音 UI 测试：2 个测试
python3 scripts/cargo_slot.py cargo dev-test vw-desktop app::components::voice_chat::tests::voice_task_11_

# 当前仓库已实测通过的配置测试：1 个测试
python3 scripts/cargo_slot.py cargo dev-test vw-config-types config_defaults_promote_shiju_as_primary_provider
```

保持进程运行，编辑函数体后查看新的 `testverdict`：需要实际运行数大于 0、失败数为 0，并且通过数符合所选测试。故意引入错误会给出失败 verdict；继续修改后，同一会话可以恢复通过。结束阶段按 Ctrl+C 释放槽位。

入口固定为 lib 测试、默认 features、单测试线程，要求明确包名和非空过滤条件。它使用仓库固定补丁版 Relax，沿用槽位与安装完整性校验。缺参数、空过滤条件及歧义参数在准备工具前报错。

聚焦测试默认使用 Relax 已有的 `minimal` 按需编译策略，优先编译实际到达的断言路径，减少未到达调用的推测编译。显式 `MAKEPAD_RUN_AHEAD` 设置会被保留，例如 `MAKEPAD_RUN_AHEAD=balanced cargo dev-test ...`。桌面与网关运行入口沿用原策略。策略调整不改变 Rust profile、features 或原生检查要求。

## 真实行为反馈

沿用上一轮隔离副本中的生产 `local_overlay` 月亮组件和真实 Iced 布局、Tiny-Skia 像素、鼠标事件测试。成功测试覆盖三个录音阶段、两种尺寸和明暗主题，共 12 个绘制场景。本轮增加以下修改循环：

1. 球体实际尺寸从 100px 改为 96px，检查重新布局和绘制。
2. 将“结束通话”的事件从 `ChatEnd` 错接成 `ChatMute`，要求鼠标事件断言真实失败。
3. 恢复 `ChatEnd`，要求同一测试会话重新通过。

第一组 5 轮按 balanced/minimal/balanced/minimal/balanced 顺序启动；第二组 4 轮交替策略，并为每次保存前增加 CPU 采样。9 个常驻会话、27 次真实组件修改均得到预期结果：9 次错误接线都被捕获，其余修改恢复通过。每轮测试进程在三次修改期间保持不变；每个成功 verdict 的实际运行数为 1。生产工作区语音源码未被实验修改，隔离副本最终恢复原始 SHA。

时间包含保存源码到观察到 verdict，20ms 轮询；始终执行像素和按钮断言，本轮没有额外写 PNG。首次通过单列，不混入热改。所有策略对比轮次使用同一 `rust-slot-5`，进程顺序运行，保留原生依赖与 JIT 缓存。

这些数据说明真实错误可以在约 0.6 秒内反馈，也显示繁忙机器会把反馈拉长到数秒。第二组保存前 CPU 空闲率均为 0%，仅作为功能验证，不用于可靠的性能对比。第一组只记录启动前 CPU 状态，未隔离其它任务，缓存和运行顺序也会影响启动；不能据此推出 minimal 对所有测试更快，或发布稳定提速倍率。按需策略作为聚焦断言的资源取舍，仍允许显式切回 balanced。

前一轮 Cargo 几何修改观察值为 55–136 秒，也有繁忙样本；本轮没有重新构建原生测试来计算倍率。详细限制保留在[前轮报告](Cargo开发槽位与月亮组件实测.md)。后续优化首先应减少同机并行原生构建争用，而非继续盲目增加编译线程。

## 验证与边界

- 新入口脚本 10 项、槽位脚本 8 项、清理脚本 3 项，合计 21 项通过。入口缺失及进程组退出竞态均有先失败后通过记录。
- 当前仓库真实 `cargo dev-test` 默认 minimal：配置测试 `ran=1 passed=1 failed=0`；语音 UI 渲染/按钮测试 `ran=2 passed=2 failed=0`，9720 个其它测试被过滤。
- 较宽的 `voice_task_11_` 测试族首次启动在 120 秒观察期限内没有 verdict，未计为通过；示例收窄为实际通过的 UI 测试路径。首次 C 依赖准备仍可能耗时，观察期限不足不能视为业务失败或成功。
- 整仓 `cargo clippy --all-targets --all-features -- -D warnings` 本轮两次退出 0；最终一次为 54.62 秒。本轮没有修改上一轮报告中的私有函数调用问题。
- 修复了停止运行器时 macOS 进程组短暂拒绝信号的退出竞态：等待退出/回收状态消失，再继续清理；持续存在且无法发送信号的活进程组仍明确报错。9 个实验运行器及真实别名运行器均按预期停止，保留缓存并释放自有锁。
- 固定版仍输出 iced_aw 字体宏等未解析导入诊断，未屏蔽。通过 verdict 只证明指定测试路径。类型、签名、trait、宏及依赖修改后需要重新启动并做原生验证；发布、Clippy、权限及物理音频验收继续走原有流程。

[原始命令、逐轮结果、失败与通过日志及脚本归档](evidence/relax-live-tests-2026-11-13/)可供复核。两组实验都使用前一轮相同的月亮组件与测试源；测试准备、命令选择和实际运行器来自生产脚本，隔离入口只调整启动工作目录。

下一步建议：用新入口完成同一测试族的“修改→失败→修复→通过”循环，保持会话常驻；完成任务时再执行规定的原生聚焦验证、整仓 Clippy 和实机验收。
