# ACP 工具共存审计 · 原生与严格验收

静态基线为 `c0b9cefdc34dc3beac22a82ce21839722442f61a`。审计期间另核对已合入的 GLM 平台提交 `43e6cc3651b394084cb9d2adf5a327c4070a9df2`。GLM 的未提交差异单独注明。本文的实测均为仓库已有回执，运行环境为 macOS arm64。此次复核源码、补丁、安装合约及历史回执，未重新安装、启动网关、执行协议探针或运行 Cargo。下文源码路径从仓库根起算，行号按对应快照。

### 共用路径与验收口径

- 入口由 `crates/libs/acp-agent-registry/src/agent_registry.rs:162–177` 优先选择摘要验证通过的受管命令，可回退本地命令或注册表声明的启动方式。注册表和一键安装的原版路径可浮动，本报告的原版对照以合约固定版本为准。安装先走 `acp-agent-registry/src/install.rs:5–11` 的受管分支，适用平台见 `managed_runtime.rs:359–375`。npm 安装在隔离目录按固定版本执行，iFlow 额外使用锁文件，校验包身份和完整性、应用补丁、复核文件并原子发布（同目录 `managed_runtime/install.py:632–675,707–738`，`managed_runtime.rs:633–637`）。安装目录修订和可执行入口见 `managed_runtime.rs:41–67,187–250`。
- `session_model` 从当前模型目录取配置并创建会话绑定，先验证受审可执行入口，再配置私有模型中继。七个 key 均经过此校验，MCP 和名单为空也一样。未修改的上游包即使可用原生选模方式启动，也缺少合约要求的补丁后摘要。CodeBuddy、OpenCode 的能力广告只依赖平台及版本记录，运行时仍核验文件。GLM 以外六个 key 的内置受管安装和选模能力广告仅覆盖 macOS arm64。Linux、Windows 有原版回退入口，尚无这六个 key 的受管选模及挂载实测。OpenCode 的受管安装脚本另有 Darwin arm64 二进制专属检查。参见 `crates/vw-agent/src/session/llm/acp/model_source/mod.rs:38–62,74–97`、`crates/libs/llm-runtime/src/acp/model_source/mod.rs:36–52`、`model_source/drivers/mod.rs:47–109`、`crates/libs/acp-agent-registry/src/managed_runtime.rs:273–336,359–375`，以及 `crates/libs/config-acp-install/src/lib.rs:83–95`。
- 宿主先选定有效服务，再由 ACP 客户端在新建、加载、恢复请求传入 `mcpServers`。GLM 使用专门的服务元数据。其余六个 key 在这条路径没有服务工具名单扩展，故这里的宿主 `allowedTools` 和 `deniedTools` 均不能作为外部代理已执行的过滤来计。独立验收转发器、供应商原生设置和厂商审批有各自的边界。宿主固定全局拒绝及不可表达的选择性拒绝走原权限代码，不能用一次无调用来推断全部原生执行途径被限制。见 `crates/libs/session-engine/src/acp_defaults.rs:78–105,127–179`、`crates/libs/llm-runtime/src/acp/session.rs:231`、`crates/libs/acp-client/src/client/protocol.rs:252–271,369,429,488`。
- [新版共存合同](../../../../.plans/2026-11-19-acp动态挂载mcp/plan.md#统一验收合同)要求真实目标服务的三项调用及结果续轮，前后新会话查验目标服务撤除。官方工具、附带说明和已恢复的辅助读取错误可以出现。独立回环只能验证协议和目录，真实模型回执单独计。下文提到的三轮复验均指该合同的私有 RueJS 固定副本和只读 stdio，仅在另获运行授权后执行。选模、审批和权限沿用已有配置，在获准时增加一项无副作用的官方工具探针，并以服务身份、调用 ID 和续轮结果核对。同名服务测试须另核对实际命中的服务；每轮结束查验撤除和连接释放。

## glm-acp-agent

- **固定入口**。原版 `glm-acp-agent@1.17.1` 入口为 `dist/index.js`；内置原版回退为本地 `glm-acp-agent` 或固定版本 `npx`（`agent_registry.rs:391–397`）。`e7c637e2c8` 的 `glm-acp-agent-1.17.1-mcp-only.patch` 是私有验收原型。生产入口自 `13850cbec4` 嵌入同目录的 `glm-acp-agent-1.17.1-managed.patch`，用 `managed_runtime/contracts.json:26–43` 的原始和最终摘要核验。安装调用见 `managed_runtime.rs:416–419` 和 `install.py:707–709`。当前已提交 GLM 目录修订为 v2，不代表工具策略已经变更。
- **历史实测**。原版接收会话 stdio，回环三轮目标目录为 0／8／0，成功调用三项并按原 ID 取回结果，三项均未发起宿主权限回调。指定模型挂载成功 45／5／33 次，首个旧违约是额外图谱 `status`。另一轮还实际调用两次内置目录读取，最后因错误路径和 100 轮上限没有交付调查结论；原生仍有其他闭环成功轮。私有原型把无挂载变成零工具，挂载仅展示 MCP，并在执行入口拒绝强行请求的 `list_files`。它完成严格三轮，证明的只是该私有入口。见[历史回执](../mcp-acceptance/glm-acp-agent.md#真实模型三轮)第 13–44、76–119 行及[私有补丁](../../../../patches/acp-model-source/glm-acp-agent/glm-acp-agent-1.17.1-mcp-only.patch)第 1–60 行。
- **已提交策略**。宿主仅在服务有非空允许或拒绝名单时发送 `shiju.glm.toolPolicy`。客户端在有该元数据时拒绝 `DenyAll` 并要求受审入口；这个分支的触发条件是有策略元数据（`acp_defaults.rs:135–150`，`client/protocol.rs:252–271`）。受管补丁用原名或宿主工具 ID 匹配，拒绝优先，非法策略报错；先过滤发现结果，再建立模型目录与调用绑定。只要有挂载且每个服务都有非空允许名单，就触发 `mcpOnly`，连官方工具一起从目录删除、改写系统提示并在执行前拒绝目录外工具。普通无挂载、全部无名单、仅拒绝名单以及至少一个服务无允许名单的混合会话均不触发。新建、加载、分叉以当前挂载重算。MCP `isError=true` 标为失败并保留原错误文本供续轮；上游只在文本里报告的业务错误需按原结果判断。见基线 `glm-acp-agent-1.17.1-managed.patch:1–94,108–165`。
- **选模与平台**。原版的 `ACP_GLM_MODEL`、`ACP_GLM_BASE_URL` 已有 macOS arm64 历史实测。ShiJu 驱动要求工具能力、私有回环与会话状态目录，且通用受审验证在挂载判断前执行。起始基线仅 macOS arm64 受管安装；`43e6cc3651` 将 GLM 扩到 macOS、Linux、Windows。Unix 校验目录模式 0700、属主及非符号链接；Windows 校验私有 DACL，并由已定位的 Node 启动经验证的真实 JS 入口。见该提交 `model_source/drivers/glm_acp_agent.rs:7–56,64–85`、`model_source/profile.rs:55–95`、`acp-client/src/client/process.rs:255–271`。Linux、Windows 和新安装修订的完整闭环待实测。
- **改造及复验**。全目录裁剪来自旧验收，可去掉与允许名单的捆绑，同时保留服务过滤、错误状态、受审绑定、原权限及状态隔离。审计时未提交的同名受管补丁已删除 `mcpOnly` 目录、提示和执行分支，保留过滤及 `isError` 标记，并有对应合约摘要及验收文档差异。它仅是工作区静态证据。下一轮在固定原版与该改造的受管产物间，对照无名单、仅拒绝、全服务有允许名单和混合名单；单独确认拒绝优先、带策略的宿主全拒绝、同会话官方读取与 MCP 续轮，以及加载、分叉和撤除后目录。macOS、Linux、Windows 均先记录实际入口和摘要。

## qwen

- **固定入口与职责**。原版 `@qwen-code/qwen-code@0.26.7`（`cli-entry.js`，`qwen --acp --experimental-skills` 或 `npx`，别名见 `agent_registry.rs:619–625,666–667`）。受管 v1 参数入口 `qwen --acp`，`contracts.json:147–160` 与 `install.py:720–721` 绑定 [apply.py](../../../../patches/acp-model-source/qwen/apply.py) 和 [patch.json](../../../../patches/acp-model-source/qwen/patch.json)。`25d14393f6`、`eaa34f4d71` 的改动锁定原生 OpenAI 认证、选模、隔离 home/runtime、使用会话技能根。原版有原生 OpenAI 模型配置接口，宿主驱动写隔离配置并合入原生管理员的安全和工具设置（`model_source/drivers/qwen.rs:20–77,99–155`）；普通会话沿用供应商的原生选模配置。
