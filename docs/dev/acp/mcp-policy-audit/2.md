# ACP 工具共存审计 2 · 会话入口与装载

审计基线 `43e6cc3651b394084cb9d2adf5a327c4070a9df2`。本轮实测仅包括文档和引用校验。下文的真实模型、原生 ACP 回环和启动回执均为历史实测。缺少同版本配对回执的行为标为未知。共享注册表、安装器、进程和 profile 文件有其他任务的工作区改动。证据以基线行为为准，源码链接行号按审计时的工作区标注，涉及 Windows 平台的差异另注。

## 共同边界

- **入口与权限（静态）**。注册表先选已核验的受管命令，再尝试本地入口，最后使用注册默认值。七个 key 的别名归一后沿同一路径。宿主从受信配置择取 MCP 服务。该段对这七项没有原生 MCP `allowed_tools` / `denied_tools` 注入分支，不能据此宣称单服务工具名单在原生调用端生效。验收的三工具转发器实际限制服务目录和调用，作用域为该服务。显式宿主选择性拒绝在入口报错，全量拒绝设置 `DenyAll` 并在这七项的提示入口拒绝。原生权限与 ACP 回调继续生效，`full_access` 的回读也须区分 `native`、`partial`、`client_only`。[注册选择](../../../../crates/libs/acp-agent-registry/src/agent_registry.rs#L162-L178) · [别名](../../../../crates/libs/acp-agent-registry/src/agent_registry.rs#L639-L692) · [宿主选择、名单及拒绝](../../../../crates/libs/session-engine/src/acp_defaults.rs#L78-L178) · [提示拒绝](../../../../crates/libs/acp-client/src/client/prompt_loop.rs#L35-L61) · [审批回调](../../../../crates/libs/acp-client/src/client/event_client.rs#L241-L269)
- **模型配置与重载（静态）**。七项的 MCP 声明由客户端随 `new/load/resume` 交给代理，Kiro 的 resume 走 load 以携带当前权限。模型源则在 `session_model` 分支先准备请求级私有 profile，受管启动拒绝原生命令的情形在空服务和空名单下同样成立。该分支清除待重放的原生模型选项，请求结束释放连接。MCP 声明参与客户端缓存身份，配置变化会触发不兼容连接退出。各适配器的历史三轮是新会话隔离证据，不能外推同进程热重载或恢复时的实际工具表。 `cli_local` 跳过模型 profile，仍可能由注册表选中已安装补丁，挂载 Skill 也可能另行触发摘要校验。[模型分流](../../../../crates/libs/llm-runtime/src/acp/request.rs#L283-L325) · [profile 校验](../../../../crates/libs/llm-runtime/src/acp/model_source/mod.rs#L35-L52) · [连接管理](../../../../crates/libs/llm-runtime/src/acp/request.rs#L373-L425) · [缓存](../../../../crates/libs/llm-runtime/src/acp/session.rs#L115-L151) · [new](../../../../crates/libs/acp-client/src/client/protocol.rs#L363-L383) · [load](../../../../crates/libs/acp-client/src/client/protocol.rs#L421-L438) · [resume](../../../../crates/libs/acp-client/src/client/protocol.rs#L475-L497)
- **平台（静态）**。下文七项的 MCP 历史实测均为 macOS arm64。五个有安装合同的适配器（Copilot、Goose、Hermes、Kiro、Vibe）受管安装限 macOS arm64。七项在 Linux、Windows 和 Intel macOS 都不发布 `session_model` 支持。`cli_local` 可走注册原生命令，Windows 对 Kiro 另有安装路径查找。两平台尚无本组原生工具共存回执。审计工作区出现的 Windows 私有目录和安装变更针对 GLM，七项能力发布边界照旧。[安装平台](../../../../crates/libs/acp-agent-registry/src/managed_runtime.rs#L359-L373) · [能力发布与版本](../../../../crates/libs/llm-runtime/src/acp/model_source/drivers/mod.rs#L51-L156) · [Windows Kiro 查找](../../../../crates/libs/acp-agent-registry/src/agent_registry.rs#L105-L155)
- **判据**。历史的精确标记、零额外工具和复杂源码答案用于定位旧合同的失败。现行共存口径接受已获准的官方工具，按实际发现、成功执行、调用 ID 对应结果及模型续轮判断挂载。原生目录存在、模型选择调用和权限允许分别取证。[现行验收合同](../../../../.plans/2026-11-19-acp动态挂载mcp/plan.md#统一验收合同)

## vibe

- **版本和接线（静态）**。官方 Mistral Vibe 3.0.4 `vibe-acp`，原生入口将 session MCP 转为会话配置。受管 v1 加 `--session-model-config` 绑定私有模型和历史，另接管 Skill 发现。v2 从固定 Darwin wheel 冷装，安装器执行两份补丁并核七项摘要（`0069377c26`）。第二份补丁直接改本地 harness 工具 exposure 并在运行时固定 `programmatic.mode=disabled`，连带禁用子代理与后台进程。该分支无 MCP、名单或模型来源条件。因此无挂载和选中 v2 的 `cli_local` 也会受到限制。选 `session_model` 即使无 MCP 也要求 v2 校验。[注册](../../../../crates/libs/acp-agent-registry/src/agent_registry.rs#L474-L481) · [合同](../../../../crates/libs/acp-agent-registry/src/managed_runtime/contracts.json#L175-L191) · [安装](../../../../crates/libs/acp-agent-registry/src/managed_runtime/install.py#L495-L516) · [模型绑定补丁](../../../shiju/acp-model-source/evidence/vibe/mistral-vibe-3.0.4-session-binding.patch#L18-L99) · [直挂补丁](../../../shiju/acp-model-source/evidence/vibe/mistral-vibe-3.0.4-direct-mcp-experiment.patch#L13-L47)
- **断点与共存（历史实测）**。v1 已通过原生 stdio 发现并实际执行 MCP，干净组挂载成功 66 次且执行两次原生搜索。原版回环实际公布 `search_tool_functions`，显式按名停用和停用连接器仍保留它，对照过滤确实移除了 scratchpad。旧合同在无挂载就因原生搜索和额外文本偏离，挂载首个实际失败是错误路径。v2 同版红绿验证显示仅挂载轮直列 MCP，批准回传结果、拒绝返回工具失败，真实模型三轮有 60 次成功。后续默认安装冷装证实批准、拒绝和撤除，真实模型证据复用实验补丁批次。[原生共存](../mcp-acceptance/vibe.md#L7-L35) · [原版目录与负向过滤](../mcp-acceptance/vibe.md#L55-L63) · [真实结果及冷装](../mcp-acceptance/vibe.md#L65-L83)
- **判断**。直挂与关闭程序化工具解决旧验收的额外事件，原版程序化发现已经能完成调用与续轮。优先验证恢复默认程序化暴露并保留模型绑定、私有目录及原生审批。若仍需直挂，先验证 Core 是否支持同时保留程序化工具及子代理/后台进程，并检查唯一函数名冲突和撤除。显式 deny 对 Core 特殊工具的执行是否可完全约束、已存在会话 load 后是否会残留旧工具，以及 v2 官方工具剩余全表均未知。

## 最小复验

使用各节固定原版与受管版，在同一提交的私有项目用同一权限策略分别新建空挂载、带挂载与撤除会话。通过受控回环记录首轮和续轮模型工具声明，实际调用一个原生只读工具和一个目标 MCP 工具，核对工具调用 ID、服务身份、审批拒绝及返回给模型的结果。再用已有审验环境验证真实模型答复。对支持 load/resume 的适配器复用会话 ID 改变挂载，核对当前政策及撤除后目录和调用均失效。名单单独验证全会话白名单、原生 deny、单服务过滤和宿主全量拒绝，分别记录配置来源与实际执行层。Copilot 用受控鉴权 HTTP/SSE，其余优先使用历史已验证的 stdio；Vibe 比较原生搜索与直挂并记录子代理和后台能力。仅保留脱敏回执。本轮未执行运行时探针或 Cargo。
