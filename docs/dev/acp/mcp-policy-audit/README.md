## 改造与复验顺序

1. **先更新复验条件，并确认已合入的修复**。默认测试保留厂商发现及工具权限，撤去验收专用项目裁剪。GLM 先核当前 v2，按无名单、仅拒绝、每个服务有允许名单及混合名单验证服务过滤和官方工具共存。随后核对 Cursor v5、Stakpak v3 已有同轮证据对应的真实安装入口。新版通过依据为目标工具执行、同 ID 回传、模型续轮和撤除。[旧请求](../ACP验收.md#可复用的验收请求) · [现行验收](../../../../.plans/2026-11-19-acp动态挂载mcp/plan.md#统一验收合同) · [GLM](../mcp-acceptance/glm-acp-agent.md#受管接入) · [Cursor](6.md#cursor) · [Stakpak](4.md#stakpak)
2. **恢复原生已经能完成的路径**。优先撤 DimCode 的挂载目录裁剪及执行前同条件拦截，保留原生 HTTP/SSE 和宿主审批。Vibe 先恢复默认程序化模式，用原版搜索正对照，验证无挂载、挂载、显式 deny 和恢复路径。如果仍需直接声明，先证明与原生发现、后台及子代理可同时正确工作。[DimCode](3.md#dimcode) · [Vibe](2.md#vibe)
3. **缩小混合补丁的排除范围**。Amp 和 Cortex 先让已审官方读取与当前 MCP 目录在声明和执行两处一致共存，再验各自的取消、重绑及拒绝。Corust 放在其后，先完成原生工具与图谱分派、结果归属和混合调用续轮，再开放目录。扩展固定官方安全名单另需对应权限和执行证据。[Amp](6.md#amp-acp) · [Cortex](4.md#cortex-code) · [Corust](4.md#corust-agent)
4. **锁住权限和制品边界**。逐服务 allow/deny 只在已证投影路径计为生效，拒绝优先。保留用户的全会话显式名单、宿主限制，以及 DimCode/Dirac 对不可执行名单的拒绝；先验证 siGit、OpenClaw 等未证路径的实际后端目录与执行。保留活动会话与调用绑定、单次审批、取消撤权、目录信任、私有状态和凭据、工作区及进程隔离、命名冲突处理、补丁摘要和安装检查。区分官方工具声明、权限批准与实际执行，分别验证宿主全量拒绝和逐服务拒绝。[服务策略投影](../../../../crates/libs/session-engine/src/acp_defaults.rs#L127) · [挂载前校验](../../../../crates/libs/acp-client/src/client/protocol.rs#L252) · [审批回调](../../../../crates/libs/acp-client/src/client/event_client.rs#L160) · [受审安装](../../../../crates/libs/acp-agent-registry/src/managed_runtime.rs) · [分组权限证据](3.md)
5. **按首个缺证点复验**。获运行授权后用同版本、同项目副本及同权限比较原包与受管版。先验入口、传输和模型目录，随后在同一挂载会话触发一项获准的官方只读工具与真实 MCP 工具，检查实际服务、调用 ID、批准/拒绝及续轮。最后用无挂载和撤除的新会话检查目标工具消失，支持恢复的适配器再单测加载或恢复换表。回环记录用于协议判定，真实模型回执另计。优先补 GLM 跨平台实机、VTCode 发行物、CodeBuddy 冷装参数及 Poolside 普通入口。其余首个缺证点见对应行。本轮未启动代理、执行运行时探针或运行 Cargo。[共存复验口径](../../../../.plans/2026-11-19-acp工具共存审计/plan.md#共存复验口径) · [CodeBuddy](1.md#codebuddy) · [Poolside](4.md#poolside) · [VTCode](6.md#vtcode)
