# 电脑操控执行身份与方案

审计日期：2026-11-18。范围为任务 1 的当前工作区源码及已有差异；不修改业务实现。

本轮用户要求覆盖计划原验收：不运行 Cargo、编译、单元测试、实机测试或最终回归。因此以下是静态调用链证据，不是正在运行的二进制、签名、TCC 授权或桌面行为的验证结果。工作区存在其他任务改动，无法仅凭 Git 差异证明它们来自哪次聊天；下列按功能逐项审查，不认领这些差异。

## 当前执行身份：可证实与不可证实

| 环节 | 源码证据 | 结论和边界 |
| --- | --- | --- |
| 权限按钮 | [computer_control_update.rs](../../../crates/libs/desktop-settings-security/src/computer_control_update.rs) 的 `OpenSystemPermission` | 从当前 `GatewayEndpoint` 建客户端；非 loopback 显示错误。本机地址判断不能证明服务属于桌面 App。 |
| 网关地址 | [computer_control_api.rs](../../../crates/libs/gateway-computer-control/src/computer_control_api.rs) 的 `control_send` | 请求发往 endpoint 的 `base_url()/v1/computer-control/...`，带现有请求上下文；没有固定指向桌面进程，也没有独立控制服务发现。具体活动地址本轮未读取。 |
| 申请进程 | [handlers.rs](../../../crates/libs/gateway-computer-control/src/handlers.rs) 的 `request_native_permission` | 网关处理函数直接申请权限，随后返回 `std::env::current_exe()`；返回值代表处理 HTTP 请求的进程，不是调用 UI 的进程。没有 PID、bundle、签名或 Launch Services 证据。 |
| 权限探测 | 同文件 `status`、[native/mod.rs](../../../crates/libs/computer-control/src/native/mod.rs) 的 `native_permissions` | 网关直接查询本进程权限。不能用于报告另一独立服务的授权。 |
| 系统边界 | [macos_observation.rs](../../../crates/libs/computer-control/src/native/macos_observation.rs) 的 `request_permission`、`permissions` | AX 请求调用 `AXIsProcessTrustedWithOptions`；截图权限调用 `CGRequestScreenCaptureAccess`；查询用 `AXIsProcessTrusted`、`CGPreflightScreenCaptureAccess`。提示调用返回后再查权限，不把提示当授权。 |
| 原生执行器 | [tool-computer/lib.rs](../../../crates/libs/tool-computer/src/lib.rs) 的 `start`、`session`、`NativeBackend for NativeObserver` | 默认工厂直接创建 `NativeObserver`，观察和输入直接转发。`UnixStream::pair` 接 `tokio::spawn` 中的 `host.serve`，是当前进程内任务通信，并未启动外部控制进程。 |
| 部署关系 | [bootstrap.rs](../../../crates/vw-agent/src/gateway/bootstrap.rs) 的 `_computer_control` | 网关 bootstrap 持有 runtime 生命周期。网关若由 CLI 运行，原生操作就在该 CLI 进程；若嵌入主程序则在主程序内。源码不足以断言当前活动部署属于哪一种。远程网关执行发生在网关机器。 |

**TCC 归属结论：**源码能确定权限 API 的调用进程是承载网关的进程。系统最终展示、记录的 responsible application 身份仍须结合实际启动来源、可执行路径、bundle、签名和授权界面核实；不能仅以“识矩已链接原生库”或 `current_exe` 路径认定主程序已经获权。本轮没有查询 TCC 数据库，也没有发起权限提示。

## App、签名与 Launch Services

- [vw-desktop/Cargo.toml](../../../crates/vw-desktop/Cargo.toml) 的 bundle 配置声明名称 `ShiJu`、标识 `com.rsung.shiju`，桌面 bin 为 `shi-ju`。这是构建配置，不是已安装产物身份。
- [bundle_macos.sh](../../../scripts/bundle_macos.sh) 设置 `APP_BUNDLE="$BUNDLE_DIR/ShiJu.app"`，写入 `CFBundleExecutable=shi-ju`，复制 `vw-webview` 和可选 CLI/ACP，调用桥接资源 `stage`。当前脚本没有独立电脑操控 App 的装配、嵌套签名或启动路径。
- 脚本默认 `MACOS_SIGN_MODE=adhoc`；Developer ID 分支签嵌入程序及外层 App，随后 `codesign --verify --deep --strict`。这些命令存在不代表本轮已执行，也不代表证书可用或产物通过验证。脚本注释“Native control is linked into the desktop binary”不能证明实际网关进程身份。
- 当前脚本输出 `open` 使用提示，没有显式 `lsregister` 注册或查询步骤。[native/mod.rs](../../../crates/libs/computer-control/src/native/mod.rs) 注释提出 owning App 的 Launch Services 注册要求，但代码注释不是注册证据。后续打包任务需要提供自己 App 的安装、注册、启动与签名证据。
- 公共计划记载的 Codex Computer Use App 路径、Bundle ID、签名及 socket 是前序观察记录，本轮没有复测；不将其视为识矩的执行器，不复用其身份、二进制或私有协议。

## 三条路线及选择

| 路线 | 收益 | 成本与限制 | 选择 |
| --- | --- | --- | --- |
| 主程序内执行 | 复用当前 NativeObserver，少一个进程 | 要先固定网关究竟嵌入哪个程序；CLI/远程模式与主程序身份不同，主程序退出影响执行生命周期 | 不作为本计划交付路线 |
| 识矩独立控制服务 App | 执行、探测、申请由同一自有身份承担；网关与服务生命周期明确 | 需要独立可执行程序、受鉴权 IPC、注册与签名、取消和断连处理；须保留目标与版本校验 | **采用** |
| 第三方驱动 | 可复用其系统执行实现和入口 | 新增分发、许可、安全审查和授权归属依赖；技能/CLI/MCP 仍需实际驱动与系统权限 | 本轮不新增 |

独立 App 是本项目的产品选择，不是所有电脑操控方案都必须如此。计划目标链路为：设置/技能 → 已鉴权网关与用户目标策略 → 受鉴权本机 IPC → 识矩自有控制 App → NativeObserver/系统 API。保留稳定工具 key；服务端也须检查请求版本、目标、取消和生命周期，不能把网关确认等同于任意输入授权。

## Chrome 专项未完成

共享 Chrome 的 native messaging 注册只是安装入口；仍需核对扩展安装、真实 profile/标签页连接、导航后授权、origin 与传输策略的真实执行，以及卸载/冲突恢复。历史记录、完整 CDP、网站工具/WebMCP 尚无完整执行后端；本机应用服务交付不覆盖这些项目。不得复用 Codex 的授权或宣称识矩已接管其浏览器连接。
