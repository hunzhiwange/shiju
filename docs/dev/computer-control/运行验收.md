## 未来跨进程验证入口

取得已构建的本项目 helper 后，显式设置 `SHIJU_CONTROL_HELPER` 为其可执行文件绝对路径，再从仓库根目录运行：

```sh
python3 -m unittest discover -s scripts/computer_control -p test_runtime_integration.py
```

脚本不会构建、下载或请求系统权限。缺少可执行文件直接报错，不以 skip 或零测试作为通过。当前编写 7 个测试方法，实际发现数、退出码和执行结果均待以后运行记录。

| 测试 | 预期关键断言 |
| --- | --- |
| 缺服务 | 连接不存在的 Unix socket 返回 FileNotFoundError |
| 私有 socket 与握手 | 目录 0700、socket 0600、当前 UID、合法 Hello 返回 ready |
| 鉴权 | 错误凭证拒绝；正确凭证仅可附着一次 |
| 协议不兼容 | 未知消息类型返回 invalid_request；这不是版本协商测试 |
| 重复启动与撤权 | 两个独立进程产生不同 socket/session；关闭一条租约通道，仅该进程退出并清理 socket，另一个仍可鉴权 |
| 租期结束 | 真实 helper 自行退出并清理 socket |
| 策略拒绝 | 明确 deny 的目标在 bootstrap 阶段退出，不返回 ready |

测试直接启动真实 Rust 可执行文件，通过继承 fd 3 和真实 Unix socket 通信；不替代鉴权、协议、策略或生命周期。fixture 目标仅用于授权握手，不进行观察和输入，故不需要启动真实目标应用。凭证只在内存通道中传递，不打印响应载荷。进程清理仅针对本测试创建的句柄。

## 静态核对来源

- `crates/libs/computer-control/src/bin/shiju-computer-use.rs`：fd 3 bootstrap、按 UID 检查、ServiceReady、租约关闭/到期终止；原生观察和输入才创建 NativeObserver。
- `crates/libs/computer-control/src/service.rs`：ServiceBootstrap 字段、独占 session 目录、私有 socket 权限、Drop 清理及 Unix 专用监听。无 TCP 地址配置；远程地址的产品入口拒绝仍须另验。
- `crates/libs/computer-control/src/host.rs`：大端 u32 长度 JSON 帧、1 MiB 上限、Hello 单次凭证、未知消息拒绝。测试不伪造协议版本字段。
- `crates/libs/config-computer-control/src/lib.rs` 与 `policy.rs`：当前 UID 用户键、精确 bundle grant、permission_version；允许 locked_use 仅为握手授权，不作为锁屏输入支持证据。
- `scripts/computer_control/bundle_helper.py` 与 `install_local.py`：固定 ShiJu bundle 布局及 helper-path 发现；测试显式指定二进制，不覆盖安装发现和签名验证。
