# 定时任务运行记录

在系统设置的「定时任务」中切换到「运行记录」。任务配置和原有逐任务历史入口仍可使用。

运行记录汇总当前工作区最近 200 条已结束记录及当前运行项。状态包括运行中、成功和失败；运行中不显示最终耗时和输出。时间使用本机时区，并显示 UTC 偏移。刷新会替换快照，完成记录与运行中快照交接时去重。页面可见时自动刷新，离开页面后停止轮询；切工作区会清空旧记录并丢弃旧请求的响应。

## 筛选与详情

- 状态选择「全部状态」「运行中」「成功」「失败」。
- 类型只有「全部类型」和「本地」；Shell、Agent 是执行器，并非云端类型。
- 搜索按钮展开任务名称搜索；任务下拉内的搜索独立筛选任务候选，包括尚无运行记录的任务。重名候选显示完整任务 ID，实际选择使用完整 ID。
- 状态、名称和指定任务筛选取交集，且只作用于上述记录窗口。恢复全部状态、全部类型、全部任务并清空名称即可重置。
- 「查看详情」按单次执行标识定位，显示该次状态、时间和服务端保留的输出，可复制输出。记录已删除或超出保留范围时明确提示不可用。

## 保留和执行边界

`max_run_history` 限制每个任务持久化的历史数量；汇总窗口不会绕过该限制。服务端输出最多保留 16 KiB，详情不代表原始完整输出。删除任务会级联删除其历史，一次性任务自动删除时沿用同一规则。

运行中数据只存在于当前服务进程内存，进程退出后不保留，也不会在重启时伪造成功或失败。执行结束后的历史存于当前工作区 SQLite。任务池任务展示提交阶段的结束状态，不追踪下游任务的完整生命周期。

## 失败排查

刷新失败时保留已有记录并提示数据可能过期，使用「重试」重新查询。鉴权失败需检查当前网关连接与凭据；接口不兼容时按提示升级网关。空态表示当前范围无记录或筛选无匹配，并不表示全部历史为空。投递失败应结合该次输出及原有投递策略判断；运行记录不会扩大执行权限或绕过审批。

验证命令、实际用例数和渲染证据记录于对应计划的任务文件或 `evidence/` 目录；未通过的检查不可视为验收完成。
