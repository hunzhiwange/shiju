# 显式 Git 与消息动作

工作流沿有向边执行。普通任务不配置工具节点时，不会提交、合并或通知；
失败节点的下游不会执行。容量、工位和员工展示不决定 Git 或消息权限。

以下为原生会话绑定工作流的完整 YAML。调用者需已有 `git_operations`
能力及写权限；仓库需要配置 Git 作者。目录取当前会话（含当前 worktree），
不能用工作流输入的 `__vw_full_access` 获取权限。工具能力与会话权限取交集。

```yaml
workflow:
  graph:
    nodes:
      - id: start
        data: {type: start}
      - id: add
        data:
          type: tool
          provider: shiju
          tool_name: git_operations
          inputs: {operation: add, paths: output.txt}
      - id: commit
        data:
          type: tool
          provider: shiju
          tool_name: git_operations
          inputs: {operation: commit, message: '保存明确选择的产物'}
      - id: merge
        data:
          type: tool
          provider: shiju
          tool_name: git_operations
          inputs: {operation: merge, source: feature, target: main}
      - id: answer
        data: {type: answer, answer: '显式动作完成'}
    edges:
      - {source: start, target: add}
      - {source: add, target: commit}
      - {source: commit, target: merge}
      - {source: merge, target: answer}
```

合并目标必须是当前有效目录检出的分支。通常在目标分支目录运行合并图，
在功能分支目录运行提交图；按真实目录拆分这些步骤，不隐式切换分支。
普通非 Git 目录可直接运行：

```yaml
workflow:
  graph:
    nodes:
      - id: start
        data: {type: start}
      - id: answer
        data: {type: answer, answer: '普通目录任务完成'}
    edges:
      - {source: start, target: answer}
```

同项目线程发送使用现有工具节点：

```yaml
id: notify
data:
  type: tool
  provider: shiju
  tool_name: send_message_to_thread
  inputs:
    thread_id: '替换为当前项目可见的线程 ID'
    prompt: '明确授权的消息正文'
```

将 notify 显式接到成功前置节点后。发送要求当前线程、租户和项目上下文，
目标须在现有工具允许范围内；缺少目标、越项目或工具禁用均应在投递前失败。
独立网关工作流不具备原生会话消息绑定，不能靠输入模拟授权。

外部渠道只能选择当前会话已配置、已授权的插件 MCP 工具名与该工具自己的
收件人参数；同样使用 `provider: shiju`，不得填造 credential 或用 action
覆盖工具身份。没有配置渠道就不能发送，不存在通用跨渠道工具。

暂停后恢复沿既有运行状态继续，不默认重放已成功节点。重新启动图是新运行，
可能再次产生副作用；外部投递结果未知时，保留运行错误和节点结果，由操作者
核实后处理，不自动重试发送，也不保证 exactly-once。示例不自动导入或发布。
测试仅使用临时仓库及不可投递目标，不向真实收件人发送。

普通目录任务、容量/工位/员工交互与回归入口见[任务池使用与回归](重构验收.md)。
