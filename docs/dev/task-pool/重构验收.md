# 任务池使用与回归

普通任务可以使用已注册且存在的 Git 或非 Git 项目目录。在任务看板选择现有智能体并启动任务；失败后可通过重试入口继续。每次运行有独立 run/session，员工展示来自智能体定义及其运行。未知或禁用智能体应被拒绝，后台运行不增加工具权限。

容量仍是逻辑工位容量，保留已有配置值、增减规则、预热和回收机制；容量不受智能体定义数量限制。增加员工、打开看板、预热或调节容量不应创建磁盘 worktree。列表/像素办公室、展开/收起、状态统计、员工操作、确认和操作日志继续使用原入口。工位资源状态与智能体身份分开展示。

普通任务成功进入默认完成状态，不自动暂存、提交、合并或通知。已有 Git 暂存内容保持原样。显式选择开发生命周期时，运行成功可停在等待审核状态，不应越过用户配置的工作流。需要提交、合并或消息时，按[显式动作示例](显式动作示例.md)配置工具节点；节点沿依赖执行，权限取会话与工具能力交集，前置失败不能触发下游发送。

同目录以及父子目录的写任务保守串行；不同目录可并发。取消或恢复不能仅因租约过期就释放仍有写入者的目录。失败产物保留用于检查和重试。worktree 只由显式工具按需创建，资源归属于对应运行；清理由用户显式发起，不能自动删除已有目录或未提交产物。

## 验证入口

所有 Cargo 检查经 `python3 scripts/cargo_slot.py` 自动领取共享槽位，保留默认 features。桌面测试注册在 lib 中，`--bin shi-ju` 命中零测试，不能算验收。建议同一入口按顺序执行：

```sh
cargo test -p vw-agent --lib task_pool_acceptance_ -- --nocapture
cargo test --config profile.test.package.vw-desktop.opt-level=0 -p vw-desktop --lib task_pool_acceptance_ -- --nocapture
cargo test -p vw-agent --lib task_pool_ -- --nocapture
cargo test --config profile.test.package.vw-desktop.opt-level=0 -p vw-desktop --lib task_pool_ -- --nocapture
cargo test -p vw-api-types --lib task_pool_workspace_ -- --nocapture
cargo test -p vw-gateway-client --lib task_pool_capacity_ -- --nocapture
cargo test -p vw-cli --lib task_pool_capacity_ -- --nocapture
cargo clippy --all-targets --all-features -- -D warnings
```

模型响应使用本地执行边界夹具，目录、Git 和 SQLite 使用真实临时资源；不向真实收件人发送消息。新增验收测试并不单独代表完整矩阵通过，须结合跨任务测试中的显式工具权限、智能体解析、目录互斥、取消恢复、按需 worktree 和办公室交互结果。具体结果见下表。并发全局环境干扰与零命中检查单独记录，不能计作通过。
