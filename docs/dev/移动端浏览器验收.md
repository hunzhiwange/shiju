# 移动端浏览器验收

本轮仅准备代码与验收入口，未运行构建、测试、打包、Clippy 或实机验收。
以下是后续执行步骤，不代表已获得通过证据。

## 产物与环境

使用 [WASM 本地运行](WASM本地运行.md) 的完整 shi-ju 产品构建，不使用 web_ime 示例。
绑定工具版本应与 Cargo.lock 一致（本计划为 0.2.126）。版本取
crates/vw-desktop/Cargo.toml；保留 ZIP、SHA-256、snippets 和原始截图。
预览源码产物可用 `python3 scripts/serve_shiju_wasm.py /tmp/shiju-wasm-dist --port 8765`；
独立包解压后用 `npm start`。两个预览器保持回环监听，端口冲突时选择新端口。
子目录站点保留末尾 `/`，JS/WASM 缺失返回 404，不重写为 HTML。

手机使用已有、明确授权的 HTTPS 站点。HTTPS 网页连接 HTTPS 远端网关，
网关允许该站点来源，认证在设置中输入，不能写入静态包。
手机 localhost 指手机自身。局域网监听、部署、证书或网关授权须另行确认，
不能为了测试扩大默认监听或放宽认证/CORS。

## 人工与实机矩阵（全部未验收）

Android Chrome 与 iOS Safari 各记录设备、系统和浏览器版本、产物 SHA-256、
站点地址、日期、截图路径以及每项通过/失败/阻塞；记录中不得包含令牌。
Chromium 触摸模拟或 WebKit 自动化不能代替 iOS 实机。

| 场景 | 需核对的结果 |
| --- | --- |
| 首次连接与设置 | 远端网关、认证失败反馈、修正后连接、设置保存和返回 |
| 中文输入 | 首次触摸唤起系统键盘，候选确认一次，删除、换行、粘贴与选区替换 |
| 会话导航 | 项目抽屉、新建/切换会话、草稿保留、返回入口 |
| 聊天 | 中文请求和可见回复、长消息/代码滚动、重试、连续两轮 |
| 审批与询问 | 拒绝/同意分别到达真实协议接口，询问提交，错误可见且可恢复 |
| 视口 | 竖横屏、软键盘开关、安全区、缩放、无溢出或遮挡，触控命中准确 |
| 连接恢复 | 网关中断后恢复、前后台切换，不重复提交、不丢失待审批状态 |
| 布局与桌面 | Auto 阈值 768，显式 Mobile/Desktop；桌面工作与代码模式均可用 |
| 字体与主题 | 深浅应用主题中文实际字形可读，无整形 panic，按钮/滚动条可见 |

不承诺后台常驻、所有浏览器兼容或原生移动能力。手机仅作为远端网关客户端，
不在手机浏览器执行本机文件与命令。上述项目取得证据前不得宣称移动支持已验收。
