# 应用程序生命周期

标准的 Iced 应用程序生命周期与 [Elm](https://elm-lang.org/) 的方式非常相似。

流程如下：

- `view` 使用当前状态渲染组件
- 用户与这些组件交互（例如点击按钮）
- 按钮发送一条消息
- 消息由 `update` 处理并改变状态
- 循环往复...

从实际角度考虑我们的应用程序：

- `view` 在 [column](https://docs.rs/iced/0.13.1/iced/widget/macro.column.html) 布局中渲染 [text](https://docs.rs/iced/0.13.1/iced/widget/text/index.html) 和 [button](https://docs.rs/iced/0.13.1/iced/widget/button/index.html)
- 用户点击按钮，监听事件（`on_press`）
- 按钮发送消息（`Message::ButtonPressed`）
- 消息在 `update` 函数中被匹配，计数器增加 1
- 循环往复...

```rust
use iced::widget::{button, column, text};

fn main() -> iced::Result {
    iced::run("My App", MyApp::update, MyApp::view)
}

#[derive(Debug, Clone)]
enum Message {
    ButtonPressed,
}

#[derive(Default)]
struct MyApp {
    counter: usize,
}

impl MyApp {
    fn update(&mut self, message: Message) {
        match message {
            Message::ButtonPressed => self.counter += 1,
        }
    }

    fn view(&self) -> iced::Element<Message> {
        column![
            text(self.counter),
            button("Increase").on_press(Message::ButtonPressed),
        ]
        .into()
    }
}
```
