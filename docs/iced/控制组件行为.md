# 控制组件行为

有些组件不能仅仅依靠状态来改变某些行为。以 [`TextInput`](https://docs.rs/iced/0.13.1/iced/widget/text_input/struct.TextInput.html) 为例。设置文本输入的焦点不依赖于状态。这是一个一次性函数调用，假设文本输入存在，预期它能正常工作。

Iced 中的文本输入组件有一个 [focus](https://docs.rs/iced/0.13.1/iced/widget/text_input/fn.focus.html) 函数正是用于此场景。它需要一个 [text_input::Id](https://docs.rs/iced/0.13.1/iced/widget/text_input/struct.Id.html) 作为参数，这是输入的 ID。在能够设置焦点之前，我们必须通过调用 [id](https://docs.rs/iced/0.13.1/iced/widget/text_input/struct.TextInput.html#method.id) 函数来设置输入的 ID。

一旦设置完成，我们就可以调用 [focus](https://docs.rs/iced/0.13.1/iced/widget/text_input/fn.focus.html)，传入输入的 ID。

注意下面的例子，我们 `MyApp` 的 update 函数返回一个任务。当这种情况时，我们必须在 `match` 之后返回 `Task::none()` 来满足类型约束。毕竟，并非所有消息都会返回任务。


```rust
use iced::{
    Task,
    widget::{button, column, text_input},
};

fn main() -> iced::Result {
    iced::run("My App", MyApp::update, MyApp::view)
}

const MY_TEXT_ID: &str = "my_text";

#[derive(Debug, Clone)]
enum Message {
    EditText,
    UpdateText(String),
}

#[derive(Default)]
struct MyApp {
    some_text: String,
}

impl MyApp {
    fn update(&mut self, message: Message) -> Task<Message> {
        match message {
            Message::EditText => return text_input::focus(text_input::Id::new(MY_TEXT_ID)),
            Message::UpdateText(s) => self.some_text = s,
        }
        Task::none()
    }

    fn view(&self) -> iced::Element<Message> {
        column![
            button("Edit text").on_press(Message::EditText),
            text_input("", &self.some_text)
                .id(text_input::Id::new(MY_TEXT_ID))
                .on_input(Message::UpdateText),
        ]
        .into()
    }
}
```
