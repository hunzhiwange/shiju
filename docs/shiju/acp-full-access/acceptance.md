# ACP 完全访问交付说明

日期：2026-11-06（Asia/Shanghai）。范围：内置注册表的 22 个 ACP 后端及共享授权、恢复和状态展示链路。逐项版本、权限分类及供应商限制见 [支持矩阵](support-matrix.md)，协议来源见该表链接的独立证据。

## 当前可用行为

- 会话入口解析显式完全访问选择，传入当前 ACP 客户端。显式关闭覆盖默认值；宿主 DenyAll 优先。完全访问开启与普通审批模式分别记录，不因关闭完全访问就认定整个后端不可用。
- Codex、Claude、Qwen 在已确认的固定入口和协议条件下同步原生权限；Qoder、Hermes、iFlow、Kimi、CodeBuddy、Goose、Kiro 复用各自已确认的配置或协议字段。其余后端保留正常访问及已有客户端批准路径，不统一注入 CLI yolo 参数，也不把 plan、ask 或 agent 选择当作工具免审批。
- 客户端自动批准遵循各后端策略；逐次批准只选 AllowOnce，没有允许选项则取消，不能用拒绝选项或永久授权冒充成功。远端硬拒绝、企业规则、登录及供应商确认仍由后端决定。
- new/load/resume 及 prompt 前使用现有权限同步。恢复先处理非提升偏好，当前授权覆盖历史提升值；客户端缓存继续按租户、逻辑会话、目录和权限隔离。切换等待当前轮结束或取消，旧进程关闭失败时不启动替代进程。
- 会话选项通过 `AcpSessionOptions.access_status` 展示请求值、后端、握手版本、实际支持分类与固定说明。原生、客户端批准、部分支持、不可用及同步失败分别展示；未公布或未确认能力不会仅凭模式名称标为原生支持。

## 覆盖入口与限制

| 入口或边界 | 本轮确认范围 |
| --- | --- |
| 普通 / 托管启动 | 沿用注册表与托管制品校验，不安装、不升级、不改全局配置；具体命令及权限策略按支持矩阵逐项说明。 |
| cli_local / session_model | 共用会话权限链路；保留现有模型来源门控。模型来源不支持不代表 cli_local 不可用，也不证明权限能力。 |
| 新建 / 加载 / 恢复 | 共享协议同步与非提升偏好恢复已接入；不更换逻辑会话来规避权限失败。 |
| 远端拒绝 / 无 allow 选项 | 保留拒绝或取消结果，不构造允许选项。 |
| 模式未公布 / 同步失败 | 保留客户端访问能力；需要确认撤销而无法确认时明确阻断当前 prompt，并提示重试。 |
| 旧会话高权限 / 租户隔离 / 取消 | 源码中已有恢复过滤、缓存隔离和取消屏障；本轮未执行竞态或行为测试。 |
| 客户端文件 / 终端 | 使用当前授权处理；远端原生工具及其沙箱属于另一执行边界。 |
| Pi | 原生文件和终端不经过 ACP 客户端批准；关闭客户端完全访问不能限制 Pi 原生工具，宿主 DenyAll 拒绝 prompt。 |
| Vibe / Gemini | Vibe 显式 auto-approve agent 受授权与撤销保护；Gemini 不自动提权，无法确认恢复到受限模式时拒绝继续。 |
| 计划 / 问答 / 企业策略 | 完全访问不自动回答计划或问答，不绕过供应商强制确认、deny 或原生沙箱。 |
