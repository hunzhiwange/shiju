# 任务 14：共享项目槽位接口

新增范围由批次调度明确授权；实现位于 `providers/live/project_binding.rs`，沿用 `ProviderTransactions` 的 host/app 状态、物理 guard、事务锁和 pending，不增加旁路存储。

- `AppState.project_scope: Option<ProjectScope>`：兼容旧状态读取，缺字段为 None。`require_project(&ProjectScope)` 只读检查，未绑定或同租户其他项目均 Conflict，绝不自动认领。
- `commit_project_checked(scope, guard, expected, claim_unowned, changes, target, validate)`：调用前执行端必须授权主机、项目、应用及物理槽位。首次认领显式传 true，并独立验证旧原生输入的归属与恢复能力；`validate` 在事务发布前重新核验授权及输入修订。非首次传 false。归属随原文件和模式同一事务提交，expected 失配、现有不同项目或任意 pending 都拒绝，需要先恢复并重算。
- `recover_project(scope, guard)`：请求恢复只消费同项目同租户 pending；进程启动恢复沿用可信主机生命周期，但也验证绑定预像。
- `PendingTarget.project_scope` 写入后生成 version 7 pending；pending 记录 `project_preimage`，恢复前允许原归属或已落定目标归属，拒绝第三方归属。version 1–6 按原格式读取；旧执行器拒绝 version 7。
- 已绑定状态不再接受缺 project_scope 的旧写动作，避免其他旧接口覆盖聚合所属项目。后续发布通过上述 scoped 方法提交；只读网关先 require_project 再投影。首次预览不得因租户相同隐式认领，必须由已授权写动作给出独立槽位证明。
