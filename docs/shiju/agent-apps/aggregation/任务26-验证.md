## 实现与边界

- 唯一实现为 `crates/vw-agent-apps/src/aggregation/catalog_generation.rs::{observe,read,Snapshot::revision}`。输入是执行端授权后持有的真实 `CodexFiles`、`ProviderTransactions`、`ProjectScope`，不接受客户端文件路径、账号或命令。模块最小注册于 `aggregation/mod.rs`，测试位于独立 `catalog_generation_tests.rs`。
- `read`核对既有项目归属，拒绝未绑定/其他项目和未结束事务；从固定原生文件读取快照，不恢复事务、不记录代次、不改登录。`observe`是发布/重接生命周期消费的原生入口；本任务不新增HTTP、进程探测、ACK、重启动作，也未在事务发布中夹带新的非事务副作用。后续客户端/发布组合任务负责在已完成文件写入后调用。
- 精确匹配当前原生所有者的相对 `shiju-model-catalog.json` 指针才读取受管目录，外部指针视为不使用受管目录且不跟随。目录按文件内容指纹化，文件时间变化不产生新代；退出撤下指针记录none，再接回同内容保留原历史可比性。
- 只有默认/file存储读取auth.json；keyring/auto/ephemeral不从该文件猜测登录。复用原账号所有者的 `extract_codex_auth_user_identity`，仅将其可见性由providers内部扩大到crate内部，没有复制JWT解析器。登录指纹只取account_id与稳定sub身份，不包含令牌、到期时间等轮换字段；同workspace的不同用户可区分。
- 两类历史分别追加和裁剪，各保留32项；同时写入一个固定历史文件，以既有AppWriteGuard私有原子替换保存，权限0600。相同内容不写入；变化时若时钟回拨则返回Conflict。损坏/过大文件、符号链接及写入错误明确失败，不将失败改报成功。
- Snapshot不实现Debug/Serialize，指纹不可从业务快照字段取出；公开修订为绑定项目、执行主机、Codex应用与当前两类指纹的摘要。原始配置、账号和令牌不进入修订、历史或错误文本。历史判定保留2秒边界，首次登录不推断为换号；未登记外部变化仅标unverified，读取不补写。
