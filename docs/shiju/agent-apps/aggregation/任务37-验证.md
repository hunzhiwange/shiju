# 任务 37 · OMP 活动 profile 读取验证

macOS arm64 原生目标，`vw-agent-apps` 默认 features。前置任务 2 由 `3902ad096` 交付，[接口契约](接口契约.md)记录原生读取及后续网关边界。来源 `cc-switch@ca58c0313360eae7c851fbd7553c1614c7af03e7` 的 `omp_config.rs::{get_omp_active_profile,get_omp_agent_dir,read_default_provider_id}` 及 `commands/omp.rs::current_state` 提供行为对照。

## 实现

- 沿用 [OMP 原生配置所有者](../../../../crates/vw-agent-apps/src/providers/omp.rs)。`read_native_directory` 从执行端读取 `OMP_PROFILE`，缺失时回退 `PI_PROFILE`。空值和 `default` 显式选默认 profile。命名 profile 优先于继承的 agent 目录。受信任的绝对目录覆盖及原生环境覆盖均受授权 HOME 约束。
- `models.yml` 优先于 `models.yaml`。旧式 `models.json` 单独存在时返回 `UnsupportedFormat`。`config.yml` 优先于 `config.yaml`，只投影 `modelRoles.default`，按第一个斜杠分割供应商和完整模型 ID。内置默认供应商可以不在显式成员中。
- 目录读取沿用有界、拒绝符号链接的文件读取。非法 profile、越界路径和损坏的设置返回 `InvalidConfiguration`，无法安全打开的源返回 `Unreadable`。只读入口不创建缺失目录。用例核对 OMP 登录数据库、登录链接和原生设置保留原状。
- 本地源修订覆盖活动 profile、相对目录、选中文件名及其内容。网关授权、公开修订的作用域绑定和写入冲突校验由后续任务消费此结果。测试使用隔离配置文件。真实 OMP 客户端消费配置与登录另行实测。
