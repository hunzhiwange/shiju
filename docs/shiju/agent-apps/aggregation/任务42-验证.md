- `handlers/aggregation_exit.rs::prepare`：`POST /v1/agent-apps/{app}/aggregation/exit`；严格 `AggregationExitRequest {targetHostId,projectId,expectedRevision,requestId,confirmed}`。逐次验证Bearer、租户、主机、项目、应用、聚合写/配置写和路由授权。鉴权失败不落文件；旧修订、未确认、未知字段及无执行控制器明确拒绝。响应no-store，不回传原始配置、路径或凭据。
- `gateway/aggregation_resync/exit.rs`：在原 `RecordPublicationContext` 下重验当前修订及授权；Claude调用 `exit_restore::restore_claude`、Codex调用 `restore_codex` 与原登录/目录所有者，Desktop调用 `claude_desktop::publication::run(DesktopTarget::Restore)`。已分离的保存意图仅在原事务清除启用状态。以 `RoutingListener::restore_provider` 联合恢复及撤销当前作用域的路由凭证，其他应用、项目及会话relay不在撤销范围。
- 现有 `app_providers/operations/aggregation.rs` 增加退出动作的幂等域及成功判定，沿用同一 `ProviderOperation`。相同主体/作用域/动作/请求ID和载荷返回同ID；载荷变化409。同一请求ID可分别用于publish和exit。轮询/取消复用 `GET|DELETE /v1/app-providers/operations/{id}?targetHostId=...&projectId=...`，重验原权限并隔离项目/主体。
- `AggregationOutcome::Exited {state}` 只在原事务已落定、没有pending且已清除聚合/附着时返回，恢复状态为restored（原本已退出时none）。失败保留实际 `status/code/recovery`，IO恢复错误为502/recovery_failed，不能核实存储时recovery=failed，有pending时为pending；不将部分发布报告成功。取消沿用原不可逆发布闸口：发布前等待worker停止再Cancelled；发布后继续跟踪真实终态。
