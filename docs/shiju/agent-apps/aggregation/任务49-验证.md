## 实现

- 真实所有者为 `handlers/app_providers/omp.rs`，保留既有 `/v1/app-providers/omp/config/state`，带 projectId 的请求进入 `handlers/aggregation_omp.rs::read_scoped`。返回 profile（默认为 null）、成员、默认供应商、默认模型和作用域修订，响应 no-store。
- 同一既有 OMP router 增加 `PUT /v1/app-providers/omp/{id}/directory-entry`。DTO 位于 `vw-api-types/src/agent_apps/aggregation.rs`，拒绝未知输入及客户端 profile/path/MCP 选择器。
- 读写各要求同一授权项内的 provider_config_read+aggregation_read 或 provider_config_write+aggregation_write；沿持久事务核对租户、主机、项目、应用，未绑定409、不同项目403、pending409。读取不认领、不恢复、不写状态。
- 修订为进程随机密钥 HMAC，绑定主体、作用域、原事务状态及 OMP 原生输入指纹，包含实际 profile 解析、文件选择及 config.yml 默认模型。发布前重验授权、源输入和修订；重启使旧修订失效。
- `OmpFiles::apply_project` 在原 OMP 文件所有者中调用 `commit_project_checked`，显式不认领旧槽位；沿用原 YAML 局部编辑和文件选择冲突检查。insert 已存在409，replace 缺失404，remove 缺失幂等。仅修改活动 profile 中目标 providers 条目，不写默认设置、登录或 MCP 文件，不维护供应商档案副本。
- 旧接口没有项目选择器，不能访问已绑定项目的槽位；读取和归属检查在同一应用锁中执行。未绑定旧客户端保留原协议。
