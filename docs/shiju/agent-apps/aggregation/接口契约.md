## 业务与作用域

- `vw-agent-apps` 是成员、默认项、标识、目录投影、客户端设置和专属资源规则的唯一所有者。Gateway 校验权限和作用域，调度目标主机及常驻路由。SDK 是 Iced 唯一业务入口，Iced 只采集意图、展示状态及取得确认。目录元数据由母 5、账号由母 6、代理传输与协议转换由母 8、普通路由故障转移由母 9 持有。 [原生模式规则](../../../../crates/vw-agent-apps/src/providers/mode_state.rs) · [路由装配](../../../../crates/vw-agent/src/gateway/router.rs)
- 租户来自 `tenant_scope_middleware` 的 `TenantScope`（平台、公司头），主体由管理策略验证 Bearer token，策略缺失时拒绝新动作。租户头和主机、项目选择器都须经授权。下表记 `S = {targetHostId: string, projectId: ProjectId}`，GET 用 query，其他方法用 JSON。`app` 取路径 `AppId`，固定应用路径隐含应用。用现有 `ProjectScope` 构造项目上下文，校验主体的目标项目和应用授权。执行端从策略绑定取本机 home、配置及凭据根、可执行文件搜索路径。 [租户中间件](../../../../crates/vw-agent/src/gateway/middleware.rs) · [项目类型](../../../../crates/vw-api-types/src/id.rs) · [管理策略](../../../../crates/vw-agent/src/gateway/api/handlers/agent_apps/access.rs)
- 新动作复用同一策略文件和授权路径，按租户、主机、项目、应用限定。表中 **读** 需要 `provider_config_read` 及 `aggregation_read`。**写** 需要 `provider_config_write` 及 `aggregation_write`。**路由** 包含写权限，并检查现有项目/应用路由管理授权。**重启** 使用独立 `aggregation_codex_restart` 授权，不由配置写权限推导。后面三项 `aggregation_*` 均为拟新增授权。资源读取、启动操作、轮询及取消各次独立授权，进度仅向提交主体在原作用域内开放，取消须重验原动作授权。
- 同一物理配置只有一个写所有者。沿用 `AppProviderStore` 和 `ProviderTransactions` 的主机/应用事务锁及租户归属。聚合接入须在同一事务中绑定项目并防止其他项目访问或覆盖同一原生槽位。共享原生文件按实际文件串行，跨项目争用拒绝。不能仅凭租户一致推断既有配置的项目归属，无法验证归属时拒绝变更。账号从已授权供应商档案、`AuthAccountStore` 的绑定或目标主机原生登录所有者解析，核对主体、主机和服务。请求不收账号、主机文件路径、登录凭据或命令。 [供应商存储](../../../../crates/vw-agent/src/app_providers.rs) · [事务](../../../../crates/vw-agent-apps/src/providers/live/commit.rs) · [账号存储](../../../../crates/vw-agent/src/agent_apps/auth_accounts.rs)
- 聚合支持 `claude`、`codex`、`claude-desktop`，Desktop 始终有独立的应用作用域和投影。名单保留稳定路由键，删除或移除不释放键。合格默认供应商自动入名单，生效默认项须先替换才能移除。官方账号不能作为成员，Codex 官方默认路由例外须由账号所有者验证真实登录及恢复能力。普通模型只走聚合默认项，聚合标识只发精确匹配的成员。无效或失效标识拒绝，聚合与故障转移互斥，启用前发起的迟到切换不得覆盖默认项。 [supports_stack、allocate_key、resolve](../../../../crates/vw-agent-apps/upstream/src-tauri/src/mode/stack.rs) · [check_stack_member、set_stack_member、record_failover_route](../../../../crates/vw-agent-apps/upstream/src-tauri/src/mode/controller.rs)

## 通用协议

- JSON 字段为 camelCase，新增枚举字符串为 snake_case，新增请求拒绝未知字段。所有新类型定义在 `crates/vw-api-types/src/agent_apps/aggregation.rs`，复用现有 ID、模型能力、错误外层及操作类型。成功读取和同步写入均返回 `200`，异步接受返回 `202` 和 `ProviderOperationProgress`。读与预览响应设 `Cache-Control: no-store`。以下 `revision` 为非空不透明字符串，`T?` 表示可空，`[T]` 表示有序数组。
- 修订绑定授权作用域与资源。聚合修订覆盖状态、名单、默认项、供应商及目录输入、Codex 设置、客户端托管字段、路由参数与账号绑定/登录代次。专属资源各用其实际受控输入的修订。写请求带必填 `expectedRevision`，在现有写锁内、启动业务副作用前核对，并用 `commit_checked` 在发布前再验证。源输入或归属变化返回冲突，读取新状态后重新预览。原生 `Contract.version/key` 只用于判断相同客户端投影免写文件，与并发修订分离。
- 预览读取已落定状态，在内存计算默认项、合格名单、冲突和提醒。禁止恢复 pending、持久化预览或路由键、写配置或代次、启动进程及刷新外部目录。未结事务只返回恢复状态或冲突。无阻塞时给出短时有效的 `previewToken`，服务端认证其完整性，绑定主体、作用域、修订、候选默认项和目录策略。令牌仅用于重算及核验意图。 [stack_views、enter_with_route、write_proxy](../../../../crates/vw-agent-apps/upstream/src-tauri/src/mode/controller.rs) · [claude、claude_desktop](../../../../crates/vw-agent-apps/upstream/src-tauri/src/mode/contract.rs) · [commit_checked](../../../../crates/vw-agent-apps/src/providers/live/commit.rs)
- 异步动作携带 `requestId: string`。同主体、作用域、动作和请求 ID 重送同一规范化载荷返回同一操作及当前快照，载荷不同返回 `request_conflict`。在重验授权后先查已有操作，再验证首次提交的修订/令牌。服务进程重启后先查询实际状态并处理 pending，禁止 SDK 自动重放。持久恢复由原事务完成，进度记录本身不授予重放权限。
- 复用 `GET|DELETE /v1/app-providers/operations/{id}`，轮询/取消 query 沿用 `targetHostId`，聚合操作加必填 `projectId` 并核对记录的应用、主体和权限。复用 `ProviderOperation`、`TaskId`、`TaskStatus` 和 `preparing|publishing|settling|terminal`，在 `ProviderOperationProgress` 增加可选 `aggregationOutcome`（判别字段 `kind`，`published {state: AggregationState}`、`exited {state: AggregationState}`、`restarted {result: restarted|not_running}`、`failed {status: u16, code: AggregationErrorCode, recovery: RecoveryState}`）。配置操作在首次不可逆发布前可取消，等待工作停止后才显示 `Cancelled`。此后取消仅记录请求，继续完成或前滚恢复。重启一旦交给固定命令，取消仅停止等待的意图，仍须追踪命令的真实结果。同步操作不提供独立取消，断开 HTTP 连接不能撤销已开始的事务。 [现有注册](../../../../crates/vw-agent/src/gateway/api/handlers/app_providers/operations.rs) · [DTO](../../../../crates/vw-api-types/src/app_providers/operations.rs) · [发布闸口](../../../../crates/vw-agent-apps/src/providers/operations.rs)
- 所有新契约失败使用 `ApiErrorBody {error: {code, message, details?}}`。下面的 `AggregationErrorCode` 是稳定判别码，拒绝透出原始配置、路径、进程命令或凭据。已接受的异步动作发生业务失败时，状态查询仍返回 `200`，结果中的 `status/code` 对应同一套错误。 [网关错误外层](../../../../crates/vw-api-types/src/error.rs)

| HTTP | 错误码 | 条件 |
| --- | --- | --- |
| 400 | `invalid_request` | DTO、选择器、类型、必填确认字段或模型标识格式错误 |
| 401 | `unauthenticated` | Bearer 凭证缺失或无效 |
| 403 | `forbidden` | 租户、项目、主机、应用、动作、账号或槽位无授权 |
| 404 | `not_found` | 授权范围内的供应商、模型或操作不存在。不可见操作不披露 |
| 409 | `revision_conflict`, `request_conflict`, `default_member_required`, `failover_conflict`, `recovery_pending`, `already_exists`, `variant_conflict` | 状态已变、预览过期或不匹配、重复请求载荷变化、移除生效默认项、故障转移启用、待恢复、显式插入已存在条目或 OMO 变体冲突 |
| 422 | `unsupported_app`, `unsupported_target`, `invalid_member`, `invalid_model`, `invalid_configuration`, `confirmation_required` | 目标/应用无此能力、官方成员、模型未发布或档位无效、目录损坏或无法安全编辑、确认值为 false |
| 502 | `target_failed`, `recovery_failed` | 目标执行或已启动事务的恢复失败 |
| 503 | `target_unavailable` | 主机离线、必需执行端未接通或探测不足以安全执行 |
| 504 | `target_timeout` | 目标操作超时。保留真实执行及恢复状态 |
