# 项目组合 MCP 应用槽位合同

2026-11-14，任务 12 实现；依赖任务 10 的只读预览与母任务 11 的 MCP 目录、原生读取和绑定分发。按本轮用户覆盖要求，未运行 Cargo、构建、检查、单元测试、实机测试或最终回归；未领取 Cargo 槽位，CARGO_TARGET_DIR 与 CARGO_BUILD_BUILD_DIR 均未设置。源码阅读和局部格式化不构成编译或行为验证。

`vw-agent-apps::project_profiles::apply_mcp::apply_mcp` 仅处理指定组的 MCP 槽位。null 直接返回空结果，不调用读写；非 null 读取一次目标安装的完整目录引用与实际启用状态，去重并按 ID 顺序逐项计算最小 toggle。空集停用该目标全部已启用目录项，已经达到目标态的条目不调用分发。悬空 ID 返回 Missing，分发失败逐项记录后继续；不改变供应商、技能、提示词、其它应用组、快照或选择指针。返回值仅表达 MCP 所需动作结果，不能单独作为整个组合 Applied 的依据。

执行端入口是 macOS 的 `McpCatalogStore::apply_project_profile_mcp`，上下文 `agent_apps::mcp::profile_slot::ProjectProfileMcpSlot` 包含已授权的 SnapshotScope、目录作用域、McpBindingTarget 和账号存储。入口核对目录属于同项目或同租户、目标主机和应用组一致，并沿用绑定目标校验、安装及事务主机身份校验。目录观察通过 list_for_host，原生观察通过已有 import::read；只使用目标安装的绑定，不采用其它安装/应用的启用位。原生不可读、未托管条目或原生状态与目录绑定矛盾明确返回失败，不伪造空集合。原生缺失且目录未启用的条目可以作为已停用观察。

每个必要动作均调用母任务 11 的 `set_app_binding`，继续使用目录 revision 检查、凭据使用授权、目录记录锁及物理应用/目录写入锁。不得在外层预持原生锁；调用者须先进入组合操作串行化边界。目录意图已保存但原生发布失败时仍返回 Failed；NotVerified 不计成功；Desktop 非 null MCP 槽位明确返回 Unsupported。错误只包含稳定 reason code，不回传原生连接、账号载荷或底层错误文本。

后续任务 16/19–21 必须接入上述执行端入口，先完成真实项目、执行主机、安装、目录写权限和凭据权限授权/分派，解析可信原生路径及 Claude 账号租约，并消费逐项结果；当前没有组合 API 的生产调用者，不能宣称端到端闭环。预览不是执行凭据，执行时重新读取并校验权限、版本及状态，不隐式修复漂移或扩大管理范围。
