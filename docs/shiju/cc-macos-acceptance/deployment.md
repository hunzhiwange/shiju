## launchd 生命周期：源码参考

来源：[macos.rs](../../../crates/vw-agent/src/service/macos.rs)，函数名见下文；本轮仅阅读，未执行这些路径。

- `install_macos` 将 plist 写入当前用户的 `~/Library/LaunchAgents/com.vibewindow.daemon.plist`。安装使用当时进程的可执行文件绝对路径，传入配置文件父目录作为 `--config-dir`，子命令为 `daemon`。移动或删除该可执行文件后，原 plist 不会自动指向新位置。
- `build_launchd_plist` 设置 `RunAtLoad` 与 `KeepAlive`。这些字段不构成应用健康或请求成功的证明。
- `start_macos` 依次调用 launchctl 的 `load -w` 与 `start`；`restart_macos` 优先尝试 `kickstart -k gui/UID/com.vibewindow.daemon`，失败后走启动分支。这是内部调用描述，不是本轮执行记录。
- `stop_macos` 忽略 stop/unload 的错误后打印停止消息，不能单凭该消息确认进程已退出。
- `status_macos` 在 launchctl list 输出中搜索服务标签，并显示 running/loaded 或 not loaded；不检查网关健康或业务成功。
- `uninstall_macos` 删除 plist，不负责先停止进程。后续隔离验收应分别观察停止与卸载结果，不能把文件删除等同于运行进程终止。

不在缺少隔离配置与清理契约时操作个人 LaunchAgent。

## 日志与请求关联

`install_macos` 将标准输出和标准错误设置为配置文件父目录下的 `logs/daemon.stdout.log`、`logs/daemon.stderr.log`；若配置路径没有父目录，源码回退到当前目录下 logs。实际配置位置应来自冻结启动契约，不假定固定用户目录。[运行契约](runtime-contract.json)的 `resources.log_paths` 仍为空，本文没有实际日志样本。

诊断记录应保存时间和时区、运行主机引用、架构、应用版本、二进制摘要、脱敏命令、退出码及日志片段。请求关联仅使用实际响应或日志提供的字段；未核证统一请求 ID 时，记录时间窗口、操作与响应状态，并明确关联证据不足。不要臆造请求头、端点或关联 ID，也不要收集原始令牌、完整配置、用户数据或敏感载荷。

## 常见故障定位参考

以下为后续排查方向，尚未实测恢复效果；不提供未经核证的修复命令。

| 现象 | 应收集的证据及排查方向 |
| --- | --- |
| 安装后启动失败 | 记录实际退出码；对照 plist 的可执行文件路径和配置目录，检查是否移动了安装时的程序；回交运行入口所有者 |
| 显示 loaded 但请求失败 | 分别记录服务登记、进程状态和请求结果；loaded 不表示业务就绪，补录真实日志 |
| 停止提示成功但仍有进程 | stop/unload 错误可能被忽略，需独立观察进程和服务状态；不要直接删除用户数据或扩大权限 |
| SSH 或无图形登录态重启失败 | 记录会话条件及 gui 服务目标是否存在；不要擅自改成系统 LaunchDaemon 或使用 sudo 绕过 |
| 远端拒绝或连接失败 | 记录脱敏地址、执行主机引用、响应状态和时间；由网关/授权所有者核对策略，不关闭认证或放宽访问范围 |
| 日志不存在 | 核对实际配置父目录、安装结果和 plist 输出路径；未启动时不存在日志不能算行为失败或通过 |
