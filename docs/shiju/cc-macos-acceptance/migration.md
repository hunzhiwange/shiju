## 1. 先保存原状

在恢复验证授权并取得当前版本操作说明后，先记录 CC Switch 与目标应用版本、macOS 版本、CPU 架构、执行主机和当前直连/代理模式。记录应用实际使用的配置位置、原有端点及代理环境变量名称；凭据只留受控引用，不写入工单、截图或本指南。

使用原应用该版本的备份入口保存来源数据，并另行保存原生应用配置和恢复所需资源。不要假定单个数据库备份包含 Keychain、技能文件、外部会话或全部原生配置。先证明备份可读且能够在隔离环境恢复，再迁入；当前指南没有经过验证的备份菜单、固定路径或恢复命令，因此此门槛尚未满足。

保留 CC Switch 安装、数据及备份。不要删除目录、覆盖宿主数据库或将源 SQL 直接导入识矩数据库。可能含敏感信息的本机回退归档应保存在受控本机位置；可迁移导出与完整回退分开保管，不默认上传同步或共享。

## 2. 选择迁入范围并预览

先由能力所有者补齐当前基线可执行入口、授权目标及回退能力。确认目标租户、项目、用户、执行主机；远端不可用时停止，不改用桌面本机路径。使用来源副本，保持原数据不变；不要同时让两个应用修改相同 live 配置。

逐类选择供应商、MCP、技能、规则、项目组合、偏好和用量，仅执行已有生产接线且已验证的类别。逐项核对预览中的新增、替换、跳过、无效引用和排除原因；不要将当前预览未支持的 `keep_both` 当作可用选项。组合引用须核对新旧 ID 映射；技能须核对资源，不能只迁记录；用量明细与同源汇总不能重复计入。上述规则来自数据管理合同，七类完整迁入仍未验收。

没有覆盖所选对象和资源的回退点、冲突未决、源摘要或目标版本变化时，不提交。此阶段缺口交母任务 18 及各领域所有者补齐，不通过直接调用数据库或猜测 API 绕过。

## 3. 迁入后逐项核对

执行入口就绪后，保留任务 ID、来源摘要、所选范围、目标身份、回退点引用和逐项结果。记录持久化提交与原生投影的各自结果；`partial`、投影失败、取消或超时不能记为成功，不盲目重复迁入。

核对记录数量与排除项、供应商实际启用状态、MCP 实际分发、技能资源、规则内容及激活、组合引用、偏好和用量去重。保存了记录不代表激活或应用已使用；当前供应商 live 投影缺口未关闭前，不能确认迁入可替代旧应用。各类别及实际应用须取得绑定冻结产品树、产物哈希、macOS/架构和应用版本的证据，ARM64 结果不能代替 x64。

## 4. 异常时恢复直连

若迁入部分失败、原生应用无法使用、仍依赖旧代理或无法证明回退完整，先停止继续写入，保留错误摘要和回执。不要删除失败任务或唯一备份。

恢复前保存当前状态并确认无外部并发修改；按原应用和各领域已验证的恢复说明，恢复本次拥有且版本匹配的配置、端点及代理环境设置，重新启用原有直连凭据。不要假定退出代理应用会自动清除接管配置。恢复后需要在隔离场景证明应用直接连接原端点，且不依赖 CC Switch 或识矩代理；本轮没有可复用的已验证直连恢复入口，因此不得现在照此尝试生产切换。

若存在版本冲突、恢复失败或远端失联，保留两侧数据，由对应配置/路由所有者处理；不整库覆盖、不重置其他用户数据。恢复成功也不自动证明七类迁入成功。

## 5. 满足条件后停用旧应用

只有备份恢复、所选类别迁入、原生投影、目标应用实际使用和直连回退均取得当前证据，才进入停用步骤。当前证据未满足条件，建议继续保留旧应用作为回退资源。

后续按旧应用当前版本的已验证说明解除配置接管、关闭其自动启动，再正常退出。逐个确认目标应用运行时不再依赖旧进程、监听端口或残留代理设置；发现依赖即按上节回退。停用仅指停止使用与自动启动，不包含卸载或删除 CC Switch 数据。数据保留期限由用户决定，本指南不自动清理。
