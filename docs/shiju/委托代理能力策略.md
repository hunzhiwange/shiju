# 委托代理能力策略

委托代理的工具在对话开始前完成注册，`allowed_tools` 是最终工具清单；未注册工具不可调用。技能仍通过 `skill_policy` 控制可见范围，`allowed_skills` 表示默认选择。

```toml
[agents.reviewer]
allowed_tools = ["file_read", "grep"]
skill_policy = "strict"
allowed_skills = ["code-review"]
```

| 技能策略 | 实际可见技能 | 默认注入 |
| --- | --- | --- |
| `strict` | 仅默认选择 | 默认选择 |
| `unrestricted` | 当前可用的全部能力 | 默认选择 |

技能的用户显式选择只能来自 UI 或 API 请求边界，并在创建子会话时固化。模型输出、提示词文本和技能正文中的名称都不会扩大能力范围。未知 ID 会被忽略；禁用或不可用技能不会重新暴露。

工具自己的文件、命令、网络和审批权限照常执行；工具清单不授予额外底层权限。递归委托工具始终对委托代理隐藏。

旧 `delegate` 的 agentic 适配、`AgentTool` 与 Gateway 使用同一工具注册清单和技能策略。
