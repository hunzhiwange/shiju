# 工具发现与技能注入

VibeWindow 在桌面会话 processor、`Agent::turn` 和 `QueryEngine` 中按需提供 MCP 工具规格与技能正文。工具注册、请求授权和模型可见性分别处理；搜索结果、历史消息或技能内容都不能授予额外权限。

## 工具发现

已经获准的内置工具直接向模型提供参数定义。MCP 工具先保留在本轮用户请求的授权目录中；有延迟候选且请求允许 `tool_search` 时，模型起初只看到搜索入口和服务器概要。

调用顺序如下：

1. 调用普通客户端函数工具 `tool_search`，例如 `{"query":"查找报告","limit":8}`。
2. 结果中的 `tools` 返回命中的稳定 `id`、描述和完整 `input_schema`。搜索只读当前授权目录，不执行远端 MCP 动作。
3. 在下一次模型请求中，命中工具加入可见规格；模型再按返回的 ID 和参数调用它。工具仍经过既有权限、审批和 hook 检查。

搜索采用本地轻量 BM25，支持中文与英文查询，默认返回 8 项，上限为 32；空查询、无可搜索字符或越界 `limit` 明确报错，无匹配时返回空集合。重复命中不会重复添加规格。

工具调用使用该次模型请求开始时的可见快照。一个并行批次里的搜索不能使同批次其他调用获得可见性；批量工具的内层调用也受该快照和授权约束。新用户轮次按当前授权重建目录，不从历史搜索 JSON 恢复已加载集合。

显式选择 MCP 工具仅收窄本次请求的工具范围。请求关闭搜索入口时，仍获准的 MCP 工具直接提供规格，避免无法调用；`disable_tools` 则保持工具集合为空。禁止的工具不能通过搜索重新出现。达到最后一步时，不再向模型发送工具规格。

## 技能目录与正文

技能目录包含名称、短描述和规范化来源路径，并以 `developer` 消息提供使用规则。目录不包含技能正文；正文仅在默认配置、有效指令引用、明确用户选择或成功 `skill` 调用后读取，以 `user` 消息注入。用户自行写入 `<skills>` 等标签不会变成指令角色，普通文件读取或 shell 读取也不会隐式激活技能。

模型可按目录选择 `skill` 工具，例如 `{"skill":"review","args":"检查当前变更"}`。目录可见不等于允许执行：当前模型能力、选中代理的权限和技能策略仍会校验。`disable-model-invocation: true` 的技能不会作为模型可选项提供；有效的明确用户选择沿现有用户调用规则处理。

新目录元数据按上下文窗口的 1% 预算分批提供，超出的条目延后，不截断为残缺条目。状态按代理、规范化来源和元数据指纹跟踪；描述或来源变化会重新提供，移除与禁用会失效。同名技能沿加载器既定来源优先级选择，旧来源记录不能静默切换到另一份同名正文。

目录和已激活正文属于临时模型请求上下文，后续请求会继续提供所需内容，不写入可见聊天历史。压缩后重建目录并从当前有效来源恢复正文。OpenAI 适配保留 `developer`；Anthropic 适配把系统与 developer 指令合并到其系统指令通道，正文继续作为 user 内容，并保持消息顺序。

## 默认技能与策略

代理配置中的 `allowed_skills`（兼容别名 `skills`）指定默认注入的技能。例如：

```json
{
  "agents": {
    "main": {
      "provider": "configured-provider",
      "model": "configured-model",
      "allowed_skills": ["review"],
      "skill_policy": "unrestricted"
    },
    "reviewer": {
      "provider": "configured-provider",
      "model": "configured-model",
      "allowed_skills": ["review"],
      "skill_policy": "strict"
    }
  }
}
```

这里的 provider/model 应替换为已有配置；技能名应对应已安装且当前可访问的来源。默认列表不授予工具、文件或网络权限，仍需在现有权限设置中授权。`main` 与子代理均传递默认列表；默认来源缺失、禁用或被拒绝时明确报错，不静默跳过。

`unrestricted` 允许在当前权限与能力范围内按需选择其他技能；`strict` 将技能目录、正文预载和 `skill` 调用限制在配置上限内，临时选择不能扩大它。空默认列表表示没有配置默认预载，不会从请求中的任意列表补回默认能力。

## 恢复与错误定位

运行时只记录真实成功调用的来源、技能名和参数；普通工具输出中的同名字段或 `context_updates` 不能伪造激活记录。跨请求存储使用租户、项目、会话、代理和原始历史前缀作为边界，原子保存来源记录，不保存展开的正文。恢复时重新检查当前来源、禁用标记、权限和策略，再读取正文。

fork 只复制来源及历史锚点，目标会话仍重新校验；回退、重试和修改历史不能恢复截点以后的调用。新会话不继承其他会话的技能记录或工具曝光。来源被删除、禁用、替换或不再授权时，恢复会报告可定位的错误，而不是沿用旧正文或扩大权限。

遇到失败时，可依次检查当前选中代理、默认技能配置、规范化来源路径、技能禁用标记及现有权限设置。搜索无结果时，先确认工具已注册且在本次请求授权范围内；调用提示不可见时，确认已经在前一次请求成功搜索，且没有跨用户轮次沿用旧 ID 的曝光状态。

## 与 Codex 的协议边界

本实现参考 Codex 的工具延迟暴露、技能 developer 目录和 user 正文行为，采用跨供应商的客户端函数搜索。它不发送原生 `type=tool_search`、`defer_loading` 或 `tool_search_output`，不实现 Codex 云技能服务、远端执行托管或 shell 隐式技能访问；不能据此宣称完整 wire 协议一致。

回归用真实临时技能、隔离存储和本地 stdio MCP，只有模型响应脚本化。聚焦验证入口为 `cargo test -p vw-agent --lib --all-features codex_ -- --nocapture`；运行前须遵守仓库共享 Cargo 槽位规则，之后执行规定的全目标 Clippy。
