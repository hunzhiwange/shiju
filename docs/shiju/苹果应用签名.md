# macOS 应用签名与公证

## 当前状态

签名、公证和 CI/CD 流程代码已经接入仓库，但 Apple 证书及 GitHub
Secrets 尚未配置，暂缓启用。

- 本地开发使用 `make macos-dev`，生成 ad-hoc 签名的 `.app`。
- 正式本地发布使用 `make macos`，要求 Developer ID 证书和公证凭据。
- GitHub Pull Request 只进行 ad-hoc 打包，不读取 Apple Secrets。
- GitHub Tag 发布要求正式签名和公证；缺少任一 Secret 时会明确失败，避免发布未签名产物。

在完成本文配置前，不要用正式 Tag 触发对外发布。

## 最终目标

正式发布流程如下：

```text
构建内嵌二进制
  → 逐个 Developer ID 签名
  → 签名 ShiJu.app
  → 验证签名
  → 公证并装订 App
  → 生成 ZIP 和 DMG
  → 公证并装订 DMG
  → 上传 GitHub Release
```

产物包括 ARM64 和 x86_64 两种架构的 ZIP、DMG。

## 证书选择

VibeWindow 是通过 GitHub、官网等 Mac App Store 之外渠道分发的 macOS
应用，应使用：

```text
Developer ID Application: 企业名称 (TEAM_ID)
```

不要使用下面这些证书签名公开下载的 `.app`：

- `In-House and Ad Hoc`
- `Apple Development`
- `Mac App Distribution`
- `Developer ID Installer`

`Developer ID Installer` 只用于签名 `.pkg` 安装器。当前发布物是 ZIP 和
DMG，不需要该证书。

## 需要登录的三个网站

整个流程会用到三个不同入口，不要混淆：

| 网站 | 用途 |
|---|---|
| https://developer.apple.com/account/ | 查看会员、切换团队、创建和下载 Developer ID 证书 |
| https://account.apple.com/ | 开启双重认证、创建 App 专用密码 |
| https://github.com/doyouhaobaby/vibe-window/settings/secrets/actions | 配置 CI/CD 使用的 Repository Secrets |

Apple Developer 和 Apple Account 使用同一个 Apple 账户登录，但两个网站管理的
内容不同。GitHub 使用项目管理员自己的 GitHub 账户登录。

## 零、登录 Apple Developer 并确认企业团队

### 0.1 登录开发者账户

打开：

```text
https://developer.apple.com/account/
```

点击右上角“账户”或“Account”，使用注册 Apple Developer 付费计划时所用的
Apple 账户登录。如果你是后来被企业邀请加入团队，应使用收到团队邀请的那个
Apple 账户。

不要使用以下账户：

- 没有加入开发团队的私人 Apple 账户。
- 尚未接受企业团队邀请的账户。
- 默认无权访问开发者资源的“管理式 Apple 账户”，除非企业已在 Apple
  Business Manager 中为它开放权限。

登录时可能要求输入受信任设备上显示的六位数双重认证验证码。不要把 Apple
账户主密码或验证码提供给任何人，也不要存入 GitHub Secrets。

### 0.2 首次登录

首次进入 Apple Developer 时，页面可能要求：

1. 接受《Apple Developer 协议》。
2. 补充姓名、电话或地址。
3. 完成双重认证。
4. 接受企业账户最新协议。

这些步骤未完成时，“Certificates, Identifiers & Profiles”可能不可用。

### 0.3 切换到正确团队

同一个 Apple 账户可能同时属于个人团队和多个企业团队。登录后：

1. 点击页面右上角显示的团队名称。
2. 在团队列表中选择实际持有 VibeWindow Developer ID 的企业团队。
3. 不要选择 `Personal Team` 或其他公司的团队。

后续创建证书、查询 Team ID、公证应用必须使用同一个团队。

### 0.4 检查会员资格

进入“Membership details”或“会员资格详细信息”，确认：

- 企业法定名称正确。
- 会员状态有效，尚未过期。
- Team ID 是预期的 10 位字符串。
- 当前账户职能正确。
- 没有等待接受的协议。

如果页面显示“Join the Apple Developer Program”，通常表示登录了错误的 Apple
账户、没有加入付费团队，或没有切换到正确团队。

如果使用 Apple Developer Enterprise Program，看不到 App Store Connect 是正常的；
本流程只需要 Developer ID、钥匙串和 Apple 公证服务。

### 0.5 检查账户职能

手工创建 Developer ID Application 证书通常需要“账户持有人”
（Account Holder）。管理员只有在被授予相应云管理式 Developer ID 权限时才能处理
部分证书，但 CI/CD 需要可导出的私钥，因此本文使用“本机 CSR + 可导出 `.p12`”
流程。

如果证书页面没有 `Developer ID` 选项：

1. 再次确认已经切换到正确企业团队。
2. 检查会员是否有效。
3. 检查是否有待接受协议。
4. 联系 Account Holder 创建证书，或授予所需权限。

### 0.6 进入证书管理页面

在开发者账户主页点击：

```text
Certificates, Identifiers & Profiles
  → Certificates
```

也可直接打开：

```text
https://developer.apple.com/account/resources/certificates/list
```

确认页面顶部或右上角仍显示正确企业团队，然后再执行下一节。

## 前置条件

开始配置前需要：

1. 有效的 Apple Developer Program 或 Apple Developer Enterprise Program 会员资格。
2. 有权创建 Developer ID Application 证书的账户。
3. 已启用双重认证的 Apple 账户。
4. GitHub 仓库 `doyouhaobaby/vibe-window` 的 Settings 管理权限。
5. 一台用于创建证书和导出私钥的 Mac。

## 一、创建 Developer ID Application 证书

登录 Apple Developer：

```text
Certificates, Identifiers & Profiles
  → Certificates
  → +
  → Software
  → Developer ID
  → Developer ID Application
```

按页面要求，在 Mac 的“钥匙串访问”中创建 CSR：

```text
钥匙串访问
  → 证书助理
  → 从证书颁发机构请求证书
  → 存储到磁盘
```

上传 `.certSigningRequest`，下载生成的 `.cer`，双击安装到“登录”钥匙串。

检查签名身份：

```bash
security find-identity -v -p codesigning
```

预期出现：

```text
Developer ID Application: 企业名称 (TEAM_ID)
```

## 二、导出 `.p12`

打开“钥匙串访问”：

1. 进入“登录”→“我的证书”。
2. 找到 `Developer ID Application` 证书。
3. 展开证书，确认下面存在“专用密钥”。
4. 右键证书，选择“导出”。
5. 导出为 `DeveloperIDApplication.p12`。
6. 设置一个独立的高强度导出密码。

如果不能导出 `.p12`，或者证书下没有专用密钥，说明当前 Mac 没有对应私钥。
仅下载 `.cer` 不能恢复私钥，需要在持有原 CSR 私钥的 Mac 上导出，或者重新创建证书。

将 `.p12` 转成可存入 GitHub Secret 的 Base64：

```bash
/usr/bin/base64 -i "DeveloperIDApplication.p12" | pbcopy
```

剪贴板中的内容是 `MACOS_CERTIFICATE_P12_BASE64` 的值，不是文件路径。

## 三、准备 Apple 公证凭据

访问：

```text
https://account.apple.com/
  → 登录与安全
  → App 专用密码
  → 创建
```

使用前面已经确认属于正确企业团队的 Apple 账户登录。不要使用其他私人账户。
如果页面没有“App 专用密码”，先确认该账户已经启用双重认证。

建议名称：

```text
VibeWindow CI
```

生成的密码用于 `APPLE_NOTARY_PASSWORD`。不要使用 Apple 账户的主密码。

Team ID 可在 Apple Developer 的 Membership Details 中找到，是 10 位字符串。

公证使用的 Apple 账户必须属于对应开发团队，并有权提交 Developer ID
软件公证。

## 四、配置 GitHub Actions Secrets

进入：

```text
https://github.com/doyouhaobaby/vibe-window/settings/secrets/actions
```

先登录有该仓库管理权限的 GitHub 账户。如果仓库页面没有 `Settings`，说明当前
GitHub 账户没有足够权限，需要由仓库 Owner 配置，或者先授予管理权限。

依次选择：

```text
Settings
  → Secrets and variables
  → Actions
  → New repository secret
```

配置以下 6 个 Repository Secrets：

| Secret | 内容 |
|---|---|
| `MACOS_CERTIFICATE_P12_BASE64` | `.p12` 的完整 Base64 内容 |
| `MACOS_CERTIFICATE_PASSWORD` | 导出 `.p12` 时设置的密码 |
| `MACOS_SIGN_IDENTITY` | 完整 Developer ID Application 名称，不带引号 |
| `APPLE_NOTARY_APPLE_ID` | 用于公证的 Apple 账户邮箱 |
| `APPLE_NOTARY_PASSWORD` | Apple App 专用密码 |
| `APPLE_TEAM_ID` | 10 位 Team ID |

也可用 GitHub CLI 配置。证书内容通过标准输入传递，避免出现在命令参数中：

```bash
/usr/bin/base64 -i "DeveloperIDApplication.p12" |
  gh secret set MACOS_CERTIFICATE_P12_BASE64 \
    --repo doyouhaobaby/vibe-window
```

其余 Secret 使用交互输入：

```bash
gh secret set MACOS_CERTIFICATE_PASSWORD --repo doyouhaobaby/vibe-window
gh secret set MACOS_SIGN_IDENTITY --repo doyouhaobaby/vibe-window
gh secret set APPLE_NOTARY_APPLE_ID --repo doyouhaobaby/vibe-window
gh secret set APPLE_NOTARY_PASSWORD --repo doyouhaobaby/vibe-window
gh secret set APPLE_TEAM_ID --repo doyouhaobaby/vibe-window
```

只检查 Secret 名称，不会显示值：

```bash
gh secret list --repo doyouhaobaby/vibe-window
```

## 五、本地正式打包

首次在本机保存公证凭据：

```bash
xcrun notarytool store-credentials "vibewindow-notary" \
  --apple-id "apple-account@example.com" \
  --team-id "TEAM_ID"
```

命令会安全提示输入 App 专用密码。

执行正式签名、公证和打包：

```bash
MACOS_SIGN_IDENTITY="Developer ID Application: 企业名称 (TEAM_ID)" \
NOTARY_KEYCHAIN_PROFILE="vibewindow-notary" \
make macos
```

默认输出：

```text
dist/macos/ShiJu-macos-release.zip
```

仅做本地开发构建：

```bash
make macos-dev
```

## 六、CI/CD 正式发布

工作流文件：

```text
.github/workflows/release.yml
```

正式发布由符合语义版本格式的 Tag 触发：

```bash
git tag v0.4.1
git push origin v0.4.1
```

工作流执行：

1. 从 GitHub Secrets 解码 `.p12`。
2. 创建 runner 临时钥匙串。
3. 导入 Developer ID 证书与私钥。
4. 将 Apple 公证凭据写入临时钥匙串。
5. 逐个签名 `vw-webview`、`shiju`、可选 `vibe-agent`、可选 `acp`。
6. 签名外层 `ShiJu.app`。
7. 公证 ZIP，装订并重新打包 App。
8. 创建 DMG，再公证和装订 DMG。
9. 上传 ZIP、DMG 到 GitHub Release。
10. 无论成功或失败，都删除临时证书文件和钥匙串。

Pull Request 构建不会读取 Apple Secrets，也不会提交 Apple 公证。

## 七、验收

### 检查 App 签名

```bash
codesign --verify --deep --strict --verbose=2 ShiJu.app
codesign --display --verbose=4 ShiJu.app
spctl --assess --type execute --verbose=4 ShiJu.app
```

### 检查 App 公证票据

```bash
xcrun stapler validate ShiJu.app
```

### 检查 DMG 公证票据

```bash
xcrun stapler validate ShiJu-macos-release.dmg
```

### 检查内嵌二进制

```bash
find ShiJu.app/Contents -type f -print0 |
  xargs -0 file |
  grep 'Mach-O'
```

每个 Mach-O 可执行文件都必须被 Developer ID 签名。正式签名应从内向外进行；
`codesign --deep` 只用于验证，不用于正式签名。

## 八、常见错误

### `Missing ... secret`

GitHub Secret 名称缺失或为空。检查 6 个名称是否完全一致。

### `signing identity not found`

可能原因：

- `.p12` 没有包含私钥。
- `MACOS_SIGN_IDENTITY` 与证书名称不完全一致。
- 导入 `.p12` 使用了错误密码。

重新运行：

```bash
security find-identity -v -p codesigning
```

### `Unable to validate your credentials`

检查：

- Apple 账户邮箱。
- App 专用密码。
- Team ID。
- Apple 账户是否属于该团队。
- Apple Developer 会员资格是否有效。

修改 Apple 账户主密码后，旧的 App 专用密码会失效，需要重新创建并更新
GitHub Secret。

### `The signature of the binary is invalid`

通常表示：

- 某个内嵌 Mach-O 没有签名。
- 签名后又修改了 `.app` 内容。
- 使用了错误证书。
- Hardened Runtime 未启用。

所有文件复制完成后才能签名；签名外层 App 后不能再修改 Bundle。

### CI 公证长时间等待

`notarytool --wait` 会等待 Apple 返回结果。失败时查看公证日志：

```bash
xcrun notarytool log "SUBMISSION_ID" \
  --keychain-profile "vibewindow-notary" \
  notarization-log.json
```

## 九、安全要求

- `.p12`、私钥、App 专用密码不得提交到 Git。
- 不在 issue、日志、聊天或截图中展示 Secret 值。
- CI 只在 Tag 发布时加载 Apple Secrets。
- 签名证书只导入临时钥匙串。
- 怀疑私钥泄露时，立即在 Apple Developer 撤销证书。
- 怀疑公证密码泄露时，立即撤销 App 专用密码并更新 GitHub Secret。
- 定期轮换 `.p12` 密码和 App 专用密码。
- 只给必要管理员访问 GitHub Actions Secrets 的权限。
