# 主机内授权流程状态机

母任务 6／子任务 8。批次 1–7 的正式交付依次为 `cd0dfb217`、`14acbba54`、`c7d8474f1`、`f2e90ecc8`、`ba4883457`、`ceb96d943`、`d6037055c`。沿用批次 4 的开工裁定，核对已验收的来源快照、原生包、认证与主机合同、双后端存储及已有供应商事务，不将尚缺的真实应用验收列作完成。来源为 cc-switch 4.0.25 的 `ca58c031`；对照 `commands/auth.rs` 的授权分派与 `services/kimi_oauth/mod.rs` 的流程创建、提交前二次核验及迟到结果测试。参见[接口契约](接口契约.md)与[底座交付](../底座交付映射.md)。

- `vw_agent_apps::auth::flow::AuthFlows` 生成独立随机 ID。每条记录绑定平台、公司、可信主体、执行主机、服务、登录方式及该次启动选项。快照、取消和完成均在同一作用域内查找；跨作用域与未知 ID 均返回 `not_found`。现有 `AuthAccountStore` 复用同一个作用域类型与格式校验，原有元数据键不变。
- `pending` 可转为 `approved`、`cancelled`、`expired` 或 `failed`，终态保留供读取。执行主机持有单调截止时刻；UTC 时间只用于显示。完成在单流程锁内复核资格与目标，最多进入一次持久化操作。持久化成功才发布 `approved`，失败只返回稳定错误码、静态说明和独立关联 ID。
- 服务适配器负责验证挑战、规范化域或地区、核验上游身份和账号代际，并在提交操作内完成凭据与元数据持久化。状态机不保存上游设备码、授权码、令牌或回调秘密。批次 8 验证的是主机提交边界；进程/监听器清理、轮询节流、自动回收和服务端点接入留给对应批次。
