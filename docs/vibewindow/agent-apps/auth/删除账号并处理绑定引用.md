# 删除账号并处理绑定引用

母任务 6／批次 35。直接前置为 `c0868fc9a`，官方卡引用前置为 `aeff6b430`。删除沿用批次 3 的完整作用域及显式解绑合同。来源是冻结的 cc-switch 4.0.25（`ca58c0313360eae7c851fbd7553c1614c7af03e7`）的 `commands/auth.rs::auth_remove_account`、`findManagedAccountUsers`、Kimi `remove_at` 和 DSH 本地共享 grant 路径。[接口契约](接口契约.md) · [供应商事务交接](../../../shiju/agent-apps/provider-contracts.md#官方卡账号引用与删除事务交接)

- agent 的 `AppProviderStore::remove_auth_account` 接收已授权作用域和执行端解析的原生目标。Claude、Codex、Kimi 的引用检查持账号租约直到提交，Claude 同时持供应商目录锁。AGY 在绑定与启动共用的钥匙串锁下检查官方卡和原生当前登录，之后才删除托管副本并读回确认。引用冲突返回 `account_in_use`，错误只包含稳定码。
- Claude 同时检查目录卡和主机默认登录引用。无引用时复用 Claude 文件锁，校验独立目录与钥匙串身份，清理私有目录及作用域条目。Codex 仅删除隔离账号材料，全局切换接口对该绑定稳定返回 422。Kimi 的原生 OAuth 槽由原生登录持有，账号删除只清理私有受管凭据。待恢复的供应商事务显式拒绝。
- Copilot 和 xAI 当前的代理供应商没有生产受管账号消费者。Copilot 每次使用派生会话缓存前都在租约内复查账号凭据。DSH 删除只清除目标执行端的单一共享 grant，设备信息与其他授权材料仍由原文件保有。后续批次接入登出、撤销、流程代际和 HTTP。
- SQLite 与 PostgreSQL 在同一事务中移除记录及仍精确指向它的默认值。SQL 先执行，持租约完成主机清理后提交。SQL 或主机清理失败时保留诊断记录。若主机清理完成后数据库提交失败，重试会接受已经缺失的私有凭据，并继续清理数据库记录。历史启动账号沿用各自的命名空间。
