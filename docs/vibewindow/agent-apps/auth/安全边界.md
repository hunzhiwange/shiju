账号尚未建立时，流程以平台、公司、可信主体、执行主机、授权服务和不透明流程 ID 定位。定向重登从启动时绑定目标账号，提交时核验同一作用域、流程仍有效及上游身份相符。轮询、回填、取消、刷新、写回和撤销均沿用已绑定作用域。应用自管的浏览器回调由主机用 state 和有效流程定位，并用同一流程持有的 PKCE verifier 兑换。Claude CLI 回填只交给原流程绑定的进程。回调和回填参数不能选择账号或租户。默认账号在同一平台、公司、主体、执行主机、服务内解析。供应商绑定通过目标账号的完整作用域和操作授权校验，外部用户 ID、邮箱相同也不能合并或转授。GitHub Enterprise 域、Kimi 地区及 DSH issuer 要与该账号的身份来源一致。子 8–10、11、16、21、31、33–37、54。

现有启动查询由 `gateway/api/handlers/agent_apps/launch.rs:49–51` 注册，公开投影受身份 grant 限制。Claude 原生切换已调用 `claude_login_account` 取得所有者租约，再执行供应商事务（`gateway/api/handlers/app_providers/claude_login.rs:47–89`）。这些入口提供可复用的底座。统一授权能力、成员绑定和公开授权路由仍由后续任务交付。

## 执行主机与拒绝条件

| 拓扑或失败条件 | 合同判定与依据 |

| Iced 与网关异机，网关就是已授权执行主机 | SDK 发请求，客户端负责打开浏览器、显示用户码和用户主动回填。设备流仍可由网关轮询。浏览器流仅在浏览器能访问该执行主机的已允许回调、且满足服务重定向约束时启动。Codex 绑定 IPv4 回环并使用固定重定向（`proxy/providers/codex_oauth_auth/browser.rs:15,145–149`），AGY 与 DSH 绑定随机回环端口（`services/agy_account/oauth.rs:89–116`、`services/dsh_account.rs:392–407`）。异机浏览器访问自己的回环时返回回调不可达。设备方式须由调用者按支持矩阵明确选择。 |
| 网关与所选执行主机异机 | 当前 `authorize_scoped` 对在线 `Binding::Remote` 返回 501，对已授权但离线的主机返回 503（`gateway/api/handlers/agent_apps/access.rs:197–226`）。统一授权分别报告无执行通道与执行主机不可达。后续只有已有可信执行通道、明确绑定、可达和功能齐备的执行端才能启用。子 3、54、56 验证错误分类。 |
| 所选方法依赖钥匙串，但实际执行 OS 用户的钥匙串缺失、锁定或不可访问 | 返回钥匙串不可用或访问失败。平台缺少该实现时报告能力不支持。钥匙串可访问但目标条目缺失属于账号未配置或需重登。当前 Claude 适配检查实际 HOME、拒绝 `CLAUDE_CONFIG_DIR` 覆盖并区分条目不存在（`crates/vw-agent-apps/src/auth/claude_keychain.rs:18–51,56–79`），AGY 上游有 macOS 门控和条目缺失分支（`services/agy_account/keychain.rs:79–83,96–117,186–217`）。子 7、29、54。 |

认证、授权与可预判的能力检查必须先于凭据读取、流程创建及 CLI 启动。失败后禁止转到其他主机、桌面本机、其他账号或其他存储介质执行。`gateway/instance.rs:35–57,91–110` 的 `resolve_directory` 只从 query、`x-vibewindow-directory`、网关 cwd 选择项目目录，`with_instance` 建立项目上下文，`load_local_project` 走默认租户项目查询。授权端点不用这些路径来决定租户、执行端、凭据根或钥匙串用户。主机标识只能匹配服务端登记和授权；客户端给出的绝对路径、命令、数据库键及任意 Tauri command 均不属于授权接口。

## 元数据与秘密

- **元数据由网关唯一持有。** 复用 `AuthAccountStore` → `GatewaySettingsStore` → `GlobalDatabase`。现有 `agent_apps.auth_accounts` 的配置键序列化 `(host, app, account_id)`，值为配置标记；`agent_apps.auth_defaults` 保存 `(host, app)` 对应的账号 ID（`crates/vw-agent/src/agent_apps/auth_accounts.rs:57–63,77–93,99–154`）。两后端共享 `gateway_settings` 的 `(platform_id, company_id, namespace, config_key)` 主键（`gateway/settings_store.rs:20–29,56–73`、`gateway/settings_store/postgres.rs:11–20`）。子 5、33–35 在现有适配内补齐作用域及一致性，数据库只存授权业务所需的安全标识、状态、绑定和默认引用。不能把元数据存在等同于秘密存在或流程已提交。
- **SQLite 由网关运行环境持有。** `GlobalDatabase::for_home` 从网关运行时 home 解析配置，缺配置默认 SQLite。正式构建为该 home 下的 `.shiju-harness/database/vibe-window.sqlite3`，调试构建用 `.shiju-harness-dev`。两个后端由相应配置目录下的 `database/config.json` 选择（`crates/vw-config-types/src/paths.rs:10–26,42–55`、`crates/vw-agent/src/global_database.rs:123–160,189–223`、`crates/vw-agent/src/global_database/config.rs:31–77`）。
- **PostgreSQL 元数据落在配置的数据库服务和 schema。** agent 使用 `VIBEWINDOW_DATABASE_URL` 和默认 `vibewindow` 或显式 schema 建立共享连接池，物理数据归 PostgreSQL 服务。缺连接配置或故障显式失败。两种部署均继续使用已有库及生命周期，无额外账号数据库、上游 `cc-switch.db` 或双写路径。见[存储与生命周期](../存储与生命周期.md)。
- **凭据由实际执行主机持有。** 现有 `CredentialFileStore` 使用策略提供的绝对私有根，把租户、主机、服务及账号编码成路径，校验私有权限与符号链接，同目录临时文件写入、同步和替换，租约覆盖子进程退出和凭据轮换写回（`crates/vw-agent-apps/src/auth/credential_file.rs:106–181,196–225,300–340`、`crates/vw-agent-apps/src/auth/credential_lease.rs:15–49`、`crates/vw-agent/src/agent_apps/auth_accounts.rs:24–47`）。当前仅支持 Claude token、Claude 受管目录和 Codex auth，AGY 明确要求隔离的 OS 钥匙串。子 6–7 复用适配并验证完整所有者作用域。文件方案要求私有目录和文件、原子替换、路径越界及异常权限拒绝。钥匙串方案要求获授权的 OS 用户、正确条目和访问控制，写后回读。原生单槽按物理资源序列化并核对来源所有者与代际。文件和数据库部分失败须可判定与恢复，不能发布无效凭据或覆盖别人的记录。
- **秘密的消费只发生在主机内。** access/refresh token、上游设备码、PKCE verifier、授权码、原始 Authorization 和含秘密的原生配置不进入数据库元数据、SDK 返回、事件、普通日志及 Debug。客户端只收脱敏状态、关联 ID、不透明流程 ID 和完成交互所需的用户码、经校验的登录链接。用户主动回填是定向输入，禁止回显或记录。模型目录、额度和代理仅能通过受控内部能力使用同作用域账号凭据。子 4、13、55 核验，母 5、7、8 各自负责目录、额度、代理逻辑。

## 上游原生槽及后续归属

`commands/auth.rs:18–22,70–78,174–270,373–388,390–544,544–727` 通过 Tauri `State` 按服务分派，处理目标账号、列表、默认、删除及登出，由 `lib.rs:1933–1940` 注册，`src/lib/api/auth.ts:69–138` 消费。它只覆盖 Copilot、Codex、xAI、Claude、AGY 五类。Kimi 与 DSH 经独立命令进入（`lib.rs:1946–1959`）。源命令参数和进程内状态不能提供网关调用者、租户或执行主机授权。

| 服务与现有来源 | 迁入后的槽位所有权及执行任务 |
| --- | --- |
| Copilot、Codex、xAI | 上游各自把账号数据保存在管理器数据目录（`proxy/providers/copilot_auth.rs:582`、`codex_oauth_auth.rs:403`、`xai_oauth_auth.rs:211`）。迁入时按服务和账号分离凭据，Copilot 会话令牌按同账号派生（子 11–13），Codex 只有已匹配身份的受管 live `auth.json` 才能吸收外部轮换（上游 1079–1250，子 14–18），xAI 刷新及失效由子 19–20 负责。 |
| Kimi | 上游 `services/kimi_oauth/mod.rs:170–191,923–1086` 区分配置指向的原生凭据与独立账号材料，`account.rs:179–245` 读写凭据。子 21–22 按地区和所有者读写目标材料，修改原生 profile 前校验槽位归属。 |
| Claude | `services/claude_account/layout.rs:28–86,102–153` 生成 `claude-accounts/<32 位小写 hex>/config`，拒绝非绝对路径、父目录跳转、根外或默认目录，并按目录字符串 SHA256 前 8 位选钥匙串 service。上游代码直接哈希原字符串，非 ASCII 可能与 CLI 的 NFC 规则不匹配。`services/claude_account/mod.rs:253–257,690–724` 用该布局分配登录目录及查删钥匙串。沿用本仓所有者目录与现有 Claude 钥匙串适配，其当前拒绝非 ASCII 目录，默认 CLI 槽需单独授权。子 23–24 拥有隔离登录和回填，子 25–27 拥有切换、恢复、外部轮换。 |
| AGY | `services/agy_account/mod.rs:152–158,280–357,434–461` 管理托管副本和当前 CLI 登录，`keychain.rs:63–81,120–181,186–217` 的原生条目固定为 service `gemini`、account `antigravity`。作用域账号仅能切入获授权的 OS 单槽，现用 CLI 可能写回。保留原 ACL 并回读核验，不迁入上游超长值进入命令参数的分支。子 7 负责安全钥匙串访问，子 28–30 负责浏览器流、切号和刷新。 |
| DSH | `dsh_config.rs:123,506–595` 的共享 `.credentials.yaml` 每个原生凭据文件只有一个 `deepseek-account-platform/default` grant，设备记录独立；写入及移除持文件锁。操作须校验原生槽归属，向上游发送凭据前校验 issuer，本地移除保留其他记录（`services/dsh_account.rs:177–253`）。子 31–32 拥有回调及共享文件，子 36–37 拥有本地登出、上游撤销及与刷新的竞争。 |

相同 OS 钥匙串用户、默认 CLI 目录或共享文件可被多个逻辑主机或租户引用。只要实际目标是同一原生槽，就必须在受信配置中确定其独占授权域，并在切换、写回或撤销时校验该域及账号。无法证明槽位所有权时拒绝，即使元数据的逻辑键不同。既有供应商事务继续由母 4 持有；账号绑定校验与删除解绑由子 33–35 持有，授权服务不得另建供应商配置写路径。

## 允许与拒绝示例

以下为合同审查案例，实际 HTTP、存储与 macOS 账号证据由子 54–64 交付。

| 请求或状态 | 判定 |
| --- | --- |
| 已绑定主体在获准公司和在线 macOS 本机执行主机启动受支持的设备流，凭据存储可用 | 允许。主机持有待兑换数据，Iced 显示登录链接和用户码。 |
| 正确 Basic 或配对 skey，提交另一公司的有效租户头，无法证明对该公司的成员权限 | 拒绝成员访问，连已有账号是否存在也不披露。 |
| 上游账号 ID 相同，但主体、公司、主机或服务不同；请求查询、取消、绑定、切换或刷新 | 在已授权作用域内判定缺失或拒绝。禁止借外部 ID 跨作用域寻找材料。 |
| 旧客户端持有流程 ID，当前主体不同，或原流程已取消后才收到回调 | 拒绝写入。并发撤销后的过期代际也不能恢复登录。 |
| 远端在线但无通道；已授权执行主机离线；异机浏览器只能到达自己的回环；钥匙串访问失败 | 分别报告无通道、执行主机不可达、回调不可达、钥匙串不可用。 |
| 两家公司获准访问同一 macOS 主机，但指向同一个 AGY 钥匙串槽 | 缺少可证明的独占授权域时，拒绝读、切换、吸收写回或移除该槽的凭据。 |
