# 桌面设备码登录弹窗

母任务 6／批次 50。依赖批次 49 的授权中心（`b9496f83b`）和批次 47 的[授权流程 SDK](提供授权流程SDK.md)。沿用已有的回环管理连接、授权主机和作用域策略。对照 cc-switch 4.0.25（`ca58c031`）的 `useManagedAuth.ts` 和 `KimiAccountLogin.tsx`。

在「设置 → 授权中心」的 Copilot、Codex、xAI 或 Kimi 卡片启动设备码登录。Kimi 提供中国大陆和国际入口，Copilot 使用主机的默认 GitHub 域。弹窗显示用户码、授权地区或验证域、验证地址和剩余秒数。倒计时来自主机截止时间，桌面按 SDK 返回的间隔读取状态，授权执行主机处理兑换、到期及提交。主机确认授权后刷新账号列表。

关闭弹窗、离开授权中心或切换管理作用域时，取消原流程。若启动请求已发出，桌面等待它返回流程 ID，再向原作用域发送取消。旧响应须匹配当前作用域与登录代次才可写入弹窗。失败可重试，重试分配新代次并重新启动授权。错误只使用固定界面文案，消息调试输出不含验证码、地址、流程 ID 或连接凭据。

首轮绿灯构建发现错误横幅收到 `&&str`，两个测试入口均退出 101。修正为 `&str` 后重新格式化、渲染和测试。macOS 链接器仍报告既有的 `__eh_frame` 大小提示。

聚焦测试通过真实回环 HTTP 套接字核对 SDK 的启动、状态查询与取消路径、服务、主机和租户头、Basic 与主体认证以及禁止缓存。Copilot 夹具验证授权域含端口、用户码、剩余时间、待定和批准。Kimi 夹具验证启动请求携带地区，关闭后迟到的启动响应触发原流程 DELETE，旧代次无法改写新弹窗。新的启动请求获得不同流程 ID，收到非 HTTPS 验证地址时显示失败并取消该流程。夹具使用合成账号与验证码。

实窗在隔离快照复用原生窗口目标加载生产授权中心视图和生产 Noto Sans CJK SC 字体。浅色窗口显示 Kimi 中国大陆，倒计时从 120 秒降至 118 秒。深色窗口显示 Copilot 授权域和端口。两个主题均显示中文动态码，未触发字形整形 panic。标题和底部取消固定在卡片内，正文复用 4px 滚动条及两侧 7px 留白。
