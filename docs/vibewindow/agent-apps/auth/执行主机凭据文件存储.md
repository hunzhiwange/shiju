## 所有者与文件边界

- 执行端从授权主机策略取得绝对凭据根。现有 `CredentialFileStore`、`CredentialLease` 及 agent 的启动账号适配复用同一文件实现。主机代码可在验证主体和动作权限后，通过 `CredentialFileStore::for_owner` 选择受管作用域。文件键依次包含平台、公司、可信主体、执行主机、服务和受管账号。受管作用域使用独立目录和小写路径摘要。既有启动记录继续读取原布局，macOS 验证实际目录项拼写以拒绝大小写别名。
- 目录使用当前有效 OS 用户的 `0700`，文件及租约锁使用 `0600`。从固定根目录向下逐级打开，拒绝符号链接、非预期文件类型、外部所有者、硬链接和 macOS 扩展 ACL。初次装载根目录时允许解析其上方的受信系统路径别名，例如 macOS 的 `/var`。租约写回前确认根、父目录和锁文件仍指向原来的对象。
- 原子写入在目标目录中独占创建临时文件，完成写入和同步后通过 `renameat` 发布。写入、复核或发布失败时清理暂存文件，保留既有记录。错误文本不带路径、输入值或凭据负载。
- 文件入口当前支持 Claude token、Claude 受管目录标记和 Codex auth。AGY 需要隔离的钥匙串。受管授权流程和其他服务原生槽位由后续批次接入。验收使用真实临时文件及合成凭据。
