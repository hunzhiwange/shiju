## 归属与持久化

- 现有 `AuthAccountStore` 通过 `GatewaySettingsStore` 读写 `gateway_settings`。平台和公司沿用数据库租户键，`agent_apps.auth_accounts.v2` 下的复合键依次是可信主体、执行主机、授权服务和不透明受管账号 ID。
- 调用方必须先核实主体、成员关系、服务动作和主机授权，再构建作用域。元数据仅包含已验证的上游身份摘要和认证时间。服务调用方负责将 issuer、地区等来源信息纳入规范身份。凭据就绪由实际凭据判断。
- 两库均使用同一个原子插入接口。重复提交返回 `conflict`，旧记录保持原值。不存在的作用域返回 `not_found`，非法身份返回 `invalid_input`。新命名空间隔离无主体的历史启动账号，原入口继续按既有作用域读写。流程提交、默认账号、绑定及 HTTP 授权入口各在后续批次实施。[安全边界](安全边界.md) · [接口契约](接口契约.md)
