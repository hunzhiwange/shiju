## 请求上下文与公开 DTO

按[安全边界](安全边界.md)校验管理链、可信主体与租户成员或明确委托、执行主机、操作能力，然后访问资源。平台与公司取已验证的租户头，所有者由服务端的主体或明确委托解析。每个请求的查询参数包含 `host_id` 和 `service`，前者只匹配受信主机登记。客户端提交的账号、流程和供应商 ID 均仅在当前作用域内解析。JSON 请求严格校验字段与服务组合。拒绝路径、命令、自定义 OAuth 地址及调用者指定的凭据键。授权资源的响应均使用 `Cache-Control: no-store`。

| DTO | JSON 字段与约束（子 4、55） |
| --- | --- |
| 账号 | `account_id`（不透明受管 ID）、`service`、`label`（供调用者显示的安全账号名）、`credential_state`（`ready`、`reauth_required`、`signed_out`）、`is_default`。可选 `authenticated_at`、`login_expires_at` 为 UTC Unix 毫秒，`github_domain` 和 `region` 仅由相应服务返回。受管 ID 不使用上游登录名、邮箱或设备码。 |
| 状态 | `service`、`default_account_id`（无默认时为 null）、`capabilities`。能力含 `login_methods`、`can_set_default`、`can_bind`、`can_revoke`，按服务、已授权动作及当前主机能力计算。账号就绪由凭据状态判定。 |
| 启动 | 请求为 `method` 及上表允许的可选 `github_domain`、`region`、`target_account_id`。响应为流程 DTO，启动时含 `verification_url`，设备流另含 `user_code`，Claude 返回 `can_paste`。 |
| 流程 | `flow_id`（独立生成的不透明随机标识）、`state`、`expires_at`（UTC Unix 毫秒）。仅 `pending` 含 `retry_after_seconds`（整数秒），仅 `approved` 含脱敏 `account`，仅 `failed` 含脱敏 `error`。挑战只在启动响应发放。 |
| 绑定 | `provider_id`、`service`、`account_id`。读列表可按 `account_id` 过滤绑定使用者。写入通过同一供应商事务，校验配置写权限、账号使用权和服务兼容性。 |
| 错误 | `code`、`message`（安全说明）、`correlation_id`。SDK 保留稳定码与关联 ID，UI 可按码本地化。 |

`verification_url` 只从主机适配器生成或校验后的允许 HTTPS 授权页发放，按服务校验目标及重定向配置。浏览器链接可含发起授权所需的 state 或 PKCE challenge。上游 device code、verifier、兑换授权码、access/refresh/id token 和原始认证头留在执行主机。Claude 的用户主动回填是定向敏感输入。所有 URL、用户码、回填值、流程 ID 和原始请求路径都应在调试输出、日志、追踪和错误展示中遮盖。服务支持条件及账号查询权限与 [安全边界](安全边界.md) 一致。

## 状态机

- 启动后为 `pending`。设备流只由执行主机按上游间隔发起兑换，同一流程至多一个在途兑换。客户端过早或并行 GET 只读取快照，不加速兑换。`authorization_pending` 保持状态，`slow_down` 延长间隔并返回新等待时间。主机负责到期清理，桌面退出不影响该责任（子 8、10，来源 `proxy/providers/copilot_auth.rs:780–833`、`services/kimi_oauth/mod.rs:754–838`）。
- 浏览器回调由执行主机监听。按方法校验回调地址、路径、state 和有效流程，使用该流程的 verifier 兑换。无法到达约定回环的 Codex、AGY 或 DSH 启动请求提前拒绝。Claude 可通过显式回填完成，向原 CLI 写入格式有效的代码，或转发与原流程端口匹配的回环 URL，仅由主机按绑定端口转发且禁止代理和重定向。回填接受仅表示已交给原流程，客户端继续轮询（子 15、23–24、28、31、51、54；`services/claude_account/login.rs:87–149`、`services/dsh_account.rs:538–579`）。
- 唯一提交点重新校验作用域、目标身份、流程仍为 `pending`、未到期且代际有效。凭据和元数据成功提交后转 `approved`。到期转 `expired`，用户拒绝、身份冲突或不可恢复错误转 `failed` 并带安全错误。四种终态不可逆。重复 GET 返回同一已知终态，回收后统一按 `not_found`。账户后续失效通过账号查询反映（子 5–10、16、37、40）。
- 取消先使流程失去提交资格，再关闭监听、停止或等待 CLI、清理临时秘密，转 `cancelled`。同一已取消流程可重复确认取消，其余已知终态返回冲突。迟到回调及在途兑换只可丢弃结果。DSH 上游 `auth_cancel` 可尽力终止发起的尝试，本地取消成功取决于本地清理（子 9、31、41；`services/dsh_account.rs:661–685`）。

## 默认、删除与撤销

- 供应商只解析显式且匹配服务的可用绑定。默认账号只服务于声明使用默认的调用者。删除时即使引用者对请求方不可见，也必须检测并拒绝，错误不列出其身份。删默认后不另选账号。Kimi 上游移除默认原生记录只隐藏（`services/kimi_oauth/mod.rs:1010–1055`），本合同只删除授权作用域所拥有的材料；无法证明原生槽所有权时拒绝操作。AGY 删除托管副本与切换 CLI 登录分开。供应商配置唯一写入者为母 4，子 33–35 负责账号侧校验和默认、删除的一致性。Codex 上游删除会锁内解绑（`commands/auth.rs:544–617`），本合同统一采用先显式解绑以避免隐式修改卡配置。
- `logout` 终止所选账号的定向流程并清除本地凭据，`all` 还终止同作用域未指定目标的流程。默认选择仅在支持默认且确有目标时可用，分别以 `unsupported` 和 `not_found` 报告不支持和缺少目标。`all` 也受服务和所有者作用域约束。保留账号记录与绑定以供诊断，将凭据状态改为 `signed_out`，清除指向该账号的默认，解析绑定时拒绝使用。清理仅覆盖已授权且明确归属的原生槽或托管材料。AGY／Claude 上游的 `remove_all` 清理托管材料，不能据此推断另一个原生 CLI 登录已退出。通用上游 `auth_logout` 为服务级清理，Codex 仅处理本机所删账号（`commands/auth.rs:668–735`）。子 36–37 负责作用域、代际失效和重试。
- 远端撤销只对 DSH 有已查来源支持。源 `sign_out` 先移除共享 grant，再以原 token 请求 `POST /auth-api/v0/users/logout`，失败仍保留本地登出（`services/dsh_account.rs:93–138,177–186,236–253`）。新端点先校验 issuer，再按同一账号代际失效本地 grant，仅在本次请求内暂持用于远端撤销的 token。请求禁止跳转，只有上游 HTTP 与业务码均确认成功才返回 204。若目标已无可撤销凭据，返回 `conflict`。若本地失效失败，返回存储错误并停止远端请求。若远端失败或结果不明，保留本地登出并返回 `remote_revocation_unconfirmed`，SDK 可重新查询本地状态。其他六类的已查路径为本地删除、移除副本或清缓存，`revoke` 返回 `unsupported` 且没有副作用（`commands/auth.rs:544–727`、`services/kimi_oauth/mod.rs:923–943,1010–1055`）。删除、登出及撤销须阻止旧代际的刷新、CLI 写回或登录提交恢复账号，子 36–37 验证。

## 错误与判定示例

复用[任务事件与错误契约](../任务事件与错误契约.md)的安全错误投影。下表 HTTP 状态用于请求失败。若流程进入 `failed`，轮询仍返回 200，流程中的 `error` 使用对应领域码。认证链先处理身份和授权，跨作用域的资源 ID 与随机不存在 ID 使用同一 404 表现。

| HTTP | 稳定码 | 条件 |
| --- | --- | --- |
| 400 | `invalid_input` | 租户头或请求字段缺失、重复、不合法，未知服务或方法，域不合法、地区与目标冲突、回填格式或回环地址错误。 |
| 401／403 | `unauthenticated`／`forbidden` | 无有效管理或主体凭据，或已认证但缺少可信成员绑定、所选主机、动作或原生槽授权。沿用认证链状态。 |
| 404 | `not_found` | 在已授权作用域找不到目标主机、账号、供应商或流程。 |
| 409 | `conflict`、`account_in_use`、`identity_mismatch`、`codex_oauth_duplicate_account`、`reauth_required` | 分别对应流程或原生槽冲突、删除时仍有引用、定向登录身份无法匹配、Codex 身份已归另一记录、目标凭据不可用且需重登。 |
| 409 | `callback_unreachable` | 执行主机的回环对实际浏览器不可达且所选方法无安全回填。 |
| 501 | `unsupported`、`execution_channel_unavailable` | 服务或平台缺少所选能力，或已授权在线远端缺少可信执行通道。 |
| 502 | `upstream_failure`、`remote_revocation_unconfirmed` | 上游响应无法安全处理，或 DSH 本地已登出但远端撤销结果未确认。 |
| 仅流程错误 | `authorization_denied` | 用户在上游拒绝授权，流程转 `failed`。 |
| 503 | `execution_host_unavailable`、`keychain_unavailable`、`storage_unavailable` | 已授权主机离线、钥匙串锁定或不可访问、数据库或凭据写读失败。可恢复故障不得当作成功或凭据永久失效。 |

关联 ID 只关联本次错误，诊断记录限操作类型、稳定结果码及关联 ID。取消、删除、登出或撤销的响应丢失时，先读取状态确认已生效的动作，再按当前状态操作（子 40、45–48、54–55）。

| Codex 目标重登取得同 workspace、同用户但邮箱改变；另一尝试撞到已有记录 | 前者原 ID 更新，后者报 `codex_oauth_duplicate_account` 且保留原记录。子 16、58。 |
| Kimi 新登录选全球，已有大陆账号重登时显式选全球 | 新登录走全球端点。重登请求拒绝，保持原地区与凭据。子 21–22、60。 |
