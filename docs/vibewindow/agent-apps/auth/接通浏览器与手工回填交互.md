# 接通浏览器与手工回填交互

母任务 6／批次 51。直接前置是批次 50 的桌面设备码弹窗（`0a9c92a4e`）。累积前置可追溯至批次 1 的来源映射，浏览器和 Claude 回填消费批次 39–41 的网关路由及批次 47 的流程 SDK。沿用批次 4 的开工边界，核对冻结来源、已注册原生包、管理鉴权、执行主机、存储和供应商事务。来源为 cc-switch 4.0.25（`ca58c031`）的 `authLoginLink.ts`、相邻测试及 Claude 官方账号表单。[设备码弹窗](展示桌面设备码登录弹窗.md) · [流程 SDK](提供授权流程SDK.md) · [开工边界](脱敏账号与流程DTO.md#开工边界)

第 50 批的 `agent_apps_auth/device.rs` 扩展为 `agent_apps_auth/flow.rs`，链接和回填交互放在 `agent_apps_auth_browser.rs`。授权中心默认自动打开浏览器。关闭偏好后复制执行主机发出的授权链接，本机 `auth-browser.json` 只保存这个布尔值。设备码和浏览器流程共用这项偏好。弹窗保留「打开浏览器」和「复制链接」按钮，系统操作失败时显示固定错误 toast。Claude 在复制模式下按 `copy_link` 启动，其他服务按自身支持的浏览器或设备码方式启动。桌面只接收校验后的 HTTPS 挑战，额外拒绝含用户信息或控制字符的链接。

只有主机声明允许回填的待定 Claude 流程才显示遮罩输入框。编辑及提交事件绑定弹窗代次，发送队列随原流程关闭。原流程的 SDK 任务持有请求的网关、租户、主机及流程 ID。回填请求获得 202 后继续轮询，只有主机确认批准才刷新账号。关闭、切换作用域或重试会丢弃未发送的旧回填并忽略迟到结果。客户端不保存 OAuth 令牌或回填内容，事件调试输出省略敏感输入和授权链接。

红灯的占位实现触发两个断言，分别为 `reopening the desktop must preserve copy-only mode` 和 `a replaced login must reject stale paste events`。首轮绿灯编译发现链接交付分支同时可变借用应用和登录状态，修正后两条聚焦命令均重新运行。macOS 测试链接仍有既有的 `__eh_frame` 大小提示。

聚焦用例通过临时文件验证默认打开及重启后保留复制模式，通过可替代的浏览器与剪贴板边界验证精确链接及固定失败提示。真实回环 HTTP 夹具核对 `copy_link`／`browser` 请求体、管理凭据、租户、执行主机和 `/flows/{flow_id}/paste` 路径，覆盖 202 后继续轮询、重复及旧代回填、作用域切换取消、主机拒绝以及带用户信息的无效 HTTPS 地址。厂商公网登录沿用后续各服务验收批次。

实际 macOS 窗口复用生产授权中心、弹窗和 Noto Sans CJK SC 字体。先用截图定位长链接挤压回填框，再将完整地址移到回填区之后。最终截图验证明暗主题下的输入框、遮罩、固定按钮、中文动态账号和倒计时，未触发字形整形 panic。滚动正文沿用 4px 滚动条和两侧 7px 留白。
