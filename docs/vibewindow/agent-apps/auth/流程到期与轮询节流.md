# 流程到期与轮询节流

母任务 6／子任务 10。沿用[主机内授权流程状态机](主机内授权流程状态机.md)与[取消后的提交保护](阻止取消后回调复活登录.md)。前置批次 1–9 的交付依次为 `cd0dfb217`、`14acbba54`、`c7d8474f1`、`f2e90ecc8`、`ba4883457`、`ceb96d943`、`d6037055c`、`a016b9f18`、`c209eeea2`。对照 cc-switch 4.0.25（`ca58c031`）的 Copilot 设备兑换和 Kimi `services/kimi_oauth/mod.rs` 中的首轮等待、`authorization_pending`、`slow_down` 与 `expired_token`。

- 执行主机调用 `AuthFlows::poll_device` 推进设备授权。首轮遵守启动间隔，同一流程至多一个兑换在途。待授权保持原间隔；每次 `slow_down` 将当前间隔累加 5 秒，并从收到该响应后按新间隔等待。状态读取调用 `snapshot`。
- 流程以单调时钟判定到期。主机维护任务调用 `reap_expired`，独立于桌面和状态查询。到期先阻止提交，再调用注册的清理操作；失败时保留操作供下次扫描重试，终态仍可查询。供应商适配器负责结束其实际资源，后续主机装配负责调度扫描。
- 兑换留在提交锁外。响应返回后再次核验流程仍有效，再通过既有作用域和账号校验进入写入操作。到期或取消后的响应无法写入。上游明确返回 `expired_token` 时也转入 `expired`，由主机扫描完成清理。
