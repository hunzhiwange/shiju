# 绑定供应商与授权账号

母任务 6／批次 33。前置批次 1–32 已核对。复用母任务 4 在 `aaf217b6f` 交付的 [Kimi 供应商事务](../../../shiju/agent-apps/provider-contracts.md#供应商事务交接给统一账号授权批次-33)。来源为 cc-switch 4.0.25（`ca58c0313360eae7c851fbd7553c1614c7af03e7`）的 `src/lib/authBinding.ts`、`src-tauri/src/commands/auth.rs` 及相邻供应商表单测试。历史 `githubAccountId` 回退留在来源。

- `AppProviderStore::bind_kimi_account` 和 `kimi_account_binding` 复用同一主机事务和受管账号存储。服务端先校验 Kimi 官方连接、执行主机及账号的租户、可信主体和服务。写入方在发布前复核账号、档案和原生凭据。已提交的绑定只返回账号引用，凭据留在主机。
- `AppProviderStore::use_kimi_account_binding` 取同一档案快照及已提交引用。Kimi 适配在消费时再次要求显式绑定，复核账号、区域、原生 OAuth 槽、档案及原生连接，并在模型选择发布时检查档案仍匹配。缺失绑定读取为空，消费返回 `not_found`，即使作用域已有可用账号和原生默认模型。过期档案或连接变化返回 `conflict`。原有显式选号独立保留。
- 当前绑定事务只支持已有的 Kimi 官方 OAuth profile 与身份匹配的有效 grant。该适配对其他授权服务返回 `unsupported`。绑定的业务落点沿用 `auth/kimi_account.rs` 和 `auth/kimi_account/binding.rs`。统一 HTTP 接线归批次 42，真实账号和客户端归后续专项验收。
