# 阻止取消后回调复活登录

母任务 6／子任务 9。复用批次 8 的 `vw_agent_apps::auth::flow::AuthFlows` 和已有测试注册。对照 cc-switch 4.0.25（`ca58c031`）的 Kimi 提交前复核、Codex 等待账号锁期间取消及 Claude CLI 终止后等待退出。参见[主机内授权流程状态机](主机内授权流程状态机.md)与[接口契约](接口契约.md)。

- 通过 `start_with_cleanup` 把适配器的本机清理操作绑定到一次有作用域的授权。没有本机资源的流程仍使用 `start`。清理操作关闭监听或终止并等待 CLI 退出，也负责清理适配器的临时秘密。
- `cancel` 先在提交锁内阻止完成，再释放提交锁并等待清理。兑换留在锁外，迟到结果返回 `conflict`，不会调用写入操作。先完成提交的流程保持原终态，随后取消返回 `conflict`。
- 清理成功后发布 `cancelled`，重复取消直接确认。清理失败时仍禁止提交，快照暂为 `pending`，原作用域可以重试清理。跨作用域取消返回 `not_found`，不会触及清理操作。
- 此处确认本机取消。供应商适配器负责实际进程与监听器的生命周期，远端撤销由供应商能力单独报告。
