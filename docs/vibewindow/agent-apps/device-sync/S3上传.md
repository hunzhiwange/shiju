# S3 制品上传契约

`device_sync::s3_transport::S3UploadTarget::new` 消费已解析凭据的 `S3Config` 与共享快照所有者提供的非零兼容版本；不保存配置或申请网络授权。Gateway 负责执行授权、锁内重读凭据、快照过滤及发布顺序。

`upload(UploadArtifact, Vec<u8>)` 仅接受 Config、Skills、Manifest，目标为 `remote_root/profile/shiju-device-sync/v1/data-v{version}/{artifact}`（格式与协议段使用 manifest 常量）。配置路径解码一次后由签名器编码，禁止任意对象名。config.json 使用 application/json，skills.zip 使用 application/zip，manifest.json 使用 application/octet-stream，与 WebDAV 一致。

制品沿用 MAX_ARTIFACT_SIZE，manifest 沿用 MAX_MANIFEST_BYTES；超限在签名与网络操作前拒绝。SigV4 签署 Content-Type 和原始完整字节，直接执行返回的请求。请求总超时 30 秒，不跟随任何重定向，不自动重试。仅 2xx 成功；超时或网络失败可能已写入远端。调用方必须最后发布 manifest。

错误只包含 PUT、可选 HTTP 状态与静态说明，不保留 URL、查询、原始网络错误、响应体或秘密。暂不支持 session token；沿用现有签名器能力。

本轮仅实现并静态审阅，依用户指令未运行 Cargo、单元测试、loopback 或实机验证，未领取构建槽位。签名 PUT、Content-Type、原始字节、状态与网络错误的运行验证留待统一执行。
