# 同步任务持久化契约

任务 37：生产实现已交付，未验证。按本轮指令未执行 Cargo、单元测试、实机测试或最终回归；未领取构建槽位，未设置 CARGO_TARGET_DIR。后续统一验证持久化、重启恢复、提交后状态写入失败及租户隔离。

网关在取得执行主机的独占所有权、完成完整目标授权后，调用 `device_sync::tasks::initialize(database, target)`，再接受该目标的任务。重复初始化不重新恢复当前进程中的任务。没有初始化的目标拒绝接受任务，返回 `StatePersistenceFailed`。后续 API 和调度任务负责调用此入口；本模块不启动调度器或网络操作。

任务日志存入统一 `GatewaySettingsStore` 的 `device_sync.status.local.v1` 命名空间，按租户及完整目标（项目、主机、主体）隔离；此命名空间不产生同步变更提示。日志保留幂等请求、来源 manual/auto、进度、提交事实和终态；按传输分别保留最后成功、最后错误和成功 manifest 基线。只存类型化安全错误码，不存配置、凭证、归档或原始传输错误。

初始化将持久化的非终态任务标为 interrupted，保留已记录提交事实；恢复失败则拒绝初始化。恢复不自动重放上传、下载或本地写入，旧 request ID 仍返回同一个任务。状态写入使用条件替换，检测并发更新，不覆盖其他写入者。执行主机独占所有权由网关生命周期保障，不能让多个进程同时恢复同一目标。

提交边界前，无法持久化的任务变更返回明确错误并恢复内存前像。提交完成后或终态写入失败时，保留内存中的真实结果，并增加 `StatePersistenceFailed` 警告，不撤销已完成的数据写入。后续状态读取可看到该警告。若数据库持续不可写并且进程退出，重启只能依据最后持久化记录判断中断，不能宣称获知未落盘的提交结果。
