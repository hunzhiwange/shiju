# 制品完整性

任务9实现 `vw_agent_apps::device_sync::artifact`，消费任务3同步契约，不依赖尚未交付的 manifest 解析器。解析器将固定制品名、声明 size 和小写 SHA256 映射为 `ArtifactDeclaration`。

下载端在读取 body 前调用 `ArtifactVerifier::new`，校验声明与可选 Content-Length；逐块先 `update` 再写隔离暂存。任一错误或传输中断均丢弃暂存，不进入应用阶段。成功 EOF 后调用消耗 verifier 的 `finish`，仅长度完全相等且 SHA256 一致才能取得 `VerifiedArtifact`。应用端必须消费同一份受控暂存内容，不能根据凭证重新打开可被替换的任意路径。该模块没有网络、文件写入或应用副作用，传输接线由后续任务23/27负责。

512MiB 为单制品包含端点的上限；每块累计长度校验在摘要更新之前执行。失败状态不可恢复；短流、超声明、超限或摘要不符均无校验凭证。模块只保留摘要状态，不为声明长度分配缓冲区。底层传输须使用有界块，禁止先聚合整个响应。

`compute_snapshot_id` 要求恰好 config.json 与 skills.zip，拒绝重复、未知名称、非法摘要及超限声明；按名称排序，用 `name:sha256|name:sha256` 的 UTF-8 字节计算 SHA256 小写十六进制，不包含时间。此函数只计算声明身份，不能替代下载校验或 manifest 原始字节并发摘要。

未验证：按用户本轮指令，未运行 Cargo、任何测试或最终回归，未领取构建槽位。后续统一验证应覆盖空制品、多块、截断、错误摘要、Content-Length 不符、失败后 finish、声明512MiB边界及排序稳定性；本轮不新增测试文件。
