# 任务 15 · OpenCode MCP 配置适配

## 前置与实现

- 核对任务 03 的管理契约（`2a85d1b93`）、任务 04 的连接校验、任务 09 的 `McpCatalogStore::resolve_for_execution`（`9bc4e9ceb`）和任务 10 的 `NativeFile`、`JsonServerPatch`（`584684b57`）。两次 `git show | cmp` 确认仓内 `mcp/opencode.rs` 与 `opencode_config.rs` 均匹配固定来源 `ca58c0313360eae7c851fbd7553c1614c7af03e7`。
- 核对了网关已有供应商授权入口和 `AppInstallation`、`LocalReadEnvironment`。适配器 `mcp::adapters::opencode` 使用授权主机上的 `OpenCodeFiles`，优先选择 `opencode.jsonc`，缺失时选择 `opencode.json`。MCP 与供应商事务共用目录锁和发布前路径优先级校验。变更使用 `NativeFile` 在同一个 `ProviderTransactions` 所有者下发布。受管绑定归属和目录修订由执行方通过发布前回调复核。
- `apply` 将 stdio 投影为 `local`、命令数组和 `environment`，将 SSE 投影为带 URL 与 headers 的 `remote`。按固定快照，原生 `remote` 读回 SSE。Streamable HTTP 无法独立往返，显式返回 `UnsupportedTransport`。不支持的 `cwd`、未解析引用、格式错误和文件冲突各有结构化结果。需要注入的账号凭据沿用任务 09 的执行主机解析，适配器只写解析后的字段。
- 新增同名项时保留用户配置。更新只替换连接字段并保留启用状态。禁用写原生 `enabled: false`，删除移除已核实归属的条目。只读 `read` 独立返回每个候选或错误。候选可含原生凭据，只在主机侧传递，未建目录时读取得到空结果。导入遇到 `oauth` 等无法往返的选项会逐项报错。
