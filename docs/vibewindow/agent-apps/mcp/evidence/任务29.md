## 2026-11-12 补充受管详情读取

提供 `vw_agent::acp::read_catalog_mounts(&ProjectScope, session_id)`，返回 `CatalogMountSnapshot { project, sessionId, revision, catalog }`。逐项 `CatalogMountSelection` 包含原始 `McpCatalogMount { scope, record }` 与 `failure`。`failure=None` 表示精确目录修订仍存在，`StaleRevision`、`NotFound` 和存储错误分别报告。响应代表 `MountRecord` 的已提交选择代次，连接存活与工具调用授权由既有执行链路判断。

读取先用 `ui_store::load_agent_session_strict` 按租户、项目和会话精确取元数据，从记录取得目录，再经 `SessionScope::new` 与 `runtime::validate_session_scope` 复核会话归属，最后读取并验证 `mount_store::load` 的绑定哈希。持久化引用还须属于同租户或同项目。普通原生会话没有 ACP 提交时返回 NotFound。读取不接受客户端目录，也不恢复连接或加载历史。返回投影仅有身份、引用、挂载修订和逐项状态。

管理 API 的最小输入是 `targetHostId + ProjectScope + sessionId`，目录只能由上述服务端链路确定。调用方须先完成当前执行主机及该项目/会话的认证授权。`agent_apps::authorize_mcp_catalog_read` 仅证明租户和策略目标主机成员资格，不能单独当作会话读取许可。`authorize_mcp_native_read` 可解析受信本地主机环境，但应用配置的 home 仍需与当前 ACP 运行时的存储身份一致，不能根据客户端目标标识或任意应用配置 home 推断挂载所属主机。若详情入口仅持有单记录的 `McpProbePermit`，还须按许可中的目录作用域和记录 ID 过滤内部快照，不能顺带返回同会话的其他引用。该读取函数作为入站 ACP 所有者的底层入口，管理路由与 SDK 由对应任务接线；不以同名服务、原生 CLI 绑定或桌面出站 ACP 配置推断关联。

聚焦测试 `cc_mcp_t29_read_mounts_checks_exact_identity_and_exposes_only_committed_references` 使用独立进程、真实 SQLite、真实原生会话与 stdio MCP 进程。验证精确身份、空挂载与无 ACP 提交的区别、跨租户/项目/会话拒绝、过期与删除状态、读取不重启进程、返回不含命令及路径、损坏引用的作用域拒绝。
