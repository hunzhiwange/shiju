`probe_jobs::start_connection_checks` 将授权后的服务 ID 和连接修订提交给执行主机共享的 `DiagnosticJobs`。底座登记任务所有者与取消令牌，跨批次共享三个活动探测名额。每项拿到名额后才开始 30 秒探测计时。取消通过同一个注册表按所有者和任务 ID 执行。stdio 探测启动时将子进程转交给批次，取消、超时及探测完成后终止私有进程组并回收直接子进程，然后交还名额。握手尚未完成时也能清理。网络探测复用任务 30 的 MCP 握手与工具发现。Streamable HTTP 使用探测生命周期令牌中止 rmcp 后台 worker 的请求及响应流，显式检查禁用 HTTP 与 SSE 重试。

`DiagnosticResult::McpConnectionCheck` 携带目录作用域、请求代次、服务 ID、连接修订和脱敏结果。任务 ID 来自诊断快照。`McpCatalogStore::current_connection_check_items` 接受当前请求的任务 ID 与代次，检查目录作用域及现有连接修订。进行中的旧连接成功也会被判为 `StaleRevision`。保存相同连接后，记录修订变化仍保留可用结果。任务 39 负责网关路由接线，调用方在等待启动响应期间收到取消时可使用最终返回的任务 ID 调用底座取消。
