# 任务 34 · 更新 MCP 目录 API

## 接口与实现

`PUT /v1/agent-apps/mcp/{id}` 接受 `McpUpdateRequest`：必填 `targetHostId`、`expectedRevision`、`connection`，可选 `projectId`。租户来自认证中间件，拒绝客户端提交租户字段或其它未知字段。成功返回 `200` 和公开 `McpCatalogRecord`，不返回连接定义或原生同步成功状态。

真实入口为 `mcp_management_read::router`，已被 `agent_apps::router` 合入 Basic 管理路由和 bootstrap skey 客户端路由，因此不重复修改 bootstrap。父模块注册 `mcp_management_update` 及独立的 `mcp_management_update_tests`。处理函数 `update_catalog_record` 复用任务 33 的 `authorize_mcp_catalog_write`，要求可信目标主机及相应租户/项目目录写权限；缺省拒绝。

业务更新直接调用 `McpCatalogStore::update_connection`：检查调用者作用域内的预期修订，递增目录修订和实际变化的连接修订，保留显示元数据及底层既有的凭据引用保留规则，通过存储比较并交换保存。陈旧修订返回 `409 stale_revision`，不存在/已删除项返回 `404 not_found`，非法定义返回 `400 invalid_definition`，存储不可用返回 `503 storage_unavailable`。沿用目录路由的 `Cache-Control: no-store`。

更新只保存期望定义，不触发握手、stdio 进程或原生配置改写。原生分发仍归既有绑定/重同步事务，凭据仍归执行端解析，更新响应不代表实际同步成功。
