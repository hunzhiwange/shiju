## 接口与实现

接口 `DELETE /v1/agent-apps/mcp/{id}` 接受 `McpDeleteRequest`：`targetHostId`、`expectedRevision`，可选 `projectId`。租户来自认证中间件；未知字段（包括客户端租户字段）拒绝。入口复用 `mcp_management_read::router`，由既有 `agent_apps::router` 同时合入 Basic 管理路由和 bootstrap skey 路由，无需重复注册 bootstrap。

`mcp_management_delete::delete_catalog_record` 先复用 `authorize_mcp_catalog_write` 校验成员、可信主机及目录作用域，再调用 `McpCatalogStore::delete` 保存删除记录。陈旧修订返回 `409 stale_revision`，不存在返回 `404 not_found`。删除期望定义与原生清理分别报告：成功响应为 `McpDistributionResult`，每个目标携带删除修订、`enabled=false`、`desiredCommitted=true` 及原生结果；部分原生清理失败返回 `partially_succeeded`。沿用 `Cache-Control: no-store`，不返回连接定义或原始错误。

逐目标清理重新校验该主机的目录写权限、既有 provider 配置写权限及管理员配置的安装搜索根。`authorize_mcp_native_write` 从授权主机快照取得本地发现环境与私有事务根；安装 ID 经 `resolve_cli_installation` 和实际发现重新验证。实际写入复用 `McpCatalogStore::revoke_app_binding`、`McpBindingTarget` 与 `ProviderTransactions`，不引入另一套原生写入通道。已成功清理的目标直接返回 `unchanged`，不再改写后来出现的外部替换配置；失败结果保留，重试只继续失败目标。未拥有原生项的成功空操作也返回 `unchanged`。

既有 Claude 绑定没有保存原始账号/profile 身份。本接口对此返回逐目标 `credential_unavailable` 并保留撤销记录，不推断默认账号或使用本机 HOME。清理不解析已删除连接定义的凭据。非 macOS 原生清理明确失败，本任务仅验收 macOS。
