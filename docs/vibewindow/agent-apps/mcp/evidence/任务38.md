## 接口与实现

`POST /v1/agent-apps/mcp/resync` 接入现有 `mcp_management_read::router`，沿用 Basic 与 bootstrap skey 认证及 TenantScope 中间件。`agent_apps::router` 为提交及现有生命周期查询路由共享本任务的有限作业集合；bootstrap 自动复用该 router，无需重复注册。

请求示例：

```json
{"targetHostId":"host","targets":[{"appId":"codex","installationId":"发现得到的ID"}]}
```

可选 `projectId` 选择项目目录，省略选择租户目录。`targets` 为1–12个不同的受管应用，Claude另需授权官方账号的 `accountId`，其它应用不得设置。拒绝未知字段、外部路径、空安装ID、重复应用和不支持原生分发的Claude Desktop/OpenClaw；安装不存在在逐应用结果中报告。非macOS明确返回501，不伪造支持。

返回202及底座 `AppActionExecutionResult`（`operationId/status`）。复用以下资源，查询均需 `targetHostId`：

- `GET /v1/agent-apps/operations/{id}?targetHostId=host`
- `GET /v1/agent-apps/operations/{id}/events?targetHostId=host`（既有长轮询）
- `DELETE /v1/agent-apps/operations/{id}?targetHostId=host`

查询在底座 `AppOperationStatus` 上增加 `outcome` 与 `targets`。每个目标带 `appId`，成功进入分发的应用带 `distribution: McpDistributionResult`，目标解析/授权失败带封闭 `code`。作业执行期间逐应用更新已完成结果；结束后保留全部目标结果，包括取消项。部分成功时 `outcome=partially_succeeded`，底座作业状态为 `failed`，成功项仍完整保留。响应不包含连接定义、原始错误、主机路径或凭据。作业为进程内状态，进程重启不恢复；最多保留1024个作业，满时先回收终态项，仍满则429。

`mcp_management_resync::submit/run` 复用 `McpCatalogStore::resync_apps`、底座 `Operation::start_task`、`McpBindingTarget`、发现的安装实例、`ProviderTransactions` 和 `AuthAccountStore`。无独立命令分发、配置写入器或秘密存储。写入及发现移到阻塞线程执行；目录期望和修订保持不变。提交、排队后、逐应用写入前再次校验目录及原生配置写权限，凭据使用时重新检查账号绑定授权。主机home/事务根变化时明确拒绝继续写入。

`agent_apps::lifecycle::OwnedOperation` 增加MCP作业分支，复用原查询、事件和取消入口。查询/取消检查保存的租户、主机和目录范围，并重新授权；跨租户/错误主机隐藏作业存在性返回404。取消调用底座 `cancel_and_wait`，确认worker结束后重新授权并返回结果，不回滚已完成事务。认证或成员授权失败不能创建作业。
