# 任务48：桌面重新同步进度

## 入口与边界

MCP 设置页的“重新同步”进入统一设置弹窗，选择当前网关、租户、主机及凭据代次对应的可信 macOS 安装实例；每种应用最多一个实例。Claude 使用官方账号 ID 引用，凭据在执行端解析；Claude Desktop、OpenClaw 明确不支持。未选择目录项时同步租户目录；选择目录项时使用其共同作用域，同步该作用域在所选应用上的全部受管绑定，不仅是勾选记录。混合作用域、过期记录和陌生安装不能提交。

真实 UI 入口为 `system_settings_mcp::{view,view_overlays}` → `system_settings_mcp_resync::{panel,overlay}` → `message/settings/mcp_management_resync::update/execute`。复用任务42交付的 `McpResyncOperationStatus`、`McpResyncTargetResult` 及 `mcp_management_resync_status/cancel`，没有自行解析作业 JSON、直连文件或新增执行通道。作业先读取实际目录及目标主机原生状态，再提交 SDK `mcp_management_resync`；500ms 间隔读取同一作业，展示阶段、状态、已报告目标数量、整体结果与逐应用/逐记录结果。

取消复用授权 operations DELETE，等待执行端确认，不回滚已完成事务；取消使在途轮询的旧代次结果失效；取消请求在途期间，重复点击不会再发请求。终态后重新读取目录及各目标原生状态，读取失败明确显示。仅重试明确失败的应用，保留原请求作用域、安装身份和账号引用；重试前再次读取实际目录/原生状态，未出现失败项的成功或取消应用不会被自动纳入重试。

连接、租户、项目、主机、凭据代次及请求代次隔离迟到响应。查询失败保留原作业 ID，可刷新恢复；提交响应丢失或无法解析时禁止重放，明确提示核对执行端。已确定的4xx拒绝及预检失败允许用户修正后重试。响应中的错误作业 ID、未知/重复应用、目标主机/安装不匹配、重复记录或终态异常缺项不会被当作成功。
