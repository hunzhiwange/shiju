## 生产链路

- `POST /v1/agent-apps/mcp/tools/discover`：query复用 `DiagnosticScopeQuery`（projectId/targetHostId/appId），body为 `McpToolDetailsRequest { scope, record, connectionRevision, generation }`。在打开数据库前校验独立成员凭据、租户、项目、可信本地主机、MCP探测许可及已有provider_config_read配置读取许可，拒绝scope或连接修订不匹配。探测许可本身不能读取持久化项目选择，McpProbeAccess::authorize_details在每个执行/发布检查点重新校验两类许可及同一主体。精确记录修订、stdio定义摘要/可信workspace、URL摘要及凭据引用仍由原 `McpProbeAccess`/`McpHandshakeProbe` 校验。
- `network_probe/details.rs::start_details/discover_details` 复用同一 `DiagnosticJobs`、真实受限检查传输、凭据解析、30秒期限和进程清理。查询/取消复用 `/v1/agent-apps/diagnostics/jobs/{id}` 及 `/cancel` 的原主机、项目、应用、提交主体校验。新增 `DiagnosticResult::McpToolDetails` 保留完整请求身份。
- 真实tools/list复用有界分页加载器及 `mcp_tools_to_specs`，返回正式ToolSpecDto（身份、稳定ID、schema、注解与exposure）。连接错误和工具发现错误分开，仅发布McpFailureCode；不返回原始传输错误、私有连接或凭据。规格是发现结果，未授予工具调用。
- `McpCatalogStore::runtime_usage` 只读取已授权项目、同scope/ID的原StoredSelection，返回所选修订、disabled、generation及修订是否仍存在；不修改选择，不解析连接凭据，不用原生绑定推断运行时。即使工具发现失败，仍可独立显示已授权的选择快照。
- `GET /v1/agent-apps/mcp/acp-mounts/query`：query为 `McpAcpUsageQuery { targetHostId, projectId, sessionId }`。新增默认空的管理员许可 `mcp_acp_read: [{ "project_id": "project", "session_id": "exact-session" }]`，与既有租户和主机grant同时匹配。普通目录读取、MCP连接探测、管理员配置读取均不会隐式获得该权限。读取前后重新校验许可，远程主机明确拒绝；目录由任务29读取服务从会话记录解析，客户端不能提供路径。响应仅为主机、ProjectScope、sessionId、mountRevision及带scope/精确修订/失效码的挂载引用，不恢复连接、不读取历史/私有传输配置。
- 新API路径采用多段资源，避免遮蔽已有ID为tools或acp-mounts的目录更新/删除路由。SDK均复用原无重定向/无重试传输和敏感成员请求头，不增加执行通道。
