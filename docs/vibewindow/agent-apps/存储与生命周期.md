| 路线 | 结论与原因 |

| 整库抽离 | 不采用。upstream Database 初始化连带历史迁移、备份、定价、清理和同步 hook，跨越多个领域所有者。 |

依赖箭头表示“使用”：

```text
Iced → vw-gateway-client（SDK）→ vw-api-types
agent → vw-api-types
```

空库读取返回空集合，不为 GET 创建记录。payload_json 为图标集合 JSON，后续共享合同确定精确结构；下文 PostgreSQL 初始化参数 `$5` 是该合同的合法空集合编码，SQLite 的 `:next` 是纯规则输出，不在本任务臆定字段。损坏 JSON 或非法结构应报错并保留原值，不静默清空覆盖。集合删除保留该固定键的空集合，避免删除锁锚点。新业务包不得拥有 ~/.cc-switch、cc-switch.db 或任何独立数据库。

现有 get 和 upsert 各开连接，不能拼成原子读改写；必须在 agent 适配内用同一连接、同一事务完成下述过程。不得在事务外读取旧集合，再用无条件 upsert 覆盖。

## SQLite 原子读改写

所有参数绑定；`:p/:c` 是租户，`:ns/:key` 只能由内部常量提供，时间戳由 agent 生成。语句是后续实现合同：

```sql
BEGIN IMMEDIATE;
SELECT payload_json FROM gateway_settings
 WHERE platform_id=:p AND company_id=:c AND namespace=:ns AND config_key=:key;
-- 无记录按合法空集合处理；同一事务内解析、校验并应用纯集合变更。
INSERT INTO gateway_settings
 (platform_id,company_id,namespace,config_key,payload_json,updated_at_ms)
 VALUES (:p,:c,:ns,:key,:next,:now)
 ON CONFLICT(platform_id,company_id,namespace,config_key)
 DO UPDATE SET payload_json=excluded.payload_json, updated_at_ms=excluded.updated_at_ms;
COMMIT;
```

BEGIN IMMEDIATE 在读取前取得写事务；首次写入 A 取得锁并读到缺失，B 在 BEGIN 等待；A 写入并提交后 B 才读取 A 的集合并应用变更，因此不会丢更新。若 A 回滚，B 从空集合开始。锁超时返回明确失败，不当作空库。任何解析、规则、SQL 或提交失败均走回滚/事务 RAII 释放；不报告成功。

## PostgreSQL 原子读改写

使用同一池化连接、显式 READ COMMITTED 事务；初始化键必须与行锁、变更、提交处于同一事务。不能只锁不存在的行：

```sql
BEGIN ISOLATION LEVEL READ COMMITTED;
INSERT INTO gateway_settings
 (platform_id,company_id,namespace,config_key,payload_json,updated_at_ms)
 VALUES ($1,$2,$3,$4,$5,$6)
 ON CONFLICT(platform_id,company_id,namespace,config_key) DO NOTHING;
-- $1/$2 租户，$3/$4 固定键，$5 合法空集合，$6 时间戳。
SELECT payload_json FROM gateway_settings
 WHERE platform_id=$1 AND company_id=$2 AND namespace=$3 AND config_key=$4
 FOR UPDATE;
-- 在事务内解析并应用纯规则，输出 $5；刷新 $6。
UPDATE gateway_settings SET payload_json=$5, updated_at_ms=$6
 WHERE platform_id=$1 AND company_id=$2 AND namespace=$3 AND config_key=$4;
COMMIT;
```

SELECT 必须命中一行，UPDATE 必须影响一行，否则失败回滚。首次竞争时 A 插入，B 的 INSERT 等待唯一键冲突结果；A 提交后 B 的 INSERT 不覆盖，下一条 SELECT 在 READ COMMITTED 新快照下锁定并读取 A 最新值。A 回滚时 B 插入成功后锁定自己的空集合。已有键时 FOR UPDATE 串行化修改；不同租户锁不同键。禁止其它图标写路径绕过该协议；不把 schema advisory lock 当业务行锁。失败显式回滚或由事务 RAII 回滚后归还连接，损坏连接不得作为健康连接复用。

## 启动、停止与取消时序

资源所有权由 agent 统一承担。启动合同：在数据库工作线程加载现有配置及 GlobalDatabase → 初始化匹配提供者的 GatewaySettingsStore → 注入图标适配 → 接收图标请求。初始化失败返回错误，不能用临时空库伪装成功。纯规则无启动/停止钩子；API/SDK/Iced 都不拥有连接。

请求流程：异步层完成作用域和请求边界校验 → 阻塞工作线程取得连接 → 开事务 → 读取并调用纯规则 → 写入并提交 → 释放事务、语句及连接 → 异步层返回结果。图片解码等可预处理工作在锁外完成，依赖当前集合的去重/上限/改名检查在锁内完成。锁内不等待 HTTP、模型、文件下载或其它外部网络；PostgreSQL SQL 本身的数据库通信属于事务必要操作。

现有 desktop 设置处理器使用 spawn_blocking；GlobalDatabase 也有 run_isolated 工作线程边界。新适配沿用明确阻塞边界，连接和事务只在该闭包内持有，不跨 await，也不在 Iced 主线程或 Tokio 工作线程运行同步 SQL。run_sync_database 会同步 join 工作线程，不能单靠它保证异步调用者不被阻塞。

| 中断时点 | 结果与资源释放合同 |
| --- | --- |
| 工作开始前 | 可取消排队工作，不取得事务或连接。 |
| BEGIN 后、COMMIT 前 | HTTP future 被丢弃不等于工作线程停止。工作继续至完整提交，或在提交前观察取消后完整回滚；不能留下部分更新。 |
| COMMIT 成功、响应前 | 更新已生效，响应可能丢失；客户端超时不能推断回滚。 |
| SQL/规则失败或闭包展开 | 回滚后释放语句、事务、连接；panic 转失败，不记录载荷/凭证。进程被杀由数据库恢复未提交事务，不能承诺已确认提交的持久性超出当前数据库配置。 |

重试依赖业务去重：例如同图片新增遵守集合去重规则，删除遵守既定幂等语义；不得因超时盲目重放整次写入。非幂等操作先查询确认结果，或由后续业务合同提供去重证据；本任务不新增通用去重表/框架。提交结果不确定时保留不确定性并查询，不返回虚假成功。

服务停止合同：停止接收新图标请求 → 等待已启动数据库工作结束并提交/回滚 → 释放每请求连接与适配引用 → 结束服务。必须持有可等待的工作完成证据；abort 异步句柄不能证明阻塞闭包已退出，不能在仍执行 SQL 时宣称排空完成。现有 daemon shutdown_handles 直接 abort 尚未完成任务，尚不具备该排空保证；后续接入必须验证本领域工作收束，不能据此改写其它服务停止逻辑。

SQLite 连接为每次打开，闭包结束关闭；PostgreSQL 池化连接归还共享池。GlobalDatabase 的 BACKENDS_BY_CONFIG_PATH 持强 Arc，因此释放请求或图标适配不代表销毁进程级后端/连接池；服务停止不清空共享注册表、不关闭其它服务正在使用的池，进程退出由系统回收。避免把 upstream 最后 AppState Arc 释放误写成当前池释放时机。
