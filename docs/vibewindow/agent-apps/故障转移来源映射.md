## 来源数据面与切换

- `src-tauri/src/proxy/handlers.rs` 的协议 handler 构建 `RequestContext::new`。`proxy/handler_context.rs` 调用一次共享 `ProviderRouter::select_providers_with_current`，然后将候选传给 `RequestForwarder::forward_with_retry`。Stack 绕开队列并保留原设置，Stack 请求旁路路由健康、切换统计和状态写入。`select_providers` 是读取当前目标和应用开关的包装。开关关闭只选当前目标，开启按有效队列从 P1 开始，明确区分全熔断和无供应商。
- `proxy/provider_router.rs` 按应用/供应商懒建熔断器。`select_providers_with_current` 调 `is_available` 筛选，`allow_provider_request` 才申请实际半开名额。`record_result` 记内存成功或失败并按应用失败阈值更新持久健康。`release_permit_neutral` 释放名额，`reset_provider_breaker` 重置，`update_app_configs` 和 `update_all_configs` 热更新。`proxy/circuit_breaker.rs` 的 `allow_request`、`allow_half_open_probe`、`record_failure`、`record_success`、`reset` 管理关闭、打开、冷却后半开、一次并发探测、失败重开及成功恢复。关闭态达到连续失败阈值，或达到最小样本且错误率达阈值时开路。
- `proxy/forwarder.rs::forward_with_retry_inner` 按候选尝试，`max_retries + 1` 在上游发送前限制候选尝试数，单候选绕过发送前熔断许可。签名、预算、媒体、opaque state 整流另有同供应商重发，因此该计数不能作为总网络预算。`categorize_proxy_error` 区分超时、传输错误、可重试上游状态与客户端错误，非重试错误走中性释放。官方 Codex 错误禁止转移，xAI OAuth 本地鉴权错误亦为终止错误。`prepare_success_response_for_failover` 在提交下游响应前检查部分失败包。`RequestContext::create_forwarder` 与 `streaming_timeout_config` 提供非流总时限和流式首字节/空闲时限，`response_processor.rs` 管流式分块。这些应用参数在来源关闭故障转移时旁路。原生 16–22 需用同一个网络尝试预算，独立验证首字节、空闲和总时限，以及取消、已发流或工具副作用后的重放拒绝。
- `finish_success` 更新请求使用的实际供应商、成功数及最近错误。实际目标与请求起点不同则增加切换次数，异步调用 `FailoverSwitchManager::try_switch`。`proxy/failover_switch.rs::try_switch` 以应用/供应商去重，`do_switch` 依赖 Tauri 状态并调用 `mode/controller.rs::record_failover_route`。后者在模式锁内复查代理、同目标和 Stack，提交路由指针并更新活跃目标，保留客户端配置及直连指针。显式启用时的 `switch_route_for_failover` 另走 `switch_route_checked`。原生任务 23 需依赖实际路由事务和网关事件，按作用域与版本提交，处理并发、过期请求和重复事件。
- `provider-switched` 的两个来源是 `commands/failover.rs:301`（`source=failoverEnabled`）和 `proxy/failover_switch.rs:116`（`source=failover`），载荷含 `appType`、`providerId`、`source`。`src/lib/api/providers.ts::onSwitched` 监听，`src/App.tsx` 失效应用供应商与模式缓存。设置、托盘和 UI 通知由来源应用消费，原生事件需要脱敏切换原因、实际目标和关联 ID。
- 相邻覆盖已核对。DAO 的 `provider_loading_preserves_list_and_queue_order_with_app_local_endpoints` 断言顺序及应用端点隔离。`provider_router.rs` 的 `test_failover_enabled_uses_queue_order_ignoring_current`、`test_failover_enabled_uses_queue_only_even_if_current_not_in_queue`、`codex_official_current_stays_single_route_when_failover_is_stale`、`stale_codex_official_queue_entries_are_not_retry_targets`、`test_select_providers_does_not_consume_half_open_permit` 和 `test_release_permit_neutral_frees_half_open_slot` 覆盖候选及许可。`circuit_breaker.rs` 覆盖开路、半开恢复、半开占用及重置。`forwarder.rs` 的 `failover_to_the_second_provider_counts_a_switch`、`non_retryable_error_is_neutral_for_the_breaker`、`official_codex_failures_are_not_retryable` 覆盖运行结果。`mode/controller.rs` 有 `failover_moves_the_route_without_writing_client_files` 与两项 Stack 竞态回归。`src-tauri/tests/proxy_commands.rs` 只有计价往返用例。
