## 真实调用链与边界

实际路径为 `app_routing::dispatch::forward_json → failover_execution::Plan::forward / observe → timeouts::first_output_body / first_output`。母任务8已经交付 `AppTimeouts` 和有效协议事件判定，因此复用 `app_routing/timeouts.rs`，不新建第二个 gateway 超时业务模块。独立网络测试位于 `gateway/agent_apps_failover_timeouts_tests.rs`，由 gateway 父模块显式注册；半开许可测试位于 `app_routing/failover_execution_tests.rs`。

首事件等待消费原始请求截止时间，包含建连、响应头、退避及此前尝试所耗时间。HTTP响应头、注释保活、ping和空模型元数据均不能解除等待。共享 `OutputObserver / StreamObserver` 判断实际模型输出或合法终止，完整首段保留原顺序，已有大小限制不变。首段同时包含下一帧片段时保留原始片段字节，避免重建下游解码状态时丢帧。合法首段之后继续走现有协议验证、空闲检查和响应体生命周期。

修复前外层首事件超时会丢弃响应体、中性释放生产许可，却不报告供应商失败。现在唯一重试所有者在同一截止时间内等待首段，超时或协议失败先报告生产失败并释放许可和上游，再直接返回。取消保持中性，仍使用既有代次约束；已发送且执行状态不明的请求不访问备用供应商，不扩大重试权限。未修改会话恢复预算、Cargo配置或空闲/总超时策略。
