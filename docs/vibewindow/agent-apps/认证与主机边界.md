## 四类边界

| 边界 | 当前入口与资源所有者 | 图标竖切允许与拒绝 |
| --- | --- | --- |
| 管理 API | agent 的受管路由、管理员凭据及 GlobalDatabase；SDK 只发送请求，Iced 只持展示状态 | 只管理指定租户的图标集合；不提供命令、SQL、任意路径或通用 RPC |
| 模型数据流 | model_relay 的独立回环监听器、RelayBinding 与 provider transport；agent 持 capability 生命周期 | 只转发绑定的模型协议；不挂载图标管理、主机命令或管理路由，不执行模型返回的工具调用 |
| 执行主机 | 对应领域的网关主机或明确绑定的远程执行端拥有进程、工作区、文件和执行凭据 | 图标管理无主机文件动作；未来不支持/不可达执行端明确报 unsupported/unreachable，不转向客户端本机 |
| 客户端本机 | Iced 客户端拥有窗口、展示缓存与用户明确发起的本地交互 | 通过 vw-gateway-client 管理图标；不得把远程失败解释成本地执行许可，不直接访问 agent 数据库 |

## 实际认证链：必须按启动入口区分

`gateway/runtime.rs:59–75` 的 start/serve 使用 `router::build_router`。`gateway/router.rs:119–126` 同时保留无版本路由并挂 `/v1`，请求顺序为 CORS → Basic → tenant_scope_middleware → handler。Basic 的 `VIBEWINDOW_SERVER_PASSWORD` 未配置时直接放行；用户名来自 `VIBEWINDOW_SERVER_USERNAME`，缺省 vibewindow。已配置密码时严格解析 `Authorization: Basic <base64(username:password)>`，不匹配返回 401 和 `WWW-Authenticate: Basic realm="vibewindow"`。OPTIONS 跳过 Basic 与租户解析，预检不构成业务授权。CORS 只控制浏览器跨源读取，不能充当身份认证。

计划中的“旧 /api Bearer 配对通道”是历史称呼。当前实际装配 `gateway/bootstrap.rs:753–835` 的 client_router 已将 stateful_handler_router（含 desktop）挂到 `/v1`，外层 skey_auth_middleware → 租户解析 → handler；不经过 build_router 的 Basic。`gateway/mod.rs:120–137` 调用 `api/auth.rs:30–48` 的 require_auth：pairing.auth_enabled() 为 false 时放行，否则必须是已认可的 Bearer skey，失败返回 401。bootstrap 从 config.gateway.auth_enabled/skeys 构造 PairingGuard。公开 global/health 例外绕过 skey，但仍在租户中间件内。standalone_client_router 只有统一租户层，认证由各协议 handler 负责，不能把 stateful 路由认证结论推广到所有 `/v1`。

仓内 gateway 对 `"/api` 与 `nest("/api` 的搜索只命中文档示例，未发现实际 `/api` 挂载；因此不能凭前缀判断 Basic 或 Bearer，也不能描述为两个认证叠加。后续图标接入要核对真实使用的启动入口：build_router 管理链沿用 Basic；若也挂载 bootstrap 的 stateful 链，则沿用该链的 skey 认证，分别验收，不增加兼容别名或混用凭据。Bearer skey、Basic 凭据、relay capability 均不能互换。

## TenantScope 的证明范围

`middleware.rs:164–207` 从请求 `X-Platform-ID`、`X-Company-ID` 读取作用域，要求各有且仅有一个可转换为字符串的非空值，错误返回 400；随后构造 TenantScope 并注入 Extension。`vw-api-types/src/id.rs:60–139` 只校验去空白后非空，保留原字符串；没有公司存在性查询、成员表查询或凭据到公司的可信绑定。类型自身有 Default，不表示受管请求缺头时可以回退默认租户。

该作用域仅证明输入满足当前语法，并为存储隔离提供键。图标存储继续使用《存储与生命周期.md》的 `(platform_id, company_id, agent_apps.custom_icons, default)`，必须把该作用域贯穿每次读写；不能从 directory、项目路径、图片或客户端本机配置推导/覆盖租户。固定 namespace/key 由 agent 提供，客户端不能指定。

沿用当前管理员凭据权限：管理员选择作用域是现有管理信任模型，不是“调用者属于该公司”的证明。知道其它公司 header 的普通用户不能据此获得成员资格；Basic 或 skey 本身也没有提供跨公司成员鉴权。本任务未发现可信成员绑定，亦未获得当前部署要求成员授权的证据。若部署要求成员级授权，全部四个图标端点须在可信身份绑定验收前拒绝该访问或登记部署阻塞，不能仅凭客户端 header 对成员开放；本任务不臆造身份服务或降低要求。未配置 Basic 密码/关闭 skey 认证的开放行为是当前实现事实，不能表述为“已认证管理员”。

## 固定最小 API 合同（待后续实现）

| 方法与路径 | 唯一业务动作 |
| --- | --- |
| GET /v1/agent-apps/custom-icons | 列出当前租户图标集合 |
| POST /v1/agent-apps/custom-icons | 添加图片并按图标集合规则去重 |
| PATCH /v1/agent-apps/custom-icons/{id} | 修改该租户库中指定条目的名称 |
| DELETE /v1/agent-apps/custom-icons/{id} | 删除该租户库中指定条目 |

DTO 放在 vw-api-types，SDK 在 vw-gateway-client，Iced 只消费 SDK；纯集合规则在 vw-agent-apps，agent 负责认证、作用域与存储适配。精确字段、图片/名称校验、错误映射由子任务 73–88 实现，当前不臆定响应体或声称路由已注册。接口不接受 target_host、path、directory、命令、SQL 或任意 RPC；客户端应上传图片内容，不让服务器按路径读取图片。携带这些能力请求应明确拒绝，不能静默忽略后执行其它主机动作；后续 DTO/处理器验证覆盖此边界。

## 主机与资源所有权

| 主机 | 资源所有者与实际位置 | 本任务约束 |
| --- | --- | --- |
| 网关主机 | agent/GlobalDatabase 拥有配置、SQLite 文件或 PostgreSQL 连接；远端 PostgreSQL 服务拥有其物理文件；现有 desktop handler 的 Command、应用发现、路径打开均在运行网关的 OS 执行 | 图标只写既有设置表，不拥有本机图片路径；远程连接网关不等于这些命令在 Iced 客户端执行 |
| 远程执行主机 | 对应领域显式绑定的执行端拥有自身进程、文件、工作区及凭据 | 本块无远程文件/执行协议、不接受 host 选择；未来端点 unsupported/unreachable 时由领域返回明确错误，不回退网关或客户端 |
| 客户端本机 | Iced 拥有窗口、展示状态及明确的客户端交互资源 | 图标 API 不在本机执行任何文件或进程动作；网关不可达时报告失败，不直接改本地库代替远程成功 |

`gateway/instance.rs:35–57,91–107` 中 directory 优先取查询参数，再取 x-vibewindow-directory，否则取网关进程 cwd；with_instance 绑定网关项目上下文，load_local_project 还使用默认租户项目查询。它们既不选择远程主机，也不授予公司成员权限。图标库是租户资源，不调用这条目录/默认项目回退链。

`api/handlers/desktop.rs:45–69,83–163,430–492,625–632` 注册外部应用打开、路径定位、服务命令；service 使用网关 current_exe/config_dir，macOS 应用探测读取网关 /Applications，open 命令也在网关主机启动。这些是既有领域端点，本次不改动；不能因名称 desktop 将其复制成客户端本机 fallback。现有其它平台分支没有获得本轮实机验收。

`model_relay/server.rs:25–41,61–91,118–129` 以独立监听器绑定到 IPv4 localhost 的临时端口，绑定 project/capability，释放时撤销 capability。路由为模型协议，未合并管理 router；RelayBackend 合同禁止执行返回工具调用。图标管理不得接入此监听器，也不能把 relay token 当管理凭据。

## 允许与拒绝请求例子及人工验收

以下为源码推演和未来图标合同示例，不是实际发送请求的证据；Basic 示例假定服务器已配置密码，Bearer 示例假定启用配对认证。

| 请求条件 | 结论 |
| --- | --- |
| build_router：GET /v1/global/health，正确 Basic，X-Platform-ID: platform-a，X-Company-ID: company-a | 可进入 handler；只证明管理员凭据与作用域语法通过 |
| 同上但缺 Authorization 或改为 Bearer skey | Basic 返回 401，先于租户解析 |
| 同上正确 Basic，但缺少/重复/空白公司 header | 租户层返回 400，不取默认公司 |
| bootstrap stateful：GET /v1/desktop/preferences，已配对 Bearer skey，两个合法租户头 | 可进入该 handler；Basic 凭据不能替代 skey；不证明公司成员身份 |
| 未来 GET /v1/agent-apps/custom-icons，匹配启动入口的管理员凭据与合法租户头 | 允许按固定租户键读取；当前未实现，不能据此宣称返回 200 |
| 未来 POST/PATCH/DELETE 图标请求，含 target_host/path/command/sql 或任意存储 namespace/key | 按图标合同拒绝额外能力请求，不读文件、不执行命令 |
| 要求成员授权的部署：仅管理员凭据与客户端 company-b header，无可信成员绑定 | 成员访问拒绝或登记阻塞，不能将 company-b header 当身份凭据 |
| 向 model relay 请求图标管理或服务命令；远程主机不可达后要求本机执行 | 不提供该管理能力；执行领域明确失败，不回退客户端 |
