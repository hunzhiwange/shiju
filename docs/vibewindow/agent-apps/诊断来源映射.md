## 上游供应商可达性

- `src/components/providers/ProviderList.tsx` 将卡片操作交给 `src/hooks/useStreamCheck.ts` 的 `checkProvider`。`src/components/providers/ProviderCard.tsx` 用 `src/utils/providerCapabilities.ts` 的 `supportsConnectivityCheck` 隐藏官方、OMO/OMO Slim 及 MCode、DSH、Kimi 的入口。Hook 按供应商 ID 显示检查中，分别提示连通、连通但较慢、不可达和命令出错。调用为一次性请求，由 `src/lib/api/connectivity-check.ts` 传入 `{appType, providerId}`，完成或异常时清理加载状态。
- `src-tauri/src/commands/stream_check.rs` 的 `stream_check_provider` 按应用取供应商。Copilot 通过 `providerType` 或配置的 `ANTHROPIC_BASE_URL` 识别，`isFullUrl` 跳过动态覆盖。否则交由 `src-tauri/src/proxy/providers/copilot_auth.rs` 按绑定账号或默认账号解析 OAuth 动态 API 地址，缓存未命中时可惰性取端点，失败时可回退账号域名的默认端点。实际探测 GET 不携带账号凭据。其余供应商走 `resolve_base_url` 的应用配置或适配器。
- `src-tauri/src/services/stream_check.rs` 的 `probe_reachability` 对 `base_url` 发 GET，收到 HTTP 响应头即返回并记录耗时。任意 HTTP 状态都算可达，包括 401、500。DNS、拒连、TLS 和超时等网络错误归入探测失败。默认每次 8 秒，`check_with_retry` 仅对 `timeout`、`timed out`、`abort` 类错误文字重试一次。超过 6000 ms 为 `degraded`，仍为可达。此路径无模型请求，也不会读写或重置生产熔断状态。
- Rust 与 TS 返回形状为 `{status, success, message, responseTimeMs, httpStatus, testedAt, retryCount}`，状态为 `operational/degraded/failed`，HTTP 状态与耗时可缺，时间戳单位为秒。网络失败仍可带失败耗时。服务内相邻测试覆盖默认值、超时类判定、任意 HTTP 状态、网络失败与慢响应，命令相邻测试覆盖 Copilot 识别及完整 URL 元数据。
- `src-tauri/src/database/dao/stream_check.rs` 的 `cleanup_old_stream_check_logs` 仅删除历史行，`src-tauri/src/database/mod.rs` 和 `src-tauri/src/database/backup.rs` 的清理调用均保留七天。当前探测不写日志。旧库兼容与迁移归母任务 18，本诊断域不新增日志历史表。

## 上游端点测速与保存

- `src/components/providers/forms/ProviderForm.tsx` 调用 `src/components/providers/forms/hooks/useSpeedTestEndpoints.ts`。Claude/Gemini 合并表单当前地址、编辑初值中的环境地址、选中非自定义预设的地址和候选端点。Codex 从当前地址及编辑初值、预设 TOML 提取地址，再合并预设候选。顺序为当前、初值、预设，去空白及末尾斜杠，以字符串键保留首项。`src/components/providers/forms/ClaudeFormFields.tsx`、`src/components/providers/forms/CodexFormFields.tsx`、`src/components/providers/forms/GeminiFormFields.tsx` 挂载测速面板；`src/components/providers/forms/GrokBuildProviderForm.tsx` 单独合并当前、预设和草稿候选后复用 Claude 字段。
- `src/components/providers/forms/EndpointSpeedTest.tsx` 补入候选缺失的当前选中地址，编辑时合并已保存端点，重合项标为自定义。手动添加通过 URL 解析限制 HTTP(S)，规范化后拒绝重复。展示按延迟升序，无结果置后，同值按 URL 排序。自动选择取最小有效数值延迟，仅回填表单地址，即使该 HTTP 状态为 4xx/5xx 也可能被选中。删除选中项时回退到剩余列表第一项，或清空地址。
- `src/lib/api/vscode.ts` 将 `{urls, timeoutSecs}` 传给 `src-tauri/src/commands/provider.rs` 的 `test_api_endpoints`。面板超时表中 Codex、Grok Build 为 12 秒，其余应用为 8 秒。`src-tauri/src/services/speedtest.rs` 的 `test_endpoints` 并行处理有效地址，每个先做一次 GET 热身并忽略结果，再做一次 GET 计到响应头。两次 GET 各自使用同一超时设置，服务默认 8 秒、限制 2–30 秒。每项结果为 `{url, latency, status, error}`，延迟为毫秒，可空。服务按输入顺序返回，空或无效地址单项报错，超时和连接失败可区分。相邻测试覆盖超时限制、空列表、无效地址。面板等待整批返回，取消按钮只关闭面板。
- 编辑保存对比初始与当前自定义集合，先逐条调用 `add_custom_endpoint` 再逐条调用 `remove_custom_endpoint`，可能部分写入；取消关闭不会执行这一批写入，地址选择已通过表单回调同步。命令调用 `src-tauri/src/services/provider/endpoints.rs`，按应用和供应商持久化，读取按新增时间倒序。`update_endpoint_last_used` 是单独命令，本面板保存不调用它。新建将自定义 URL 集合交回父表单，随供应商提交为 `meta.custom_endpoints`，值含 `url/addedAt/lastUsed`。`src/components/providers/AddProviderDialog.tsx` 在没有自定义端点时还可从预设和配置补种端点。识矩持久化归母任务 4，测速只返回测量结果，选中地址交给供应商表单。

## 上游 MCP 握手与取消

- `src/components/mcp/UnifiedMcpPanel.tsx` 通过 `src/hooks/useMcpConnectivity.ts` 手动发起全量或单行检查，只选至少为一个应用启用的条目。加载页面、焦点变化和应用启用状态本身不会触发握手。页面把启用状态与 `unchecked/checking/connected/disconnected` 分开展示。Hook 以连接配置和请求代次隔离结果，阻止同配置重复运行，忽略过期事件。配置修改重置显示。全量操作会替换在途批次，离页取消，即使批次 ID 尚未返回也会在注册后补发取消。
- `src/lib/api/mcp.ts` 对接 `src-tauri/src/commands/mcp.rs` 的 `start_mcp_connectivity_checks` 与 `cancel_mcp_connectivity_checks`。开始传 `serverIds` 和结果 channel，命令按所选 ID 读已保存的服务定义，返回批次 UUID，取消传 `batchId`。结果按完成顺序逐项发送 `{serverId, connected}`。该 channel 逐项反馈进度，无独立终止或错误事件；传输错误折叠为 `connected: false`，避免携带含凭据的配置或错误。
- `src-tauri/src/services/mcp_connectivity.rs` 的 `start_checks` 跨批次共用 3 个并发许可，单项获得许可后开始 30 秒计时。取消中止批次，channel 关闭也会放弃未完成项。`connect` 支持 stdio、Streamable HTTP 和旧 SSE，`handshake` 执行 MCP `initialize` 与 `notifications/initialized`，随后关闭服务，不调用工具。HTTP 禁止重定向和传输重试，旧 SSE 的消息地址必须同 scheme 和 authority 才能携带已配置头部。
- stdio 使用配置的命令、参数、环境和工作目录。macOS 上为缺省 PATH 合并登录 shell 路径，解析限 10 秒，显式 PATH 优先。握手结束、取消或超时均释放短期传输。`ProbeProcess::drop` 终止进程组，并异步 `wait` 回收。上游的异步回收与许可释放分离，识矩任务 36 另要求验证退出后归还许可。
- `src-tauri/src/services/mcp_connectivity/tests.rs` 和 `src-tauri/tests/fixtures/mcp_connectivity_server.rs` 的夹具覆盖真实初始化、跨源 SSE 拒绝、普通 HTTP 成功仍判未连接、跨批次排队、慢启动及取消/超时后的子孙进程回收。`tests/hooks/useMcpConnectivity.test.tsx` 覆盖手动开始、替换、配置变更、离页与注册竞态；`tests/components/UnifiedMcpPanel.test.tsx` 覆盖进度灯与启用分离、页级/单行操作及禁用条件。

## 上游故障转移页面与事件

- `src/components/proxy/AutoFailoverConfigPanel.tsx` 由 `src/components/providers/mode/RouteSettingsSheet.tsx` 和 `src/components/settings/sections/RoutingSection.tsx` 使用。它通过 `src/lib/query/proxy.ts` 读写应用级代理配置，加载和写入期间禁用相应操作。整数输入范围为重试 0–10、流式首字节 1–120 秒、流式空闲 0–600 秒、非流式 60–1200 秒、连续失败 1–20、恢复成功 1–10、恢复等待 0–300 秒、错误率 0–100%、最小请求数 5–100。错误率读时转整数百分比，保存除以 100。重置回到已加载配置。诊断超时独立于这些生产字段。
- `src/lib/api/failover.ts` 分别封装队列及候选、启停、生产健康、熔断状态/设置和手动重置。`src/types/proxy.ts` 中，队列项含 `providerId/providerName/providerNotes/sortIndex`，生产健康含 `is_healthy/consecutive_failures/last_error` 和时间，熔断统计含 `closed/open/half_open` 及连续成功、连续失败、总数和失败数。`src/lib/query/failover.ts` 对健康和熔断统计每 5 秒刷新。队列变更使相关缓存失效，启停乐观更新、失败回滚且最终重新读取。独立的手动熔断重置刷新健康、供应商和代理状态。此刷新用于展示生产状态。
- `src-tauri/src/commands/failover.rs` 在启用时、`src-tauri/src/proxy/failover_switch.rs` 在实际切换后发出 `provider-switched`，形状为 `{appType, providerId, source}`，`source` 分别为 `failoverEnabled` 和 `failover`。`src/lib/api/providers.ts` 的 `onSwitched` 接收。`tests/integration/App.test.tsx` 覆盖事件刷新。识矩任务 23、44 消费 Gateway 路由事件。
