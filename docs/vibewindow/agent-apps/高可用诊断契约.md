# 高可用诊断契约

本契约供故障转移连通检测与诊断的后续任务使用。审查基线为识矩 `c04b107df`，上游固定提交为 `ca58c0313360eae7c851fbd7553c1614c7af03e7`（CC Switch 4.0.25）。直接前置任务 1、2 已分别以 `862fdb4d2`、`1cd32bb00` 提交 [故障转移来源映射](故障转移来源映射.md) 和 [诊断来源映射](诊断来源映射.md)。下列 API、领域模块和接线属于后续设计。本次交付契约及静态核对证据。

## 执行位置与作用域

| 路线 | 结论 |
| --- | --- |
| 整包迁移 Tauri | 排除。上游路由切换、状态发布和托盘刷新依赖 Tauri 状态及事件，数据库初始化还牵连迁移、备份和其它领域。 |
| 业务包加 agent 资源适配 | 采用。 `vw-agent-apps` 持有队列资格、熔断、重试分类等纯规则。agent 持有授权、数据库、常驻监听、网络、子进程及任务生命周期。API 负责边界转换，Iced 通过 SDK 读写和显示。 |
| 桌面独立调度 | 排除。窗口关闭会影响生产控制和任务状态，且桌面与网关各持一份队列或健康会造成状态分歧。 |

- 应用资源作用域为 `TenantScope(platform_id, company_id) → ProjectScope → 执行主机 → AppId`。租户与成员从可信认证链取得，项目选择须通过该成员的授权，执行主机由认证上下文和执行主机策略解析。请求中的目标标识只用于选择并核对已授权资源。主机不可达明确返回错误，禁止回退本机。
- 队列、开关和策略属于应用资源。队列成员、生产健康、实际尝试、失败和诊断目标在同一应用作用域下按供应商 ID 隔离，并保留经过验证的账号绑定及其代次。无托管账号的配置使用明确的无绑定身份。若配置授权使用默认绑定，由账号服务在启动前解析并固定具体账号。显式绑定缺失或失效时拒绝执行。MCP 握手使用同一租户、项目、主机和应用边界下已授权的 MCP 配置 ID；按配置区分任务项。账号或配置换代后，迟到结果不得更新新一代的状态。
- 所有入口先核对资源作用域及操作权限，再读取配置、取得凭据或启动网络/进程。正文不能覆盖租户、项目、主机、应用或绑定账号，任务 ID 和关联 ID 也不授予权限。执行目标由服务端从已授权配置解析并校验；拒绝任意 URL、命令、参数、环境及凭据覆盖。端点候选查询只规范化授权表单草稿并返回可引用的候选身份，查询本身不连接或保存草稿。
- 故障转移仅向能力允许、处于实际路由模式的 Claude、Codex、Gemini、Grok Build 应用开放。直连、Stack 和不支持的应用拒绝开启或执行切换，保存的队列可供获准读取。关闭开关保留队列。开启时从有效队列选 P1，空队列只允许补入合格的当前供应商，开启失败保持原队列、开关和路由。队列按持久顺序去重，重排须为现有成员的完整排列，任何切换须复核模式、绑定和配置版本。
- 官方 Codex 按真实账号、凭据来源及官方路由能力识别，禁止入队，残留队列也不能覆盖当前账号的单路由。对所有供应商都禁止更换请求的已授权账号或复制授权、账号绑定的上下文引用及不透明状态。无绑定的第三方候选只可使用自身已授权配置。模式与凭据各自沿用既有所有者。

## 唯一重试所有者

- 每次模型逻辑请求只确定一次所有者。常驻路由直接接收的请求，由路由所有者统一消费最多 `1 + max_retries` 次上游发送预算，0 表示最多一次。候选切换、同目标重发或协议纠偏重发都消耗同一预算，每次实际发起发送前扣减一次。预检筛除候选不计发送，也不能生成额外预算。退避按指数增长，受原始截止时间和取消约束。
- 会话请求继续由 `crates/vw-agent/src/session/processor/recovery.rs::RetryBudget::run` 所有。`runner.rs::request_provider_retry_policy` 从请求可靠性快照取 `provider_retries`，`llm_runner.rs::run_llm_step_with_budget` 消费同一会话预算。若这类请求将来桥接常驻数据面，必须在服务端建立与原请求、作用域和绑定代次关联的可信归属，由会话预算发出单次尝试，路由侧不再独立退避、重发或切换重试。归属不明时拒绝该桥接，客户端 header、正文或声明的已重试次数不构成证明。
- 暂时性传输错误、429 或选定的暂时性 5xx 只提供重试候选分类。必须同时证明本次失败可以重放、仍有预算与时间、账号与模式有效且未取消。鉴权拒绝、无效请求、已撤销、取消、截止时间耗尽或副作用不明均终止。取消时中止等待和传输，释放半开名额。

| 请求状态 | 处理 |
| --- | --- |
| 未提交、未输出 | 只有可信传输或协议证据证明未执行或安全可重放，并满足预算、时间和授权条件，才允许重试。超时、断线、上游状态码或没有下游输出本身不足以证明安全。 |
| 已提交，或是否提交无法确定 | 已提交下游响应、已确认上游执行，或存在不明副作用时终止自动重放。保留实际失败阶段，并把不可重放语义交给外层（会话桥接使用 `replay_safe=false`）。 |
| 已输出流事件或工具事件 | 锁定不可重放状态，包括协议模型增量及工具调用/执行相关事件。保留部分输出和已发生的效果，不再发送备用请求，不重新触发工具。会话现有 `RetryBudget` 已识别非空 Delta 和 Tool，常驻协议适配还须给出自己的提交与有效输出信号。 |

## 字段与超时

| 策略字段 | 取值范围及单位 |
| --- | --- |
| 最大重试次数 | 0–10，整数次 |
| 流式首字节 | 1–120，整数秒，等待首个有效协议事件 |
| 流式空闲 | 0–600，整数秒，0 仅关闭空闲检查 |
| 非流式超时 | 60–1200，整数秒，覆盖完整响应体 |
| 连续失败阈值 | 1–20，整数次 |
| 半开恢复成功阈值 | 1–10，整数次 |
| 恢复等待 | 0–300，整数秒，0 表示无冷却等待，仍受半开并发限制 |
| 错误率阈值 | 0–1，有限比值，界面百分比在边界转换 |
| 最小样本 | 5–100，整数个请求样本 |

流式和非流式始终共享母任务 8 实际提供的有限总请求截止时间，各次发送、等待、读完整正文或流处理消费同一个剩余时间。心跳和空帧既不能满足首字节条件，也不能延长总截止时间。当前 `AppTimeouts` 只配置三项时限，流式总截止时间的实际边界待母 8 交付后核对，不新增参数或猜测数值。

## Gateway API 与诊断任务

下表为拟新增 HTTP 接口。路由参数或查询只选择已授权的项目、主机和应用，领域请求正文只携带操作字段及资源选择 ID。任务 ID 由服务端签发并与作用域和关联 ID 一起返回。

| 前缀 | 方法和相对路径 | 资源与结果 |
| --- | --- | --- |
| `/v1/agent-apps/high-availability` | `GET /queue`、`GET /candidates` | 读取有序队列、版本、开关和合格候选，只返回公开供应商标识、名称和必要顺序。 |
| 同上 | `POST /queue/members`、`DELETE /queue/members`、`PUT /queue/order`、`PUT /enabled` | 版本化增删、重排及启停，返回已提交的最新状态及版本。 |
| 同上 | `GET /policy`、`PUT /policy` | 读写重试、超时和熔断策略，返回策略及版本。 |
| 同上 | `GET /health`、`GET /route`、`POST /health/reset` | 分别读取生产健康/熔断态、实际路由与脱敏失败原因，以及显式恢复授权目标。健康与实际路由分开返回。 |
| `/v1/agent-apps/diagnostics` | `POST /jobs` | 按探测种类验证最小字段和已授权资源，受理返回 202 与任务身份。 |
| 同上 | `GET /jobs/{id}`、`POST /jobs/{id}/cancel` | 读阶段、单调进度、部分结果和终态，或请求取消。取消受理与取消完成分别表示。 |
| 同上 | `POST /endpoint-candidates/query` | 按授权配置归并和规范化候选，返回公开候选 ID 与来源，供测速选择。 |

- 诊断分别报告可达性、测速、模型、流式、MCP 握手。可达性以响应头为证据，401/500 也表示可达。沿用 8 秒超时、仅超时重试一次、超过 6000 毫秒标慢。测速热身后计 GET 响应头耗时，默认 8 秒、范围 2–30 秒。显示时允许按延迟排序，诊断不得自动选最快端点或保存配置。
- 模型探测使用获准模型和单一绑定账号，发送固定、最小的无工具请求，检查有效模型响应。流式还须收到有效增量及合法终止。结果区分真实上游与受控夹具，提供公开模型身份、阶段、耗时和可能费用。MCP 只初始化并关闭受控短期连接，单项 30 秒且跨批次最多 3 并发，旧 SSE 消息地址需同源。取消 stdio 后终止并等待子进程回收，再归还并发许可。所有主动诊断与生产熔断、路由切换、换账号和工具执行隔离。
- 任务阶段为 `queued/running/cancelling`，终态为 `succeeded/failed/cancelled/interrupted`。进度记录已完成数和已知总数，未知总数显式缺省。取消等待、传输及进程并完成清理后才发布 `cancelled`。完成与取消竞争按实际完成和清理结果收敛到唯一终态，终态重复取消返回现状，迟到事件不得覆盖终态。启动响应丢失或断线先查询已知任务，SDK 不自动重发创建或变更请求。
- 公共错误沿用 `crates/vw-api-types/src/error.rs::ApiErrorBody` 的 `error.code`、`error.message` 和受控 `error.details`，在 `details` 中提供关联 ID。输入不合法为 400 `invalid_input`，未认证沿用 401，权限不足为 403 `forbidden`，已授权作用域内缺失或过期为 404 `not_found`，版本冲突为 409 `version_conflict`，当前模式或应用不支持该操作为 409 `unsupported_mode`，任务容量耗尽为 429 `capacity_exceeded`，存储或执行主机不可用为 503 `unavailable`。跨作用域请求拒绝且不披露资源是否存在。取消终态是任务状态。响应、事件及日志仅保留公开标识和脱敏字段，禁止记录凭据、请求正文、原始错误链或带秘密的 URL。

后续 DTO 拟放 `crates/vw-api-types/src/agent_apps_high_availability.rs` 与 `agent_apps_diagnostics.rs`。业务规则拟放 `crates/vw-agent-apps/src/high_availability/`，重试分类在 `retry.rs`。agent 执行适配拟放 `crates/vw-agent/src/gateway/agent_apps_failover_runtime.rs`，领域 API 拟落在 `gateway/api/handlers/agent_apps_high_availability.rs` 与 `agent_apps_diagnostics.rs`，经现有网关注册与 `GatewayClient` 对接。

## 任务17实际接线

常驻请求入口是 `app_routing::dispatch::forward_json`，凭据由 `RouteAuth::publish_provider` 绑定到 `AuthorizedRoute`；已提交供应商证明为 `provider_publication::PublishedProvider`。启用故障转移后，`app_routing::failover_execution::prepare` 复用领域 `selection::select`，按已发布模式、保存队列和供应商资格构造本次请求快照。`Plan::forward` 为整个请求创建一个领域 `RetryBudget`，候选切换和同目标再次发送均消耗此预算，退避与发送共用原始截止时间。发送前复核原生配置、当前发布供应商记录、候选记录和队列版本；发布撤销沿用原有取消令牌。

`gateway::agent_apps_failover_runtime` 持有执行主机有界健康注册表及策略读取。策略仍在 `agent_apps.high_availability` namespace，键为 `policy:` 加现有队列作用域编码；读取 `FailoverPolicy` 并验证，默认值沿用上游固定配置。现有 `RoutingConfigStore` / `AppTimeouts` 继续作为超时权威所有者，本接线仅消费策略的重试与熔断字段。后续策略写入端须复用这一键与现有版本事务，组合编辑超时仍须通过既有超时所有者原子提交。

`SharedTransport::forward_attempt` 只将自己观察到的建连/TLS握手失败标为“未发送”。已发出请求后的错误、任何HTTP状态以及不明确的阶段都不证明可重放，不能凭502再次执行。生产许可经 `CircuitBreaker::allow_owned_request` 随响应体保留：有效流终止或传输完成记录成功，读取失败记录供应商失败，取消或丢弃中性释放；协议合法性继续由现有解码器校验。

当前生产链没有会话桥接常驻路由的调用，`recovery.rs` 和会话 `request_provider_retry_policy` 保持原路径。会话与常驻路由的令牌相互拒绝；客户端重试所有者或预算头不被信任，也不转发到供应商。若以后增加桥接，仍须按本契约建立服务端请求/作用域/账号代次证明，不能将两套预算嵌套。
