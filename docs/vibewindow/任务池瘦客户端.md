# 任务池：瘦客户端

瘦客户端只负责展示任务板、收集用户意图并调用 gateway。它不拥有任务状态机，不选择调度候选，
不判定 review/merge 结果，也不扫描 worktree 推导任务结果。

## 职责

- 从 gateway 拉取 workflow、staff、任务、日志、产物和 worktree resource 快照。
- 将用户操作转换为 `AgentSchedulerCommandRequest` 或 `StaffCommandRequest`。
- 维护仅用于渲染的内存 cache、选择状态、滚动位置和详情面板状态。
- 在 command 被接受后刷新受影响任务，而不是直接改写状态。
- 在 SSE 断线后按 cursor 补事件并重新拉取必要快照。

## 禁止本地推导

瘦客户端禁止执行以下逻辑：

- 根据旧看板列名、本地状态枚举或拖拽目标自行推进状态。
- 根据日志文本、退出码、diff 或分支名判断执行成功、审核通过、审核阻塞、合并成功或合并失败。
- 根据 worktree slot 空闲情况挑选待执行任务。
- 根据 staff 配置在本地生成下一阶段负责人或自动调度计划。
- 直接把删除、归档、批量移动、编辑 metadata 写入旧任务文件。

允许保留的本地写入只有兼容导入、事件缓存和 UI 草稿；这些数据不能成为后续调度依据。

## 自动调度边界

自动路径以 lifecycle outcome 为输入。瘦客户端可以触发 `start`、`retry`、`run_stage_action` 或 wake，但不能指定自动
推进的目标列；gateway 会用当前 `status_key`、status role 和 transition outcome 计算下一阶段，并返回新的快照。

阶段能力按钮只提交 capability、输入和可选 saved workflow UUID。能力执行后的 success、failure 或 blocked 结果由
gateway 映射回 lifecycle；客户端不得用按钮类型、列顺序或本地 role 推断目标状态。

## 最小客户端状态

```ts
type TaskBoardClientState = {
  projectId: string;
  workflow?: TaskPoolWorkflowSnapshotDto;
  tasks: AgentSchedulerTaskBoardTaskDto[];
  staffProjection?: StaffProjectionResponse;
  worktrees?: TaskPoolWorktreeSnapshotResponse;
  eventCursor?: number;
  selectedTaskId?: string;
  visibleLogs: Record<string, AgentSchedulerTaskLogDto[]>;
  visibleArtifacts: Record<string, AgentSchedulerTaskArtifactDto[]>;
};
```

`tasks` 中的 `read_model` 是列标题、阶段标签、负责人、阶段动作按钮的首选来源。
客户端只在渲染层把 DTO 映射成组件模型，不把它们写回本地状态机。

## 首屏流程

1. `POST /v1/projects/resolve` 得到 `projectId`。
2. 并发读取 lifecycle workflows、项目 workflow、staff projection、任务快照和 worktree 快照。
3. 渲染 `/tasks` 返回的卡片；缺少 workflow 时显示 gateway 返回的错误或空态。
4. 为首屏可见任务按需读取日志；详情面板打开时再读取产物。
5. 用最近 cursor 建立 `/events/stream` 连接。

## 命令映射

| UI 操作 | Gateway 调用 |
| --- | --- |
| 新建任务 | `POST /v1/agent-scheduler/tasks` |
| 拖拽到新列 | `command=move`，仅用于临时人工修正 |
| 批量移动 | `POST /commands/bulk`，每项 `command=move`，仅用于临时人工修正 |
| 编辑优先级、模型、prompt、stage metadata | `command=update_metadata` |
| 删除 | `command=soft_delete` |
| 归档 | `command=archive` |
| 重试/暂停/恢复/取消 | `command=retry/pause/resume/cancel` |
| 运行阶段动作 | `command=run_stage_action` |
| 修改员工分配 | `POST /v1/staff/projects/{project_id}/commands` 或 `command=assign_staff` |
| 刷新日志/产物 | `GET /logs` / `GET /artifacts` |

命令返回 accepted 后仍以快照刷新为准。客户端可以短暂显示 pending 状态，但不能把 pending 状态写成任务真实状态。
`move` 和批量移动不作为调度正确性的来源；后台自动调度、policy 和 worker event 都不能依赖这些人工入口补齐状态流转。

## 事件与刷新

SSE 事件用于降低轮询成本。推荐策略：

- 收到任务事件后，只刷新受影响任务的日志和产物。
- 收到状态相关事件后，节流刷新 `/tasks`。
- 收到 workflow/staff 相关事件或 command 拒绝后，刷新 workflow、staff 和任务快照。
- 页面重新可见、网络恢复、gateway 地址变化时重新执行首屏流程。

## Worktree Resource

worktree 面板展示 `TaskPoolWorktreeSnapshotResponse`。回收、释放、合并锁只调用
`/v1/task-pool/worktrees/*`。worktree 池不会告诉客户端哪个任务应该运行；运行选择来自
Agent Scheduler 的 `/wake`、`/tasks` 和 command 响应。

## 兼容边界

Rust 桌面旧 store 可以作为旧任务迁移输入和 Matrix 事件缓存，但 JS 客户端不需要读取它。
迁移入口完成导入后必须回到 gateway 快照；旧文件缺失或内容过期时，JS 客户端不做恢复推断。
