# 委托代理能力策略

委托代理分别为工具和技能配置访问策略。`allowed_tools` 与 `allowed_skills` 表示默认选择；它们不再是默认白名单。两个策略字段均省略时默认为 `unrestricted`。

```toml
[agents.reviewer]
tool_policy = "user_override"
allowed_tools = ["file_read", "grep"]
skill_policy = "strict"
allowed_skills = ["code-review"]
```

| 策略 | 实际可见能力 | 默认注入 |
| --- | --- | --- |
| `strict` | 仅默认选择 | 默认选择 |
| `user_override` | 默认选择加用户显式选择 | 默认选择 |
| `unrestricted` | 当前可用的全部能力 | 默认选择 |

用户显式选择只能来自 UI 或 API 请求边界，并在创建子会话时固化。模型输出、提示词文本和技能正文中的名称都不会扩大能力范围。未知 ID 会被忽略；禁用或不可用能力不会重新暴露。

无论策略为何，工具自己的文件、命令、网络和审批权限照常执行；策略不授予额外底层权限。递归委托工具始终对委托代理隐藏。

旧 `delegate` 的 agentic 适配与 `AgentTool`、Gateway 使用同一解析规则：默认不限制，严格模式只使用默认选择，用户覆盖模式只合并可信的用户选择。
