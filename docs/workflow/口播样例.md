# 本地口播方案工作流

样例源文件：`crates/vw-agent/testdata/workflow/talking_head.yaml`。输入人工转写、秒级时间戳、风格和要求，输出含 `duration`、`segments` 的 JSON 剪辑方案。每段包含原文锚点、起止时间、画面类型和素材建议。本样例生成方案；不渲染、上传或导出视频。

`start → plan → (keywords ∥ visuals) → validate → answer`。两条 LLM 分支共享简报，各自独立构造上下文；Python 校验节点等两支完成后运行。并发仍仅允许 LLM，不扩展工具并发。运行环境需要现有 Python 代码节点支持。

## 模型配置

先在系统设置中配置 Provider、凭据和模型，再用当前租户请求 `GET /v1/provider` 核对 `connected` 和模型 ID。密钥只保存在现有凭据配置中，不写入 YAML。

- 单模型：原样保存，三个 LLM 节点均为 `deepseek/deepseek-flash`，需要已配置且可用的 `deepseek` Provider。
- 双模型：复制 YAML，仅将 `visuals.data.model.name` 改成第二个已配置的 `provider_id/model_id`；例如已配置 `shiju` 且模型目录包含该模型时，可用 `shiju/deepseek-v4.1-flash`。`plan` 和 `keywords` 保持原值。这里第二模型仍生成文本画面建议。

显式模型不可用必须失败，不能把默认模型调用成功当作该模型验收通过。

## 保存与调用

先确认连接的是带运行时的 Agent gateway。`gateway/bootstrap.rs` 的 `client_router` 将 workflow router 挂在 `/v1`；执行入口为 `/v1/workflow/applications/{uuid}/chat-messages` 或 `/v1/workflow/applications/chat-messages`。轻量 `gateway/router.rs` 只挂保存和查询应用接口，不能据此推断有执行能力。

从仓库根目录运行以下示例。`BASE_URL` 使用实际监听地址，`PLATFORM_ID`、`COMPANY_ID` 使用当前租户，`SKEY` 使用已授权网关 skey。保留服务器认证设置；不要为复现关闭认证。若网关返回 401，先解决认证；跨租户 UUID 不可复用。

```bash
export BASE_URL='http://127.0.0.1:<实际端口>'
export PLATFORM_ID='<当前平台>'
export COMPANY_ID='<当前公司>'
# 通过安全方式将现有 skey 注入 SKEY；不要开启 shell 跟踪。
python3 - <<'PY'
import json
from pathlib import Path
sample = Path('crates/vw-agent/testdata/workflow/talking_head.yaml').read_text()
Path('/tmp/talking-head-save.json').write_text(json.dumps({
    'name': '本地口播样例', 'description': '只生成剪辑方案', 'workflow_yaml': sample
}, ensure_ascii=False))
PY
curl --fail-with-body -sS "$BASE_URL/v1/workflow/applications" \
  -H "Authorization: Bearer $SKEY" \
  -H "X-Platform-ID: $PLATFORM_ID" -H "X-Company-ID: $COMPANY_ID" \
  -H 'Content-Type: application/json' --data-binary @/tmp/talking-head-save.json
```

将保存响应的 `uuid` 写入 `WORKFLOW_UUID`。下面使用公开的人工短句，不使用客户转写。

```bash
export WORKFLOW_UUID='<保存响应的 uuid>'
python3 - <<'PY'
import json
from pathlib import Path
body = {
    'query': '生成口播剪辑方案', 'user': 'local-acceptance', 'response_mode': 'blocking',
```

也可在集合执行入口的请求体添加 `application_workflow`（完整 YAML），省略 UUID，直接运行未保存样例。路径 UUID 调用时不要同时传 `application_uuid` 或 `application_workflow`。

## 验收口径

阻塞响应的 `answer` 应可解析为 JSON，包含三种 `visual_type`：`keyword`、`b_roll`、`motion_graphic`；锚点必须来自原文，时间不得越过转写时长，素材数组非空。注意现有 blocking 响应只转换聊天答案，不携带工作流状态和节点错误；HTTP 200 本身不能证明执行成功。失败诊断使用 SSE。

SSE 应有 `workflow_started`、各节点的 `node_started`/`node_finished`、最终 `workflow_finished` 和 `message_end`。检查两个分支都完成后才开始 `validate`，所有节点状态为 `succeeded`，最终答案通过 JSON 解析。模型错误场景检查对应 `node_finished.data.error` 和 `workflow_finished.data.status == failed`；不要只检查 HTTP 状态或等待顶层 `error` 事件。

实际验收记录模型引用、各节点输入字符数、耗时、两分支开始/结束区间。聊天响应 usage 当前为零占位，SSE 的 `total_tokens` 也不代表 Provider 实际用量；没有底层用量证据时标“不可用”，不能用零宣称没有 token 消耗。只保存长度、状态和耗时，不保存凭据、签名链接或客户原始输入。

自动回归使用真实路由、认证、租户、YAML、变量池、执行器与校验器，仅替代模型传输，并用屏障断言 LLM 分支同时进入：

```bash

cargo test -p vw-agent --lib talking_head_api -- --nocapture
```
