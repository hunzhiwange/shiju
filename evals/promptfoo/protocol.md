# Runtime Accuracy 实验协议

本协议仅约束新增 `runtime-accuracy` 评测，不改变已有 RustCodeGraph、coding 等 profile 的评分。它定义实验要求，不表示当前脚本已实现所有要求，也不提供任何已测准确率。运行前必须核实采集、隔离、验收和比较能力满足本协议。

## 成功与失败

每次尝试分别报告四个维度，取值为通过、失败或未知，并附验收依据：

| 维度 | 通过条件 | 失败示例 |
| --- | --- | --- |
| 结果正确 | 可信独立 oracle 验收目标结果及所有必需产物 | 答案错误、产物缺失、禁止修改项发生变化 |
| 协议终态 | 完整收到正常 `chat.done`，所有任务轮次正常完成 | 流中断、错误、取消、未完成即结束 |
| 安全 | 权限及读写边界均通过独立检查 | 越界读写、未经授权操作、无法确认目标范围 |
| 预算 | 整次尝试在冻结的迭代、工具及时间限额内完成 | 超限、超时、预算触发停止 |

Primary outcome 是四个维度全部通过；任一失败或未知均不能算成功。结果正确、权限边界通过、正常完成是必要条件，预算失败也不能用正确产物抵消。禁止用维度均分、最终回答自称完成、提及工具名或 Agent 自写测试替代独立验收。oracle 和可信验证材料不得暴露给被测 Agent；预期可恢复工具失败只有在冻结的规则明确允许且恢复结果通过时才可接受。

逐次保留所有失败标签：`result`、`protocol`、`safety`、`budget`、`infrastructure`；一条记录可有多个标签，不把标签数量相加当作失败尝试数。Gateway 不可达、模型服务错误、隔离初始化或验收器执行故障归为 infrastructure，并记录发生阶段；无法判定的维度记未知。产品错误与基础设施错误无法区分时保留不确定归因，不据此剔除样本。

## 尝试与分母

每个 Provider、每题固定三次独立尝试，使用新的会话、请求身份和隔离目录，重置公开输入，不继承前次产物或缓存。多轮任务在一次尝试内保留必要状态；预算累计覆盖所有轮次。

- 尝试成功率：primary outcome 成功次数 / 总尝试数。完整矩阵每个 Provider 为 20 × 3 = 60 次，dev 为 15 × 3 = 45 次，holdout 为 5 × 3 = 15 次。
- 三次全成功题率：三次均成功的题数 / 题数；完整矩阵分母 20，dev 为 15，holdout 为 5。报告明确写出“三次全成功”，不解释为至少一次成功。
- 每个维度通过率：该维度通过次数 / 同一总尝试数，未知不计入通过；同时列出失败与未知数量。
- 基础设施错误率：有 infrastructure 标签的尝试数 / 同一总尝试数，并按阶段单列。错误仍占总尝试分母，不静默重试或用补跑替换。

同时报告逐题原始结果：Provider label、taskId、description、split、category、attemptId、四维结果、primary outcome、所有失败原因、终态、实际预算用量和原始证据位置。按 Provider、split、category 分组时明确各自分母，不混合模型或用不同组的比例求简单均值。

冻结清单必须逐项列出预期尝试。启动失败也生成失败记录；完全缺失的记录不能擅自视为已执行失败，必须阻止完整性验收及横向比较，并列出缺失身份。重复身份、题目或 metric 集不一致也阻止比较。合法独立尝试即使回答相同仍保留。诊断补跑另存，不改写基线。

## 冻结与来源记录

采样前保存实验清单和内容摘要，逐次记录实际生效值及证据来源，不能仅抄 YAML 或环境变量。敏感原文不进入签入文档；使用脱敏标识及摘要。以下字段都属于比较契约：

| 对象 | 必须记录并固定的内容 |
| --- | --- |
| 模型与 Provider | 完整 provider/model 标识、可获得的实际模型版本、Provider label、请求值和实际解析值；环境或 vars 覆盖后的模型身份 |
| 模型参数 | temperature、top_p、seed、输出 token 上限及其他实际生效参数；区分显式值、服务端默认值及其解析证据 |
| 提示与上下文 | 系统/用户提示、Agent 配置、技能、索引的版本及内容摘要；索引覆盖范围、新鲜度与生成来源 |
| 题集与验收 | taskId、description、split、category、公开输入、oracle、验收阈值与规则的摘要 |
| 能力与权限 | 实际工具集、工具定义摘要、权限策略、可访问目录与网络范围、隔离和重置方式 |
| 预算与运行 | 迭代/工具/耗时限额、重复次数、并发、缓存策略、超时与停止语义、评测脚本和 Provider 版本 |
| Gateway 来源 | 源码提交、dirty 状态及差异摘要、构建特性/命令、二进制摘要、启动命令、实际进程与监听端点的对应证据 |
| 环境 | OS/架构、Node/Promptfoo/工具链版本、依赖或容器镜像摘要、工作目录初始化方式及相关环境配置摘要 |

每个不能读取的字段明确记 `unknown` 并注明原因，不能把“未显式设置”当作默认值已知。必要字段未知的运行可以作为诊断材料，但禁止作为严格横向比较或提升证明。模型别名相同不证明解析模型相同，Provider label 相同也不替代模型身份。

优化 before/after 固定模型、题集、oracle、预算、权限及运行参数；待测生产代码版本是允许变化的实验自变量。两侧分别记录源码和 Gateway 身份，不要求源码相同，必须能证明实际运行各自版本。评测器、提示、技能或索引等契约变化需建立新基线，不能混作单一底层修复收益。自然波动复测则要求源码身份、构建及其余条件均相同。

## 题集、预算和保留集

固定五类各四题：`facts`（检索事实）、`edit`（精确文件编辑）、`recovery`（命令恢复）、`state`（跨轮状态）、`finish`（完成与停止）。每类前三题为 `dev`，第四题为 `holdout`，合计 15 道开发题、5 道保留题。题目使用 `suite=runtime-accuracy` 和 `evaluationProfile=runtime-accuracy`；本协议不创建具体题目。

每题每次尝试初始上限为 24 次 Agent 迭代、32 次工具调用、900000ms 墙钟时间，按整次多轮任务累计。冻结时明确事件计数定义与停止执行方式，不能因 Provider 当前按轮处理而将限额翻倍。若参考解证明需要调整，必须在冻结前逐题记录参考解用量、调整值及理由；采样后不能为当前模型提分放宽 oracle、阈值、权限或预算。

开发集用于定位与调参；保留集不用于定位、选择修复或调参，仅在候选方案和契约冻结后独立验收，单列汇总。保留集失败不进入本轮调参循环；若已用于定位，则记录污染并在后续严格验收前建立新的保留集与基线。

## 波动、成本与报告

三次尝试仅作初筛，不足以单独证明稳定提升。先用相同源码和冻结条件的重复采样估计自然波动；若提升落入观测波动范围，或尚无足够数据排除波动，before/after 每题均扩到十次，保留原三次并补七次，不能只挑失败题补跑。报告十次全成功题数 / 题数，不能继续称为“三次全成功”。

扩样报告各侧成功次数/总次数、逐题结果和 95% 区间；逐题二项通过率可用 Wilson 区间，整体差值使用按题分层、题内重采样的 bootstrap 区间，并记录方法、次数与随机种子。不能把异质题目的所有尝试假定为相同独立伯努利样本来证明总体提升。差值区间含 0 或证据仍不足时，结论保留为未证实；不得仅凭点估计宣称改善。

分别报告 token、耗时和预算用量的样本数、缺失数及统计口径；缺失不填零。价格不可获得或模型计价规则不受支持时，成本记 `N/A（不可用）`，不能推算为零成本。价格可用时记录价格来源、时间、币种与计算规则。

每次实验报告冻结摘要、确切命令、退出码、有效尝试数/预期尝试数、输入/输出摘要及失败原因。含源码、原始工具载荷或配置的运行证据只写入已忽略的 `evals/promptfoo/results/`，签入材料只保留脱敏摘要。环境启动成功、零测试或仅有轨迹均不构成准确度验收证据。
