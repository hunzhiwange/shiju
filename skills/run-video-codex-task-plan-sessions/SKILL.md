# 执行视频任务会话

开始时说明正在使用 run-video-codex-task-plan-sessions。先读取 [视频任务契约](../create-video-task-plans/references/video-tasks.md)。主会话只读取计划、任务和结果记录，并创建、等待及恢复任务会话；不亲自执行剪辑或改写任务状态。

## 入口与环境

1. 读取用户指定的 prompt.md；未指定时，仅在视频工作目录有唯一合理候选时选择。读取其 plan.md，要求 `任务类型：视频制作`，按 `# 批次 N`、`## 任务 N` 和 text 代码块解析，每个任务只对应一个会话，提示词原样传入。
2. 使用 list_projects 按 plan.md 的视频工作目录绝对路径匹配项目，不使用调度器所在代码仓库代替。缺少匹配项目、依赖技能或会话工具时报告缺口并保留续做入口，不转回主会话执行整条长流程。
3. 默认 local 环境，共享视频工作目录；默认不指定 model/thinking，沿用用户配置。用户指定模型时遵循其选择。读取现有调度记录，已有任务会话先核实状态，不重复创建。
4. 自动创建和恢复会话须属于用户授权的视频计划执行范围；缺少该授权时只交付计划入口。子任务不能因此取得额外付费、发布或导出权限。

## 调度

- 启动前检查每个任务的工程标识、访问模式、依赖、专属输出目录、结果路径和验收要求；缺失或冲突时不启动该任务，报告具体问题。
- 默认最大并发 3；计划另有明确值时遵循，但最多 10，并受实际宿主和服务限额限制。同一工程任何时刻最多一个写入任务，外部生成提交也串行。只读任务不得在运行中升级为写入。
- 按批次递增、任务编号顺序创建所有依赖已验收的任务，用 create_thread 指定匹配项目和 local 环境。每个会话创建成功后立即在计划目录 scheduling.md 记录任务编号、hostId、threadId（或尚在准备的 clientThreadId）；这是唯一由调度器写入的调度记录，不写任务状态、密钥或服务端模板正文。clientThreadId 不能传给要求 threadId 的等待或消息工具。
- 用 wait_threads 传入活动会话的 hostId、threadId 和最新 afterCursor；单次最多 8 个目标，活动集合更大时分组轮换。等待不超过 60 秒，期间保持简短必要进度说明。任一任务完成或暂不可运行，立即补位该批次可运行任务。
- 会话结束不是完成证据。读取任务状态和结果后按下面状态机判断；不能只依赖会话最终文本。

## 状态与恢复

- `已完成`：任务文件保留，结果记录存在，所需产物和验收证据完整，才满足后续依赖。
- `未开始` 或缺少完成证据：在原会话用 send_message_to_thread 要求继续、补齐验收和记录，不创建替代会话。
- `已阻塞`：读取具体证据。临时网络、队列或作业未完成时在原会话续查既有标识，不重新提交；相同阻塞无新证据不反复重试。权限、用户决定或预览确认缺失时保持阻塞。
- 文件缺失、未知状态或声称完成但证据不一致：视为异常，要求原会话先核实工程与已有作业，再恢复记录，不能推断成功。
- 阻塞恢复严格保持访问模式和原授权，不允许扩大范围、重复建工程、增加付费任务或重新导出。写入回执不明先核实远端状态。
- 当前批次暂不可运行的任务不占并发；可继续后续批次中不依赖阻塞项且满足互斥的任务。没有可运行任务后才停止并报告阻塞。

## 预览、收口与续做

预览确认必须有来自用户的证据。等待确认时向用户提供 shareUrl 和需要确认的事项，保留相关任务阻塞；恢复时继续原任务会话。用户未要求新成片时遵循 cutvideo 微调短路径，不默认导出。

所有任务完成后只核对最终交付记录及任务验收证据，不套用代码回归、不额外整片渲染。导出任务只提交一次，恢复时查询既有 exportId。成片只交付查看页 shareUrl。

最终简短报告整体完成或阻塞状态及用户所需的预览/成片链接。每个成功创建的会话仍单独输出 `::created-thread{threadId="..."}`（准备中则为 clientThreadId）。保留计划、任务、结果和 scheduling.md，续做时通过这些记录复用原会话与作业。
