# 执行视频任务会话

开始时说明正在使用 run-video-shiju-task-plan-sessions。先读取 [视频任务契约](../create-video-task-plans/references/video-tasks.md)。主会话只读取计划、任务和结果记录，并使用 ShiJu 内置会话工具创建、等待及恢复任务会话；不亲自执行剪辑或改写任务状态。

## 入口与环境

1. 读取用户指定的 prompt.md；未指定时，仅在视频工作目录有唯一合理候选时选择。读取其 plan.md，要求 `任务类型：视频制作`，按 `# 批次 N`、`## 任务 N` 和 text 代码块解析，每个任务只对应一个会话，提示词原样传入。
2. 确认当前主会话绑定的工作目录与 plan.md 的视频工作目录绝对路径一致。ShiJu 创建的任务继承当前项目与工作目录，不能通过创建参数切换项目；不一致时报告需从视频工作目录的会话执行，保留续做入口。缺少依赖技能或内置会话工具时同样报告缺口，不转回主会话执行整条长流程。
3. 使用同一工作目录内的原生可见任务会话。模型继承当前会话的非自动选择；当前使用自动选择时由运行时继续选择。工具不接受模型或推理参数；用户指定模型时先确认当前会话已选择该模型。读取现有 scheduling.md，用 list_threads 和 wait_threads 核实已有任务，不重复创建。只能访问当前主会话所属的可见子会话，其他主会话的记录不能直接接管。
4. 自动创建和恢复会话须属于用户授权的视频计划执行范围；缺少该授权时只交付计划入口。子任务不能因此取得额外付费、发布或导出权限。

## ShiJu 内置会话工具

使用当前运行时提供的以下工具名及参数，不调用 Codex App 插件。

| 用途 | 调用参数与返回值 |
| --- | --- |
| 创建 | `create_thread({"title":"任务标题","prompt":"完整任务提示"})`；异步启动，返回 `thread_id`、`project_id`、`directory`、`state`。 |
| 列举 | `list_threads({})`；返回当前项目、当前主会话所属的可见子会话 `threads`，用于核对已保存的任务映射。 |
| 等待或查状态 | `wait_threads({"thread_ids":["会话ID"],"timeout_ms":60000})`；任一目标进入终态即返回 `tasks` 快照与 `timed_out`，传 `timeout_ms: 0` 可立即查状态。 |
| 读取 | `read_thread({"thread_id":"会话ID","max_chars":65536})`；返回最近消息，可能截断，仅在理解结果或准备恢复提示时使用。 |
| 续发 | `send_message_to_thread({"thread_id":"会话ID","prompt":"恢复提示"})`；只允许续发已结束的可见子会话，成功后返回 `state: running`。 |

参数使用蛇形命名。创建只传 `title`、`prompt`，不传项目、环境、宿主、模型或推理字段；等待不传 `targets`、游标或 `condition`。会话状态为 `queued`、`running`、`succeeded`、`failed`；后两者只代表本轮结束。

## 调度

- 启动前检查每个任务的工程标识、访问模式、依赖、专属输出目录、结果路径和验收要求；缺失或冲突时不启动该任务，报告具体问题。
- 默认最大并发 3；计划另有明确值时遵循，但最多 10，并受实际宿主和服务限额限制。同一工程任何时刻最多一个写入任务，外部生成提交也串行。只读任务不得在运行中升级为写入。
- 按批次递增、任务编号顺序创建所有依赖已验收的任务，用 create_thread 传入任务标题和原始完整提示。每个会话创建成功后立即在计划目录 scheduling.md 记录任务编号、`thread_id`、`project_id` 和 `directory`；这是唯一由调度器写入的调度记录，不写任务状态、密钥或服务端模板正文。这里的 `project_id` 是 ShiJu 项目标识，与视频任务中的 cutvideo `projectId` 分开记录。
- 用 wait_threads 传入活动会话的 `thread_ids` 和不超过 60000 的 `timeout_ms`，期间保持简短必要进度说明。`timed_out: true` 只表示本次等待结束；仍为 `queued` 或 `running` 的任务继续等待，不续发、不释放其写入互斥或并发名额。处理终态后将其移出活动等待集合，立即补位该批次可运行任务，避免已结束目标导致等待反复立即返回。
- 会话结束不是完成证据。读取任务状态和结果后按下面状态机判断；不能只依赖会话最终文本。

## 状态与恢复

- `已完成`：任务文件保留，结果记录存在，所需产物和验收证据完整，才满足后续依赖。
- `未开始` 或缺少完成证据：确认原会话已为 `succeeded` 或 `failed` 后，用 send_message_to_thread 要求继续、补齐验收和记录，不创建替代会话。目标仍忙时继续等待，不重复续发。
- `已阻塞`：读取具体证据。临时网络、队列或作业未完成时在原会话续查既有标识，不重新提交；相同阻塞无新证据不反复重试。权限、用户决定或预览确认缺失时保持阻塞。
- 文件缺失、未知状态或声称完成但证据不一致：视为异常，要求原会话先核实工程与已有作业，再恢复记录，不能推断成功。
- 阻塞恢复严格保持访问模式和原授权，不允许扩大范围、重复建工程、增加付费任务或重新导出。写入回执不明先核实远端状态。
- 当前批次暂不可运行的任务不占并发；可继续后续批次中不依赖阻塞项且满足互斥的任务。没有可运行任务后才停止并报告阻塞。

## 预览、收口与续做

预览确认必须有来自用户的证据。等待确认时向用户提供 shareUrl 和需要确认的事项，保留相关任务阻塞；恢复时继续原任务会话。用户未要求新成片时遵循 cutvideo 微调短路径，不默认导出。

所有任务完成后只核对最终交付记录及任务验收证据，不套用代码回归、不额外整片渲染。导出任务只提交一次，恢复时查询既有 exportId。成片只交付查看页 shareUrl。

最终简短报告整体完成或阻塞状态及用户所需的预览/成片链接。原生任务会话由 ShiJu 展示，无需输出 Codex App 的会话 UI 指令。保留计划、任务、结果和 scheduling.md，续做时在原主会话中通过这些记录复用原任务会话与作业。
